# 阶段 5.10 - 发布前优化 Agent 化与步骤级开销追溯踩坑记录

## 1. ThreadLocal 不会自动跨异步工具线程

问题：

`LlmUsageContext` 使用 `ThreadLocal` 保存任务和步骤上下文，但 `ToolExecutor` 内部通过 `CompletableFuture.supplyAsync(...)` 执行工具。工具线程不是原业务线程，默认读不到 `ThreadLocal`。

影响：

Agent 调用 `knowledge_search` 时，工具内部触发的 Embedding 或 Rerank 可能写入模型调用日志，但没有 `workflow_step_id`，前端过程弹窗无法把它挂到 Agent 步骤下。

处理：

- `LlmUsageContext` 增加 `restore(...)`。
- `ToolExecutor` 在进入异步工具线程时恢复捕获到的上下文。

经验：

只要模型调用可能发生在异步线程，就不能假设 `ThreadLocal` 自动可见。后续如果引入线程池、异步事件或并发工具执行，都要显式传播上下文。

## 2. 旧直连方法内部重新打开上下文可能覆盖步骤场景

问题：

旧的 `generateSuggestion(...)` 内部会调用 `LlmUsageContext.open(taskId, "发布前优化")`。如果外层已经打开了 workflow step，上下文里的 step 信息需要保留。

影响：

如果直接覆盖，模型调用能保留 taskId，但步骤归属或场景名可能丢失，导致前端展示不准确。

处理：

`LlmUsageContext.open(...)` 在已有 workflow step 时继承 workflow 字段，并保留外层 scene。

## 3. Agent 失败不能直接覆盖为成功步骤

问题：

如果 Agent 失败后在同一个步骤里执行旧直连 LLM，并把该步骤标记成功，过程弹窗会误导用户，以为 Agent 成功生成了建议。

处理：

Agent 失败时：

- `AGENT_REASONING` 标记失败。
- 新建 `LLM_CALL` 回退步骤。
- 回退成功后只把 `LLM_CALL` 标记成功。

这样用户能看到真实链路：Agent 参与了主流程，但本次结果来自回退链路。

## 4. rawOutput 默认展示会干扰创作者主流程

问题：

原步骤回放在主页面直接展示输入、输出和 rawOutput。对开发排查有用，但对 UP 主阅读建议是噪声。

处理：

主页面改成轻量摘要。完整步骤和 rawOutput 放入过程弹窗，且 rawOutput 默认隐藏。

## 5. 过程弹窗按钮触控区域要满足移动端要求

问题：

原按钮基础高度是 38px，不满足本阶段“触控区域不少于 44px”的要求。

处理：

统一把主按钮、次级按钮、幽灵按钮和危险按钮的 `min-height` 调整为 44px。rawOutput 展开按钮也不用 `creator-mini-button`，避免移动端过小。

## 6. 消息流默认展示仍然会干扰主流程

问题：

发布前优化主页面虽然已经把步骤回放收进过程弹窗，但消息流和消息详情仍然默认占据首屏。对 UP 主来说，材料全文和系统消息属于排查信息，不应该盖过“生成建议”和“查看建议”动作。

处理：

主页面只保留顶部“查看消息流”入口按钮。消息列表、消息详情和补充要求输入框统一放入应用内弹窗，并保留刷新、Esc 关闭和移动端单列布局。
