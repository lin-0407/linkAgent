日期：2026-10-21。基线 `09e7695`，分支 `feature/creator-workspace-s1`。作者要求子 agent 独立审查，确认无阻断问题后继续开发。本轮实现见[S4-3a 阶段记录](../develop/视频自动制作-S4-3a音乐字幕与时长建议.md)，接口见[说明](../reference/音乐字幕与时长建议接口说明.md)。

## 独立审查与后续修复

三位子 agent 分别只读核对 S4-2 业务与版本/发布门禁、费用/运行/模型调用、素材/编译/渲染及恢复。均未确认当前公开 S4-2 链路存在阻止继续开发的代码缺陷。该结论基于当前源码和已有测试核对，不等于重新运行供应商或部署验收。

更正两项文档：静音工程仍有 AAC 音轨，验证的是无可听声音；总预算准入与发送前剩余可用预算/UNKNOWN 检查分别发生，可能先受理再因 reserve 拒绝而失败。旧内部 runtime.retry 不创建故事板关联记录，但全仓没有调用或公开重试路由，记为未来开放该入口必须处理的边界，没有把未开放路径包装成现存用户缺陷。

审查通过后推进 S4-3a，再由子 agent 跨模块复查新实现，发现并修复：

1. **纯 BGM 被 Java 误判为静音**：Python 已根据背景音乐正常出片，Java 产物验收仍仅根据场景旁白/原声判断，导致 NO_DIALOGUE+音乐工程被拒。现在存在非空音乐设置时按有声验收，保留声音/削波规则；新增 Java 纯音乐原生用例经过落盘、冻结、新租约恢复、真实渲染及再次验收。
2. **时长提案缺少视频依赖**：2 秒视频叠 3 秒录音时，仅建议延长镜头会造成选区不符或越界。现在延长/缩短视频场景明确要求同步调整选区；真实视频不足则提示补视频或换图，不单独给无法实现的延长方案。
3. **跨层约束同步**：仅独占背景音乐角色可使用 64 MiB；音乐不能兼任旁白。淡入/淡出各至多 10 秒、合计不得超过选区，音乐源和 API 上限统一 20 分钟；其他单文件 32 MiB、旁白 30 秒、合计 256 MiB 不变。

音乐、SRT 和时长建议不会自行调用收费服务；字幕保存和真实素材引用继续复用原不可变版本、任务锁、工作区 CAS 和活动制作门禁。

## 行为证据及适用范围

- 实际 PCM/FFmpeg 检查音乐截取、增益、全片淡入淡出、主音轨前无压低、对白稳定区音乐频段降低和恢复、量化尾部不读选区外声音、源不足及削波拒绝。信号来自受控测试波形，没有把测试音当成人声供应商结果。
- Java 原生链路实际走编译→私有对象夹具拷贝→冻结工程→新租约恢复→Python/FFmpeg→产物验收。覆盖原声/录音加音乐、只有音乐及原无音乐工程；存储夹具不是本次真实云 OSS 验收。
- 真实 MySQL 验证无音乐旧摘要兼容、仅 READY MUSIC 引用、音乐设置与历史引用冻结、SRT 新版本与父关系、原始换行/BOM 不同则同键拒绝、过期修订和超出音轨拒绝、无新增付费运行/账本，以及时长/音乐不足提案只读。
- SRT 来源明确为 `USER_PROVIDED`，只核对合法时间与真实媒体范围，不承诺系统核实每个字确实被说出。没有按字数推算 TTS 秒数或伪造自动对齐。
- 大音乐文件协议测试用 33 MiB 稀疏字节夹具验证摘要/拷贝/角色上限，明确不是音频解码证明；真实音频解码由独立原生用例验证。
