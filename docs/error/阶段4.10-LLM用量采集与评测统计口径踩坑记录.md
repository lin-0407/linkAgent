# 阶段 4.10 - LLM 用量采集与评测统计口径踩坑记录

## 1. 不能把人工评分说成自动准确率

问题：`accuracyScore` 是人工按评测用例给出的分项评分，不是模型自动准确率。

处理：文档和字段说明统一称为“准确性分项均值”，不写成“准确率”。真正的准确率需要标准答案、自动判定规则或多评审一致性。

## 2. usage 缺失不能伪造成 0

问题：不同模型供应商不一定返回完整 usage。如果代码把缺失值写成 0，会误导后续成本统计。

处理：`LlmCallResult` 中 token 字段使用 `Integer`，供应商未返回时保留 `null`。Spring AI 的空 usage 可能表现为三个 token getter 都返回 0，所以服务层需要把这类空 usage 归一成 `null`。

## 3. `List.of` 不能放 null

问题：统计每条结果的分项评分时，评分字段允许为空。如果用 `List.of(record.getAccuracyScore(), ...)`，只要其中一个字段为 null 就会抛异常。

处理：改用普通数组遍历，忽略 null 分项，只统计实际填写的评分。

## 4. 扩展响应字段后前端类型必须同步

问题：后端 `CreatorEvalPromptVersionStatsResponse` 和 `CreatorFeedbackChatResponse` 新增字段后，前端 TypeScript 类型如果不更新，后续类型检查会报错或页面无法提示新字段。

处理：同步更新 `src/types/creator.ts`，并在开发者测试弹窗和反馈追问结果中展示关键指标。

## 5. 标准差只能解释稳定性，不能替代质量判断

问题：分数波动低只说明同一版本输出更稳定，不代表质量一定更高。

处理：Prompt 版本对比同时展示均分、准确性均值、成功率、token 和评分覆盖率，避免单一指标误导判断。

## 6. 前端可选 token 字段不能默认提交 0

问题：开发者测试弹窗没有 total token 输入框，但草稿对象默认值是 0，提交时会把后端自动推导逻辑覆盖成 0。

处理：耗时和 token 这类可选数值默认用 `null`，提交前只把用户真正填写的数字放进请求体；token 输入最小值设为 1，后端也用 `@Positive` 和服务层归一兜底。

## 7. 统计接口不能复用最近结果分页查询

问题：结果列表只需要最近 N 条，但 Prompt 版本统计要解释“该版本的评测次数、成功率、token 总量和分数波动”。如果复用 `listResultsByCaseId(caseId, limit)`，超过 100 条后统计会被截断。

处理：Mapper 增加统计专用全量查询，页面列表继续分页，统计接口单独读取当前用例下全部结果。
