# 阶段 6.4 - 发布前优化证据化建议链路踩坑记录

## 1. 证据收集不能依赖 Agent 自己想起调用工具

问题：如果只在 Prompt 里要求 Agent 调用 `knowledge_search`，模型可能因为上下文、温度或输出格式压力而跳过工具。

处理：新增 `PrePublishEvidenceCollector`，由代码层前置生成检索 query 并调用案例检索服务。Agent 仍可补充调用工具，但已有证据包是稳定输入。

## 2. RAG 不可用不能中断发布前优化

问题：知识库开关关闭、Milvus 未就绪或检索失败时，如果直接抛错，会影响 UP 主主流程。

处理：证据收集器把不可用情况转成 `SYSTEM_LIMITATION` 证据，提示模型保守生成。

## 3. 响应字段扩展要和 Mapper、record、前端类型同时对齐

问题：`CreatorSuggestionResponse` 是 Java record，参数数量必须和 `toResponse` 完全一致；Mapper 也要同步 select、insert、result map。

处理：新增字段时同时更新 `CreatorSuggestionRecord`、`CreatorSuggestionResponse`、`CreatorSuggestionMapper` 和 `frontend/src/types/creator.ts`。

## 4. 本阶段不做审查器

原因：审查器会引入二次 LLM 调用、重写策略和失败处理，属于独立质量门禁。当前切片先让建议可追溯，避免一次改动过大。
