# 阶段 4.14 - 复盘报告 Markdown 导出踩坑记录

## 1. 不要把路径写成 `/reports`

问题：

最初方案写成 `GET /api/creator/tasks/{taskId}/reports/markdown`，但现有复盘接口分组是 `/api/creator/tasks/{taskId}/report`。

处理：

最终使用：

```http
GET /api/creator/tasks/{taskId}/report/markdown
```

原因：

接口路径风格要跟现有 Controller 保持一致，否则前端会同时出现 `report` 和 `reports` 两套路径。

## 2. `taskId` 不是数字 ID

问题：

最初方案提到可以用 `@Min(1)` 校验 `taskId`，但项目实际使用字符串 UUID 作为任务 ID。

处理：

沿用现有校验：

```java
@NotBlank
@Size(max = 64)
```

原因：

校验规则必须贴合真实数据结构，不能把数据库自增 ID 的习惯套到业务 ID 上。

## 3. 前端不要拼 Markdown

问题：

如果前端自己把报告 JSON 拼成 Markdown，后端接口和前端下载会变成两套格式来源。

处理：

前端只下载后端返回的 `Blob`，报告章节和 JSON 转 Markdown 规则统一放在 `CreatorReportService`。

原因：

导出格式属于业务产物，应该以服务端为准；前端只负责交互和下载。
