# 阶段 4.1.1 - 创作任务材料文件导入踩坑记录

## 1. 文件选择状态不能只靠界面重建

问题：前端文件输入框即使重新渲染了，`File` 引用本身还会留在响应式状态里。

处理：切换任务、取消编辑、保存修改和导入完成后，都要同步清空文件 ref，并重建输入框 key。

## 2. 导入动作必须和任务状态联动

问题：文件导入本质上也是材料更新，如果不把任务状态压回 `DRAFT`，后续发布前建议和复盘报告会继续沿用旧输入。

处理：导入成功且内容发生变化时，直接复用任务状态回退逻辑，让用户重新生成后续结果。

## 3. 文件导入也要遵守材料长度边界

问题：本地文件看起来像“纯文本”，但如果不校验长度，标题草稿和简介草稿就可能被导入成过长内容。

处理：文件导入沿用材料长度限制，并对不同材料类型分别做上限判断。

## 4. 只接受文本文件

问题：用户如果误传二进制文件，UTF-8 读取虽然能跑，但内容会变成乱码。

处理：接口只允许 TXT、MD、SRT、ASS 这类文本文件，避免把不可解析文件写进任务材料。
