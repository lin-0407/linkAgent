# 阶段 4.8 - 演示环境成本保护踩坑记录

## 1. 成本保护不要分散在每个业务 Service

问题：发布前优化、评论追问、竞品分析、复盘报告都会调用 LLM，如果每个 Service 单独限制，后续很容易漏掉新入口。

处理：把保护放在 `LLMService`，让所有模型调用共享同一条保护线。

## 2. 先不要为了 token 精度引入新依赖

问题：不同模型的 tokenizer 和计费规则并不完全一致，MVP 阶段强行做精确 token 计算，会让演示保护变成成本系统开发。

处理：本轮先用 `system prompt + user prompt` 字符数做粗粒度限制，后续真要做模型成本对比再升级。

## 3. 超限必须发生在模型调用前

问题：如果等 Spring AI 请求已经发出后再处理异常，成本保护就失去了意义。

处理：`LLMService.chat` 在构建 `ChatClient` 请求前先执行 `validatePromptLength`。

## 4. 默认值要适合演示环境

问题：如果保护默认关闭，作者很容易在 Docker 演示时忘记打开。

处理：`LLM_GUARD_ENABLED` 默认 `true`，并通过环境变量允许作者显式关闭。
