## 4. 本轮发现并修复的问题

1. **场景重建会丢 `visualPrompt`**：配音运行、时间线采纳、字幕导入都通过 `new Scene(...)` 重建场景；新增字段后仍用旧构造器会把 AI 提示词丢掉，下一次编译就会 `AI_VIDEO_PROMPT_MISMATCH`。三处都已补上 `scene.visualPrompt()`。
2. **时间线采纳不识别 `AI_VIDEO`**：延长场景时只同步 `VIDEO_CLIP` 的截取终点，AI 场景会保持旧终点并被编译器拒绝。现在两类视频布局都同步区间，并检查素材真实时长。
3. **场景级阻断没有进入总阻断**：估算只在场景里标 `BLOCKED`，受理却只检查顶层 `blockers`，会带着未解决的原声/超长问题开始付费。现在场景原因聚合到顶层，`generate` 直接 409。
4. **取消后已发送的费用静默停留在 RESERVED**：现在取消收口时把已发送调用的预留标为 `UNKNOWN`，未发送的由运行收尾释放；不承诺供应商退款。
5. **失败任务可能按请求秒数臆造费用**：结算改为成功时才允许以请求秒数兜底；失败且没有用量证据保留 `UNKNOWN`。
6. **并发同键可能多建一个没有任务行的运行**：受理只先查幂等键、再建运行；两个同键请求都能通过预检，第二个的 `DuplicateKeyException` 被捕获后事务照样提交，留下一个占用工作区的孤儿运行。现在在查重前先 `SELECT … FOR UPDATE` 锁任务行，并由唯一键兜底。同一问题在上一轮配音受理里存在，已一并修复。

以下为测试代码自身的问题，不是产品缺陷：

- 首轮 `view.storyboardId()` 取到的是来源故事板而非结果版本，断言改为 `storyboardResultId()`；
- 提案 `code` 是作者动作（`SHORTEN_SCENE`），失败原因在场景 `errorCode`（`VIDEO_CLIP_TOO_SHORT`），断言按此拆分；
- 下载用例只排了一个 mock 响应，第二次调用需要第二个期望。

## 5. 独立审查

独立子 agent 只读审查确认 1 个 P0、7 个 P1、6 个 P2。已修复并补测试：

### 5.1 P0：先配音后生成视频时保存必然失败

`saveGenerated` 只用"简报素材 + 本次运行产出"重建新版本的素材快照，父版本里的 TTS 配音不在其中；`codec.policy` 因"故事板引用了简报范围外素材"拒绝保存。结果是视频片段已付费并登记、运行却失败，重试仍卡在同一处。

修复：

- 保存新版本时并入父版本冻结快照的全部素材；
- `saveBoard` 不再依赖调用方逐项声明生成素材，而是从冻结快照的 `metadata.generated` 派生白名单；
- 新增 `savingVideoOnVoiceBoardKeepsNarrationAssets`，用真实 MySQL 验证"配音 + AI 视频"混合版本可保存、可编译。
