## 5. 本轮发现并修复的问题

独立审查确认 1 项 P1，并在实现过程中补了 3 处防御性校验。

### 5.1 P1：字幕全局时间用四舍五入的场景起点与未取整的片尾比较

原代码：

```java
double globalStart = Math.round((frameCount - count) * 1000.0 / FPS);
double actualSceneStart = (frameCount - count) * 1000.0 / FPS;
...
|| globalStart + cue.endMs() > frameCount * 1000.0 / FPS
```

`globalStart` 取整、片尾不取整。当场景起始帧 `k ≡ 2 (mod 3)` 时 `k * 1000 / 30` 的小数部分是 0.67，`round` 后最多比真实起点大 0.5ms。若该场景最后一条字幕结束时间正好等于量化后的场景末尾，`globalStart + cue.endMs` 会超出片尾 0.33ms，被误判为 `CUE_OUT_OF_RANGE`。

这类帧起点在 S4-3a/S4-3b 中很少出现（场景多为整秒），但 S4-3c 采纳 `EXTEND_SCENE` 后，场景时长来自"向上取整到帧"的音频长度，96 个场景里有近三分之一的起点会落在 `k ≡ 2 (mod 3)`。结果是：接口返回 200、写入新版本，但新故事板 `renderable=false`，作者只会看到一条无法解释的字幕越界。

修复（`StoryboardCompiler`）：

- 全局时间改用未取整的 `actualSceneStart`；
- 音轨末尾与片尾比较加 1ms 量化容差，与 `CLIP_DURATION_INVALID` 的 1ms 口径一致；
- 删除会造成重复计算的 `globalStart`。

同时给 `StoryboardAudioService#applyTimeline` 增加**采纳前后问题对比**：只拦截本次新引入的问题，原本缺配音或缺字幕的场景仍可继续按其它提案补齐（`timelineApplyStillWorksWhenAnotherSceneIsNotPreparedYet`）。

### 5.2 防御性校验

| 位置 | 校验 | 目的 |
| --- | --- | --- |
| `StoryboardPersistence#saveTimeline` | 新简报 `targetDurationMs` 必须等于调整后场景帧长 | 防止服务层计算错误被写成不可变简报 |
| `StoryboardAudioService#applyTimeline` | 视频区新终点 ≤ 1800000ms | 与编译器的截取上限一致 |
| `StoryboardAudioService#applyTimeline` | 音乐区新终点 ≤ 1200000ms | 与简报校验的 20 分钟上限一致 |

### 5.3 测试代码自身的错误

原生用例首次失败在 `expected: 4000L but was: 0L`，原因是断言读取了简报字段名 `sourceOutMs`，而 V2 工程字段名是 `sourceEndMs`。修正断言后通过；产品代码本身没有问题。
