# 阶段 4.13 - 踩坑记录

## 坑 1：OpenAI Embedding 自动配置 `matchIfMissing=true`

**现象：** `spring.ai.model.embedding` 如果不显式写，`OpenAiEmbeddingAutoConfiguration` 会默认激活（因为 `matchIfMissing=true`），导致 Spring 容器尝试创建 `OpenAiEmbeddingModel`，即使你没有打算用 Embedding。

**原因：** Spring AI 1.1.4 的 `@ConditionalOnProperty(name="spring.ai.model.embedding", havingValue="openai", matchIfMissing=true)` 中 `matchIfMissing=true` 意味着属性缺失时也满足条件。

**解法：** 在 `application.yml` 显式写 `spring.ai.model.embedding: ${EMBEDDING_MODEL_TYPE:none}`，`none` 不等于 `openai`，自动配置不激活。

## 坑 2：Milvus 自动配置同样有 `matchIfMissing=true`

**现象：** 同理，`spring.ai.vectorstore.type` 缺失时 `MilvusVectorStoreAutoConfiguration` 也会尝试激活，导致启动时连接 Milvus 超时（历史踩坑）。

**已处理：** 项目早期已加 `VECTOR_STORE_TYPE=none`，配置有效，本阶段不需要再改。

## 坑 3：`@Transactional` 不能包裹 Milvus 写入

**现象：** 若给 `IndexService.rebuild()` 加 `@Transactional`，遇到 Milvus 写入异常回滚时，MySQL `embedding_status` 会回到旧值，但 Milvus 里的向量可能已经写进去了，造成状态与实际分叉。

**解法：** 不加 `@Transactional`，按批提交，按批逐条更新状态，让 `embedding_status` 始终真实反映向量库现状。

## 坑 4：`VectorStore` 不能强依赖注入

**现象：** 默认 `VECTOR_STORE_TYPE=none` 时没有 `VectorStore` Bean，如果直接 `@Autowired VectorStore`，启动报 `NoSuchBeanDefinitionException`。

**解法：** 改用 `ObjectProvider<VectorStore> vectorStoreProvider`，`getIfAvailable()` 返回 null 时走 SQL 兜底，不影响启动。

## 坑 5：MyBatis `<script>` 标签在 `@Select` 注解中需要换行

**现象：** MyBatis 动态 SQL 标签 `<script>` 写在 `@Select` 的文本块时，如果 XML 标签格式不标准会报解析错误。

**注意：** 用 Java 文本块（`"""`）写多行时，`<if test='...'>`、`<foreach>` 等标签必须是完整 XML，属性值要用单引号，不能用双引号（会和文本块的 `@Results` 引号冲突）。
