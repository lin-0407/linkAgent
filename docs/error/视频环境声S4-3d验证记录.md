## 3. 本轮新增的 Java 覆盖

### 3.1 编译器（`StoryboardCompilerTest`）

| 用例 | 验证的事实 |
| --- | --- |
| `ambienceIsAnIndependentBedWithItsOwnVolumeAndNoDuckingField` | 合法工程输出 `ambience`，`gainDb=-24`，**没有** `ducking` 字段，且不产生 `backgroundMusic` |
| `ambienceMustMatchTheWholeFilmAndStayInsideRealSource` | 区间 1000ms 对全片 2000ms → `AMB_DURATION_MISMATCH`；选区超过素材 1.5 秒 → `AMB_OUT_OF_RANGE`；无素材 → `AMB_MISSING`；用 `NARRATION` 素材顶替 → `AMB_MISSING` |
| `ambienceAndBackgroundMusicCannotShareOneSource` | 两路引用同一素材 → `AMB_DUPLICATE_SOURCE` |
| `invalidAmbienceMixAndRangeAreExplicitProblems`（4 个参数） | 音量 > 0、淡入淡出合计越界、小数起点、负起点都命中 `AMB_MIX_INVALID` |
| `ambienceUsesTheSameSixtyFourMibLongAudioRole` | 64 MiB 允许，64 MiB + 1 字节 → `ASSET_RENDER_LIMIT` |

### 3.2 真实 MySQL（`StoryboardPersistenceIntegrationTest`）

- `ambienceIsStoredAsAnIndependentBedAndCannotReuseMusicSource`：简报同时保存两路音轨，`ambience` 没有 `ducking` 字段；用同一素材再建简报被拒绝，简报数仍为 1。
- `timelineApplyMovesAmbienceWithTheNewTotalDuration`：采纳 `EXTEND_SCENE` 后总时长 3000→4067，环境声终点从 3500 调整为 4567，`notes` 明确写出；新故事板 `renderable=true`。

上轮 87 项，本轮新增 7 项（`test_music.py` 的 `AmbienceTest` 6 项 + `AmbienceNativeTest` 1 项）：

| 用例 | 验证的事实 |
| --- | --- |
| `test_ambience_keeps_its_level_while_music_ducks_under_speech` | 同一工程中，0.2–0.4s 与 0.8–1.2s 的 220 Hz 环境声电平一致（±20%），660 Hz 背景音乐在有对白时段降到一半以下，440 Hz 旁白存在 |
| `test_ambience_alone_still_counts_as_a_real_audio_plan` | 去掉背景音乐、只留环境声时，工程仍被判定为有声，输出 96000 样本且峰值 > 0.002，不被静音检查误判 |
| `test_ambience_range_must_cover_the_whole_film` | 区间只有 500ms → 拒绝，提示"环境声选区时长" |
| `test_ambience_cannot_reuse_the_music_source` | 与背景音乐同素材 → 拒绝 |
| `test_v1_rejects_ambience_and_unknown_fields_are_refused` | V1 携带 `ambience` → 拒绝；V2 加未知字段 `ducking` → 拒绝 |
| `test_ambience_gain_and_fades_are_strict` | 音量 1 dB → 拒绝；淡入 1500 + 淡出 501 超过 2000ms 区间 → 拒绝 |
| `AmbienceNativeTest.test_real_ambience_survives_encoding_while_music_ducks` | 真实 FFmpeg 编码 2000ms 出片，`fullDecodePassed=true`；解码后 0.6–0.9s（有对白）与 1.6–1.9s（无对白）的 220 Hz 环境声能量在 ±30% 内，660 Hz 背景音乐在有对白时降至 60% 以下 |

过程中修正了两个测试自身的问题：

1. 单频幅度没有按窗口样本数归一化，比较 0.2s 与 0.4s 窗口时出现 2 倍差；改为除以 `len(data)`。
2. 断言把背景音乐频率写成 440 Hz，实际素材是 660 Hz（440 Hz 是旁白）；按真实频率改回后通过。

两处都是测试代码错误，产品实现没有因此改动。

## 5. Java 原生渲染

本轮创建了 `linkagent-s4-ambience-native-20261022`（`maven:3.9.9-eclipse-temurin-21`），在容器内安装 FFmpeg、Python 3.12、Pillow/numpy/fonttools 与 Noto CJK。apt 索引和软件包下载在 20 多分钟内只推进到约 120/300 个包，未能在本轮完成环境搭建，容器已删除。

因此 `StoryboardCompilerNativeTest` 的 8 项在宿主全部跳过，本轮**没有**执行 Java 侧原生出片。

已有的等价覆盖：

| 断点 | 证据 |
| --- | --- |
| Java 编译器把 `ambience` 写进 V2 工程 | `StoryboardCompilerTest` 断言 `assetId/sourceStartMs/sourceEndMs/gainDb`，并确认没有 `ducking` 字段 |
| Python 契约接受该结构 | `AmbienceTest` 全部经过 `load_project` 校验 |
| 混音行为：环境声不压低、背景音乐压低 | `AmbienceNativeTest` 真实编码后解码，比较 220 Hz 与 660 Hz 能量 |
| 整片编码与时长 | `AmbienceNativeTest` 断言 2000ms 与 `fullDecodePassed=true` |

仍然缺的是"Java 编译器输出直接交给 Python 渲染器"这一跳。两端字段名分别由各自测试固定，但没有一次端到端串接。这一项保留为未完成，不写成已通过。
