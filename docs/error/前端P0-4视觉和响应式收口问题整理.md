# 前端 P0-4 视觉和响应式收口问题整理

## 1. 移动端左侧流程栏容易挤压主内容

问题：创作台桌面端使用左侧流程栏，但窄屏下如果完整保留，会让主内容区域变窄。

处理：新增移动端进度摘要，并在 820px 以下把流程卡片固定在顶部区域。

原因：移动端用户更需要知道“当前到哪一步”，不需要一直看到完整桌面侧栏。

## 2. CSS Grid / Flex 子项可能撑出横向滚动

问题：长标题、长标签、错误信息和结果文本在 Grid/Flex 容器里可能因为默认最小宽度撑破页面。

处理：对创作台主容器、结果块、表单网格、面板标题和操作区补充 `min-width: 0` 与自动换行规则。

原因：这能让子项按容器宽度收缩，优先在内部换行，而不是把整个页面撑宽。

## 3. 小按钮在移动端不方便点击

问题：历史样式里部分小按钮高度低于移动端推荐触控尺寸。

处理：统一把主要按钮、次级按钮、幽灵按钮、危险按钮、小按钮、步骤按钮和设置入口的 `min-height` 收口到 44px。

原因：44px 是移动端常见的最小触控目标，能减少误触。

## 4. 开发者辅助入口不应污染普通四步进度

问题：`activeStep` 可能进入 `usage`，但普通创作者流程只有四步。

处理：当当前步骤是 `usage` 时，移动端进度条仍显示在“复盘报告”。

原因：开销统计属于开发者辅助入口，不应在普通路径里变成第五步。
