# 阶段 4.5.2：创作任务管理体验优化踩坑记录

## 1. 不要只改列表样式，不补后端动作

问题：任务列表看起来更清楚了，但没有更新和删除接口，前端按钮依然是摆设。

处理：先补 `PUT /api/creator/tasks/{taskId}` 和 `DELETE /api/creator/tasks/{taskId}`，再改界面。

## 2. 任务更新不能直接覆盖旧材料而不做状态处理

问题：如果材料改了，旧的发布前建议和复盘结果会和新内容不一致。

处理：只要材料变化，就把任务状态退回 `DRAFT`，让用户重新走生成链路。

## 3. 删除任务不能顺手把上下游证据一起抹掉

问题：任务和材料删掉后，历史分析记录还在，前后端证据会断。

处理：任务删除改成软删除，材料也做逻辑删除，历史结果继续保留。

## 4. 编辑模式不能和创建模式共用一个空状态

问题：如果编辑和创建都不区分，用户很容易误以为自己在改当前任务，实际上是在新建。

处理：前端把任务表单拆成“创建 / 编辑”双模式，并在标题和按钮文案里明确当前状态。

## 5. 删除一定要二次确认

问题：任务列表里直接放删除按钮，误点成本很高。

处理：删除先进入侧栏确认条，用户再次确认后才真正执行。

## 6. 高级感不是继续加装饰

问题：第一版任务管理区虽然功能完整，但颜色和阴影太重，容易显得像按钮和卡片的堆叠。

处理：收敛为中性工作台视觉，弱化粉色背景、硬阴影和渐变，用标题、状态、材料数和蓝色激活线建立层级。
