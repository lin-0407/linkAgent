# 阶段 5.4：Agent 内核结构化输出升级踩坑记录

> 本文件记录阶段 5.4 实现中必须记住的坑点。阶段 5.4 已由作者在 2026-06-09 完成编译与开关两态自测，后续改 Agent 内核时优先回看本文件。

## 1. `json_object` 只保证 JSON 合法，不保证字段正确

**问题**：DeepSeek 兼容 OpenAI 的 `response_format=json_object` 可以约束模型返回合法 JSON，但不会强制它一定包含 `thought/action/actionInput/finalAnswer`。

**处理**：`LLMService.chatStructured` 同时使用 `.entity(type)` 做强类型解析，并在解析失败时最多重试 3 次。

**原因**：JSON 语法正确不等于业务 schema 正确。强类型解析能把缺字段、字段类型不对等问题显式暴露出来。

## 2. 结构化内核初期必须默认关，稳定后再默认开

**问题**：`AgentExecutor` 是通用聊天入口和后续创作 Agent 化的共同内核，一次性替换默认路径风险太大。

**处理**：阶段 5.4 初期新增 `agent.kernel.structured.enabled`，默认 `false`。完成开关两态自测后，后续将默认值调整为 `true`，并接入设置面板运行期开关；关闭开关时仍可回退文本 ReAct。

**原因**：这是内核级改动。初期默认关可以保证 `/api/agent/chat` 不被结构化改造影响；稳定后默认开，才能真正减少对 `Thought:/Action:` 文本格式提示词的依赖。保留运行期开关，是为了结构化输出兼容性异常时能快速回退。

## 3. 不能把发布前优化内部取证写进用户会话记忆

**问题**：阶段 5.3 新增的 `runTask()` 是任务内部推理入口。如果复用 `run()`，会把内部取证过程写进短期记忆，还可能触发长期记忆抽取。

**处理**：`runTask()` 不读写短期记忆、摘要记忆和长期记忆；阶段 5.4 也让它支持结构化内核。

**原因**：发布前优化的取证过程不是用户聊天回合。写进会话会污染历史记录，也会产生无意义的长期记忆。

## 4. 结构化系统提示词不要再写文本格式约束

**问题**：文本 ReAct 的系统提示词要求模型输出 `Thought:`、`Action:` 等格式。结构化路径如果继续强调这套文本格式，会和 JSON schema 目标冲突。

**处理**：结构化系统提示词使用 `agent_executor_structured.system`，只说明每步如何在 `ReActStep` 字段里二选一：要么调用工具，要么给最终答案。

**原因**：结构化路径的格式约束由 `BeanOutputConverter` 追加的 schema 指令承担，系统提示词只需要解释业务语义。

## 5. 运行期 options 只设置 responseFormat

**问题**：`chatStructured` 创建 `OpenAiChatOptions` 时只设置 `responseFormat`，没有显式设置模型名。如果 Spring AI 的运行期 options 合并行为变化，可能导致模型默认值没有正确带上。

**处理**：当前阶段按 Spring AI 1.1.4 的 options 合并行为实现，并在开发文档中记录运行期待确认。

**原因**：只设置必要字段能避免复制一份模型配置。后续如果实跑出现模型缺失，再把模型名显式补进 options。

## 6. 提示词 DB 化后单测构造点要同步补 `PromptService`

**问题**：阶段 5.5 把 `AgentExecutor` 的系统提示词迁到 DB 后，构造器新增 `PromptService`。单测里手动 `new AgentExecutor(...)` 的地方如果漏传 `StubPromptService`，会直接编译失败。

**处理**：`AgentExecutorLongTermMemoryTest` 的 3 个构造点已补 `new StubPromptService()`。

**原因**：Spring 容器能自动注入新增依赖，但单测手动构造不会自动补参数。后续改构造器时要全仓搜索 `new AgentExecutor(`。

## 7. 文本 ReAct 格式漂移不能记录成空步骤

**问题**：文本 ReAct 路径中，如果 LLM 没有输出 `Thought:`，旧逻辑会先追加一个空 `AgentStep`，随后继续解析 `Action:`。当 `Action:` 也不存在时，同一轮又追加一条相同编号的空步骤。前端会显示两个“第 1 步”，并提示“后端返回了步骤编号，但没有返回本步的思考、行动或观察内容”。

**处理**：`run()` 和 `runTask()` 在未解析到 `Thought:` 时，只记录一条带诊断说明的步骤，并立即 `continue` 进入下一轮，让模型按错误提示重试。

**原因**：这类步骤不是正常推理步骤，而是模型格式漂移的恢复过程。前端需要看到明确诊断，后端也不能把同一次格式错误拆成两条空步骤。
