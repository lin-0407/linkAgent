## 验证边界

在本轮独立容器内使用 Java 21、Maven、FFmpeg/FFprobe，Testcontainers 创建真实 MySQL 8.4 和 RustFS。未连接作者已有 `bd_mysql`、其他容器数据库、生产 OSS 或收费供应商。接口验证使用真实 Controller 的 MockMvc，再用 HTTP 直传到真实 S3 分片短签；没有浏览器或完整 Spring Boot 平台部署。

源码快照只含当前后端和 renderer 文件，以及本轮新增测试，共 759 文件；按排序后的相对路径 UTF-8、零分隔、实际文件字节计算 SHA-256：`3a367ee9a26f0e5b3cadd63467fc84bcd2ba75f5fbf439ad344ae7f0f36c0c77`。没有复制 `.env` 或前端工作区。

测试过程发现并修复：

- 新表显式使用 unicode 排序规则、旧表采用 MySQL 8 默认规则，跨表归属查询出现 `Illegal mix of collations`；新表改为仓库一致的字符集声明，使用真实 MySQL 再验证。
- `List<@Valid ...>` 不会拒绝 null 元素，素材服务补充空记录校验，HTTP 返回 400。
- 无扩展名文件被误识别成扩展名、裸 AAC 在上传后才拒绝，改为创建前拒绝。
- PUT 前无持久清理依据、在途取消可能提前确认清理，补对象清单、请求总超时、清理屏障和再次核对。
- 延期取消可能占满候选队列，首次撤销后改为等待屏障到期再扫描。
- 磁盘预检未涵盖完整 GET 校验副本，预留改为源大小加 4 GiB 和 128 MiB 余量。
- READY 提交后响应丢失、任务又软删除时，公开归属查询为空不能认定对象未被引用；改为保留并由内部清理扫描核对历史清单。
- 存储查询返回后与派生 PUT 前再次核对数据库执行权，避免取消后因旧心跳缓存继续启动新写入。
- 失租执行器不得撤销新代正采用的同一分片句柄；只在明确取消时撤销，恢复按准确对象键接管。

初次离线测试缺少 Surefire JUnit provider，在线补齐到本轮容器缓存后恢复离线运行；一次测试编译修正 `Container` 通配导入冲突。这些失败尝试不计为通过结果。
