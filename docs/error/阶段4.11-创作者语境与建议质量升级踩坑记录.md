# 阶段 4.11 - 创作者语境与建议质量升级踩坑记录

## 1. 只改 Prompt 不改输出结构，容易继续泛泛而谈

问题：如果只在 Prompt 里写“请更有深度”，但响应结构仍然只有摘要、受众、标题、标签，模型会倾向于把深度压缩到几句泛泛理由里。

处理：新增 `creatorDilemma`、`audienceHook`、`contentPositioning`、`actionableRevisionPlan`，让模型必须回答创作者困境、观众动机和下一步动作。

## 2. 新字段必须贯穿 Record、Response、Mapper 和前端类型

问题：发布前建议字段链路较长，只改实体或只改响应都会导致 MyBatis 查询缺字段、前端类型缺字段或弹窗无法展示。

处理：同步更新 `CreatorSuggestionRecord`、`CreatorSuggestionResponse`、`CreatorSuggestionMapper`、`src/types/creator.ts` 和 `CreatorWorkspace.vue`。

## 3. 已有本地库不会因为 CREATE TABLE 自动补列

问题：`CREATE TABLE IF NOT EXISTS` 只对新库有效，已有 `creator_suggestion` 表不会自动新增列，新代码上线后会出现未知列错误。

处理：在 `init.sql` 中加入基于 `information_schema.COLUMNS` 的条件式 `ALTER TABLE`，本地重复执行脚本也不会重复加列。

## 4. RAG 不是低质量建议的第一解法

问题：当前输出质量差的主要原因是分析框架浅，不是证据量不足。直接接入 RAG 会把问题变成“带证据的浅建议”。

处理：先完成发布前优化质量结构升级，再考虑把反馈追问或外部资料作为 RAG 证据源接入。
