# RAG 主题中块与三层分块踩坑记录

## 1. 不能把中块做成 LLM 新摘要

**问题**：如果让 LLM 为每个视频生成主题中块，会增加导入成本，也可能产生原材料里没有的结论。

**处理**：中块只从标题、简介、标签、亮点摘要和已清洗评论弹幕确定性拼装。

**原因**：本轮优化目标是“召回粒度”，不是生成新知识。

## 2. 老数据没有中块

**问题**：上线前已导入的视频只有父块和子块，直接新增中块索引会找不到待索引数据。

**处理**：`/index/chunks/rebuild` 在索引前先查询没有中块的视频，并补齐主题中块。

**原因**：不要求作者重新采集或重新导入旧案例，降低升级成本。

## 3. 中块文档 ID 不能当 videoId

**问题**：中块向量文档的 id 是 `chunkId`，不是 `videoId`。如果检索时回退 `document.getId()`，会把中块 ID 当成视频 ID。

**处理**：中块召回只从 metadata 读取 `videoId`，不回退文档 id。

**原因**：父块、主题中块、子块的主键语义不同，回查父表时必须统一使用 `videoId`。

## 4. hybrid 路径先不混中块 dense 集合

**问题**：当前 `HYBRID` 表示父 / 子 hybrid 集合的 dense+BM25 召回。如果混入中块 dense 集合，mode 名称会无法说明真实路径。

**处理**：中块 dense 召回只在非 hybrid 路径启用。

**原因**：检索模式回显要可信。中块 hybrid 应作为独立后续切片。

## 5. 历史补齐不能按三类硬凑

**问题**：有些历史视频没有评论或弹幕素材，无法生成观众反馈中块。如果补齐查询按“少于三类”判断，这类视频会反复被扫描。

**处理**：补齐条件改为“缺少可生成的中块”。标题包装和内容定位从父表生成，观众反馈只有存在子条目时才要求补齐。

**原因**：分块要忠于已有材料，不能为了凑齐三类制造空块。
