# 阶段 4.4.1.5：反馈追问与 RAG 预留踩坑记录

## 1. 不要把前端问题扩展成“前端传证据”

问题：追问接口如果允许前端提交报告片段或证据列表，用户可以伪造评论弹幕依据。

处理：请求体只接收 `question`，报告和证据都由后端按 `taskId` 查询。

## 2. 没有向量库时也要有证据结构

问题：如果第一版只返回纯文本回答，后续接 RAG 时前端还要重写展示结构。

处理：响应中保留 `evidenceItems`、`retrievalMode` 和 `ragEnabled`。当前 `ragEnabled=false`，但前端已经按证据列表展示。

## 3. 旧追问结果不能跨数据版本残留

问题：用户重新导入样例或重新分析反馈后，之前的追问回答可能引用旧证据。

处理：保存样例、导入文件、BV 拉取和重新分析反馈时清理 `feedbackChatResult`。

## 4. 追问入口不能回到表单下方

问题：如果把回答铺在评论弹幕输入区下面，会重新回到“输入和结果混杂”的设计问题。

处理：追问输入、回答和证据都放在反馈分析报告独立弹窗内。
