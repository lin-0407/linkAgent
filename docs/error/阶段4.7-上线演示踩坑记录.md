# 阶段 4.7 - 上线演示踩坑记录

## 1. 前端和 API 最好走同源

问题：如果前端直接连后端端口，后面做 SSE 和文件上传时会多出一层 CORS 排查。

处理：让前端容器里的 Nginx 统一代理 `/api`，浏览器只访问一个入口端口。

## 2. SSE 不能被 Nginx 缓冲

问题：如果代理层默认开启 buffering，工作流消息会攒到最后一起返回，看起来像“没有流式输出”。

处理：在 `/api` 代理段显式关闭 `proxy_buffering` 和 `proxy_cache`，并把超时时间拉长。

## 3. MySQL 初始化脚本只会在第一次启动时执行

问题：很多人会以为改了 `init.sql` 后重启容器就会自动重跑，但 MySQL 官方镜像不会这么做。

处理：演示环境默认把样例数据一次性放进初始化脚本里；如果后续要重置数据，要清掉卷再重建。

## 4. 构建上下文要尽量小

问题：把 `target` 或 `node_modules` 带进 Docker 构建上下文，会让打包明显变慢。

处理：后端和前端各自加 `.dockerignore`，只保留真正需要的源码和锁文件。

## 5. 初始化库名不能和连接串分离

问题：`init.sql` 里把库名写死成 `link_agent`，如果 Compose 再放一个可变的 `MYSQL_DATABASE`，很容易出现“脚本写到 A 库，后端连到 B 库”的假正常。

处理：演示环境直接把库名固定为 `link_agent`，减少首次启动时的配置分叉。
