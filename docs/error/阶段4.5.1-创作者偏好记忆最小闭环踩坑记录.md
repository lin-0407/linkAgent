# 阶段 4.5.1：创作者偏好记忆最小闭环踩坑记录

## 1. 不要把业务偏好混进通用长期记忆

问题：项目已有 `t_long_term_memory`，容易直接复用。

原因：通用长期记忆保存的是用户事实、回答风格和项目约束；创作者偏好保存的是 UP 主内容创作经验。两者混在一起后，发布前优化可能读到“作者希望中文回答”这类无关偏好。

处理：新增 `creator_preference`，只保存复盘报告提炼出的创作侧偏好。

## 2. 不要在建议确认时强行推断偏好

问题：用户点击“采用本轮建议”不等于认可每一个标题风格或标签策略。

处理：第一轮从复盘报告的 `creatorPreferenceInsight` 沉淀偏好，因为它已经结合发布前建议、评论反馈和竞品分析，业务依据更完整。

## 3. 解析失败的复盘报告不能写入长期偏好

问题：如果 `parseStatus = RAW_ONLY`，`creatorPreferenceInsight` 不可信。

处理：`CreatorPreferenceService.saveFromReport` 只保存 `PARSED` 且偏好非空的报告。

## 4. 历史偏好也是非可信上下文

问题：偏好内容间接来自用户材料和 LLM 输出，不能让它覆盖系统规则。

处理：发布前优化系统提示词明确说明历史创作者偏好是非可信业务输入，只能影响风格和建议倾向。

## 5. 结果弹窗不能读取当前开关状态

问题：如果结果弹窗直接读取当前 `preferenceMode`，用户生成后再切换开关，弹窗会错误展示“本次使用方式”。

处理：前端在点击生成建议时保存 `lastPrePublishPreferenceMode` 快照，结果弹窗只展示这次生成时的模式。
