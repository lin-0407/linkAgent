# 阶段 4.3.3：B 站评论弹幕样例采集脚本踩坑记录

## 1. F12 可见不等于可以无边界采集

问题：

浏览器能看到评论和弹幕请求，但这只说明页面加载需要这些数据，不等于可以批量脚本化采集或绕过登录态。

处理：

脚本限制为单 BV、本地、限量、非登录，不读取 Cookie，不绕过风控。

原因：

作品集项目要展示工程边界意识。把本地样例采集做成批量爬虫，会偏离当前“用户主动提供/样例数据”的主线。

## 2. 评论不能拉平成一段文本

问题：

评论区有主楼评论和回复评论。如果直接拼成一段，AI 后续分析会丢失讨论链路。

处理：

JSON 中使用 `rootComments[]` 表示主楼评论，每条主楼下使用 `replyComments[]` 表示回复评论。

原因：

争议点、误解点和互动建议往往出现在回复讨论中，保留层级比简单拼接更利于分析。

## 3. 弹幕和评论不能混在一起

问题：

弹幕有播放时间轴，评论有楼层和回复关系，两者语义不同。

处理：

输出结构将 `comments` 和 `danmaku` 分成两个顶级区块，弹幕按分 P 组织。

原因：

后续做 AI 分析时，弹幕更适合做“时间段情绪/吐槽点”分析，评论更适合做“观点和讨论链路”分析。

## 4. 外部网页接口不是稳定依赖

问题：

B 站网页接口可能调整参数、访问策略或风控规则。

处理：

脚本遇到限制时写入 `warnings` 或直接失败，不把失败伪装成空数据，也不自动尝试绕过。

原因：

外部接口不稳定时，清晰失败比隐式错误更容易排查。

## 5. 旧评论接口可能静默返回空列表

问题：

实测视频的视频信息里 `stat.reply` 有评论数量，但旧 `x/v2/reply` 接口返回 `reportedTotal=0`、`rootCount=0`，脚本会误以为没有评论。

处理：

当旧接口没有返回主楼评论，并且视频统计显示存在评论时，自动回退到 `x/v2/reply/wbi/main`。

原因：

B 站新版评论区使用 cursor 分页和 WBI 签名。只使用旧页码接口会在部分视频上得到“假空结果”。

## 6. WBI 签名接口未登录也可能返回 key

问题：

`x/web-interface/nav` 可能返回 `code=-101`，但 `data.wbi_img` 中仍包含公开视频接口签名需要的 key。

处理：

脚本优先读取 `data.wbi_img`，只有缺少该字段时才视为签名信息不可用。

原因：

WBI key 是网页公开接口的一部分，不是登录 Cookie。把 `-101` 直接当失败会导致非登录场景无法读取新版评论接口。

## 7. 默认输出目录不能依赖当前命令行目录

问题：

如果从 `E:\linkAgent` 运行脚本，旧默认相对路径会输出到仓库外的 `E:\linkAgent\exports`，导致排查时找不到文件。

处理：

默认输出目录改为脚本所在项目根目录下的 `exports/bilibili_feedback`。

原因：

脚本产物应该稳定落在项目内被 `.gitignore` 忽略的位置，和运行命令时所在目录无关。

## 8. 本地输出不能进入 Git

问题：

评论和弹幕可能包含真实用户内容，误提交会污染仓库并带来隐私风险。

处理：

默认输出到 `exports/bilibili_feedback/`，并在 `.gitignore` 中忽略 `exports/`。

原因：

样例数据属于运行产物，不应成为项目源码的一部分。

```bash
python scripts/bilibili_feedback_fetcher.py --help
python scripts/bilibili_feedback_fetcher.py not-a-bv

```

结果：

1. 语法检查通过。
2. CLI 帮助正常输出。
3. 非法 BV 只输出业务错误，不暴露 Python traceback。
4. 实测视频可以拉取主楼评论和回复评论。
