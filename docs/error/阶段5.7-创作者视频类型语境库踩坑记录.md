# 阶段 5.7 - 创作者视频类型语境库踩坑记录

## 1. 语境库不能做成全网热梗爬虫

### 现象

最初讨论过前端按钮联网获取相关热梗和小圈子黑话。

### 风险

热梗粒度太细，且不同视频类型差异很大。

如果做成全网自动抓取，容易把不适合当前账号的表达注入提示词，反而降低发布前建议质量。

### 处理

阶段 5.7 改为创作者私有语境库。

词条由用户手动保存、采纳 AI 建议、后续评论弹幕候选或历史成功视频候选逐步沉淀。

## 2. 语境库不等于 RAG 事实证据

### 现象

评论和弹幕才是判断观众反馈的重点，单纯知道主题或关键词没有足够业务价值。

### 风险

如果把语境词条当证据使用，LLM 可能把“适合怎么表达”误当成“观众真实反馈”。

### 处理

语境库只进入发布前优化的表达上下文。

评论弹幕事实仍由反馈分析和证据检索链路提供。

## 3. 任务类型变化必须让任务回到草稿态

### 现象

创作任务新增 `videoType` 后，用户可能在已有建议生成后改视频类型。

### 风险

旧建议基于旧视频类型语境生成，继续展示会让用户误以为建议仍然适配。

### 处理

`CreatorTaskService.updateTask` 判断视频类型变化。

只要材料或视频类型变化，就把任务状态退回 `DRAFT`，要求用户重新生成建议。

## 4. Mapper 接口变更会破坏测试假实现

### 现象

`CreatorTaskMapper` 新增 `updateTaskBasicInfo` 后，多个测试里的 `FakeCreatorTaskMapper` 没有实现新方法。

### 风险

即使业务代码没问题，测试编译也会因为接口未实现失败。

### 处理

给相关测试假实现补齐 `updateTaskBasicInfo`。

不需要该方法的测试直接抛 `UnsupportedOperationException`，避免测试误用。

## 5. 拒绝反馈的禁用条件不能用旧权重

### 现象

拒绝词条时 SQL 同时更新 `weight` 和 `enabled`。

### 风险

如果 `enabled = IF(weight <= 4, 0, enabled)` 使用的是更新前权重，权重刚好从 5 降到 1 时不会立即禁用。

### 处理

禁用判断改为：

```sql
enabled = IF(GREATEST(0, weight - 4) <= 4, 0, enabled)
```

这样判断的是本次扣分后的权重。

## 6. 文档索引位置要以外层 AGENTS 为准

### 现象

当前 Git 项目根目录没有 `AGENTS.md`，协作文件位于 `E:\linkAgent\AGENTS.md`。

### 风险

如果在项目根目录新建一个 `AGENTS.md`，后续协作上下文可能分裂。

### 处理

阶段 5.7 文档路径补充到外层 `E:\linkAgent\AGENTS.md`。
