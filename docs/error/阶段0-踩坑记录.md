 阶段 0.5 踩坑记录

## 1. mvnw 与 PowerShell 不兼容

**现象：** 在 PowerShell 中运行 `./mvnw` 报错 `ConvertFrom-StringData` 解析失败

**原因：** `mvnw.cmd` 是 CMD 批处理 + PowerShell 混写脚本。新版 Maven Wrapper（3.3.4+）在 CMD 中启动后会调用 PowerShell 执行下载逻辑，但 PowerShell 解析 `maven-wrapper.properties` 时编码不兼容

**解决：**
- 切到 CMD 运行 `mvnw spring-boot:run`（仅在 CMD 中 batch 部分可执行）
- 或使用本地安装的 Maven：`mvn spring-boot:run`
- 最终直接删除 `mvnw` / `mvnw.cmd` / `.mvn/`，只用 `mvn` 命令

---

## 2. Spring Boot 与 Spring AI 版本不兼容

**现象：** 启动报 `ClassNotFoundException: org.springframework.boot.autoconfigure.web.client.RestClientAutoConfiguration`

**原因：** Spring AI 1.1.4 依赖 Spring Boot 3.5.11，而项目初始选择了 Spring Boot 4.0.5。Spring Boot 4.x 移除了某些 3.x 的自动配置类

**排查：** 查看 Spring AI starter 的 POM，发现其编译依赖 `spring-boot-starter:3.5.11`

**解决：** Spring Boot `4.0.5` → `3.5.11`

---

## 3. MyBatis 与 Spring Boot 版本不匹配

**现象：** 降级 SB 到 3.5.11 后，启动报 Bean 重复注册冲突：
`The bean 'hikariPoolDataSourceMetadataProvider' could not be registered. A bean with that name has already been defined`

**原因：** MyBatis Spring Boot Starter 4.0.1 是为 Spring Boot 4.x 设计的。SB 3.5.11 使用了 MyBatis 4.0.1 后，两者内部的 `HikariPoolDataSourceMetadataProvider` 分别来自不同包路径造成重复

**解决：** MyBatis `4.0.1` → `3.0.5`

---

## 4. Milvus 向量库未启动导致应用启动失败

**现象：** 启动后连接 Milvus 超时：`DEADLINE_EXCEEDED: deadline exceeded`

**原因：** Spring AI 的 `MilvusVectorStoreAutoConfiguration` 默认自动配置（`@ConditionalOnProperty` 的 `matchIfMissing=true`），即使没用到也会尝试连接

**排查：** 反编译 `MilvusVectorStoreAutoConfiguration.class`，找到条件注解：
```java
@ConditionalOnProperty(value = "spring.ai.vectorstore.type", havingValue = "milvus", matchIfMissing = true)
```

**第一反应（错误）：** 直接加了 `enabled: false`，但该配置类没有 `enabled` 属性

**最终解决：** 在 `application.yml` 中排除该自动配置：
```yaml
spring:
  autoconfigure:
    exclude:
      - org.springframework.ai.vectorstore.milvus.autoconfigure.MilvusVectorStoreAutoConfiguration
```

## 5. Redis 端口环境变量未设置

**现象：** 启动报 `Failed to bind properties under 'spring.data.redis.port' to int`，值显示为字面量 `"${REDIS_PORT}"`

**原因：** `application.yml` 中 `port: ${REDIS_PORT}` 没有设默认值，环境变量未加载时 Spring 尝试把字面字符串 `${REDIS_PORT}` 转为 int

**解决：** 添加默认值：`port: ${REDIS_PORT:6379}`，同理 `host: ${REDIS_HOST:localhost}`

---

## 6. spring-dotenv 不好使

**现象：** 加了 `me.paulschwarz:spring-dotenv:5.1.0` 依赖后，`.env` 文件中的环境变量未加载，`${LLM_BASE_URL}` 等依然未解析

**原因（推测）：** spring-dotenv 使用 `EnvironmentPostProcessor` 机制在 application.yml 加载前执行。但它的配置属性 `spring.dotenv.location` 需要从系统属性或环境变量读取，而非 yml 文件（因为此时 yml 尚未加载）。这是一个"先有鸡还是先有蛋"的问题

**尝试过的方法：**
1. 在 `application.yml` 中配置 `spring.dotenv.location: ../` → 不生效（yml 加载太晚）
2. 在 `pom.xml` 的 `spring-boot-maven-plugin` 中加 `<jvmArguments>-Dspring.dotenv.location=../</jvmArguments>` → 也不生效（原因待查）

**最终解决：** 删除 spring-dotenv 依赖，改用 `application-dev.yml`（profile 特定配置）+ `.gitignore` 排除。`application-dev.yml` 不会被提交，在其中硬编码 dev 环境的值

---

## 7. CMD 中 & 符号导致环境变量设置失败

**现象：** 在 CMD 中 `set DB_URL=jdbc:mysql://...?useUnicode=true&characterEncoding=utf8` 报错 `'characterEncoding' 不是内部或外部命令`

**原因：** CMD 中 `&` 是命令分隔符，URL 中的 `&` 被解析为新命令

**解决：** 用双引号包裹整个赋值：`set "DB_URL=jdbc:mysql://...?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai"`
