# 阶段 4.3.1：创作工作台前端接入踩坑记录

## 1. 不要覆盖原 Agent 控制台

问题：

直接把 `App.vue` 改成创作工作台会导致原来的 ReAct 会话调试入口丢失。

处理：

把原 `App.vue` 内容拆到 `AgentConsole.vue`，新 `App.vue` 只做模式切换。

原因：

项目底层 Agent 能力仍然重要，前端入口应该共存，而不是互相替代。

## 2. LLM 结构化字段需要前端容错

问题：

后端为了保持 MVP 简单，把标题建议、高频观点等列表字段以 JSON 字符串返回。

处理：

前端统一 `JSON.parse`，失败时把原字符串作为单项展示。

原因：

这样即使模型输出不稳定，也不会导致页面渲染失败。

## 3. 自动选择第一条任务时要处理空数组

问题：

`tasks.value[0].taskId` 在 TypeScript 严格检查下会报可能为 `undefined`。

处理：

先取 `const firstTask = tasks.value[0]`，再判断是否存在。

原因：

类型检查应该在开发阶段发现潜在空值问题，不要为了省一行代码绕过它。

## 4. 样例文本不应直接占据真实输入区

问题：

把演示用稿件、评论和偏好写成表单初始值，会让用户分不清哪些内容会真实提交，演示时也容易误保存无关数据。

处理：

输入区初始化为空，把输入建议改成简短的框内隐性提示；可编辑指导仅在用户点击“恢复默认指导”时写入推荐内容。

原因：

提示承担引导职责，输入值只承载用户准备提交的数据，表单语义更清晰。

## 5. 前端可用态应与后端校验保持一致

问题：

移除默认样例后，用户可能在没有材料或反馈样例时直接提交，随后才收到后端 `@AssertTrue` 校验错误。

处理：

前端根据稿件材料和反馈样例是否含有效文本禁用对应提交按钮，后端校验仍然保留作为最终保护。

原因：

前端用于减少无效操作，后端用于守住接口边界，两层职责不能互相替代。
