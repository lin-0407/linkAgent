# 阶段 4.3.2：创作指导可编辑窗口踩坑记录

## 1. 不能把完整系统提示词作为可编辑参数

问题：

若前端显示并提交完整系统提示词，用户不仅能改写创作风格，也能删除角色边界、结构化输出要求和平台数据约束。

处理：

接口字段由完整提示词参数收束为 `customGuidance`。后端始终使用固定系统提示词，用户指导只进入业务输入区。

原因：

隐藏按钮或文本框无法保护接口；必须从后端请求契约上取消系统规则替换能力，才能防止绕过界面的提示词注入。

## 2. 用户指导仍需明确优先级边界

问题：

即使字段名称是业务指导，用户仍可能在内容中写入“忽略规则”或“改变输出结构”等指令。

处理：

固定系统提示词明确把创作材料、反馈样例和 `customGuidance` 都视为非可信业务输入，只允许影响风格、关注重点、建议倾向和分析顺序。

原因：

字段隔离负责减少攻击面，系统规则负责处理输入内容中的冲突指令，两层都需要存在。

## 3. 旧本地缓存可能重新暴露受保护内容

问题：

旧页面曾把完整提示词保存到 `localStorage`。即使新页面不再写入，继续读取旧键也会重新展示不应开放的规则。

处理：

前端改用 `link-agent-creator-guidance` 保存业务指导，并在加载时移除旧键 `link-agent-creator-system-prompts`。

原因：

安全修正需要覆盖存量浏览器状态，不能只关注新请求。

## 4. 不能只用 `click.self` 判断弹窗遮罩关闭

问题：

用户在弹窗内部按下鼠标，拖到弹窗外松开时，最终点击事件可能落到遮罩上，导致编辑内容被误关闭。

处理：

记录 `pointerdown` 是否从遮罩开始，只有按下起点和最终点击目标都为遮罩时才关闭窗口。

原因：

关闭弹窗是完整指针交互，记录起点可以保护拖拽选择文字等正常编辑操作。

## 5. 不要顺手做评论弹幕抓取

问题：

手动提供样例存在输入成本，但自动抓取会引入账号授权、反爬和合规问题。

处理：

本轮仍处理用户主动提供的评论和弹幕样例，不实现爬虫。

原因：

数据接入需要单独设计和评估，不能混入提示词安全修正。

