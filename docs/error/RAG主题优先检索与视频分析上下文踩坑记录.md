# RAG 主题优先检索与视频分析上下文踩坑记录

## 1. 不能只返回父视频卡片

**问题**：父块命中只能说明整条视频整体相关，不能说明标题、定位或观众反馈哪一点相关。

**处理**：先检索主题中块，再用命中的 `videoId` 展示视频卡片。

**原因**：创作者需要的是“为什么这个案例值得看”，不是一组没有解释的视频。

## 2. 不能把未展示视频的主题解释返回给前端

**问题**：如果 `matchedTopics` 返回 top20 所有候选解释，但当前页只展示 5 张卡片，前端会拿到暂时不可见的视频解释。

**处理**：`matchedTopics` 只保留当前页卡片对应的主题。

**原因**：解释要和当前可见卡片对齐。

## 3. 中块候选数要大于视频候选数

**问题**：一个视频最多有多个主题中块。如果只检索 20 个中块文档，可能去重后凑不出 20 个视频。

**处理**：中块向量检索取 60 个文档，再收敛成 20 个唯一视频。

**原因**：刷新 4 页最多需要 20 个视频候选。

## 4. 向量 metadata 过滤后还要 MySQL 二次过滤

**问题**：中块向量文档里的 `category` / `tier` 来自索引时的 metadata，后续 MySQL 事实源可能更新。

**处理**：回查视频卡片时再次按 `category` / `tier` 过滤。

**原因**：最终展示必须以 MySQL 事实源为准，不能只信向量库副本。
