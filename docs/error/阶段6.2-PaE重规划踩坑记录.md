# 阶段 6.2 - PaE 重规划踩坑记录

## 1. 重规划不能覆盖已成功步骤

问题：如果让 Replanner 重新输出完整计划，模型可能把已成功步骤再执行一遍。

处理：prompt 明确要求只输出剩余步骤，执行器也只替换 `remainingSteps`。

## 2. stepId 不能直接信任模型

问题：Replanner 可能返回和原计划重复的 stepId，前端回放会混乱。

处理：后端统一对重规划步骤重新编号。

## 3. Replanner 不能成为单点

问题：Replanner 自身可能因为提示词缺失或结构化输出失败而异常。

处理：`AgentReplanner` 捕获异常并保留原剩余计划。

## 4. 成功恢复与失败记录要区分

问题：如果第一次步骤失败后重规划成功，trace 中仍然有失败尝试，不能简单把整次 PaE 标为失败。

处理：执行器记录已被重规划替代的失败 stepId，计算 stopReason 时不把这些失败尝试当成最终失败。
