# 阶段 0-3 基础架构踩坑总结

---

## 一、环境与版本兼容性

### 1. Maven Wrapper 在 PowerShell 中不可用

**问题**：PowerShell 中运行 `./mvnw` 报 `ConvertFrom-StringData` 解析失败。

**原因**：Maven Wrapper 3.3.4+ 的 `mvnw.cmd` 内嵌 PowerShell 逻辑在解析 `maven-wrapper.properties` 时存在编码不兼容。

**解决**：删除项目中的 `mvnw`、`mvnw.cmd` 和 `.mvn/` 目录，统一使用系统安装的 `mvn` 命令。

### 2. Spring Boot 4.0.5 与 Spring AI 1.1.4 不兼容

**问题**：启动报 `ClassNotFoundException: RestClientAutoConfiguration`。

**原因**：Spring AI 1.1.4 编译依赖 `spring-boot-starter:3.5.11`，而 Spring Boot 4.x 移除了部分 3.x 的自动配置类。

**解决**：Spring Boot 版本从 `4.0.5` 降级到 `3.5.11`。

### 3. MyBatis 4.0.1 与 Spring Boot 3.5.11 冲突

**问题**：降级 Spring Boot 后，启动报 `HikariPoolDataSourceMetadataProvider` Bean 重复注册。

**原因**：MyBatis Spring Boot Starter 4.0.1 面向 Spring Boot 4.x 设计，其内部的 `HikariPoolDataSourceMetadataProvider` 与 Spring Boot 3.5.11 来自不同包路径，导致 Bean 定义冲突。

**解决**：MyBatis 版本从 `4.0.1` 降级到 `3.0.5`。

### 4. CMD 命令行中 `&` 符号被误解析

**问题**：CMD 中设置含 `&` 的 JDBC URL 环境变量时报 `'characterEncoding' 不是内部或外部命令`。

**原因**：CMD 将 `&` 解释为命令分隔符，URL 参数 `useUnicode=true&characterEncoding=utf8` 被拆成两条命令。

**解决**：用双引号包裹整个赋值语句，如 `set "DB_URL=jdbc:mysql://...?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai"`。

## 二、Spring 容器与 Bean 管理

### 5. ToolRegistry 多构造器导致自动装配失败

**问题**：`LinkAgentApplicationTests.contextLoads` 启动失败，报 `No default constructor found`。

**原因**：`ToolRegistry` 同时定义了两个构造器——单参数 `List<Tool>` 和双参数 `List<Tool>, List<ToolCallbackProvider>`。Spring 存在多个构造器时无法确定注入目标。

**解决**：在双参数构造器上显式添加 `@Autowired`，指定 Spring 使用该构造器注入；单参数构造器保留用于单元测试快速构造。

## 三、数据库、缓存与外部服务

### 6. Milvus 向量库未启动导致应用启动阻塞

**问题**：应用启动时连接 Milvus 超时报 `DEADLINE_EXCEEDED`。

**原因**：`MilvusVectorStoreAutoConfiguration` 的 `@ConditionalOnProperty` 设置了 `matchIfMissing=true`，即使未使用向量功能也默认尝试连接。

**解决**：在 `application.yml` 中排除该自动配置类 `org.springframework.ai.vectorstore.milvus.autoconfigure.MilvusVectorStoreAutoConfiguration`。

### 7. Redis 端口配置缺少默认值

**问题**：启动报 `Failed to bind properties under 'spring.data.redis.port' to int`，绑定值为字面量 `${REDIS_PORT}`。

**原因**：`application.yml` 中使用了 `port: ${REDIS_PORT}` 但未提供默认值，且环境变量未加载时 Spring 尝试将字面字符串转为整数。

**解决**：添加默认值 `port: ${REDIS_PORT:6379}`，同理 `host: ${REDIS_HOST:localhost}`。

### 8. spring-dotenv 无法加载 `.env` 文件

**问题**：配置 `spring-dotenv` 依赖后，`.env` 中的环境变量（如 `${LLM_BASE_URL}`）仍未被解析。

**原因**：spring-dotenv 通过 `EnvironmentPostProcessor` 在 `application.yml` 加载前执行，但其 `spring.dotenv.location` 配置项需要从系统属性或环境变量读取，此时 YAML 尚未加载，形成循环依赖。

**解决**：删除 spring-dotenv 依赖，改用 `application-dev.yml`（profile 特定配置）硬编码开发环境值，并通过 `.gitignore` 排除提交。

## 四、MCP 工具配置

### 9. MCP 客户端配置前缀误用 `common` 层级

**问题**：按照包名 `common.autoconfigure` 猜测 YAML 配置路径，写成 `spring.ai.mcp.client.common.enabled`，实际不生效。

**原因**：Spring AI 1.1.4 的 `@ConfigurationProperties` 真实前缀是 `spring.ai.mcp.client`，包名中的 `common` 只是 Java 包结构，不代表配置层级。

**解决**：移除 `common` 层级，直接使用 `spring.ai.mcp.client.enabled` 和 `spring.ai.mcp.client.type: sync`。后续接入第三方配置时须优先核验 `META-INF/spring-configuration-metadata.json` 或 `CONFIG_PREFIX`，不根据包名猜测。

## 五、测试数据同步

### 10. 长期记忆协议变更后测试 key 未同步

**问题**：`AgentExecutorLongTermMemoryTest` 断言期望 `user.preference.language`，但实际协议已改为 `user.preference.example_language`。

**原因**：`LongTermMemoryExtractor` 已将长期记忆 key 收敛到 5 个固定值，测试中的期望值未同步更新。

**解决**：将测试中的固定返回值及断言期望统一改为 `user.preference.example_language`。

## 六、前端架构与交互

### 11. 任务列表默认自动选中首项，屏蔽首屏入口

**问题**：创作台刷新任务列表后自动选中第一条历史任务，导致首屏"开始优化 / 继续复盘"入口不可见。

**原因**：`resolveRefreshTargetTask` 在无明确选中目标时默认 fallback 到第一条任务。

**解决**：`resolveRefreshTargetTask` 仅恢复当前选中项目或本地记录的项目，不再默认选择第一条。

### 12. 工程诊断信息侵入普通用户界面

**问题**：工作流消息、API 开销、评测样例、检索策略、证据索引等工程信息直接展示在普通页面，用户被迫理解工程概念。

**解决**：新增前端本地开发者模式开关，普通模式下隐藏上述工程诊断信息，开发者模式保持可见。

### 13. AI 浮窗在普通模式下仍展示推理轨迹

**问题**：隐藏执行模式按钮后，消息气泡组件仍输出执行模式标签、步骤轨迹和停止原因。

**原因**：`MessageBubble` 未区分展示场景，默认全量输出诊断信息。

**解决**：`MessageBubble` 新增 `showDiagnostics` 参数，AI 浮窗在普通模式下传入 `false`，开发者模式下传入 `true`。

### 14. 反馈导入结果在普通模式下可能为空

**问题**：反馈采集成功但仪表盘接口失败时，普通模式隐藏脚本输出后，弹窗可能无任何可读内容。

**解决**：在普通模式下增加兜底提示"读取完成"，仅展示评论数和弹幕数。

### 15. 移动端左侧流程栏挤压主内容区

**问题**：桌面端左侧流程栏在窄屏（<820px）下占用大量水平空间，导致主内容区域过窄。

**解决**：新增移动端进度摘要组件，在 820px 断点以下将流程卡片固定在顶部区域，仅展示当前步骤摘要。

### 16. CSS Grid / Flex 子项撑出横向滚动

**问题**：长标题、长标签、错误信息等文本在 Grid 或 Flex 容器中因默认 `min-width` 撑破页面宽度。

**原因**：Grid 和 Flex 子项默认最小宽度为其内容的最小尺寸，长文本不会自动换行。

**解决**：为创作台主容器、结果块、表单网格、面板标题和操作区域补充 `min-width: 0` 与 `overflow-wrap: break-word`。

### 17. 移动端按钮触控目标过小

**问题**：历史样式中部分按钮高度低于移动端推荐的 44px 最小触控尺寸，易造成误触。

**解决**：统一将主要按钮、次级按钮、幽灵按钮、危险按钮、小按钮、步骤按钮和设置入口的 `min-height` 设置为 44px。

### 18. 开发者辅助步骤污染普通用户的四步进度

**问题**：`activeStep` 可进入 `usage` 步骤，但普通创作者流程仅设计四步，导致进度指示异常。

**解决**：当 `activeStep` 为 `usage` 时，移动端进度条仍显示为"复盘报告"步骤，不将开销统计暴露为第五步。
