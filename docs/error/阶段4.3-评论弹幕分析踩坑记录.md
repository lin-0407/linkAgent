# 阶段 4.3：评论弹幕分析踩坑记录

## 1. 不要把评论样例和弹幕样例混进稿件材料表

问题：

评论、弹幕和稿件是不同语义层的数据。放进同一张表，后面很难区分发布前输入和发布后反馈。

处理：

单独建立 `creator_feedback` 和 `creator_feedback_report`。

原因：

这样 4.1、4.2、4.3 的业务边界更清楚，后续做复盘报告也更容易串联。

## 2. 不要假设 LLM 每次都会返回稳定 JSON

问题：

反馈分析里如果直接按 JSON 解析，模型一旦多输出解释文字，就会丢结果。

处理：

先保留 `rawOutput`，再尝试解析固定字段，失败时标记为 `RAW_ONLY`。

原因：

这样至少不会丢掉原始样本，后面还能回放和调 Prompt。

## 3. 不要一开始就做真实平台抓取

问题：

评论和弹幕一旦走爬取或开放平台接入，合规、授权和稳定性问题会一起上来。

处理：

本阶段只接收用户主动粘贴的样例和补充背景。

原因：

先把业务闭环跑通，再考虑真实数据接入。

## 4. 不要把反馈分析和复盘总报告合并

问题：

如果把 4.3 和 4.4 一起做，接口、存储和提示词都会变大，排查问题也更难。

处理：

4.3 只做反馈分析，4.4 再做复盘汇总。

原因：

符合“每次只解决一个明确问题”的开发原则。

## 5. 本轮未运行 Maven

说明：

按项目约定，Maven 编译和测试由作者执行。

