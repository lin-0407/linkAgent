# 阶段 4.9 - Prompt 版本评测闭环踩坑记录

## 1. 只保存 raw output 不够复盘

问题：模型输出坏了，只看 raw output 并不能知道当时 Prompt 怎么写，后续只能凭印象改。

处理：评测结果增加 `prompt_version`、`prompt_hash` 和 `prompt_snapshot`，把结果和提示词绑定。

## 2. Prompt 版本号不能替代快照

问题：同一个版本名可能被人改过内容，如果只保存 `v1`，后续仍然无法复现。

处理：额外保存 SHA-256 哈希。版本名给人看，哈希用来确认内容是否一致。

## 3. 不要一上来做复杂 PromptOps 平台

问题：自动批量评测、多模型调度、Prompt 模板后台都会扩大范围，容易偏离创作者工作台主线。

处理：本轮只扩展已有评测结果表和开发者测试弹窗，先把可复现对比跑通。

## 4. 已有 MySQL 卷不会自动补新字段

问题：`init.sql` 里的 `CREATE TABLE IF NOT EXISTS` 只在表不存在时生效。如果本地已经有旧版 `creator_eval_result` 表，新增的 `prompt_version`、`prompt_hash`、`prompt_snapshot` 不会自动出现，后端查询会报 `Unknown column`。

处理：演示环境可以删除旧的 MySQL 数据卷后重建；本地保留数据时，需要手动给 `creator_eval_result` 补这三个字段和索引。
