# 阶段 5.6 - 设置面板踩坑记录

## 1. Git safe.directory 拦截

### 现象

在沙箱用户下执行：

```powershell
git -C E:\linkAgent\linkAgent status --short
```

出现：

```text
fatal: detected dubious ownership in repository
```

### 原因

Windows 仓库 owner 是 `Administrator`，当前执行用户是沙箱用户。Git 为安全起见拒绝读取仓库状态。

### 处理

使用单次命令参数：

```powershell
git -c safe.directory=E:/linkAgent/linkAgent -C E:\linkAgent\linkAgent status --short
```

不写全局 Git 配置，避免影响作者本机环境。

## 2. 运行期开关不能直接改 Environment

### 现象

设置面板需要动态修改部分开关。

### 风险

如果直接改 Spring `Environment`，启动期 Bean 不会重新装配，容易造成“前端显示开了，但实际能力没创建”的错觉。

### 处理

只把适合运行期判断的开关做成动态开关。结构化 Agent 内核已经从 `@Value` 固定读取改为调用前读取 `RuntimeSettingService`，所以也可以动态切换。

启动期装配类配置只读展示：

- `knowledge.rag.enabled`
- `knowledge.rag.hybrid.enabled`
- `agent.memory.short-term.store-type`

## 3. SummaryMemory 多构造器注入风险

### 现象

为了兼容已有单元测试，需要保留 3 参数构造器。

### 风险

Spring 看到多个 public 构造器时可能无法判断应该注入哪个。

### 处理

给 4 参数构造器显式加 `@Autowired`，让 Spring 使用带 `RuntimeSettingService` 的构造器。

3 参数构造器只服务测试，内部回退到原配置值。

## 4. Redis ping 方法不能凭空假设

### 现象

最初想用 Redis `ping()` 做连通性检测。

### 风险

当前 Spring Data Redis 版本的顶层 `RedisConnection` 字节码中没有直接声明 `ping()`。

### 处理

改用已核准存在的：

```java
connection.serverCommands().info()
```

它能验证 Redis 连接和命令执行，同时不写入数据。

## 5. 索引面板迁移不能保留残留 onMounted 调用

### 现象

原 `KnowledgeWorkspace.vue` 在 `onMounted` 中自动拉取 4 个索引状态。

### 风险

如果只删除模板不删脚本，会造成无用请求、编译残留或未来维护误判。

### 处理

完整迁移：

- 删除索引 API import。
- 删除 4 组索引状态。
- 删除 8 个索引方法。
- 删除 `onMounted` 中索引状态加载。
- 删除 4 个索引模板区块。

索引状态改为设置弹窗内 `KnowledgeIndexPanels.vue` 挂载时加载。
