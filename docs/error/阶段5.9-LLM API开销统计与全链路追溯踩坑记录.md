# 阶段 5.9 - LLM API 开销统计与全链路追溯踩坑记录

## 1. token 未返回不能写成 0

### 现象

Spring AI 或供应商有时不返回 usage。

### 风险

如果把未知 token 写成 0，前端会误以为本次调用没有成本。

### 处理

后端把 0 或缺失 usage 统一转成 `null`。

前端显示“未返回”。

## 2. `ChatClient.entity(...)` 不暴露完整 usage

### 现象

结构化输出可以直接得到目标对象，但拿不到完整 `ChatResponse`。

### 风险

为了拿 token 强行改回字符串 JSON 解析，会破坏阶段 5.4 的结构化输出稳定性。

### 处理

结构化调用仍记录真实耗时和调用状态。

token 保持未知，不做估算。

## 3. Embedding 调用不能只在业务服务里手动埋点

### 现象

向量库内部会自动触发 embedding。

### 风险

如果只在部分业务方法里手动统计，VectorStore 内部调用会漏记。

### 处理

用 `BeanPostProcessor` 给容器中的 `EmbeddingModel` 包一层 `MeteredEmbeddingModel`。

这样业务服务和 VectorStore 共用同一个代理模型。

## 4. MyBatis 聚合对象不使用 record

### 现象

聚合 SQL 返回的是下划线别名，需要映射到 Java 属性。

### 风险

`record` 构造映射在不同 MyBatis 版本下更容易踩兼容问题。

### 处理

`LlmApiUsageCategorySummary` 使用 Java Bean，并显式写 `@Results`。

## 5. 统计失败不能影响创作主流程

### 现象

统计表写入可能因为数据库连接、字段长度或临时异常失败。

### 风险

如果统计异常向上抛，会让发布前优化、反馈分析或检索失败。

### 处理

`LlmApiUsageService` 捕获写入异常，只输出 warn 日志。

主业务继续按原逻辑返回。

## 6. 编译测试必须由作者执行

### 现象

开发中曾误执行 Maven 编译命令。

### 风险

违反项目协作约定：所有前后端编译、测试、运行任务必须交给作者执行。

### 处理

已记录到 `.learnings/ERRORS.md`。

后续只提供命令和判断标准，不再代跑 `mvn`、`npm run build` 或 `npm run type-check`。

## 7. 前端新增 tab 后滑块宽度要同步调整

### 现象

原工作台只有 4 个 tab，选中滑块宽度按 4 等分写死。

### 风险

新增“开销统计”后，如果不调整宽度，选中背景会错位。

### 处理

把滑块宽度改为 5 等分。

移动端继续关闭滑块，改用按钮自身选中态，避免小屏错位。
