# 阶段 6.1 - Multi Agent 并发与引用审查踩坑记录

## 1. 并发不能忽略依赖失败

问题：如果只按空依赖并发，依赖失败后的后续 Worker 可能继续运行，产生基于缺失事实的结论。

处理：每轮执行前检查依赖状态。只要依赖不存在或不是 `SUCCESS`，后续 Worker 标记为 `SKIPPED`。

## 2. Direct Worker 的结论不能当外部事实

问题：直接推理 Worker 没有工具观察，它的输出本质是模型推断。

处理：将它的证据类型标记为 `WORKER_REASONING`。Synthesizer prompt 明确要求不能把该类型证据当成外部事实。

## 3. 审查器不能成为可用性单点

问题：审查器也是一次 LLM 结构化输出，可能解析失败。

处理：`AgentAnswerAuditor` 捕获异常，返回通过状态并记录日志，避免辅助质检导致主回答失败。

## 4. `init.sql` 写入遇到 Windows 沙箱限制

问题：本轮使用 `apply_patch` 更新 `init.sql` 时，Windows 沙箱包装器拒绝读取该文件。

处理：改用一次受控 PowerShell 行级替换，只替换阶段 6 prompt seed，没有执行构建、测试或启动命令。
