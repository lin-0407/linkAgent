# 阶段 4.6：评测集与失败回放踩坑记录

## 1. 数据库初始化脚本不能残留半截兼容 SQL

问题：`sql/init.sql` 里原本有一段被截断的动态 SQL，文件看起来能读，实际执行时会把 schema 初始化卡死。

处理：把 `creator_report.competitor_comparison` 的兼容补丁补完整，再继续加评测表。

## 2. 评测结果不能只记分数，不记原文

问题：如果评测只存评分，后面想复盘失败原因时，只能看到“分数低”，看不到具体输出。

处理：评测结果表强制保留 `raw_output`、`failure_reason`、`elapsed_ms` 和 token 字段。

## 3. 工作流回放不要再新建一套重复表

问题：如果为了前端展示再加一套步骤表，消息、步骤、回放会各自漂移，后面不好排障。

处理：直接复用现有 `creator_workflow_step`，只补查询接口和前端展示。

## 4. 评测阶段必须和用例阶段一致

问题：评测用例如果是发布前优化，结果却被写成反馈分析，后续统计会乱。

处理：评测结果落库前先检查 `targetStage` 是否和用例一致，不一致直接拒绝。

## 5. 没有输出也没有失败原因时，不能假装记录成功

问题：如果结果接口允许空提交，评测记录会变成空壳。

处理：要求 `rawOutput` 和 `failureReason` 至少有一个，保证每条结果都有可追溯证据。

## 6. 开发者测试不能混进创作者主工作流

问题：把样例评测放进任务输入、发布前优化、评论弹幕、分析结果这一列，会让用户误以为它是创作者日常要走的主流程。

处理：主导航移除样例评测，只保留创作者主流程；右上角提供“开发者测试”按钮，点击后打开独立弹窗承载评测集和失败回放。
