# 固定工程后台执行接入说明

当前能力只服务于后端固定工程链路，还不是用户页面上的自动出片入口。实现见 [S3c](../develop/视频自动制作-S3c固定工程后台执行.md)，证据见 [验证记录](../error/固定工程后台执行S3c验证记录.md)。

## 内部怎样接入

1. 使用已有发布方案确认、专属 AI 制作计划和预算，受理一个 FULL 运行。
2. 后端将真实工程与资产放到 `<renderer.workRoot>/<runId>/<sourceAttemptId>/`，入口文件名为 `input.json`。
3. 通过 `FixedProjectJobFiles.freeze` 冻结文件，再调用 `FixedProjectJobPersistenceService.attach` 持久化。以上都是内部 Java 服务，没有开放接收本地路径的 HTTP API。
4. 后台定时领取已附加输入的运行，复制新尝试、渲染并保存登记版本。
5. 查询原运行和视频版本；登记后等待真实媒体处理/试映/发布包，不会因为 MP4 存在就显示制作完成。

工程受理与输入附加分别幂等，附加失败后保留真实错误并由调用方恢复；不能重复受理新的运行来掩盖已有活动任务。当前页面能力标识仍返回 `executionAvailable=false`。

## 部署前提与开关

需满足既有 S3a/S3b 的 Python、FFmpeg、字体、可写工作目录和私有存储配置，以及包含本步新增表的统一 SQL。仅重启旧部署不会自动创建新表或更新渲染模块。

| 配置 | 默认 | 用途 |
| --- | --- | --- |
| `creator.media.enabled` | false | 原有私有媒体能力 |
| `creator.creation.renderer.enabled` | false | 原有后端固定工程渲染 |
| `CREATOR_CREATION_WORKER_ENABLED` | false | 本步后台执行器；三个开关均开启才加载 |
| `CREATOR_CREATION_WORKER_POLL_INTERVAL_MS` | 2000 | 候选扫描间隔 |
| `CREATOR_CREATION_WORKER_LEASE_SECONDS` | 30 | 由数据库计时的租约，允许 5–600 秒 |
| `CREATOR_CREATION_WORKER_HEARTBEAT_SECONDS` | 5 | 续租/取消观察间隔，不超过租约的三分之一 |
| `CREATOR_CREATION_WORKER_MAX_ATTEMPTS` | 3 | 未登记阶段领取上限，允许 1–10；已登记恢复不触发重渲染 |

已有 renderer 部署属性继续配置实际可执行程序、模块、字体和工作根目录，不接受来自工程的命令。工作根目录应放在部署者维护的持久卷，避免尚未登记时重建容器导致源资产丢失；默认临时目录不构成持久卷保证。

这些配置没有自动写入作者部署或启动现有服务。公开入口、完整媒体链路尚未完成，不应仅开启开关就向用户承诺自动制作可用。

本步未调整现有 Compose 的变量传递和后端镜像打包；只修改 `.env` 不代表上述配置已经进入容器。部署接入时需同时核对运行进程中的实际配置、渲染模块和工作卷，不能以配置文件可解析代替执行链路验收。

## 用户取消与执行器退出

原取消接口保持不变。已排队取消立即终结；运行中取消由心跳观察并停止本次媒体进程；等待依赖的运行由下一次领取确认取消。若数据库不可用，停止本次执行并等待租约恢复，不能猜测取消已成功。

执行器退出后仍使用同一数据库及工作卷，新的执行器可在租约到期后接管。接管使用新的执行代数和尝试目录；已登记视频从数据库恢复同一个版本。测试覆盖执行器实例和调度上下文重建，尚未对完整 Spring Boot 部署做容器重启验收。

## 尚未提供

自然语言生成工程、自动蓝图步骤、用户素材导入、样片制作/下载、局部修改页面，以及原片处理/完整试映/发布包的自动串接都不能以本步代替验收。人工上传、选择历史版本和实际发布后的业务边界不变。
