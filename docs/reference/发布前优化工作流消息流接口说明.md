# 发布前优化工作流消息流接口说明

## 功能定位

发布前优化消息流用于把创作任务材料变成可追踪、可恢复的 Agent 工作流上下文。

阶段 4.4.1.1 只处理任务材料装载和用户补充要求。

阶段 4.4.1.2 已补充 SSE、发布前工作流分析、步骤记录和用户确认机制。原有同步接口 `POST /api/creator/tasks/{taskId}/pre-publish/analyze` 继续保留，用于简单联调。

## 数据表

| 表 | 用途 |
|---|---|
| `creator_workflow_session` | 保存任务在某个业务阶段的一次工作流会话 |
| `creator_workflow_message` | 保存会话内的过程消息、材料摘要和用户补充输入 |
| `creator_workflow_step` | 保存分析和确认步骤，用于失败回放 |

## 创建或恢复发布前工作流

```http
POST /api/creator/tasks/{taskId}/workflow/pre-publish/start
Content-Type: application/json
```

请求体：

```json
{
  "resumeLatest": true
}
```

说明：

1. `resumeLatest` 为空时默认恢复最新会话。
2. 没有历史会话时会创建新会话。
3. 新会话会自动写入任务材料摘要消息。
4. `userId` 仅作为兼容字段保留，当前单人工作台前端不传。

响应：

```json
{
  "sessionId": "workflow-session-id",
  "taskId": "creator-task-id",
  "stage": "PRE_PUBLISH",
  "status": "WAITING_USER_INPUT",
  "messages": []
}
```

## 查询工作流消息

```http
GET /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/messages
```

返回：

```json
[
  {
    "messageId": "message-id",
    "sessionId": "workflow-session-id",
    "role": "SYSTEM",
    "content": "已加载文稿，约 1200 字，点击查看详情。",
    "contentType": "MATERIAL_SUMMARY",
    "detailRefType": "MATERIAL",
    "detailRefId": "1",
    "sequenceNo": 3,
    "createTime": "2026-05-29T12:00:00"
  }
]
```

## 发送用户补充消息

```http
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/messages
Content-Type: application/json
```

请求体：

```json
{
  "content": "标题希望更适合 Java 后端学习者，不要太夸张。"
}
```

校验规则：

1. `content` 必填。
2. `content` 最长 2000 字。
3. 会话为 `RUNNING`、`CONFIRMED` 或 `CANCELLED` 时不能继续发送。
4. `FAILED` 后允许继续补充消息，便于用户修正要求后重试。

## 订阅工作流事件

```http
GET /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/events
```

事件类型：

```text
message_created
session_status
step_started
step_completed
step_failed
result_ready
heartbeat
```

## 执行工作流发布前分析

```http
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/pre-publish/analyze
```

说明：

1. 会话状态会从 `WAITING_USER_INPUT` 进入 `RUNNING`。
2. 分析过程会写入 `creator_workflow_step`。
3. 用户在消息流输入的 `USER` 消息会合并进本轮分析指导。
4. 成功后会话状态进入 `WAITING_CONFIRMATION`。
5. 该接口不更新 `creator_task.status`。

## 确认发布前建议

```http
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/pre-publish/confirm
```

请求体：

```json
{
  "suggestionId": "suggestion-id"
}
```

说明：

1. 只能确认当前任务下的建议。
2. 会话必须处于 `WAITING_CONFIRMATION`。
3. 确认成功后会话进入 `CONFIRMED`。
4. 确认成功后任务状态更新为 `PRE_PUBLISH_ANALYZED`。

## 消息字段说明

| 字段 | 说明 |
|---|---|
| `role` | `SYSTEM` / `USER` / `AGENT` / `TOOL` / `RESULT` |
| `contentType` | `TEXT` / `MATERIAL_SUMMARY` / `RESULT_CARD` / `ERROR` |
| `detailRefType` | 当前支持 `MATERIAL` |
| `detailRefId` | 指向 `creator_material.id`，前端据此展示完整材料 |
| `sequenceNo` | 会话内顺序号，用于后续 SSE 去重和恢复 |

## 前端对应关系

| 前端区域 | 数据来源 |
|---|---|
| 左侧消息流 | `creator_workflow_message` |
| 右侧详情面板 | 消息正文或 `creator_material` 完整内容 |
| 底部输入框 | `POST /messages` |
| 刷新消息按钮 | `GET /messages` |

## 当前限制

1. 附件上传接口尚未实现。
2. 建议版本对比尚未实现，当前每个任务仍只保留一份最新建议。
3. 评论弹幕导入与仪表盘仍在后续阶段实现。
4. SSE 只做实时展示，断线恢复仍依赖历史消息接口。
