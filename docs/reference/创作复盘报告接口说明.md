# 创作复盘报告接口说明

## 功能定位

创作复盘报告是 UP 主智能工作台的阶段性总结模块。

它基于阶段 4.1、4.2、4.3 已保存的数据，以及用户主动整理的竞品视频信息，生成：

1. 内容摘要。
2. 核心卖点复盘。
3. 标题、简介、标签和分区复盘。
4. 观众反馈摘要。
5. 竞品对照结论。
6. 争议和误解点。
7. 下一步动作建议。
8. 创作者偏好洞察。
9. 复盘总判断。

第一版不做自动抓取同类型视频，不做 PDF/Markdown 导出，不做版本管理，不做多人协作。

## 表结构

### creator_competitor_sample

用途：保存用户主动整理的竞品视频信息。

| 字段 | 说明 |
|---|---|
| competitor_bv_id | 竞品视频 BV 号 |
| competitor_video_name | 竞品视频名称 |
| task_id | 关联创作任务 |
| category | 同类型视频分类 |
| competitor_samples | 用户主动整理的竞品分析文本 |
| compare_dimension | 对比维度 |
| extra_context | 补充背景 |

### creator_competitor_report

用途：保存本视频相对同类型视频的对照分析。

| 字段 | 说明 |
|---|---|
| report_id | 竞品分析报告唯一标识 |
| task_id | 关联创作任务 |
| competitor_summary | 同类型视频整体打法总结 |
| competitor_advantages | 竞品优势 JSON |
| own_advantages | 本视频相对优势 JSON |
| own_disadvantages | 本视频相对短板 JSON |
| gap_analysis | 差距分析 JSON |
| improvement_suggestions | 改进建议 JSON |
| differentiation_strategy | 差异化定位建议 |
| raw_output | LLM 原始输出 |
| parse_status | 解析状态 |

### creator_report

用途：保存一次完整复盘报告。

| 字段 | 说明 |
|---|---|
| report_id | 复盘报告唯一标识 |
| task_id | 关联创作任务 |
| content_summary | 内容摘要 |
| core_selling_points | 核心卖点 JSON |
| title_description_review | 标题简介标签分区复盘 JSON |
| audience_feedback_summary | 观众反馈摘要 |
| competitor_comparison | 竞品对照结论 JSON |
| controversy_and_misunderstanding | 争议和误解点 JSON |
| next_action_suggestions | 下一步动作建议 JSON |
| creator_preference_insight | 创作者偏好洞察 JSON |
| overall_conclusion | 复盘总判断 |
| raw_output | LLM 原始输出 |
| parse_status | 解析状态 |

当前只保留每个任务一份最新竞品视频、竞品分析报告和复盘报告。

## API

### 保存竞品视频

```http
POST /api/creator/tasks/{taskId}/competitors
Content-Type: application/json
```

请求体：

```json
{
  "competitorBvId": "BV1xK4y1a7Bc",
  "competitorVideoName": "竞品视频A",
  "category": "AI 工具教程",
  "competitorSamples": "竞品A：标题突出收益，评论说节奏快。竞品B：封面和标题都强调结果。",
  "compareDimension": "标题、节奏、卖点表达、评论反馈",
  "extraContext": "人工挑选的竞品参考信息"
}
```

说明：

1. `competitorBvId` 必填，格式必须是 B 站 BV 号。
2. `competitorVideoName` 必填，最长 200 个字符。
3. `competitorSamples` 必填，最长 20000 个字符。
4. 这里只保存用户主动整理的数据，不做批量或定时抓取。
5. 当前每个任务只保留一份最新竞品视频。

### 查询竞品视频

```http
GET /api/creator/tasks/{taskId}/competitors
```

### 分析竞品视频

```http
POST /api/creator/tasks/{taskId}/competitors/analyze
Content-Type: application/json
```

请求体：

```json
{
  "customGuidance": "请更关注标题和节奏",
  "analysisFocus": "对比本视频相对同类视频的优缺点",
  "extraRequirement": "短板要给出可执行改法"
}
```

说明：

1. 任务必须先保存竞品视频，否则返回 400。
2. 发布前建议和反馈报告如果存在，会作为辅助上下文；不存在时仍可先做竞品分析。
3. 返回中包含本视频相对竞品的优势、短板、差距和改进建议。

### 查询竞品分析报告

```http
GET /api/creator/tasks/{taskId}/competitors/report
```

### 生成复盘报告

```http
POST /api/creator/tasks/{taskId}/report/analyze
Content-Type: application/json
```

请求体：

```json
{
  "customGuidance": "请重点看标题和观众反馈是否一致",
  "reviewFocus": "更关注下一期该怎么调整表达",
  "extraRequirement": "总结尽量短一点"
}
```

说明：

1. 核心材料从任务、发布前建议、反馈报告和竞品分析报告里读取，不需要重复提交。
2. `customGuidance` 为空时不添加本次业务指导，最长 2000 个字符。
3. `reviewFocus` 和 `extraRequirement` 都是可选项。
4. 任务必须先有发布前优化建议、评论弹幕分析报告和竞品分析报告，否则返回 400。
5. 如果报告解析成功且 `creatorPreferenceInsight` 非空，后端会自动沉淀一条 `creator_preference` 偏好快照。

### 查询复盘报告

```http
GET /api/creator/tasks/{taskId}/report
```

说明：

1. 任务不存在时返回 404。
2. 没有复盘报告时返回 404。
3. 返回中同时包含结构化字段和 `rawOutput`，便于人工检查。

## 设计取舍

竞品视频先用 BV 号、名称和长文本分析材料保存。

原因是第一版重点是验证参照分析闭环，不是管理复杂的竞品视频库。后续如果要做多竞品对比、标签筛选、指标对照，再拆明细表。

复盘报告必须依赖竞品分析报告。

原因是“优点”和“短板”需要参照系。只看本视频材料和评论，很容易做成自我总结。

本阶段保留 `rawOutput`。

原因是 LLM 输出不稳定，保留原文可以做失败回放，也能方便调整 Prompt。
