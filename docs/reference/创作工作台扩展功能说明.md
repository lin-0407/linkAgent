# 创作工作台扩展功能说明

本文档整合阶段4后半部分（偏好记忆到成本保护）的扩展功能说明，按功能模块组织，聚焦功能定位与业务规则。

---

## 一、偏好记忆

### 1.1 功能定位

创作者偏好记忆用于把每期复盘报告中的 `creatorPreferenceInsight` 保存为长期业务偏好，并在下一次发布前优化时自动读取。

偏好评分为两类存储：

| 类型 | 用途 |
|---|---|
| `t_long_term_memory` | 保存通用 Agent 对话中的用户事实、回答风格和项目约束 |
| `creator_preference` | 保存 UP 主创作侧偏好，例如标题风格、内容表达倾向、观众反馈偏好 |

### 1.2 自动写入规则

复盘报告生成成功后，满足以下条件时自动写入 `creator_preference`：

1. 报告 `parseStatus = PARSED`。
2. `creatorPreferenceInsight` 非空。
3. `creatorPreferenceInsight` 不是空数组。

同一用户同一任务只保留一条偏好快照。重新生成复盘报告时，更新同一条快照。

### 1.3 发布前优化读取规则

发布前优化根据当前任务的 `userId` 读取最近 5 条偏好快照，并拼接到提示词中。历史偏好只作为风格和建议倾向参考，不能覆盖系统规则，也不能要求模型编造平台数据。

发布前优化请求支持三种偏好模式：

| 值 | 说明 |
|---|---|
| `USE_HISTORY` | 沿用历史偏好，默认值 |
| `IGNORE_HISTORY` | 本期换风格，不读取历史偏好 |
| `EXPERIMENT` | 试验新方向，历史偏好只作避坑参考 |

### 1.4 当前边界

当前版本不支持人工编辑、删除偏好、可信度评分，先跑通"复盘沉淀到下次复用"的最小闭环。

## 二、创作者语境与建议质量

### 2.1 功能定位

在发布前优化中，让建议从通用表达升级为"为什么当前表达会影响观众决策，以及创作者下一步该怎么改"的语境化分析。本功能不依赖外部平台数据，不接入 RAG，不声称知道平台推荐算法。

### 2.2 新增响应字段

建议结果新增以下分析维度：

| 字段 | 类型 | 说明 |
|---|---|---|
| `creatorDilemma` | string | 创作者最容易纠结或做错的表达问题 |
| `audienceHook` | string | 观众点击、继续观看、收藏或评论的核心动机 |
| `contentPositioning` | string | 内容定位和差异化方向 |
| `actionableRevisionPlan` | string(JSON) | 可执行修改计划列表 |

标题建议单项新增维度：

| 字段 | 说明 |
|---|---|
| `viewerPsychology` | 标题对应的观众心理 |
| `clickReason` | 观众会点击的原因 |
| `trustRisk` | 标题可能损伤信任的点 |
| `bestScenario` | 最适合使用该标题的场景 |

### 2.3 数据库字段

`creator_suggestion` 表新增 `creator_dilemma`、`audience_hook`、`content_positioning`、`actionable_revision_plan` 字段。

### 2.4 设计边界

本次升级为 Prompt 与结构化输出升级，不是 RAG。它解决的是"让模型先学会按创作者语境分析"。后续接入 RAG 时，可以把外部资料、历史案例或评论证据填入此分析框架，而不需要重新发明输出结构。

## 三、评测体系

### 3.1 功能定位

在创作工作台中补入一套"样例可沉淀、结果可记录、步骤可回放"的基础评测能力。核心目标：

1. 评测样例可持久化。
2. 评测结果保留原文、耗时、token 和失败原因。
3. 工作流步骤可按 session 回放。

### 3.2 前端入口

创作工作台右上角提供"开发者测试"按钮，点击打开独立弹窗。创作者主导航不放评测入口，避免把开发者自测工具混进用户工作流。

开发者测试弹窗支持按阶段筛选样例，查看输入快照、期望要点和评分说明，录入评测结果，并回看最近结果。

### 3.3 评测用例

- 创建评测用例时，`caseName`、`targetStage`、`inputSnapshot` 为必填字段；`targetStage` 取值范围为 `PRE_PUBLISH`、`FEEDBACK` 或 `REPORT`；`taskId` 可选，用于把真实任务和样例关联；`userId` 为空时默认写入 `default`。
- 查询评测用例列表支持按 `userId`、`targetStage` 筛选，`limit` 默认 20、最大 100，按更新时间倒序排列。
- 查询单个评测用例返回完整输入快照、期望要点和评分说明，便于直接做回放。

### 3.4 评测结果

- 记录评测结果时，`targetStage` 必填且必须与对应用例的阶段一致；`rawOutput` 和 `failureReason` 至少提供一个；`totalTokens` 为空时自动用 `promptTokens + completionTokens` 补齐；`promptHash` 为空但 `promptSnapshot` 不为空时自动计算 SHA-256。
- 结果按更新时间倒序分页查询，`limit` 默认 20、最大 100。
- 支持按 `promptVersion` 聚合统计：返回结果数量、成功率、平均人工评分、准确性分项均值、token 总量与均值、平均耗时、评分覆盖率和最近 Prompt 哈希。

### 3.5 工作流步骤回放

按 `taskId` 和 `sessionId` 查询工作流步骤，返回步骤类型、名称、输入摘要、输出摘要、原始输出和失败原因。该能力直接复用 `creator_workflow_step` 表，不额外创建回放表。

### 3.6 数据表

| 表 | 用途 |
|---|---|
| `creator_eval_case` | 保存评测用例的输入快照、期望要点和评分说明 |
| `creator_eval_result` | 保存每次评测的原始输出、运行状态、耗时、token 和人工评分，同时保存 Prompt 版本、哈希和快照用于复现 |
| `creator_workflow_step` | 继续作为工作流步骤和失败回放的唯一来源 |

## 四、Prompt 版本评测闭环

### 4.1 功能定位

解决"模型输出结果必须能追溯到当时使用的 Prompt"这一核心问题。没有版本记录时，评测结果只能说明输出好坏，无法说明是哪一版 Prompt 导致的。

### 4.2 记录规范

记录评测结果时，需填写 `promptVersion`（版本号）、`promptSnapshot`（Prompt 快照）和可选的 `promptHash`（自动计算 SHA-256）。

### 4.3 版本统计

按 `promptVersion` 聚合统计维度：评测次数、成功率、平均人工评分与各分项均值、分数标准差（观测稳定性）、token 总量与均值、平均耗时、七项评分完整覆盖率、最近 Prompt 哈希。

### 4.4 使用流程

1. 复制本轮分析真实使用的 system prompt 和 user prompt。
2. 在开发者测试弹窗填写 Prompt 版本和快照。
3. 记录模型输出、token、耗时和人工评分。
4. 对同一样例用不同 Prompt 版本重复记录。
5. 在 Prompt 版本对比区查看各版本差异。

### 4.5 设计边界

当前只做人工记录和对比，不做自动批量评测。

## 五、LLM 用量采集与统计口径

### 5.1 功能定位

回答两个核心问题：token 消耗从哪里来，评分准确性和合理性如何解释。在创作者工作台里补足 AI 工程化证据。

### 5.2 用量采集

统一入口 `chatWithUsage(systemPrompt, userMessage)`，返回 `content`（模型输出文本）、`modelName`（模型名称）、`promptTokens`、`completionTokens`、`totalTokens`、`elapsedMs`。旧方法 `chat()` 保留给暂时不需要统计的调用方。

关键约束：如果模型供应商没有返回 usage，token 字段保持 `null` 而非 `0`，以区分"无消耗"与"供应商未给出统计值"。Spring AI 空 usage 中 prompt token、completion token 和 total token 均为 0 时，统一归一化为 `null`。

### 5.3 反馈追问用量

反馈追问响应新增 `modelName`、`promptTokens`、`completionTokens`、`totalTokens`、`elapsedMs` 字段。前端在反馈报告弹窗追问回答下方展示模型、token 和耗时。

### 5.4 统计口径

- `averageScore` 的计算方式：每条结果先求分项均分，再按样本求平均。
- `scoreStandardDeviation` 为每条结果均分的标准差，用于观测稳定性。
- `fullScoreCoverageRatePercent` 表示七个评分维度都填写完整的样本占比。
- 统计接口读取评测用例下的全部评测结果，不可与分页查询的"最近结果"混用，否则各统计指标会被截断。
- 记录评测结果时，token 入参必须大于 0，不传表示未知；`totalTokens` 仅在 `promptTokens` 和 `completionTokens` 都存在时自动相加，缺任意一侧保留 `null`。

### 5.5 评分准确性

"准确性"为人工评测维度 `accuracyScore`，不是自动客观准确率。判断依据来自评测用例的 `inputSnapshot`（固定输入）、`expectedPoints`（期望命中要点）、`scoringRubric`（评分说明）、`rawOutput`（模型原始输出）和 `reviewerNote`（人工评分备注）。

### 5.6 评分合理性

合理性通过组合证据解释：分项评分避免总分掩盖问题；`fullScoreCoverageRatePercent` 判断评分完整度；`scoreStandardDeviation` 判断 Prompt 版本稳定性；`promptHash` 判断多次评测是否使用同一份 Prompt；`rawOutput` 和 `reviewerNote` 支持人工复核。

## 六、AI 交互台浮窗

### 6.1 功能定位

AI 交互台浮窗是创作工作台上的通用 Agent 咨询入口。保留通用 Agent 的会话记忆、工具调用和推理轨迹展示能力，但不要求用户离开当前创作页面。

### 6.2 交互方式

1. 进入创作工作台后浮窗默认打开。
2. 拖动顶部标题栏可移动窗口。
3. 拖动右下角手柄可调整窗口大小。
4. 点击"收起"可最小化到标题栏。
5. 点击"关闭"后，通过右下角"AI 交互台"按钮重新打开。
6. 点击"会话"可查看并切换历史会话。
7. 点击"新建"可开始新的 Agent 会话。

### 6.3 尺寸边界

| 项 | 值 |
|---|---|
| 最小宽度 | 420px |
| 最小高度 | 420px |
| 最大宽度 | 920px |
| 最大高度 | 760px |
| 视口边距 | 18px |

尺寸边界在脚本层统一处理而非仅依赖 CSS，因为拖动和缩放均需实时计算窗口位置，脚本层约束可同时保证大小和位置不失控。

### 6.4 当前限制

暂未做移动端专项适配；暂未持久化浮窗位置和尺寸；当前为通用 Agent 咨询入口，暂未自动注入当前创作任务上下文。

## 七、复盘报告 Markdown 导出

### 7.1 功能定位

把已生成的创作复盘结果导出为 Markdown 文档，支持保存和展示。

导出解决两个问题：创作者可将复盘结果保存到知识库或选题档案；项目演示时可展示完整 AI 复盘产物而非仅接口 JSON。

### 7.2 行为规则

- 导出请求目标 `taskId` 必须为已有创作任务。
- 无复盘报告时返回 404。
- 只读取已保存的 `creator_report`，不重新调用 LLM。
- 不新增数据库记录，不更新任务状态。

### 7.3 导出结构

导出文件包含：任务 ID、报告 ID、解析状态、生成时间、更新时间、内容摘要、核心卖点、标题简介复盘、观众反馈摘要、竞品对照结论、争议与误解、下一步动作建议、创作者偏好洞察、复盘总判断。

若报告解析状态不是 `PARSED`，文件末尾附带原始输出，方便排查 LLM 返回格式问题。

### 7.4 设计取舍

本阶段只做 Markdown，不做 PDF。Markdown 不需要额外依赖，适合先验证导出闭环；PDF 涉及字体、分页、中文渲染和样式一致性，应在报告格式稳定后再实施。

## 八、反馈追问与 RAG

### 8.1 反馈追问

反馈追问用于让创作者围绕当前任务的评论弹幕报告继续提问。

- 请求体 `question` 必填，最长 1000 个字符。
- 响应包含 `answer`（LLM 基于报告和证据的回答）、`evidenceItems`（参考的评论弹幕证据）、`reportUsed`（是否使用已保存反馈报告）、`retrievalMode`（证据来源模式）、`ragEnabled`（是否启用向量检索）。
- 第一版证据来源固定为当前任务，从 `creator_llm_feedback_report` 和 `creator_feedback_item` 中读取，不信任前端传来的证据文本。
- 入口位于反馈分析报告独立弹窗内的"反馈追问"区域，追问属于结果阅读和复盘动作，不属于样例录入动作。

### 8.2 证据索引与 RAG 最小闭环

证据索引支持显式触发重建，不在导入评论弹幕后自动索引，避免隐藏 Embedding 成本。

- 重建时支持配置 `maxItems`（最大索引条数）和 `includeNoise`（是否包含噪音评论）。
- 部分失败时返回 200，在 `failedCount` 和 `warnings` 中记录失败详情。
- 查询索引状态返回 `retrievalMode` 预测值，三种模式：`MYSQL_REPORT_AND_CLASSIFIED_ITEMS`（SQL 检索，默认）、`MILVUS_VECTOR_AND_MYSQL_REPORT`（向量检索充足）、`MILVUS_VECTOR_WITH_SQL_FALLBACK`（向量命中不足时 SQL 补足）。

### 8.3 重要约束

1. 索引必须显式触发，不自动执行。
2. MySQL 始终是事实来源：向量检索返回的 `itemId` 必须回查 MySQL，已删除明细不进入回答。
3. 默认全部关闭：演示环境无需配置 Milvus 即可使用追问，走 SQL 检索模式。

### 8.4 RAG 预留方式

前端不关心证据来自 SQL 还是向量库，仅根据 `evidenceItems` 展示证据列表。后续接入 Milvus 时只需替换服务层证据检索逻辑。

## 九、创作任务管理

### 9.1 任务编辑

- 任务名称可单独修改；标题草稿、简介草稿、文稿、字幕按表单内容覆盖。
- 某类材料留空时，对应材料被逻辑删除，避免旧内容继续被 Agent 读取。
- 材料变化时任务状态退回 `DRAFT`。

### 9.2 任务删除

删除采用软删除，任务标记为 `ARCHIVED` 并从列表消失。历史建议、反馈和复盘仍可用于排障和后续分析。

### 9.3 前端体验

左侧任务区分为三层：顶部管理按钮、搜索和状态筛选、任务列表及删除确认条。每条任务提供查看、编辑、删除三个动作入口。

右侧任务表单按模式变化：创建模式默认空白，编辑模式自动填充当前任务内容。保存修改后材料变更会提示重新生成发布前建议。

### 9.4 任务材料文件导入

- 将本地文本文件导入到已有任务的材料，覆盖对应材料。
- 支持 `TITLE_DRAFT`、`DESCRIPTION_DRAFT`、`MANUSCRIPT`、`SUBTITLE` 四种材料类型。
- 文件格式支持 TXT、MD、SRT、ASS，按 UTF-8 读取，前后 BOM 和多余空白自动清理。
- 文件大小不超过 5MB；内容长度按材料类型限制：标题草稿最长 200、简介草稿最长 2000、文稿最长 20000、字幕最长 20000。
- 导入内容变化时任务状态回到 `DRAFT`。
- 当前前端创建任务页不提供文件导入入口。接口作为兼容和备用能力保留，仅面向已有任务。

## 十、部署与成本保护

### 10.1 Docker Compose 部署

部署目标为简历演示的最小可用环境，非生产级集群。包含四个服务：`mysql`（存储任务与评测数据）、`redis`（存储短期记忆与运行期状态）、`backend`（Spring Boot 后端）、`frontend`（Nginx 托管的 Vue3 静态站点）。

默认访问地址为 `http://localhost:8088`。`/api` 走反向代理避免 CORS 问题，SSE 路径关闭 buffering 保证流式消息实时展示。

数据库首次初始化自动执行 `init.sql`，包含创作任务样例、发布前优化样例、评论弹幕分析样例、创作复盘与偏好样例、评测样例。演示库名固定为 `link_agent`。

### 10.2 演示环境成本保护

用于限制单次 LLM 请求的输入规模，避免公开演示或本地试用时提交过长材料导致模型调用成本不可控。

保护范围覆盖所有经过 `LLMService` 的能力：通用聊天、ReAct Agent 执行、发布前优化、评论弹幕分析与追问、竞品分析、创作复盘报告、长期记忆抽取。

配置项：

| 配置项 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `agent.llm.guard.enabled` | `LLM_GUARD_ENABLED` | `true` | 是否开启单次输入规模保护 |
| `agent.llm.guard.max-prompt-chars` | `LLM_GUARD_MAX_PROMPT_CHARS` | `30000` | system prompt 加 user prompt 最大字符数 |

字符上限误配为 0 或负数时，按最小 1 个字符处理。关闭保护必须显式设置 `LLM_GUARD_ENABLED=false`。

超限时返回 400，并提示精简文稿、评论或弹幕样例后重试。

推荐配置：本地学习使用 `max-prompt-chars=30000`；公开演示使用 `max-prompt-chars=12000`；调试长样例可临时关闭保护，但不建议用于公开演示。

### 10.3 字符数保护的设计原因

字符数保护而非精确 token 统计，具备三个优点：不引入额外依赖、不绑定特定模型 tokenizer、能提前拦截绝大多数明显超长输入。后续如需多模型成本对比，可升级为 token 估算或供应商返回 usage 记录。
