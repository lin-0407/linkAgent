# 创作任务管理体验优化说明

## 功能定位

这次优化的目标不是新增新的创作能力，而是把创作任务入口做得更好用：

1. 任务能更快找到。
2. 任务能直接编辑。
3. 任务能直接删除。
4. 创建和编辑共用同一套表单，减少页面跳转。

工作台仍然围绕单个 `taskId` 展开，后续发布前优化、评论弹幕分析和复盘报告都不变。

## API

### 更新任务

```http
PUT /api/creator/tasks/{taskId}
Content-Type: application/json
```

请求体：

```json
{
  "taskName": "新任务名",
  "titleDraft": "新标题草稿",
  "descriptionDraft": "新简介草稿",
  "manuscript": "新文稿",
  "subtitle": "新字幕"
}
```

说明：

1. 任务名称可单独改。
2. 标题草稿、简介草稿、文稿、字幕会按表单内容覆盖。
3. 某类材料留空时，对应材料会被逻辑删除，避免旧内容继续被 Agent 读取。
4. 如果材料发生变化，任务状态会退回 `DRAFT`。

### 删除任务

```http
DELETE /api/creator/tasks/{taskId}
```

说明：

1. 删除采用软删除，不会物理清空任务和材料记录。
2. 任务会从列表中消失，并标记为 `ARCHIVED`。
3. 历史建议、反馈和复盘仍可用于排障和后续分析。

## 前端体验

### 任务管理台

左侧任务区现在分成三层：

1. 顶部管理按钮。
2. 搜索和状态筛选。
3. 任务列表和删除确认条。

每条任务都提供三个动作：

1. 查看：切换到当前任务并加载工作流上下文。
2. 编辑：把任务内容装入表单，进入编辑模式。
3. 删除：先确认再软删除。

### 创建 / 编辑表单

右侧任务表单会根据模式变化：

1. 创建模式默认空白。
2. 编辑模式自动填充当前任务内容。
3. 保存修改后，材料变更会提示用户重新生成发布前建议。

## 设计原因

这套改法优先保留当前单页工作台结构，没有把任务拆到独立页面，是为了不破坏 `taskId` 驱动的分析闭环。

同时没有引入复杂表格组件，因为当前任务数据量不大，真正需要的是动作入口清楚、筛选直接、误操作少。
