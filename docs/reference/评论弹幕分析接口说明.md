# 评论弹幕分析接口说明

## 功能定位

评论弹幕分析模块用于处理用户主动粘贴的评论和弹幕样例，帮助创作者理解发布后的观众反馈。

它输出：

1. 观众整体反馈摘要。
2. 高频观点。
3. 情绪倾向。
4. 争议点。
5. 误解点。
6. 下一期内容建议。
7. 互动回应建议。

第一版不接入真实平台数据，不做爬取，不做复盘总报告。

## 表结构

### creator_user_feedback_detail

用途：保存一轮评论和弹幕样例。

关键字段：

| 字段 | 说明 |
|---|---|
| feedback_id | 反馈样例唯一标识 |
| task_id | 关联创作任务 |
| comment_samples | 评论样例 |
| danmaku_samples | 弹幕样例 |
| extra_context | 补充背景 |

### creator_llm_feedback_report

用途：保存一轮反馈分析结果。

关键字段：

| 字段 | 说明 |
|---|---|
| report_id | 报告唯一标识 |
| task_id | 关联创作任务 |
| feedback_summary | 观众整体反馈摘要 |
| hot_topics | 高频观点 JSON |
| sentiment_summary | 情绪倾向总结 |
| controversy_points | 争议点 JSON |
| misunderstanding_points | 误解点 JSON |
| next_content_suggestions | 下一期内容建议 JSON |
| interaction_suggestions | 互动回应建议 JSON |
| raw_output | LLM 原始输出 |
| parse_status | 解析状态 |

当前每个任务只保留一份最新样例和一份最新报告。

## API

### 保存样例

```http
POST /api/creator/tasks/{taskId}/feedback
Content-Type: application/json
```

请求体：

```json
{
  "commentSamples": "这期节奏很清楚，我第一次看懂了整个流程。",
  "danmakuSamples": "讲得太实用了 / 这一段信息密度很高",
  "extraContext": "发布后 24 小时内收集的样例"
}
```

说明：

1. `commentSamples` 和 `danmakuSamples` 至少填写一项。
2. `extraContext` 可选。
3. `taskId` 不存在时返回 404。

### 查询样例

```http
GET /api/creator/tasks/{taskId}/feedback
```

说明：

1. 任务不存在时返回 404。
2. 样例不存在时返回 404。

### 分析样例

```http
POST /api/creator/tasks/{taskId}/feedback/analyze
Content-Type: application/json
```

请求体：

```json
{
  "customGuidance": "可选，分析顺序、关注重点和建议风格等业务指导",
  "analysisFocus": "重点看观众是否理解核心方法",
  "extraRequirement": "给出下一期选题建议"
}
```

说明：

1. 主要样例从数据库读取，不需要重复提交。
2. `customGuidance` 为空时不添加本次业务指导，最长 2000 个字符。
3. 分析成功后任务状态更新为 `FEEDBACK_ANALYZED`。
4. 后端系统提示词固定维护角色、平台数据边界和 JSON 输出结构，前端不能覆盖。
5. 任务没有样例时返回 400。

### 查询报告

```http
GET /api/creator/tasks/{taskId}/feedback/report
```

说明：

1. 任务不存在时返回 404。
2. 报告不存在时返回 404。
3. 返回中同时包含结构化字段和 `rawOutput`，便于人工检查。

## 设计取舍

本阶段没有上 SSE。

原因是当前目标是先把“样例输入 -> 反馈分析 -> 数据库存档”这条线跑通。SSE 更适合在后续做过程可视化，不应该和主业务逻辑混在一起。

本阶段没有拆更多子表。

原因是 MVP 先要简单。反馈摘要、争议点和建议都属于一次分析结果，先放一个表里足够支撑演示和简历展示。

本阶段保留 `rawOutput`。

原因是 LLM 输出不稳定，保留原文可以做失败回放，也方便后面调整业务指导。
