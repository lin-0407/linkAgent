# 时间线调整采纳接口说明

更新时间：2026-10-21。对应 S4-3c。时长建议本身见 [音乐字幕与时长建议接口说明](音乐字幕与时长建议接口说明.md)；配音生成见 [配音与自动字幕对齐接口说明](配音与自动字幕对齐接口说明.md)。

## 1. 适用范围

| 项目 | 说明 |
| --- | --- |
| 前置 | 故事板已保存，且其简报仍是任务当前最新简报 |
| 输入 | 当前 `timing` 报告里真实存在的 `EXTEND_SCENE` / `SHORTEN_SCENE` 提案 |
| 结果 | 新简报版本（新目标时长）+ 新故事板版本（调整后场景） |
| 副作用 | 无外部调用、无费用、无模型请求 |
| 幂等 | `Idempotency-Key` 作用于 `storyboards/{id}` + 请求体 |

不支持的操作：任意毫秒数微调、`RECORD_AGAIN` / `SUPPLY_MORE_VIDEO` / `PREPARE_REAL_AUDIO` 等需要重录、重生成或补素材的提案、跨场景顺序调整。

## 2. 请求

```
POST /api/creator/tasks/{taskId}/creation/storyboards/{storyboardId}/timeline:apply
Idempotency-Key: <最多 128 字符>
Content-Type: application/json
```

```json
{
  "expectedWorkspaceRevision": 7,
  "adjustments": [
    {
      "sceneId": "opening",
      "proposalCode": "EXTEND_SCENE",
      "durationMs": 5134
    }
  ]
}
```

字段：

| 字段 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- |
| `expectedWorkspaceRevision` | 是 | ≥ 0 | 工作区当前修订；不匹配时 409，避免覆盖他人改动 |
| `adjustments` | 是 | 1–48 项 | 每个场景最多出现一次 |
| `adjustments[].sceneId` | 是 | `[A-Za-z0-9_-]{1,64}` | 必须是当前故事板的场景 |
| `adjustments[].proposalCode` | 是 | `EXTEND_SCENE` 或 `SHORTEN_SCENE` | 其他提案代码会被字段校验拒绝 |
| `adjustments[].durationMs` | 是 | 1–30000 | 必须等于服务端提案的 `proposedDurationMs` |

`durationMs` 不是"用户希望的时长"，而是**采纳哪一条提案**的选择器。服务端重新计算 `timing` 后逐项核对，不允许传近似值。

## 3. 响应

```json
{
  "board": {
    "storyboardId": "8f1c...",
    "revision": 3,
    "briefId": "2b7d...",
    "parentStoryboardId": "5a90...",
    "runId": null,
    "documentHash": "...",
    "document": { "schemaVersion": "storyboard.v1", "subtitleTimingSource": "ASR_ALIGNED", "candidate": { "scenes": [] } },
    "check": {
      "renderable": true,
      "problems": [],
      "durationMs": 6133,
      "renderContentHash": "..."
    }
  },
  "briefRevision": 2,
  "targetDurationMs": 6133,
  "applied": [
    { "sceneId": "opening", "proposalCode": "EXTEND_SCENE", "previousDurationMs": 5000, "durationMs": 5134 }
  ],
  "notes": ["背景音乐区间终点已随总时长从 5000ms 调整为 6134ms"]
}
```

| 字段 | 说明 |
| --- | --- |
| `board` | 新故事板视图，`check` 与查询接口一致；不要求已全部可渲染 |
| `briefRevision` | 新简报版本号，原简报版本仍可按 `briefId` 查询 |
| `targetDurationMs` | 新简报的目标时长，等于调整后场景帧长 |
| `applied` | 本次实际生效的场景时长变化 |
| `notes` | 音乐区间随总时长调整等需要作者知道的事实 |

## 4. 处理规则

### 4.1 提案核对

1. 用与 `GET /timing` 相同的计算重新生成当前报告；
2. 对每个 `(sceneId, proposalCode)` 找到对应提案；
3. 提案不存在 → 409，提示不能凭任意时长调整；
4. `proposedDurationMs` 缺失或与请求不一致 → 409。

`EXTEND_SCENE` 只有在场景能容纳完整音频、且视频素材余量足够时才会出现；因此"提案存在"本身就意味着素材约束已满足，服务端仍会二次核对视频区间。

### 4.2 场景与视频区间

- 新场景时长 = 请求的 `durationMs`；
- `VIDEO_CLIP` 场景：`sourceInMs` 不变，`sourceOutMs = sourceInMs + round(frames(durationMs) * 1000 / 30)`；
- 新终点超过素材真实画面时长 → 409，提示补充视频或缩短文稿；
- 图文场景不涉及选区。

### 4.3 总时长与音乐

- 新总帧长 = 所有场景帧长之和，必须在 30–5400 帧；
- 新 `targetDurationMs = round(总帧长 * 1000 / 30)`；
- 简报有 `backgroundMusic` 时：`sourceInMs` 不变，`sourceOutMs = sourceInMs + targetDurationMs`；
- 新终点超过音乐素材真实时长 → 409，提示重新选择区间；
- 淡入淡出总长超过新区间 → 409。

### 4.4 版本与历史

| 版本 | 变化 |
| --- | --- |
| 原简报 | 原文、来源快照、素材选择全部保留，不再是最新版本 |
| 原故事板 | `document_json`、素材快照、字幕来源全部保留 |
| 新简报 | `revision+1`，文档复制后仅改 `targetDurationMs` 和必要时的 `backgroundMusic.sourceOutMs` |
| 新故事板 | `revision+1`，`parent_storyboard_id` = 原故事板，`briefId` = 新简报 |

新故事板的 `subtitleTimingSource` 沿用原版本（`USER_PROVIDED` / `ASR_ALIGNED` / `NOT_PROVIDED`），不会因为改时长把用户字幕标成机器对齐。

### 4.5 工作区与并发

- 需要任务行锁；
- `expectedWorkspaceRevision` 必须等于当前修订；
- 工作区不能有活动运行或其他活动制作；
- 故事板必须基于当前最新简报；
- 同键同请求重放返回原版本，不重复创建简报或故事板；同键不同请求 409。

## 5. 错误码

| HTTP | 场景 | 说明 |
| --- | --- | --- |
| 400 | 缺修订、`adjustments` 为空、`proposalCode` 非法、`durationMs` 越界 | 字段校验，未进入服务层 |
| 400 | 缺少 `Idempotency-Key` | 请求头校验 |
| 404 | 任务或故事板不存在 | 与查询接口一致 |
| 409 | `任务不存在` | 归属不符 |
| 409 | `当前简报已更新，请使用最新简报的故事板调整时间线` | 故事板依据过期 |
| 409 | `场景 X 当前不存在 Y 提案，不能凭任意时长调整` | 提案不成立 |
| 409 | `采纳时长必须与当前时长提案给出的毫秒数一致` | 传了近似或任意值 |
| 409 | `同一场景不能在一次请求中重复调整` | 重复项 |
| 409 | `同一时间线幂等键对应不同请求` | 幂等冲突 |
| 409 | `调整后的总时长必须在 1 至 180 秒之间` | 总长越界 |
| 409 | `延长后的视频区间超出素材实际时长，请补充视频或缩短文稿后重新生成` | 画面不足 |
| 409 | `背景音乐区间需要重新选择：随总时长延展到 Xms 会超出素材实际时长` | 音乐不足 |
| 409 | `工作区已变化或仍有活动制作，请先取消并刷新` | 修订不符或运行中 |

## 6. 与配音流程的配合

推荐顺序：

```
保存简报 → 生成故事板 → 生成配音（S4-3b，得到 ASR_ALIGNED 新版本）
        → GET timing（基于真实配音时长）
        → POST timeline:apply（采纳 EXTEND_SCENE / SHORTEN_SCENE）
        → 编译并渲染新工程
```

先采纳再配音时，配音运行保存结果会因"配音依据已变化"失败，需要基于新简报重新受理。这是有意的：音频长度未知时，时间线只能靠猜。

## 7. 未包含

- 环境声独立混音；
- 页面拖拽、输入任意时长、跨场景排序；
- 整体拉伸/压缩到固定总时长；
- 修改场景文稿后自动重新生成配音；
- 素材替换、场景增删（S6）。
