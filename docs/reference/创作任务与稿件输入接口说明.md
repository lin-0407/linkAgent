# 创作任务与稿件输入接口说明

## 功能定位

创作任务是 UP 主智能工作台的业务入口。后续字幕/文稿分析、标题简介建议、评论弹幕分析和复盘报告都围绕 `taskId` 展开。

第一版只处理用户主动提交的文本材料，包括手工粘贴和本地文本文件导入；不接入爬虫、不读取 B 站账号数据、不做自动投稿。

## 表结构

### creator_task

用途：保存创作任务主信息。

关键字段：

| 字段 | 说明 |
|---|---|
| task_id | 对外使用的任务唯一标识 |
| user_id | 用户标识，单人工作台默认写入 `default`，仅作为未来扩展字段 |
| task_name | 任务名称 |
| status | 任务状态，当前默认 `DRAFT` |

### creator_material

用途：保存任务输入材料。

关键字段：

| 字段 | 说明 |
|---|---|
| task_id | 关联 `creator_task.task_id` |
| material_type | 材料类型 |
| content | 用户主动输入的文本内容 |

当前材料类型：

```text
TITLE_DRAFT
DESCRIPTION_DRAFT
MANUSCRIPT
SUBTITLE
```

## API

### 创建创作任务

```http
POST /api/creator/tasks
Content-Type: application/json
```

请求体：

```json
{
  "taskName": "AI 工具使用经验分享",
  "titleDraft": "我用 AI 写代码的真实体验",
  "descriptionDraft": "分享一次从需求到上线的 AI 辅助开发过程",
  "manuscript": "这里粘贴视频文稿",
  "subtitle": "这里粘贴字幕文本"
}
```

说明：

1. `userId` 是可选兼容字段，当前单人工作台前端不展示，后端默认使用 `default`。
2. `taskName` 不传时优先截取 `titleDraft`，否则使用“未命名创作任务”。
3. `titleDraft`、`descriptionDraft`、`manuscript`、`subtitle` 至少传一个。

### 查询创作任务列表

```http
GET /api/creator/tasks?limit=20
```

说明：

1. `userId` 不传时查询全部任务，符合单人开源工作台的默认使用方式。
2. `limit` 不传时默认 20，最大 100。
3. 列表返回每个任务的材料数量，便于前端快速展示任务完整度。
4. 如未来需要多人隔离，可显式传 `userId` 查询指定用户的任务。

### 查询创作任务详情

```http
GET /api/creator/tasks/{taskId}
```

说明：

1. 任务不存在时返回 404。
2. 响应中包含任务主信息和材料列表。

### 更新创作任务

```http
PUT /api/creator/tasks/{taskId}
Content-Type: application/json
```

说明：

1. `taskName` 可选，不传时会沿用标题草稿的推导逻辑。
2. `titleDraft`、`descriptionDraft`、`manuscript`、`subtitle` 采用覆盖式更新。
3. 某类材料留空时，对应材料会被逻辑删除。
4. 只要材料发生变化，任务状态会回到 `DRAFT`。

### 导入本地文本文件到任务材料

```http
POST /api/creator/tasks/{taskId}/materials/import
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| materialType | 是 | 目标材料类型：`TITLE_DRAFT`、`DESCRIPTION_DRAFT`、`MANUSCRIPT`、`SUBTITLE` |
| file | 是 | 本地文本文件，当前支持 TXT、MD、SRT、ASS |

说明：

1. 文件导入只处理用户主动上传的本地文本，不触发平台采集。
2. 导入内容会覆盖对应材料，后端返回最新任务详情。
3. 如果导入内容发生变化，任务状态会回到 `DRAFT`，提醒用户重新生成发布前建议和后续复盘。
4. 标题草稿最长 200，简介草稿最长 2000，文稿和字幕最长 20000；文件内容也遵守同一组限制。

### 删除创作任务

```http
DELETE /api/creator/tasks/{taskId}
```

说明：

1. 删除采用逻辑删除，不做物理清空。
2. 任务会从列表中隐藏，状态标记为 `ARCHIVED`。
3. 任务下的材料也会一起逻辑删除，避免旧内容继续被后续分析读取。

## 设计取舍

`creator_task` 和 `creator_material` 拆表，是为了避免任务主表被字幕、文稿、评论、弹幕等长文本字段撑大。

当前使用 MyBatis 注解 SQL，是为了保持和长期记忆模块一致的学习成本。等后续出现复杂查询、动态 SQL 或多表报告聚合时，再考虑迁移到 XML。

当前任务状态链已经扩展为 `DRAFT`、`PRE_PUBLISH_ANALYZED`、`FEEDBACK_ANALYZED`、`COMPETITOR_ANALYZED`、`ANALYZED`、`ARCHIVED`。

其中：

1. `DRAFT` 代表只完成了任务和材料输入。
2. `PRE_PUBLISH_ANALYZED` 代表已完成发布前优化。
3. `FEEDBACK_ANALYZED` 代表已完成评论弹幕分析。
4. `COMPETITOR_ANALYZED` 代表已完成同类型视频竞品分析。
5. `ANALYZED` 代表已完成整套复盘汇总。
6. `ARCHIVED` 预留给后续历史任务归档。

任务编辑时，前端会按当前表单内容覆盖材料；如果材料内容变化，后端会把任务状态重新压回 `DRAFT`，避免用户误以为旧建议还能继续直接沿用。

## 后续接入点

阶段 4.2 发布前优化 Agent 可以通过 `taskId` 读取 `MANUSCRIPT`、`SUBTITLE`、`TITLE_DRAFT` 和 `DESCRIPTION_DRAFT`。

阶段 4.3 评论弹幕分析会新增反馈材料表，不应复用 `creator_material` 存评论弹幕，因为评论弹幕有来源、时间和分组等额外语义。

阶段 4.4 先保存竞品视频信息并生成竞品分析，再把发布前建议、评论弹幕分析和竞品分析挂到同一个 `taskId` 下，形成完整创作闭环。
