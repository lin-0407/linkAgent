# 评测集与失败回放接口说明

## 功能定位

这一轮不是做自动化评测平台，而是给创作者工作台补一套“样例可沉淀、结果可记录、步骤可回放”的基础能力。

核心目标：

1. 评测样例可以持久化。
2. 评测结果可以保留原文、耗时、token 和失败原因。
3. 工作流步骤可以按 session 回放。

## 前端入口

创作工作台只提供一个开发者入口：

1. 右上角“开发者测试”按钮：点击后打开独立弹窗。
2. 创作者主导航不放评测入口，避免把开发者自测工具混进用户工作流。

开发者测试弹窗支持按阶段筛选样例，查看输入快照、期望要点和评分说明，录入一次评测结果，并回看最近结果。

## 评测用例 API

### 创建评测用例

```http
POST /api/creator/evaluations/cases
Content-Type: application/json
```

请求体：

```json
{
  "userId": "default",
  "caseName": "发布前优化 - 标题表达克制样例",
  "targetStage": "PRE_PUBLISH",
  "taskId": "sample-task-prepublish-001",
  "inputSnapshot": "任务名称：标题表达优化样例；输入：标题草稿=...",
  "expectedPoints": "[\"标题应直接说明视频价值\"]",
  "scoringRubric": "[\"是否能输出可直接使用的标题建议\"]"
}
```

说明：

1. `caseName`、`targetStage`、`inputSnapshot` 必填。
2. `targetStage` 只能是 `PRE_PUBLISH`、`FEEDBACK` 或 `REPORT`。
3. `taskId` 可选，方便把真实任务和样例串起来。
4. `userId` 为空时默认写成 `default`。

### 查询评测用例列表

```http
GET /api/creator/evaluations/cases?userId=default&targetStage=PRE_PUBLISH&limit=20
```

说明：

1. `userId`、`targetStage`、`limit` 都是可选参数。
2. `limit` 默认 20，最大 100。
3. 返回按更新时间倒序排列，方便先看最近加的样例。

### 查询单个评测用例

```http
GET /api/creator/evaluations/cases/{caseId}
```

返回完整输入快照、期望要点和评分说明，方便直接做回放。

## 评测结果 API

### 记录评测结果

```http
POST /api/creator/evaluations/cases/{caseId}/results
Content-Type: application/json
```

请求体：

```json
{
  "taskId": "task-001",
  "workflowSessionId": "session-001",
  "targetStage": "PRE_PUBLISH",
  "modelName": "qwen3",
  "outputSummary": "输出摘要",
  "rawOutput": "{\"titleSuggestions\":[...]}",
  "elapsedMs": 1280,
  "promptTokens": 640,
  "completionTokens": 210,
  "readabilityScore": 4,
  "relevanceScore": 5,
  "completenessScore": 4,
  "accuracyScore": 4,
  "stabilityScore": 3,
  "costScore": 4,
  "explainabilityScore": 5,
  "reviewerNote": "标题更贴近工作台主线"
}
```

说明：

1. `targetStage` 必填，且必须和对应用例的阶段一致。
2. `rawOutput` 和 `failureReason` 至少要提供一个。
3. `totalTokens` 为空时，后端会用 `promptTokens + completionTokens` 补齐。
4. `rawOutput` 会原样保存，便于后续失败回放和人工检查。

### 查询某个用例下的评测结果

```http
GET /api/creator/evaluations/cases/{caseId}/results?limit=20
```

说明：

1. `limit` 默认 20，最大 100。
2. 返回按更新时间倒序排列，先看最近一轮结果。

## 工作流步骤 API

### 查询步骤回放

```http
GET /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/steps
```

返回内容包括：

1. 步骤类型。
2. 步骤名称。
3. 输入摘要。
4. 输出摘要。
5. 原始输出。
6. 失败原因。

这个接口直接复用 `creator_workflow_step` 表，不再新造一套回放模型，避免同一条过程数据重复存两份。

## 数据说明

### `creator_eval_case`

保存评测用例的输入快照、期望要点和评分说明。

### `creator_eval_result`

保存每次评测的原始输出、运行状态、耗时、token 和人工评分。

### `creator_workflow_step`

继续作为工作流步骤和失败回放的唯一来源。

## 设计原因

1. 先把样例和结果落库，比先做复杂评测算法更贴近当前项目阶段。
2. 评测结果必须保留 raw output，否则后面很难看清模型到底为什么失手。
3. 工作流步骤复用现有表最稳，不需要再开一张重复的回放表。
