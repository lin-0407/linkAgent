# 音乐、字幕与时长建议接口说明

更新：2026-10-21。本说明对应 S4-3a，开发边界见[实现说明](../develop/视频自动制作-S4-3a音乐字幕与时长建议.md)，原简报和故事板用法见[S4-2 接口](简报故事板与工程接口说明.md)。当前为后端接口，尚无对应公开制作页面。

统一前缀为 `/api/creator/tasks/{taskId}/creation`。沿用个人自托管工作台的 `default` 归属，要求 `creator.media.enabled=true`。真实出片仍需启用原 renderer，并准备 Python renderer `0.3.0`、FFmpeg/FFprobe、中文字体和私有存储；保存简报、导入字幕或查询建议本身不会出片。

## 选择自己的背景音乐

先用[S4-1 素材接口](独立素材导入后端说明.md)上传 `MUSIC` 素材，等待 READY。随后在 `POST /briefs` 的 `BriefInput` 增加可空 `backgroundMusic`，并把音乐 ID 加入 `assetIds`。仍需 `Idempotency-Key` 和当前 `expectedWorkspaceRevision`。

| 字段 | 约束 |
| --- | --- |
| `assetId` | 本任务 READY 的 MUSIC 素材，必须包含在本简报 `assetIds` 中 |
| `sourceInMs` | 非负整数，相对规范化音乐文件的开始位置 |
| `sourceOutMs` | 大于起点的整数；API 字段最多 1200000 毫秒（20 分钟），实际仍受素材时长和编译检查限制 |
| `gainDb` | 必填，-36 至 0，最多一位小数，例如 `-18.0` |
| `fadeInMs/fadeOutMs` | 分别 0 至 10000 毫秒，合计不能超过选区长度 |
| `ducking` | 必填布尔值；`true` 表示主音轨有声音时压低背景音乐 |

示例只展示简报请求；ID 和修订必须替换成实际值：

```json
{
  "expectedWorkspaceRevision": 6,
  "topic": "整理书桌",
  "coreMessage": "先分类，再保留常用物品",
  "audience": "第一次整理桌面的学生",
  "targetDurationMs": 5000,
  "dialogueMode": "NO_DIALOGUE",
  "contentKind": "USER_PROVIDED",
  "assetIds": ["ready-music-id"],
  "constraints": "文字卡配用户自己的音乐",
  "backgroundMusic": {
    "assetId": "ready-music-id",
    "sourceInMs": 1000,
    "sourceOutMs": 6000,
    "gainDb": -18.0,
    "fadeInMs": 300,
    "fadeOutMs": 500,
    "ducking": true
  }
}
```

不选音乐时省略该字段或使用 `null`；不会给原无音乐简报补一个新字段而改变旧请求摘要。音乐不会修改对白选择：`NO_DIALOGUE` 允许背景音乐，但不会因此生成旁白。

音乐选区要与故事板全片帧长一致，最多一帧误差；不会自动循环、变速、选歌或延长素材。保存简报成功不代表编译通过，需再查看故事板的 `check`。NORMALIZED 音乐需要真实 48 kHz、双声道 PCM16 WAV；当前素材准备时长最多 20 分钟，选区不得超过实际尾部。

渲染时背景音乐独占角色可用至 64 MiB，其他单素材至 32 MiB，引用总量至 256 MiB。换音乐或音量等设置需要新简报及相应故事板；旧版、素材摘要和引用保留。音乐来自用户上传，不涉及自动下载、版权库接入或供应商调用。

## 给指定场景导入用户 SRT

```text
POST /storyboards/{storyboardId}/subtitles:import
Idempotency-Key: 本次导入的独立键
Content-Type: application/json
```

请求：

```json
{
  "expectedWorkspaceRevision": 9,
  "sceneId": "opening",
  "srt": "1\n00:00:00,000 --> 00:00:01,000\n先把东西分类\n\n2\n00:00:01,000 --> 00:00:02,000\n再保留常用物品"
}
```

`expectedWorkspaceRevision` 取实际 runtime 修订；目标场景须存在于该故事板，且使用真实用户录音 `NARRATION` 或视频原声 `ORIGINAL`。该例要求对应音轨及场景实际容纳 0 至 2 秒字幕；不能将示例时间套用到另一段录音。

SRT 规则：

- 原文为有效 UTF-8，至多 64 KiB；可带开头 BOM，支持 CRLF 和多行正文。
- 每条包含正整数且不重复的编号、标准逗号毫秒时间、非空正文，以空行分隔。
- 时间格式严格为 `hh:mm:ss,mmm --> hh:mm:ss,mmm`，分钟和秒须在 00 至 59，结束晚于开始；按序且不重叠。
- 每场景至多 100 条，每条正文至多 120 字符；全片至多 200 条。正文不能包含换行以外的控制字符。
- 字幕必须处于真实音轨与量化场景范围内。系统不会移动非法时间来强行接受。

录音字幕相对本场景录音起点；视频原声字幕相对所选视频区间起点。例如选区为原视频 10 至 12 秒，用户 SRT 应使用 0 至 2 秒；如原声音轨从该选区的第 0.5 秒才开始，字幕也不能提前到 0 秒。

成功返回 HTTP 200、`Cache-Control: no-store`，正文为新的 `BoardView`，字段沿用 S4-2：

```text
storyboardId / revision / briefId / parentStoryboardId / runId
documentHash / document / check
```

新 `parentStoryboardId` 指向导入前版本，`document.subtitleTimingSource=USER_PROVIDED`，本场景原 `cues` 整体替换为导入结果。其他场景、旧故事板、已有成片及试映报告保持原记录。其他场景待准备可以继续存在，因此成功响应的 `check.renderable` 仍可能为 `false`。

新导入必须基于最新简报；工作区修订变化或有活动制作时，按原保存门禁拒绝。重新读取工作区、处理冲突后再明确提交，不循环盲重试。

幂等校验包含目标故事板、场景、修订和 SRT **原文**。同键同请求重放返回同一新版本；同键改正文、BOM、换行、目标或修订均拒绝，即使规范化后 cue 相同。确实要改文件时使用新键。导入只采用用户已有时间码，不调用 ASR、不承诺自动对齐，也不产生模型费用。

## 查询真实时长与处理提案

```text
GET /storyboards/{storyboardId}/timing
```

返回 HTTP 200、`Cache-Control: no-store`。该接口只读，不需要幂等键，不创建版本、不消耗工作区修订、不修改目标时长、不触发付费调用。

| 顶层字段 | 含义 |
| --- | --- |
| `storyboardId/briefId` | 查询的不可变故事板及简报 |
| `targetDurationMs` | 用户简报目标时长 |
| `quantizedDurationMs` | 所有场景量化为 30 fps 后的总帧长，按毫秒返回 |
| `differenceMs` | 总帧长减目标时长；正值表示超出目标 |
| `scenes` | 各场景时长、真实音频时长和处理提案 |
| `proposals` | 汇总的场景提案及全片时长提案 |
| `requiresUserDecision` | 是否存在需处理或确认的提案；不是制作授权 |

`scenes` 每项包含 `sceneId/audioMode/sceneDurationMs/audioDurationMs/differenceMs/timingSource/proposals`。这里场景差值为真实音频时长减场景帧长，含义与顶层总长差异对应各自范围。无实际音频时 `audioDurationMs/differenceMs` 为 `null`。

`timingSource` 可能为 `NORMALIZED_MEDIA`、`MISSING`、`NOT_GENERATED` 或 `NOT_REQUIRED`。前者来自冻结媒体元数据；TTS 尚无实际音频时使用 `NOT_GENERATED`，不会按文字长度估算。

音乐问题使用 `BGM_MISSING/BGM_FORMAT_INVALID/BGM_DURATION_MISMATCH/BGM_OUT_OF_RANGE/BGM_MIX_INVALID` 等代码返回到 proposals，要求用户选择后另存简报或素材，不自动循环、改范围或应用建议。

| 提案 `code` | 用户需要做的选择 |
| --- | --- |
| `EXTEND_SCENE` | 延长场景以容纳整段录音，并重新确认全片目标时长；可用 `timeline:apply` 采纳 |
| `RECORD_AGAIN` | 保持镜头长度，重新录制较短音频 |
| `SHORTEN_SCENE` | 缩短场景，或明确保留录音后的画面留白；可用 `timeline:apply` 采纳 |
| `SPLIT_OR_RECORD_AGAIN` | 录音超出单场景 30 秒，拆分或重新录制 |
| `SUPPLY_RECORDING` | 补充可靠的实际录音 |
| `SUPPLY_VIDEO_CLIP/SUPPLY_MORE_VIDEO` | 补素材，或把视频选区调整到实际有效范围 |
| `ADJUST_CLIP_RANGE` | 视频选区长度与场景帧长不一致，重新截取 |
| `SUPPLY_SOURCE_AUDIO` | 补充带原声的视频或重新选择有原声的区间 |
| `CONFIRM_SOURCE_SILENCE` | 原声只覆盖部分镜头，确认原始静音或重新选择区间 |
| `PREPARE_REAL_AUDIO` | 等实际配音准备完成后，再按音频给出时长判断 |
| `CONFIRM_TOTAL_DURATION` | 调整场景，或创建新简报明确全片目标 |

每条提案为 `sceneId/code/message/proposedDurationMs`；全片提案的 `sceneId` 可空，没有具体建议长度时 `proposedDurationMs` 可空。例如 3 秒录音放入 2 秒场景，会同时得到延长至 3000 毫秒和重新录音的选项，系统不会替用户决定或截断原音。

报告只说明时长事实与建议，不代替 `BoardView.check`、真实渲染和完整试映。`EXTEND_SCENE` 与 `SHORTEN_SCENE` 可以用 [时间线调整采纳接口](时间线调整采纳接口说明.md) 显式采纳，服务端会同步视频选区、音乐区间并新建简报与故事板版本；其他提案要求重录、重新生成配音或补充素材，没有自动应用入口，也不会被系统静默采纳。

## 当前尚未提供

本说明对应 S4-3a 的只读报告。真实 TTS 与转写字幕见 [配音与自动字幕对齐接口说明](配音与自动字幕对齐接口说明.md)，时长提案采纳见 [时间线调整采纳接口说明](时间线调整采纳接口说明.md)。环境声的独立可调混音、音乐下载/供应商接入、素材与故事板页面、SAMPLE 样片或自然语言局部修改仍未提供。原整片授权和发布后门禁继续生效，当前后端能力不等于浏览器端到端制作已验收。
