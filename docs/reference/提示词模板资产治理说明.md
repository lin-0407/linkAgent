# 提示词模板资产治理说明

> 本文记录 2026-07-05 对 `llm_prompt_template` 的资产盘点结果。提示词模板仍以数据库为唯一运行期来源，通过 `PromptService.get(...)` 和 `PromptService.render(...)` 每次查库读取，继续支持热更新。

## 1. 结论

当前 `init.sql` 共维护 30 条提示词模板。

盘点后没有发现可以直接删除的历史残留模板，也没有发现内容完全重复、可以无风险合并的模板。30 条模板均有后端业务调用；前端开发者模式通过 `SettingsDrawer.vue` 调用 `/api/prompt-templates` 全量展示未删除模板。

`docs/develop/linkAgent-backend-improvement-plan.md` 曾提到 `analysis_strategy` 方向，但当前 `init.sql` 没有对应 `prompt_key` 种子，后端也没有按该 key 查询提示词表。因此它属于历史方案记录，不计入本轮 `llm_prompt_template` 资产表。

状态定义：

| 状态 | 含义 |
|---|---|
| `ACTIVE` | 后端代码明确调用，或通过参数化 key 间接调用 |
| `UI_ONLY` | 只在前端展示或管理，后端没有业务调用 |
| `RESERVED` | 文档说明未来预留，但当前没有业务调用 |
| `ORPHAN` | 无代码、无前端、无文档引用 |
| `DUPLICATED` | 内容高度重复，后续可考虑合并 |
| `BROKEN` | 乱码、占位符错误或正文明显损坏 |

## 3. 前端展示结论

前端提示词管理入口在 `frontend/src/components/SettingsDrawer.vue`。

它通过 `listPromptTemplates()` 调用 `/api/prompt-templates`，展示 Mapper 查询出的全部 `is_deleted = 0` 模板。因此前端不是按固定 key 白名单展示，而是数据库当前启用模板的管理视图。

## 4. 乱码定位

已确认：

| 检查项 | 结论 |
|---|---|
| `init.sql` 文件内容 | 当前源码未发现 `�`、`???`、`鍙` 等乱码正文 |
| 数据库和表字符集 | `CREATE DATABASE` 与表定义均为 `utf8mb4` |
| Docker 初始化命令 | `db-init` 已使用 `--default-character-set=utf8mb4` |
| JDBC 示例 | `.env.example` 已统一为 `characterEncoding=UTF-8` |
| 手工执行脚本 | `init.sql` 已增加 `SET NAMES utf8mb4` |
| 已有脏数据 | 重复执行 `init.sql` 会先恢复可逆乱码，再用种子兜底不可逆乱码 |

关键风险是：如果首次初始化已经把乱码写入数据库，后续正常的 `ON DUPLICATE KEY UPDATE` 不覆盖 `content`，乱码会一直保留。当前脚本会先将 `ä½ ` 一类可逆乱码按 `latin1` 原始字节恢复成 UTF-8，保留用户后续补充的有效文本；仍命中乱码指纹的不可逆内容才用种子正文覆盖，因此正常热更新不会被重置。

## 5. 修复和回滚 SQL

执行修复前建议先备份：

```sql
CREATE TABLE llm_prompt_template_backup_20260705 AS
SELECT *
FROM llm_prompt_template;
```

重新执行修复后的 `init.sql` 后，可逆乱码会先恢复为正常 UTF-8；只有仍命中乱码指纹的已有正文才会被种子正文覆盖。

如果需要回滚提示词正文：

```sql
UPDATE llm_prompt_template t
JOIN llm_prompt_template_backup_20260705 b
  ON t.prompt_key = b.prompt_key
SET t.content = b.content,
    t.prompt_type = b.prompt_type,
    t.scene = b.scene,
    t.description = b.description,
    t.is_deleted = b.is_deleted;
```

如果作者确认当前库的提示词全部不要保留，也可以清空提示词表后重灌。但这会丢失设置面板里的人工调优内容，不作为默认方案。

## 6. 验收 SQL

查询启用模板：

```sql
SELECT prompt_key, prompt_type, scene, description
FROM llm_prompt_template
WHERE is_deleted = 0
ORDER BY scene, prompt_key;
```

确认数量：

```sql
SELECT COUNT(*) AS active_prompt_count
FROM llm_prompt_template
WHERE is_deleted = 0;
```

预期 `active_prompt_count = 30`。
