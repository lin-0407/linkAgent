# 系统成片保存与版本登记说明

S3b 在 Java 固定工程渲染桥接之后增加真实产物保存与版本登记。仍为内部接入能力，页面尚无自动出片按钮；不会部署或自动开始制作。

## 处理流程

1. 内部 `CreationRuntimeService.startProduction` 为一次明确的整片确认动作原子创建 PRODUCTION 授权和 FULL 运行。准备授权不能用于整片，发布方向确认本身也不等同于这次执行授权。
2. 受理冻结发布会话/方案、专属 AI_GENERATION 计划、基准视频、故事板和工程内容摘要。该摘要排除 runId、attemptId、inputHash，完整实际工程仍保留 S2 的完整摘要。
3. 持有当前活租约的调用者渲染工程，`GeneratedDraftService.registerGeneratedDraft` 重新核验本次本地产物及授权内容。
4. 在上传前保存 `creator_creation_render_attempt`，预分配版本身份并冻结八个文件的对象键、字节数、类型和 SHA-256。对象键由后端生成，桶来自部署配置，工程不能指定。
5. 在数据库事务外逐一 PUT、HEAD、GET 回读校验。ETag 仅观察，不替代 SHA-256。失败或取消时，未完成的文件仍有清单可查，不创建假成片或切换当前版本。
6. 短事务再次核验任务、活租约/代数、有效整片授权、基准视频、真实确认和本计划全部步骤。原子创建 UPLOADED 视频、SYSTEM_RENDER 上下文和当前指针，运行仅推进 ARTIFACT_READY。
7. 随后调用原 `DraftVideoProbeService` 做真实对象探测，再接媒体预处理和完整试映。注册接口不会直接写 READY_FOR_REVIEW，更不会将 FULL 标为 COMPLETED。

固定八项是 MP4、SRT、封面、三张实际抽帧、渲染日志和清单。视频注册时的 durationMs、编码等探测字段仍为空；这些事实必须由原媒体探测填写。

## 幂等、恢复与历史

- 同一尝试、同一租约代数和同一清单可以继续上传；同一尝试换内容或换代数会拒绝。失联执行器接管后，尚未登记的产物使用新 attemptId。
- 同一 FULL 运行最多登记一个视频。重复登记返回原结果，不再分配版本号，也不重复切换当前指针。
- 已登记结果可以跨租约代数恢复，且不依赖旧本地目录，不再次上传或渲染。恢复仍需当前运行的活租约。
- 取消后若视频已经登记，保留“视频存在、检查未完成”的真实状态。旧完整版本、试映和上下文不被覆盖。
- SYSTEM_RENDER 即使位于 `planning_skipped=1` 的任务，也必须保存真实确认和计划，版本上下文固定 `planningSkipped=false`。
- 现有删除媒体操作同时删除登记清单中的八个对象，并保留视频、制作上下文及历史报告文本。

本步整片重试尚未开放；新运行需要新的专属计划，不能默默把失败运行的计划和授权转作另一项制作。

## 边界与后续接入

没有新增公开 API、前端流程或自动调度。内部受理仅能由未来真实确认服务调用，不能把已有 CONFIRMED 记录、页面打开或模型自行判断当作整片执行授权。运行查询继续 `executionAvailable=false`。

本步尚未实现持久化 worker、自动蓝图的真实产物驱动、预处理/完整试映的精确子任务关联和发布包。`CreationRuntimeService.complete` 明确拒绝 FULL 提前结束。真实供应商费用归并、阿里云 OSS 联调和严格任务全链路预算仍未验证。

未登记尝试的对象会保留其清单，等待后续 worker 按租约与运行终态协调重试或清理。此处不在任意异常中直接删对象，避免并发请求误删已成功登记的版本；尚不能宣称后台自动回收已完成。

部署仍需 S3a 规定的 Python/FFmpeg/字体环境及现有私有存储配置。渲染模块本身保持离线，上传发生在 Java 业务层，密钥不传给 renderer。
