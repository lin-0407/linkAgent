# 创作工作台核心功能说明

## 概述

创作工作台是基于 Spring AI 的 B 站内容创作者辅助工具，围绕创作任务生命周期提供材料输入、发布前优化、评论弹幕分析、竞品分析、工作流编排和复盘报告等核心能力。所有功能以 `taskId` 为业务锚点串联，形成从稿件准备到复盘归档的完整闭环。

---

## 一、创作任务与稿件输入

### 功能定位

创作任务是工作台的业务入口，后续所有分析操作均围绕 `taskId` 展开。任务创建时仅接收用户主动填写的文本材料，不接入爬虫、不读取 B 站账号数据、不做自动投稿。

### 核心数据模型

**creator_task**（创作任务主表）

| 字段 | 说明 |
|---|---|
| task_id | 对外暴露的任务唯一标识 |
| user_id | 用户标识，单人工作台默认为 `default`，预留扩展字段 |
| task_name | 任务名称，不传时优先截取标题草稿，否则使用"未命名创作任务" |
| status | 任务状态，详见状态链 |

**creator_material**（任务输入材料表，与主表拆分以避免主表被长文本字段撑大）

| 字段 | 说明 |
|---|---|
| task_id | 关联 creator_task.task_id |
| material_type | 材料类型，枚举：TITLE_DRAFT / DESCRIPTION_DRAFT / MANUSCRIPT / SUBTITLE |
| content | 用户主动输入的文本内容 |

### 业务规则

- 标题草稿、简介草稿、文稿、字幕至少填写一项。
- 标题草稿最长 200 字符，简介草稿最长 2000 字符，文稿和字幕最长 20000 字符。
- 更新任务时某类材料留空，对应材料会被逻辑删除。
- 只要材料内容发生变化，任务状态自动回到 `DRAFT`，避免用户误以为旧建议仍可直接沿用。
- 删除采用软删除，任务状态标记为 `ARCHIVED`，任务下的材料同步逻辑删除。

### 任务状态链

| 状态 | 含义 |
|---|---|
| DRAFT | 仅完成任务和材料输入 |
| PRE_PUBLISH_ANALYZED | 已完成发布前优化 |
| FEEDBACK_ANALYZED | 已完成评论弹幕分析 |
| COMPETITOR_ANALYZED | 已完成同类型视频竞品分析 |
| ANALYZED | 已完成整套复盘汇总 |
| ARCHIVED | 历史任务归档 |

### 材料文件导入（备用能力）

后端保留本地文本文件导入接口，支持 TXT、MD、SRT、ASS 格式，作为兼容和备用能力。文件导入仅处理用户主动上传的本地文本，不触发平台采集。文件大小上限 5MB，导入后按 UTF-8 读取并清理 BOM 和多余空白。当前前端主界面不暴露此入口，避免创建任务页偏向"导入已写好文稿"的路径。

## 二、发布前优化

### 功能定位

发布前优化模块基于任务材料和创作者偏好语境，生成结构化建议。输出内容包含：内容摘要、目标受众判断、核心卖点、风险点、标题建议、简介建议、标签建议、分区建议、创作者困境、观众钩子、内容定位和可执行修改计划。

### 核心数据模型

**creator_suggestion**（发布前优化建议表）

| 字段 | 说明 |
|---|---|
| suggestion_id | 建议唯一标识 |
| task_id | 关联创作任务 |
| content_summary | 内容摘要 |
| creator_dilemma | 创作者困境 |
| audience_profile | 目标受众判断 |
| audience_hook | 观众钩子 |
| content_positioning | 内容定位 |
| selling_points | 核心卖点 JSON |
| risk_points | 风险点 JSON |
| title_suggestions | 标题建议 JSON（包含 viewerPsychology、clickReason、trustRisk、bestScenario 等子字段） |
| description_suggestion | 简介建议 |
| actionable_revision_plan | 可执行修改计划 JSON |
| tag_suggestions | 标签建议 JSON |
| partition_suggestion | 分区建议 |
| raw_output | LLM 原始输出，用于失败回放和 Prompt 调试 |
| parse_status | 解析状态 |

当前每个任务仅保留一份最新建议。

### 业务规则

- 任务没有材料时，拒绝分析请求。
- 系统提示词固定维护角色定义、平台数据边界和 JSON 输出结构，前端不可覆盖。
- customGuidance 最长 2000 字符，仅影响风格、分析重点和建议倾向，不改变角色和固定输出字段。
- 偏好模式支持三种选择：USE_HISTORY（默认，按 userId 读取最近 5 条历史偏好）、IGNORE_HISTORY（本期换风格，不读取历史）、EXPERIMENT（历史偏好仅作为避坑参考，本期要求优先）。

### 降级策略

发布前优化主流程默认通过 Agent 执行。Agent 会读取任务材料、创作者偏好和视频类型语境，并在需要时调用 knowledge_search 检索案例库。当 Agent 结构化输出失败、工具链路失败或模型异常时，工作流自动创建直连 LLM 回退步骤，保证用户仍能获得建议。

通过配置项 `creator.pre-publish.agent.enabled`（默认开启）控制开关，关闭后直接走旧直连 LLM 链路。

### 步骤级开销追溯

工作流执行过程中，LlmUsageContext 将当前 session 和 step 信息写入线程上下文，文本模型、Embedding 和 Rerank 的用量统计自动挂载到对应步骤。由于 knowledge_search 内部可能触发 Embedding 和 Rerank，ToolExecutor 使用异步线程时会显式恢复 LlmUsageContext，确保工具内部模型调用仍能正确归属到当前步骤。

开销索引 `idx_llm_api_workflow_step (workflow_session_id, workflow_step_id, create_time)` 用于按 session 查询后快速挂载到对应步骤。

## 三、发布前优化工作流消息流

### 功能定位

将发布前优化从"同步生成建议"升级为"工作流执行 + SSE 过程展示 + 用户确认"。核心约束：生成建议不等于采用建议，只有用户确认后任务状态才更新。

### 核心数据模型

| 表 | 用途 |
|---|---|
| creator_workflow_session | 保存任务在某个业务阶段的一次工作流会话，记录状态和确认结果 |
| creator_workflow_message | 保存会话内的过程消息、材料摘要和用户补充输入 |
| creator_workflow_step | 保存执行步骤（LOAD_CONTEXT / AGENT_REASONING / LLM_CALL / SAVE_RESULT），用于失败回放 |

消息字段说明：

| 字段 | 说明 |
|---|---|
| role | SYSTEM / USER / AGENT / TOOL / RESULT |
| contentType | TEXT / MATERIAL_SUMMARY / RESULT_CARD / ERROR |
| detailRefType | 当前支持 MATERIAL，指向 creator_material.id |
| sequenceNo | 会话内顺序号，用于 SSE 去重和恢复 |

### 业务规则

- 创建或恢复会话时，resumeLatest 为 true（默认）则恢复最新会话，不存在则创建新会话。
- 新会话自动写入任务材料摘要消息。
- 会话为 RUNNING、CONFIRMED 或 CANCELLED 时，禁止继续发送用户消息。
- 会话 FAILED 后允许继续补充消息，便于用户修正要求后重试。
- 执行工作流分析时，用户在消息流输入的 USER 消息会合并进本轮分析指导。
- 分析成功后会话进入 WAITING_CONFIRMATION，该接口不更新 creator_task.status。
- 确认建议必须满足：建议属于当前任务、会话处于 WAITING_CONFIRMATION 状态。确认后会话进入 CONFIRMED，任务状态更新为 PRE_PUBLISH_ANALYZED。

### SSE 事件类型

| eventType | 说明 |
|---|---|
| message_created | 新消息已创建 |
| session_status | 会话状态变化 |
| step_started | 步骤开始 |
| step_completed | 步骤成功 |
| step_failed | 步骤失败 |
| result_ready | 发布前建议已生成 |
| heartbeat | 连接心跳 |

SSE 仅作为实时展示通道，断线恢复仍以数据库消息为准，页面刷新后通过历史消息接口恢复。

### 与旧接口的关系

旧同步接口仍保留作为简单联调入口。工作流分析接口不写消息流、不写 step、不需要确认但直接推进任务状态；工作流接口写消息流、写 step、需要确认但不直接推进任务状态；确认接口写消息流、写 step、需要确认且直接推进任务状态。

## 四、评论弹幕分析

### 功能定位

评论弹幕分析模块处理用户主动提供的评论和弹幕数据，生成结构化反馈报告和可视化仪表盘，并支持基于任务数据的追问。

### 核心数据模型

**creator_user_feedback_detail**（反馈样例表，单独建表，不复用 creator_material，因为评论弹幕有来源、时间和分组等额外语义）

| 字段 | 说明 |
|---|---|
| feedback_id | 反馈样例唯一标识 |
| task_id | 关联创作任务 |
| comment_samples | 评论样例 |
| danmaku_samples | 弹幕样例 |
| extra_context | 补充背景 |

**creator_llm_feedback_report**（反馈分析报告表）

| 字段 | 说明 |
|---|---|
| report_id | 报告唯一标识 |
| task_id | 关联创作任务 |
| feedback_summary | 观众整体反馈摘要 |
| hot_topics | 高频观点 JSON |
| sentiment_summary | 情绪倾向总结 |
| controversy_points | 争议点 JSON |
| misunderstanding_points | 误解点 JSON |
| next_content_suggestions | 下一期内容建议 JSON |
| interaction_suggestions | 互动回应建议 JSON |
| raw_output | LLM 原始输出 |
| parse_status | 解析状态 |

**creator_feedback_item**（单条评论/弹幕明细表，阶段 4.4.1 新增）

| 字段 | 说明 |
|---|---|
| like_count | 评论点赞量，用于识别更有共鸣的评论 |
| reply_count | 评论回复量，用于识别互动或争议更高的评论 |
| 分类标记 | 评论/弹幕分类、情绪标签和无意义内容标记 |

**creator_feedback_metric**（视频基础指标表，阶段 4.4.1 新增）

### 数据输入路线

1. **手动粘贴**：用户直接填写评论和弹幕样例文本。
2. **BV 拉取**：用户输入 BV 号或视频链接及采集参数，后端执行项目内固定脚本 `scripts/bilibili_feedback_fetcher.py`，输出到 `export/bilibili_feedback` 后自动导入。
3. **文件导入**：用户上传脚本输出的 JSON 或 TXT 样例文件，保留作为备用入口。

脚本约束：单 BV 输入、默认限量、默认请求间隔、不读取浏览器 Cookie、不使用 Cookie、接口被限制时不绕过。脚本使用 B 站公开网页接口所需的 WBI 签名参数，不等同于登录凭证。

### 业务规则

- 评论样例和弹幕样例至少填写一项。
- 分析成功后任务状态更新为 FEEDBACK_ANALYZED。
- 系统提示词固定维护，前端不可覆盖。
- customGuidance 最长 2000 字符，空值时默认系统规则仍始终生效。

### 反馈追问

基于当前任务已保存的报告和明细数据，回答用户追问并返回证据列表。前端只提交 question，后端按 taskId 查询报告和评论弹幕证据，避免页面伪造证据。当前检索模式为 MYSQL_REPORT_AND_CLASSIFIED_ITEMS（基于 MySQL 中的报告和分类结果），RAG 预留后续接入 Milvus。

### 仪表盘

反馈仪表盘返回结构化数据：评论和弹幕数量、无意义/重复内容数、评论分类统计、弹幕分类统计、情绪分布、高频关键词、弹幕时间段热度、高反馈评论（按点赞量和回复量排序）、视频基础指标、最近导入明细。前端使用 CSS 条形统计，不引入图表库，降低复杂度。

## 五、竞品分析

### 功能定位

竞品分析模块让用户主动整理同类型视频的信息，生成与竞品的对照分析，为复盘中"优点"和"短板"提供参照系。

### 核心数据模型

**creator_competitor_sample**（竞品视频信息表）

| 字段 | 说明 |
|---|---|
| competitor_bv_id | 竞品视频 BV 号，必填 |
| competitor_video_name | 竞品视频名称，必填，最长 200 字符 |
| task_id | 关联创作任务 |
| category | 同类型视频分类 |
| competitor_samples | 用户主动整理的竞品分析文本，必填，最长 20000 字符 |
| compare_dimension | 对比维度 |
| extra_context | 补充背景 |

**creator_competitor_report**（竞品分析报告表）

| 字段 | 说明 |
|---|---|
| report_id | 竞品分析报告唯一标识 |
| task_id | 关联创作任务 |
| competitor_summary | 同类型视频整体打法总结 |
| competitor_advantages | 竞品优势 JSON |
| own_advantages | 本视频相对优势 JSON |
| own_disadvantages | 本视频相对短板 JSON |
| gap_analysis | 差距分析 JSON |
| improvement_suggestions | 改进建议 JSON |
| differentiation_strategy | 差异化定位建议 |
| raw_output | LLM 原始输出 |
| parse_status | 解析状态 |

### 业务规则

- 分析竞品视频前必须先保存竞品视频数据，否则拒绝分析。
- 发布前建议和反馈报告如果存在，作为辅助上下文；不存在时仍可先做竞品分析。
- 当前每个任务仅保留一份最新竞品视频和一份最新竞品分析报告。
- 不做批量或定时抓取，仅保存用户主动整理的数据。

## 六、复盘报告

### 功能定位

复盘报告是工作台的阶段性总结，基于已保存的发布前建议、反馈分析和竞品分析，以及用户主动整理的竞品视频信息，生成完整复盘。同时从分析结果中沉淀创作者偏好洞察，供后续发布前优化复用。

### 核心数据模型

**creator_report**（复盘报告表）

| 字段 | 说明 |
|---|---|
| report_id | 复盘报告唯一标识 |
| task_id | 关联创作任务 |
| content_summary | 内容摘要 |
| core_selling_points | 核心卖点 JSON |
| title_description_review | 标题简介标签分区复盘 JSON |
| audience_feedback_summary | 观众反馈摘要 |
| competitor_comparison | 竞品对照结论 JSON |
| controversy_and_misunderstanding | 争议和误解点 JSON |
| next_action_suggestions | 下一步动作建议 JSON |
| creator_preference_insight | 创作者偏好洞察 JSON |
| overall_conclusion | 复盘总判断 |
| raw_output | LLM 原始输出 |
| parse_status | 解析状态 |

### 业务规则

- 核心材料从任务、发布前建议、反馈报告和竞品分析报告里读取，不重复提交。
- 任务必须先有发布前优化建议、评论弹幕分析报告和竞品分析报告，否则拒绝生成复盘。
- customGuidance 最长 2000 字符，仅影响分析倾向。
- 报告解析成功且 creatorPreferenceInsight 非空时，后端自动沉淀一条 creator_preference 偏好快照，供后续发布前优化读取。
- 当前每个任务仅保留一份最新复盘报告。

### Markdown 导出

复盘报告支持 Markdown 文件导出。导出仅读取已落库报告，不重新调用 LLM。JSON 字段在服务端转换为 Markdown 列表，解析失败的字段按普通文本输出。若 parseStatus 不是 PARSED，导出文件末尾附带原始输出，便于排查模型返回格式问题。

## 七、创作者偏好记忆

### 功能定位

创作者偏好记忆将复盘报告中的偏好洞察沉淀为结构化快照，在下一次发布前优化时自动读取，让建议延续创作者的历史风格和偏好倾向。

### 业务规则

- 偏好快照按 userId 查询最近 5 条记录。
- 用户在发布前优化阶段可选择沿用历史偏好、本期换风格或试验新方向。
- 历史偏好仅影响风格和建议倾向，不改变系统提示词中的角色定义、数据边界和输出结构。

## 八、前端交互约定

### 结果独立弹窗

发布前优化建议、导入仪表盘和反馈报告均以独立弹窗展示，表单区仅负责输入和触发。弹窗只展示当前入口对应的阶段结果，不跨阶段混合其他内容。切换任务、创建新任务或重新保存样例会关闭旧结果弹窗，避免跨任务误读。

### 创作指导编辑

发布前优化和评论弹幕分析均提供可编辑指导入口，用户可调整表达风格、建议侧重点和分析顺序。指导内容保存到浏览器 localStorage。可编辑内容为业务偏好而非模型控制权，后端不会接收可替换系统提示词的字段。

### 工作台视觉约定

- 沿用红黑纸面基调，B 站蓝/粉仅用于流程状态、标签和输入焦点等辅助强调。
- 任务管理区使用中性面板和蓝色激活线。
- 新任务表单、补充项和样例默认保持为空，避免演示样例混入用户真实材料。
- 字段说明通过短占位提示展示。
- 当前按单人开源工作台处理，前端不展示用户 ID，刷新后仅恢复上次选中的任务 ID。
