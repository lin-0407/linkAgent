# 系统成片自动原片探测说明

日期：2026-10-20。内部固定工程执行能力，尚未开放产品启动入口或部署。实现见 [S3e](../develop/视频自动制作-S3e自动原片探测.md)。

## 当前行为

固定工程完成真实渲染、八对象内容校验和视频版本登记后，worker 自动对私有原片执行 FFprobe，无需调用者另行发起 `:probe`。已有用户上传成片的原手工探测入口继续保留。

成功后视频为 READY_FOR_REVIEW，包含实际时长、尺寸、帧率和编码；FULL 为 WAITING_DEPENDENCY，依赖仍指向该精确版本。此时只完成原片探测，没有完整试映结论，也不能直接进入发布后流程。

已有 READY 事实与工程一致时恢复不重复签名或探测。登记后本地工程目录丢失仍可从私有原片恢复；未登记且原资产丢失的情况继续按 S3c 返回错误，不伪造恢复。

## 故障与操作边界

- 原片信息与工程不符时，返回受控的探测不匹配错误；存储/媒体工具失败则记录探测失败，保留已经登记的视频版本。
- 取消与失租会停止 FFprobe。旧执行者不能写成功或失败，权威终态收尾清理本运行的自动探测占用。
- 活动生成运行所拥有的精确视频，由自动探测处理，手工探测和超时懒恢复不会覆盖它。运行取消或失败结束后，可按原媒体流程处理该版本。
- 删除创作任务前需结束活动制作及 RESERVED/UNKNOWN 费用核对，避免隐藏任务后无法补记费用；无阻塞时保留原逻辑删除。
- 取消未完成自动制作后，若原来有已完成的人工蓝图，可重新上传自己的成片；初次任务没有人工制作依据时仍需建立依据。

`hasAudio` 只表示存在音轨。明确静音的视频也包含静音 AAC，不代表已转写、已检测出人声或已验证对白语义。

## 内部接入与配置

原受理 → freeze/attach → worker 的调用顺序不变。worker 新增 `GeneratedDraftProbeService` 依赖，协调服务依赖已有私有存储、`FfprobeMediaProbeService` 及短事务探测持久化服务。Spring 部署需要同时包含这些 Bean，不能只在手工 `new` 的协议测试里接线。

没有新配置或 Schema。复用媒体开关、FFprobe 路径、探测超时和 Provider 读取签名 TTL；签名有效期必须继续覆盖探测超时。私有 URL 只用于本次事务外调用，不进入数据库、运行结果或日志。

渲染器和 Java 必须同步更新到本轮摘要协议。旧浮点工程需要重新准备并确认授权；不能静默重写旧授权。Java 原生集成测试通过 `LINKAGENT_RENDERER_MODULE_ROOT` 指向本次源码，避免测试错误加载镜像中预装的旧模块。
