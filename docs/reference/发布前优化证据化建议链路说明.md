# 发布前优化证据化建议链路说明

## 功能定位

发布前优化现在会在生成建议前先收集证据，让建议从“模型认为应该这样改”升级为“基于哪些材料、偏好或案例这样改”。

证据化不是审查器。它先解决可追溯问题：后续如果建议不准，可以回看当时用了哪些依据。

## 核心链路

```text
任务材料 + 创作者偏好 + 类型语境 + 案例库
  -> PrePublishEvidenceCollector
  -> evidenceRefs
  -> 发布前优化 Prompt
  -> CreatorSuggestionRecord
```

直连 LLM 和 Agent 路径都共用证据包。Agent 路径仍可继续调用 `knowledge_search`，但最终回答优先引用已收集证据。

## 证据类型

| 类型 | 来源 |
|---|---|
| `TASK_MATERIAL` | 标题草稿、简介草稿、文稿、字幕 |
| `CREATOR_PREFERENCE` | 用户本次手动填写的偏好 |
| `CREATOR_CONTEXT` | 历史偏好、创作者画像和视频类型语境 |
| `REFERENCE_CASE` | 案例库检索命中的同类视频 |
| `SYSTEM_LIMITATION` | 检索不可用、缺少主题等限制说明 |

## 响应字段

`CreatorSuggestionResponse` 新增：

| 字段 | 说明 |
|---|---|
| `evidenceRefs` | 本次生成前收集到的证据 JSON |
| `missingInfo` | 模型声明的缺失信息 JSON |
| `generationMode` | `DIRECT_LLM_EVIDENCE` 或 `AGENT_RAG_EVIDENCE` |
| `qualityStatus` | 当前为 `EVIDENCE_COLLECTED` |

## 输出约束

Prompt 要求标题建议和高优先级修改计划尽量携带：

- `evidenceIds`
- `confidence`
- `assumption`

这样前端后续可以展示“推荐理由”和“依据来源”，评测系统也可以检查建议是否无依据。

## 边界

本阶段不判断建议一定正确，也不做二次审查。证据化只保证建议有机会被追溯和评估。真正的质量门禁留给后续 `PrePublishSuggestionAuditor`。
