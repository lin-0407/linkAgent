# 简报、故事板与工程接口说明

更新：2026-10-21。实现边界见 [S4-2 开发记录](../develop/视频自动制作-S4-2简报故事板与工程生成.md)。本接口服务个人自托管工作台，沿用现有 `default` 归属，不增加注册、多租户或账号体系。

后续 S4-3a 已扩展 `BriefInput.backgroundMusic`、用户 SRT 导入子版本和只读时长提案；仅独占背景音乐的素材可至 64 MiB，其他素材仍为 32 MiB。新字段和接口见[音乐字幕与时长建议](音乐字幕与时长建议接口说明.md)，下文保留 S4-2 基础接口和本阶段范围。

接口统一前缀：`/api/creator/tasks/{taskId}/creation`。部署需 `creator.media.enabled=true`、统一 SQL 中四张简报/故事板表和原有运行/预算表。调用文本准备需要部署已配置的文本模型；真实渲染还需启用 `creator.creation.renderer.enabled` 并具备 Python renderer、FFmpeg/FFprobe 和中文字体。

## 能做什么

可以保存不可变简报、人工故事板和文本模型生成的候选，查询历史版本、来源与素材引用，并查看业务检查结果。模型准备是 `PREPARE`；`COMPLETED` 只表示候选已保存，不能据此显示“视频已生成”。当前准备查询始终返回 `fullProductionAvailable=false`。

`check.renderable=true` 表示现有结构、素材与声音范围满足受控编译检查。字体真实排版、媒体实际解码、原生编码、上传登记与完整试映仍有各自验收步骤；该值不表示视频已生成或可发布。

## 接口清单

| 方法与相对路径 | 请求与结果 |
| --- | --- |
| `POST /briefs` | `Idempotency-Key` 与 `BriefInput`；保存新简报，返回 `BriefView` |
| `GET /briefs` | 分页查询简报，revision 降序 |
| `GET /briefs/{briefId}` | 查询具体简报与保存时的来源快照 |
| `POST /storyboards` | `Idempotency-Key` 与 `Save`；保存人工候选为新故事板版本 |
| `GET /storyboards` | 分页查询故事板，revision 降序；每项含 `check` |
| `GET /storyboards/{storyboardId}` | 查询不可变故事板、正文摘要与当前检查结果 |
| `POST /storyboards:estimate` | `expectedWorkspaceRevision/briefId`；返回估算，不创建模型运行 |
| `POST /storyboards:generate` | `Idempotency-Key`、`expectedWorkspaceRevision/briefId/maxAdditionalCostCny`；受理后 HTTP 202 |
| `GET /storyboard-preparations/{runId}` | 返回 `run/storyboardId/fullProductionAvailable`，刷新后仍可恢复查询 |
| `GET /asset-references/{assetId}` | 返回引用该素材的 `storyboardId/revision/briefId` 列表 |

分页参数为 `offset`、`limit`，默认 0/20，offset 范围 0 至 100000，limit 范围 1 至 100。任务和资源标识沿用 `[A-Za-z0-9_-]{1,64}`；幂等键为非空、最多 128 字符。estimate、generate 和准备查询响应禁止缓存。

不提供独立的 `:check` HTTP 路由；查询具体故事板或列表时，由响应的 `check` 返回 `renderable/problems/durationMs/renderContentHash`。没有公开“提交任意工程 JSON”“指定磁盘路径”“启动通用 FULL”接口。

## 简报字段

| 字段 | 要求 |
| --- | --- |
| `expectedWorkspaceRevision` | 当前非负工作区修订；每次新写入前刷新，不能固定复用示例值 |
| `topic` | 必填，最多 200 字符 |
| `coreMessage` | 必填，最多 500 字符 |
| `audience` | 必填，最多 200 字符 |
| `targetDurationMs` | 1000 至 180000 毫秒；编译允许最多一帧量化误差 |
| `dialogueMode` | `TTS`、`USER_NARRATION`、`SOURCE`、`NO_DIALOGUE` |
| `contentKind` | `USER_PROVIDED` 或明确虚构的 `FICTION` |
| `assetIds` | 非空值数组、可为空数组，最多 32 个且不可重复；仅本任务 READY 素材 |
| `constraints` | 非空值字符串、允许空字符串，最多 2000 字符 |

保存时冻结真实材料正文与 SHA-256、发布确认身份及用户意图。`BriefView` 返回 `briefId/revision/document/sources`。创建新简报不覆盖旧简报；后续新故事板/准备受理必须基于最新简报。

示例：

```json
{
  "expectedWorkspaceRevision": 3,
  "topic": "周末整理书桌",
  "coreMessage": "先分类，再保留常用物品",
  "audience": "刚开始整理桌面的学生",
  "targetDurationMs": 2000,
  "dialogueMode": "NO_DIALOGUE",
  "contentKind": "USER_PROVIDED",
  "assetIds": [],
  "constraints": "只做用户提供文字的无对白说明卡"
}
```

这里的修订 3 仅为字段示例。保存成功后读取 runtime 获取新修订，再进行下一次写入。

## 保存人工故事板

请求包含 `expectedWorkspaceRevision`、`briefId`、可空的 `parentStoryboardId` 和 `candidate.scenes`。场景最多 48 个：

| 字段 | 约束与含义 |
| --- | --- |
| `id` | 稳定且不重复的场景业务 ID |
| `layout` | `TITLE_CARD/IMAGE_CARD/SPLIT_CARD/COMPARE_CARD/VIDEO_CLIP/AI_VIDEO` |
| `title` | 必填，最多 60 字符；实际字体排版仍由 renderer 验证 |
| `body` | 最多四条，每条非空、最多 90 字符；IMAGE_CARD/VIDEO_CLIP 必须空，COMPARE_CARD 正好两条 |
| `narration` | 非空值字符串、最多 1000 字符；TTS 场景须提供文稿 |
| `durationMs` | API 范围 1 至 30000；编译后必须至少一帧，各场景总帧长符合目标 |
| `visualAssetId` | 图像或视频素材身份；只能来自该简报选择的素材集合 |
| `sourceInMs/sourceOutMs` | 仅视频使用，相对规范化素材的真实视频区间 |
| `fit` | `CONTAIN` 或 `COVER`；视频显示适配方式 |
| `audioMode` | `NO_DIALOGUE/ORIGINAL/NARRATION/TTS`，且必须符合简报对白选择 |
| `narrationAssetId` | NARRATION 使用的 READY 用户录音；原声不能同时绑定旁白 |
| `cues` | 必填数组，最多 100 条；每条有 `startMs/endMs/text`，时间相对本场景实际音轨 |
| `sourceRefs` | 必填数组，最多 16 个来源标识，每个最多 128 字符 |

`USER_PROVIDED` 的场景来源至少一项，只能引用 `brief:user` 或简报 `sources.materials` 中给出的 `material:编号`。不要填 URL、模型编造的材料编号或 `asset:xxx`；素材通过独立 `visualAssetId/narrationAssetId` 引用。

对白策略：NO_DIALOGUE 的全部场景均无对白；USER_NARRATION 对应 NARRATION；TTS 对应 TTS 并保留待配音状态；SOURCE 的视频场景使用 ORIGINAL，图文过场可以无对白。录音未就绪、AI 画面未生成等候选可以保留，检查会说明阻塞，不会偷偷改成静音或测试音。

下例承接前述简报，`briefId` 替换为真实返回值，修订替换为实际工作区值：

```json
{
  "expectedWorkspaceRevision": 4,
  "briefId": "brief-id-from-response",
  "parentStoryboardId": null,
  "candidate": {
    "scenes": [
      {
        "id": "opening",
        "layout": "TITLE_CARD",
        "title": "周末整理书桌",
        "body": ["先分类，再保留常用物品"],
        "narration": "",
        "durationMs": 2000,
        "visualAssetId": null,
        "sourceInMs": null,
        "sourceOutMs": null,
        "fit": "CONTAIN",
        "audioMode": "NO_DIALOGUE",
        "narrationAssetId": null,
        "cues": [],
        "sourceRefs": ["brief:user"]
      }
    ]
  }
}
```

返回 `BoardView`：`storyboardId/revision/briefId/parentStoryboardId/runId/documentHash/document/check`。人工保存的 `runId` 为空，文档的 `subtitleTimingSource=USER_PROVIDED`；该标记只说明时间由用户提供，不代表系统做过语音对齐。

## 估算、明确授权与模型准备

1. 付费准备前读取 `GET /runtime`，通过已有预算接口初始化或调整预算；同时确认没有活动运行、上传、处理或试映。
2. `POST /storyboards:estimate`，请求为当前 `expectedWorkspaceRevision` 和最新 `briefId`。结果包含 `workspaceRevision/model/estimatedMaxAdditionalCostCny/inputTokenUpperBound/maxOutputTokens/basis`，其中 `basis=CONFIGURED_ESTIMATE`。
3. 将估算展示给用户，用户明确本次 `maxAdditionalCostCny`。它必须为正、最多 12 位整数和 6 位小数，不能低于生成受理时重新计算的估算。
4. 携带独立 `Idempotency-Key` 调用 `POST /storyboards:generate`。HTTP 202 是“已受理候选准备”，返回运行与可能为空的 `storyboardId`，不表示已经产出候选。
5. 轮询 `GET /storyboard-preparations/{runId}`；成功后用返回 `storyboardId` 查询故事板及 `check`。缺真实字幕/配音等问题须另存修订版本解决。
6. 取消复用已有 `POST /runs/{runId}:cancel`。不要通过换幂等键、循环重试或重新生成来自动绕开不明费用。

估算不创建运行、授权或费用流水，也不消耗工作区修订。生成时重新核对版本、空闲、预算与价格，因此估算值不会长期锁定。修改正文、素材、金额或修订值时使用新幂等键；网络响应丢失重放时应保留同键及原请求正文，返回同一运行而不重复调用。

后台使用当前配置的文本模型，限制输出 4096 token，不向用户额外要求选择具体模型。部署切换模型后，已排队运行的模型快照不匹配会停止处理，不能拿旧授权静默换模型。

估算输入上界为实际系统提示词和上下文的 UTF-8 字节数之和再加 4096，输出上界为 4096。按 `creator.creation.billing.text-input-usd-per-million-tokens`、`text-output-usd-per-million-tokens` 和 `usd-to-cny` 计算，预留向上保留六位小数，最低 0.000001 元。默认配置属于记账估值，不代表供应商报价或账单。

一次准备运行至多发送一次收费文本请求，不自动重发异常 POST，不执行模型工具。后台先按冻结价格结算已返回 usage，再解析候选；解析失败仍保留已发生的估算费用。实际 usage 估算结算使用六位 HALF_UP，类型为 `USAGE_ESTIMATE`，不冒充供应商实付。

缺失输入或输出任一侧 usage 时为 `UNKNOWN`；候选有效仍可能显示准备成功，但未知费用继续占用并阻止新付费调用。取消后模型可能仍执行并晚到，候选不会再被采纳，已知用量仍可能补记。取消不是退款承诺。

## 检查结果与工程限制

`problems` 每项含 `sceneId/code/message`，整片级问题的 sceneId 可空。常见代码：

| 代码 | 处理方式 |
| --- | --- |
| `TTS_NOT_CONFIGURED` | 当前尚无真实配音能力，不可用静音代替；明确修改简报后选择用户录音、原声或无对白 |
| `AI_VIDEO_NOT_CONFIGURED` | 提供真实已有画面，或等待后续供应商接入 |
| `VISUAL_MISSING` | 使用本简报已选择且 READY 的真实画面素材 |
| `NARRATION_MISSING/NARRATION_CUES_MISSING` | 准备用户录音，并提供真实相对音轨字幕时间 |
| `AUDIO_OVERFLOW` | 调整场景时长或重新录音，不会自动截断/加速 |
| `CLIP_DURATION_INVALID/CLIP_OUT_OF_RANGE` | 修正实际视频区间和场景时长，不会循环补齐 |
| `CLIP_AUDIO_MISSING` | 该区间无可保留原声，需要重新选择素材或明确改变声音方案 |
| `CUE_OUT_OF_RANGE` | 修正字幕顺序、重叠及真实音轨/场景范围 |
| `TARGET_DURATION_MISMATCH` | 修正场景总长，使 30 fps 量化后符合用户目标，最多一帧误差 |
| `ASSET_RENDER_LIMIT/ASSET_TOTAL_LIMIT` | 单素材不超过 32 MiB，实际引用合计不超过 256 MiB；先裁剪或压缩再导入 |

编译使用固定 V2 工程，720p/30fps、受控字体与布局。旁白 WAV 必须 PCM16、不超过 30 秒且完整容纳于场景；原声和录音分别作为单一主对白，视频叠录音会静音原声。无对白和原声可明确无 cue；所有旁白场景必须有真实 cue，整片最多 200 条。字幕只是把用户确认的相对时间转换到全片，不做自动 ASR 对齐。

`renderContentHash` 绑定具体故事板与实际素材内容，忽略 runId/attemptId；最终 `inputHash` 绑定具体尝试。工程只从持久化的冻结私有桶读取 NORMALIZED 文件，复核大小和 SHA-256，不接受用户磁盘路径或签名地址。纯文字无对白工程的 1×1 PNG 仅为系统契约占位，场景不会把它当真实生成画面。

## 历史引用、FULL 接入与剩余能力

`asset-references` 查询故事板冻结集合的历史引用；不会物理删除 READY 素材，也不包含精确镜头占用区间分析。正文 `documentHash`、受理 `requestHash` 和渲染 `renderContentHash` 各有用途，不能用一个摘要代替所有确认依据。

已授权 FULL 的内部桥接会复核精确 storyboardId、工程内容摘要、真实发布确认、专属制作计划及活动制作授权，再交给现有持久渲染队列。PREPARE 不会通过该桥接自动升级。此处没有可供客户端直接调用的整片 HTTP 入口。

桥接登记响应不明时保留本次文件，避免删掉实际已被运行引用的工程。全局工作目录和历史资源统一回收仍属 S7，不能把局部失败清理当成整个项目资源生命周期已经完成。

当前仍无故事板页面、素材操作页面、SAMPLE 样片入口、BGM、局部修改与缓存复用、真实 TTS/AI 视频生成和自动字幕对齐。三主题原生测试只使用受控候选与 fixture 复制的存储边界，证明本地真实渲染内容与时长，不代表真实模型或 OSS 端到端验收。真实供应商账单、部署和浏览器全业务流程仍需单独验证。
