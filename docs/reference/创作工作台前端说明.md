# 创作工作台前端说明

## 功能入口

前端默认进入“创作工作台”，顶部可以切换到“Agent 控制台”。

创作工作台当前覆盖 MVP 的五段后端能力：

1. 创作任务与稿件输入。
2. 发布前优化 Agent。
3. 评论弹幕分析。
4. 发布前优化工作流消息流。
5. SSE 过程展示和发布前建议确认。
6. 评论弹幕导入仪表盘和反馈追问。

当前页面已经在发布前优化区接入任务级工作流消息流；评论弹幕分析已支持样例文件导入、基础仪表盘和基于当前任务证据的反馈追问。RAG 只做响应结构预留，暂不接 Milvus。

## 输入与视觉约定

1. 新任务表单、发布前补充项、评论弹幕样例和可编辑指导默认保持为空，避免演示样例混入用户真实材料。
2. 字段说明通过输入框内的短占位提示展示，避免用长文案占据输入区域。
3. 创建任务必须先输入标题草稿、简介草稿、文稿或字幕中的至少一项；保存样例必须先输入评论或弹幕中的至少一项。
4. 工作台沿用 Agent 控制台的红黑纸面基调，B 站蓝/粉只用于流程状态、标签和输入焦点等辅助强调。
5. 当前项目按单人开源工作台处理，前端不展示用户 ID；刷新后只恢复上次选中的任务 ID。

## 创作指导编辑

发布前优化区域有“创作指导”按钮，评论弹幕分析区域有“分析指导”按钮。

点击后可以：

1. 修改表达风格、建议侧重点和分析顺序。
2. 输入区域默认为空，需要时可通过“恢复默认指导”快速写入推荐规则。
3. 保存到浏览器 `localStorage`。

保存后，下次点击“生成建议”或“分析反馈”时，前端会把 `customGuidance` 传给后端。

后端系统提示词、角色定义、平台数据边界和 JSON 输出结构不展示给用户，也不允许由前端覆盖。

## 结果独立弹窗

发布前优化建议、评论弹幕导入仪表盘和反馈分析报告不再直接铺在表单下方。

页面主体只保留当前阶段入口：

1. 发布前优化区：生成建议后显示“发布前 AI 分析结果已生成”入口卡片，并在阶段头部保留“查看建议 / 查看并确认”按钮。
2. 评论弹幕区：导入样例后显示“查看导入结果”。
3. 评论弹幕区或分析结果区：生成反馈报告后显示“查看分析结果”。

弹窗只展示当前入口对应的结果，不再在发布前建议弹窗里混入反馈分析报告等其他阶段产物。

这样设计是为了把“输入/触发”和“阅读/确认”分开，避免用户在同一个表单区里同时处理材料录入、脚本导入和大段 AI 结果。

## 评论弹幕导入与仪表盘

评论弹幕页现在支持三条输入路线：

1. 手动粘贴评论/弹幕样例并保存。
2. 输入 BV/视频链接和采集上限后，直接调用后端拉取并导入接口。
3. 仍保留 JSON/TXT 文件导入入口，兼容历史样例和人工整理文件。

后端拉取入口会执行项目内固定脚本 `scripts/bilibili_feedback_fetcher.py`，默认输出到 `export/bilibili_feedback`，然后自动导入 JSON 文件。

这样设计是为了把“用户主动输入 BV + 参数 -> 自动执行固定脚本 -> 自动落盘 -> 自动导入”串成一个闭环，同时保留文件导入作为备用入口。

导入结果弹窗会展示：

1. 评论数、弹幕数、无意义/重复内容数。
2. 视频基础指标。
3. 评论分类。
4. 弹幕分类。
5. 情绪分布。
6. 高频关键词。
7. 弹幕时间段热度。
8. 高反馈评论，优先展示点赞量和回复量更高的评论。
9. 最近导入明细。

设计取舍：

1. 不引入图表库，先使用 CSS 条形统计，减少前端复杂度。
2. TXT 导入只做基础解析，页面展示后端返回的 warnings。
3. 手动保存样例时清空旧仪表盘，避免导入明细和当前粘贴样例不一致。
4. BV 拉取按钮会显示加载状态，并在成功后自动打开导入结果弹窗，输出目录和生成文件列表也在弹窗内查看。

## 反馈追问

反馈追问入口位于“反馈分析报告”弹窗内。

交互流程：

1. 用户先生成反馈报告。
2. 点击“查看分析结果”打开独立弹窗。
3. 在“反馈追问”区域输入问题。
4. 前端调用 `POST /api/creator/tasks/{taskId}/feedback/chat`。
5. 回答下方展示后端返回的 `evidenceItems`。

前端只提交 `question`，不提交报告内容或证据文本。报告、评论和弹幕证据都由后端按 `taskId` 查询，避免页面伪造证据。

## 阶段 4.4.1 前端边界

1. SSE 只是实时展示通道，页面刷新后必须能通过历史消息接口恢复。
2. 上传资料第一版只支持文本类文件，不做图片 OCR、音频转写和视频解析。
3. 评论弹幕第一版只处理用户主动粘贴、主动上传或单 BV 显式触发的限量样例，不在前端暗中自动抓取平台数据。
4. 发布前建议必须由用户确认后才进入正式下一阶段。
5. Agent 控制台继续保留为通用能力入口，创作工作台中的 Agent 消息流只服务当前创作任务。

## 本地运行

前端通过 Vite 代理访问后端：

```text
/api -> http://localhost:8080
```

运行前端：

```bash
cd link-agent-frontend
npm run dev
```

构建检查：

```bash
cd link-agent-frontend
npm run build
```

## 注意事项

1. 后端必须先启动，否则页面会显示请求失败。
2. 发布前优化和反馈分析都会调用 LLM，需要确保后端模型配置可用。
3. 当前页面用于 MVP 联调，不做复杂路由和权限控制。
