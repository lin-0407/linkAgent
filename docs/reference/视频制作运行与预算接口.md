# 视频制作运行与预算接口

这是自动制作运行的后端基础接口。当前没有执行器和启动按钮；`executionAvailable=false`。预算范围为 `CREATION_RUNTIME_ONLY`，已有人工处理、助手或试映的费用尚未统一纳入，不应展示成“所有制作费用已受此限额保护”。

## 初始化和查询

先 GET `/api/creator/tasks/{taskId}/creation/runtime`。没有工作区时 `workspaceRevision=-1`；已有视频工作区但尚未初始化预算时使用实际修订号。GET 不创建工作区、不产生授权、不消费。

POST `/api/creator/tasks/{taskId}/creation`，带 `Idempotency-Key`，例如：

```json
{"expectedWorkspaceRevision":-1,"budgetLimitCny":20.000000}
```

同一初始化幂等键、金额和预期修订号重放不重复修改；不同内容返回冲突。初始化会保留旧任务原有当前视频。之后调整预算用 PATCH `/creation/budget`，传查询得到的修订号和新金额。版本冲突先刷新，不盲目覆盖。

返回预算含 `limitCny`、`knownCny`、`reservedCny`、`unknownCny`、`remainingCny`、`paidCallsBlocked`。未知费用继续占用预留，已结算费用按真实数额统计；剩余值最低显示零。已耗尽、存在未知费用或实际费用超过预留时，标识禁止新增付费调用。

## 运行与取消

GET `/creation/runs/{runId}` 查询摘要，POST `/creation/runs/{runId}:cancel` 取消指定运行。排队运行可立即 CANCELLED；RUNNING 和 WAITING_DEPENDENCY 进入 CANCEL_REQUESTED，执行器确认后才释放活动位置。取消不承诺供应商立即停止收费。

活动制作运行期间，上传覆盖、选版、重新定位、BV 绑定、删除媒体、新增或重试人工处理/试映被拒绝。历史查看与下载仍可用。修改预算不会撤销正在使用的有效租约，也不会放大既有授权。

## 后续适配器必须遵循的协议

1. 用真实用户请求调用内部 `startPreparation`，原子保存准备授权和 TEXT/PREPARE 运行。准备授权不是整片制作方向确认。不要把这个内部方法直接暴露成无人消费的公共排队入口。
2. 领取后保存租约代数；心跳维持有效期。输出落库使用同一代数；过期、取消或接管后拒绝输出。
3. 每一次可能收费的物理调用使用新的全局 `chargeKey`，先 reserve，再 markSent；只有 markSent 第一次返回 true 才发请求。不要把数据库事务包住网络调用。
4. 用真实用量或供应商账单标识 settle，分别注明 USAGE_ESTIMATE 或 PROVIDER_REPORTED。原始密钥和响应全文不写到费用依据字段。相同结算重放不叠加；变更金额或依据返回冲突。
5. 不能核实用量则 markUnknown，保留金额；取消、失败和接管也遵守这个规则。迟到的结算可补记，不能因此恢复旧执行结果。
6. retry 新建运行并关联原运行；原历史保留，授权余额跨重试合计。UNKNOWN 未核清时禁止新增付费；超出预留的事实须保留，当前基础没有自动解除超额阻断的入口。

JSON 指纹只接受有界结构化对象并排序对象键，后续故事板、资产、输入方案等仍需使用各自的类型与业务校验。本接口基础不能替代完整渲染工程校验、严格任务总预算或真实媒体验收。
