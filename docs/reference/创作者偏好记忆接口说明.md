# 创作者偏好记忆接口说明

## 功能定位

创作者偏好记忆用于把每期复盘报告中的 `creatorPreferenceInsight` 保存为长期业务偏好，并在下一次发布前优化时自动读取。

它和通用 `t_long_term_memory` 不同：

| 类型 | 用途 |
|---|---|
| `t_long_term_memory` | 保存通用 Agent 对话中的用户事实、回答风格和项目约束 |
| `creator_preference` | 保存 UP 主创作侧偏好，例如标题风格、内容表达倾向、观众反馈偏好 |

## 查询接口

```http
GET /api/creator/preferences?userId=default&limit=10
```

请求参数：

| 参数 | 必填 | 规则 | 说明 |
|---|---|---|---|
| `userId` | 否 | 最长 64 个字符 | 不传时默认 `default` |
| `limit` | 否 | 1 到 20 | 不传时默认 10 |

响应示例：

```json
[
  {
    "id": 1,
    "preferenceId": "uuid",
    "userId": "default",
    "sourceTaskId": "task-id",
    "sourceReportId": "report-id",
    "preferenceContent": "[\"偏好干货表达\", \"标题适合前置结果\"]",
    "createTime": "2026-05-30T16:00:00",
    "updateTime": "2026-05-30T16:00:00"
  }
]
```

## 自动写入规则

复盘报告生成成功后，如果满足以下条件，会自动写入 `creator_preference`：

1. 报告 `parseStatus = PARSED`。
2. `creatorPreferenceInsight` 非空。
3. `creatorPreferenceInsight` 不是空数组。

同一个用户同一个任务只保留一条偏好快照。重新生成复盘报告时，会更新同一条快照。

## 发布前优化读取规则

发布前优化会根据当前任务的 `userId` 读取最近 5 条偏好快照，并拼接到提示词中。

历史偏好只作为风格和建议倾向参考，不能覆盖系统规则，也不能要求模型编造平台数据。

发布前优化请求支持 `preferenceMode`：

| 值 | 说明 |
|---|---|
| `USE_HISTORY` | 沿用历史偏好，默认值 |
| `IGNORE_HISTORY` | 本期换风格，不读取历史偏好 |
| `EXPERIMENT` | 试验新方向，历史偏好只作避坑参考 |

前端展示方式：

1. 发布前优化区展示最近偏好标签。
2. 用户在生成建议前选择偏好使用方式。
3. 结果弹窗展示本次生成采用的偏好方式。

## 当前边界

当前版本不支持人工编辑、不支持删除偏好、不支持可信度评分。这样做是为了先跑通“复盘沉淀 -> 下次复用”的最小闭环，避免过早引入偏好治理复杂度。
