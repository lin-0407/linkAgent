# 阶段 4.14 - 复盘报告 Markdown 导出

## 需求分析

本阶段服务已经完成创作复盘的 B 站 UP 主、内容运营者和作品集演示者。

现状问题：复盘报告已经保存在后端，但只能通过接口查看结构化 JSON。对创作者来说，复盘结果需要能沉淀到 Notion、飞书文档、博客或本地资料库；对作品集演示来说，也需要一个可以直观看到“AI 复盘产物”的文件。

本阶段做：

1. 新增复盘报告 Markdown 导出接口。
2. 导出内容基于已落库的 `creator_report`，不重新调用 LLM。
3. 将 JSON 字段转换为 Markdown 列表，提升可读性。
4. 前端 Step 4 增加“导出复盘 Markdown”按钮。

本阶段不做：

1. 不做 PDF 导出。
2. 不做在线分享链接。
3. 不做报告版本管理。
4. 不新增数据库字段和第三方依赖。

## 设计方案

### 接口

```http
GET /api/creator/tasks/{taskId}/report/markdown
```

路径沿用现有复盘报告分组 `/report`，而不是新增 `/reports`。这样能保持接口风格一致，避免前端同时记忆两套复盘路径。

### 参数校验

`taskId` 沿用现有字符串任务 ID 规则：

```java
@NotBlank
@Size(max = 64)
```

原因：项目里的 `taskId` 是字符串 UUID，不是数字 ID，因此不能使用 `@Min`。

### 后端实现

`CreatorReportController`：

- 新增 `GET /markdown`。
- 返回 `text/markdown;charset=UTF-8`。
- 设置 `Content-Disposition: attachment`，文件名为 `creator-report-{taskId}.md`。

`CreatorReportService`：

- 新增 `exportMarkdown(taskId)`。
- 读取任务和复盘报告。
- 按固定章节生成 Markdown。
- 对 JSON 字段尝试解析为列表或键值结构；解析失败时按普通文本输出。
- 当 `parseStatus != PARSED` 时附带原始输出，保留排查 LLM 输出格式问题的证据。

### 前端实现

`api/creator.ts`：

- 新增 `requestBlob`。
- 新增 `exportCreatorReportMarkdown(taskId)`。
- 从 `Content-Disposition` 中提取下载文件名。

`CreatorWorkspace.vue`：

- 新增 `isExportingReportMarkdown`。
- 新增 `downloadReportMarkdown()`。
- 在 Step 4 顶部增加导出按钮。
- 前端只负责下载，不拼接 Markdown，避免报告格式出现两套来源。

## 测试验证点

作者本地验证命令：

```bash
cd E:\linkAgent\linkAgent\backend
mvn test
```

```bash
cd E:\linkAgent\linkAgent\link-agent-frontend
npm run type-check
npm run build
```

手工验证：

1. 对已生成复盘报告的任务调用 `GET /api/creator/tasks/{taskId}/report/markdown`，应下载 `.md` 文件。
2. 对不存在的任务调用接口，应返回 404。
3. 对未生成复盘报告的任务调用接口，应返回 404。
4. Markdown 文件应包含任务 ID、报告 ID、解析状态、内容摘要、核心卖点、标题简介复盘、观众反馈、竞品对照、争议误解、下一步动作、偏好洞察和总判断。
5. 前端点击“导出复盘 Markdown”时，按钮进入“导出中...”状态，成功后出现提示。

## 后续扩展

1. PDF 导出可以在 Markdown 稳定后再做。
2. 报告版本管理需要先引入 `creator_report_version`，不应直接复用当前单报告表。
3. 如果未来支持在线分享链接，需要增加权限和访问过期策略。
