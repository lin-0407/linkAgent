# 阶段 4.5.1：创作者偏好记忆最小闭环

## 需求分析

本轮服务对象是已经完成多期创作复盘的 B 站 UP 主。

要解决的问题是：每次发布前优化如果只看当前文稿，AI 会像第一次认识这个创作者，无法延续历史中已经验证过的标题风格、内容表达方式和观众反馈偏好。

本轮只做：

1. 从已完成的复盘报告中读取 `creatorPreferenceInsight`。
2. 将每期复盘提炼出的偏好按 `userId + taskId` 保存为长期偏好快照。
3. 下一次发布前优化时读取最近几期偏好，作为提示词上下文。
4. 提供只读偏好查询接口，便于本地演示和排障。
5. 在前端发布前优化区展示历史偏好标签，并允许选择“沿用历史偏好 / 本期换风格 / 试验新方向”。

本轮不做：

1. 不做人工编辑偏好。
2. 不做偏好可信度评分。
3. 不做偏好过期策略。
4. 不接 Milvus，也不把偏好写入通用 `t_long_term_memory`。
5. 不做独立偏好管理页，先把偏好控制放在发布前生成建议前。

## 设计方案

### 数据表

新增 `creator_preference` 表。

核心字段：

| 字段 | 说明 |
|---|---|
| `preference_id` | 偏好快照唯一标识 |
| `user_id` | 创作者用户标识 |
| `source_task_id` | 来源创作任务 |
| `source_report_id` | 来源复盘报告 |
| `preference_content` | 复盘报告提炼出的偏好洞察 JSON |

唯一约束：

```text
uk_user_source_task(user_id, source_task_id)
```

这样设计是为了让同一个任务重复生成复盘报告时更新偏好快照，而不是产生重复长期记忆。

### 写入流程

```text
生成创作复盘报告
  -> 解析 creatorPreferenceInsight
  -> 报告 parseStatus = PARSED 且偏好非空
  -> CreatorPreferenceService.saveFromReport
  -> upsert creator_preference
```

如果复盘报告只保留原文，说明结构化解析失败，本轮不会沉淀偏好，避免把不可控原文带入后续提示词。

### 读取流程

```text
发布前优化
  -> 前端选择 preferenceMode
  -> 根据 creator_task.user_id 查询最近 5 条 creator_preference
  -> 拼接为历史创作者偏好上下文
  -> 传入 PrePublishSuggestionService 的用户提示词
```

历史偏好只影响表达风格、分析侧重点和建议倾向，不能覆盖系统规则，也不能让模型编造平台数据。

`preferenceMode` 的处理：

| 值 | 说明 |
|---|---|
| `USE_HISTORY` | 默认，读取历史偏好并参与本次生成 |
| `IGNORE_HISTORY` | 本期换风格，不读取历史偏好 |
| `EXPERIMENT` | 读取历史偏好，但只作为避坑参考，本期用户要求优先 |

### 对外接口

```text
GET /api/creator/preferences?userId=default&limit=10
```

校验规则：

1. `userId` 可选，最长 64 个字符。
2. `limit` 可选，范围 1 到 20。
3. 不提供 `userId` 时默认查询 `default` 用户。

## 测试验证点

作者本地后端验证：

```bash
cd backend
mvn test
```

作者本地前端验证：

```bash
cd link-agent-frontend
npm run type-check
npm run build
```

联调验收：

1. 完成一个任务的发布前优化、评论弹幕分析、竞品分析和复盘报告。
2. 复盘报告返回 `creatorPreferenceInsight` 非空。
3. 查询 `GET /api/creator/preferences?userId=default`，应看到来源任务对应的偏好快照。
4. 新建第二个任务，发布前优化区应展示历史偏好标签。
5. 选择“沿用历史偏好”执行发布前优化，后端提示词会带入最近历史偏好。
6. 选择“本期换风格”执行发布前优化，后端不读取历史偏好。
7. 选择“试验新方向”执行发布前优化，后端把历史偏好作为避坑参考。

数据库验证：

```sql
SELECT user_id, source_task_id, source_report_id, preference_content
FROM creator_preference
WHERE user_id = 'default'
ORDER BY update_time DESC;
```
