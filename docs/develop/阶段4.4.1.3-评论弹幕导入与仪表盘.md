# 阶段 4.4.1.3：评论弹幕导入与仪表盘

## 需求分析

本轮服务对象是已经确认发布前优化建议、准备做视频反馈复盘的 B 站 UP 主。

要解决的问题是：阶段 4.3 只能粘贴整段评论和弹幕，缺少单条明细、分类统计和图表数据。用户即使通过脚本生成了 JSON/TXT 文件，也只能人工复制到输入框，无法形成可筛选、可追问的反馈数据底座。

本轮只做：

1. 用户在页面输入 BV/视频链接和采集上限。
2. 后端受控执行项目内 `scripts/bilibili_feedback_fetcher.py`。
3. 脚本输出保存到项目根目录 `export/bilibili_feedback`。
4. 后端自动解析脚本 JSON，保存评论、弹幕和视频基础指标。
5. 保留 JSON/TXT 文件上传入口，兼容历史样例和人工整理文件。
6. 使用轻量规则生成第一版分类、情绪和噪声标记。
7. 前端展示评论分类、弹幕分类、情绪分布、高频关键词、弹幕时间段热度、高反馈评论和最近明细。

本轮不做：

1. 不保存 Cookie，不接登录态。
2. 不做批量 BV、定时任务或后台同步。
3. 不做 LLM 批量分类。
4. 不做反馈追问和 RAG。
5. 不做复杂图表库接入。

## 设计方案

### API

新增：

```text
POST /api/creator/tasks/{taskId}/feedback/fetch
POST /api/creator/tasks/{taskId}/feedback/import
GET  /api/creator/tasks/{taskId}/feedback/dashboard
```

保留阶段 4.3 接口：

```text
POST /api/creator/tasks/{taskId}/feedback
POST /api/creator/tasks/{taskId}/feedback/analyze
```

导入接口会同时回填 `creator_user_feedback_detail`，原因是旧的“分析反馈”接口仍然基于整段样例调用 LLM。这样前端导入文件后，不需要再手动粘贴一次，也能继续使用原来的反馈分析链路。

### BV 脚本入口

前端提供 BV/视频链接输入框和数量上限，点击“拉取并导入”后调用：

```http
POST /api/creator/tasks/{taskId}/feedback/fetch
```

后端只执行项目内固定脚本：

```text
scripts/bilibili_feedback_fetcher.py
```

输出目录固定为：

```text
export/bilibili_feedback
```

请求参数只允许 BV 输入、主楼评论数、回复数、弹幕数和输出格式。后端不接收任意脚本路径，也不允许页面传输出目录。

原因：

1. 用户需要的是填参数后一键完成采集、落盘和导入。
2. 固定脚本路径和固定输出目录可以避免 BV 输入变成任意命令执行。
3. 自动导入依赖 JSON，因此页面只开放 `json` 和 `both` 两种输出格式。

### 数据表

新增：

```text
creator_feedback_item
creator_feedback_metric
```

`creator_feedback_item` 保存单条评论/弹幕，支撑仪表盘、证据查看和后续 RAG。

关键字段：

| 字段 | 说明 |
|---|---|
| `like_count` | 评论点赞量。高赞评论通常代表更多观众共鸣，是复盘时需要优先看的反馈。 |
| `reply_count` | 评论回复量。回复多的评论通常代表更多互动、争议或追问。 |

`creator_feedback_metric` 保存上传文件或 BV 脚本输出里的播放、点赞、投币、收藏、分享等基础指标。它只服务当前任务复盘，不做后台定时同步。

### 分类策略

第一版使用轻量规则分类：

1. 重复内容标记为 `DUPLICATE`。
2. 过短或无语义内容标记为 `EMPTY_MEANING`。
3. 评论按提问、建议、质疑、认可、情绪、互动和其他分类。
4. 弹幕按知识点反应、时间点疑问、情绪高峰、共鸣、吐槽不满和其他分类。
5. 情绪按正向、负向、中性粗分。

原因：

1. 先跑通明细层和仪表盘。
2. 避免一开始把大量评论塞进 LLM，导致成本、耗时和稳定性问题。
3. 后续可以把分类来源替换为 LLM 或人工复核，不影响表结构和前端展示。

## 编码实现

后端新增：

```text
CreatorFeedbackImportResponse
CreatorFeedbackDashboardResponse
CreatorFeedbackFetchRequest
CreatorFeedbackFetchResponse
CreatorFeedbackItemRecord
CreatorFeedbackMetricRecord
CreatorFeedbackStatRecord
CreatorFeedbackItemResponse
CreatorFeedbackMetricResponse
CreatorFeedbackStatResponse
CreatorFeedbackKeywordResponse
CreatorFeedbackTimelineResponse
```

后端修改：

```text
CreatorFeedbackController
CreatorFeedbackService
CreatorFeedbackMapper
backend/src/main/resources/sql/init.sql
```

前端修改：

```text
src/api/creator.ts
src/types/creator.ts
src/components/CreatorWorkspace.vue
src/styles/theme.css
```

关键实现点：

1. `MultipartFile` 只接受 JSON/TXT，单文件限制 5MB。
2. JSON 优先解析 `scripts/bilibili_feedback_fetcher.py` 的输出结构。
3. TXT 只按“评论样例/弹幕样例”区块做基础解析，因此返回 warnings。
4. 手动保存样例时会清理旧导入明细，避免仪表盘展示过期数据。
5. BV 拉取接口使用 `ProcessBuilder` 参数数组执行固定脚本，不拼接 shell 命令。
6. 脚本执行设置总超时，避免平台接口卡住时占用后端线程。
7. 仪表盘不引入图表库，先用结构化条形统计展示。

## 测试验证点

作者本地执行数据库脚本：

```bash
cd backend
mysql -u root -p < src/main/resources/sql/init.sql
```

后端编译和测试由作者执行：

```bash
cd backend
mvn test
```

前端检查由作者执行：

```bash
cd link-agent-frontend
npm run type-check
npm run build
```

联调验收：

1. 发布前建议确认后，评论弹幕页可选择 JSON/TXT 文件。
2. 输入 BV 或视频链接后，点击“拉取并导入”会自动执行脚本。
3. 文件保存到项目根目录 `export/bilibili_feedback`。
4. 拉取成功后，页面能看到评论数、弹幕数和基础指标。
4. 分类统计、情绪分布、高频关键词能正常展示。
5. 有弹幕时间戳时展示时间段热度。
6. 高赞评论能按点赞量、回复量排序展示。
7. 上传 TXT 时出现解析提示，但可生成基础仪表盘。
8. 手动保存评论弹幕样例后，旧导入仪表盘不再继续误导展示。
