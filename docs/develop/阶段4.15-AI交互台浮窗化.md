# 阶段 4.15 - AI 交互台浮窗化

## 需求分析

本阶段服务的目标用户是正在使用创作工作台的 UP 主和项目演示者。

当前通用 Agent 控制台作为独立页面存在，用户需要离开创作工作台才能向通用 Agent 提问。这个交互会打断创作者正在进行的文稿分析、发布前优化、评论复盘等工作流。

本阶段要解决的问题是：把通用 AI 交互台做成创作工作台上的可拖拽、可缩放浮窗，让用户在不离开当前业务页面的情况下临时咨询 Agent。

本阶段做：

1. 新增 AI 交互台浮窗组件。
2. 复用现有 `useAgentChat` 会话、发送、历史加载逻辑。
3. 支持鼠标拖动标题栏移动窗口。
4. 支持鼠标拖动右下角调整窗口大小。
5. 限制最小和最大窗口尺寸，避免遮住整个工作台或被拖出视口。

本阶段不做：

1. 不做移动端专项适配。
2. 不改后端 Agent 接口。
3. 不删除原 Agent 控制台页面。
4. 不引入第三方拖拽库。

## 设计方案

### 前端组件

新增：

| 文件 | 作用 |
|---|---|
| `src/components/AgentFloatingWindow.vue` | AI 交互台浮窗，负责打开关闭、最小化、拖动、缩放、会话切换和消息输入 |

修改：

| 文件 | 作用 |
|---|---|
| `src/App.vue` | 在创作工作台模式下挂载浮窗 |
| `src/styles/theme.css` | 补充浮窗、消息列表、输入区、拖拽缩放手柄样式 |

### 为什么不直接复用 `AgentConsole.vue`

`AgentConsole.vue` 是完整页面壳，包含侧边栏、顶部统计、主视觉收起、全屏等页面级能力。直接塞进浮窗会让窗口变重，也会把页面布局规则带进小窗口。

所以本阶段只复用底层聊天能力：

```text
AgentFloatingWindow
  -> useAgentChat
  -> MessageBubble
  -> ChatComposer
  -> ErrorNotice
```

这样浮窗和原 Agent 控制台共享后端接口，但 UI 互不污染。

### 拖动与缩放

拖动使用浏览器原生 Pointer Events：

1. 标题栏 `pointerdown` 记录鼠标和窗口左上角偏移。
2. `pointermove` 持续计算新的 `left/top`。
3. 每次移动都调用边界约束，避免窗口离开视口。

缩放同样使用 Pointer Events：

1. 右下角手柄 `pointerdown` 记录起始宽高。
2. `pointermove` 计算新的 `width/height`。
3. 统一走尺寸约束。

当前尺寸限制：

| 类型 | 数值 |
|---|---|
| 最小宽度 | 420px |
| 最小高度 | 420px |
| 最大宽度 | 920px |
| 最大高度 | 760px |
| 视口边距 | 18px |

## 测试验证点

作者本地验证：

```bash
cd E:\linkAgent\linkAgent\link-agent-frontend
npm run type-check
npm run build
```

页面验证：

1. 进入创作工作台后，右下区域应出现 AI 交互台浮窗。
2. 拖动浮窗标题栏，窗口应能移动，但不能被拖出浏览器视口。
3. 拖动右下角手柄，窗口应能变大或变小，但不能超过最大尺寸。
4. 点击“收起”后只保留标题栏，再点击“展开”恢复。
5. 点击“关闭”后浮窗消失，右下角保留打开按钮。
6. 输入问题并发送，应继续调用原 `/api/agent/chat` 接口。
7. 点击“会话”应能查看历史会话并切换。
