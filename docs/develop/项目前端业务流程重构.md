# PRD v0.1：LinkAgent 前端全链路用户化重构

## 1. 调研依据

YouTube Studio 以“单个视频”为中心组织标题、简介、评论、可见性等操作，并把高级设置收进二级入口，避免新手一上来面对全部选项。【turn2view0†L23

YouTube Analytics 把观众留存解释成“哪些片段有效、哪里流失、下一步怎么改”，不是只展示技术数据。YouTube 评论区还提供 AI 评论摘要，用于提炼观众反馈
和未来视频改进点。

Canva AI 的主线是“从想法开始，到可编辑产物”，用户通过对话迭代，但始终保留最终控制权。

NotebookLM 的关键启发是“基于用户选择的资料回答，并提供引用依据”，适合本项目的评论、弹幕、案例证据展示。

NN/g 对复杂流程的建议是渐进披露：先展示最重要选项，低频/高级功能放到用户主动打开的二级区域；向导式流程适合新手和低频复杂任务。

## 2. 产品定位

将现有前端从“开发者验证 Agent 能力的控制台”重构为“业余 B 站 UP 主的视频发布与复盘助手”。

一句话目标：用户只需要知道“我要优化这期视频、看懂观众反馈、得到下一期行动清单”，不需要理解 Agent、SSE、RAG、Token、Prompt、Milvus 等工程概念。

## 5. 产品原则

1. 以“视频项目”为中心，不以 Agent 能力为中心。
2. 页面只呈现用户当前要完成的动作。
3. 技术过程默认隐藏，但可在开发者模式查看。
4. 每一步都有明确输入、主要按钮、输出结果和下一步。
5. 结果必须能复制、采用、导出或沉淀为偏好。
6. 评论弹幕分析必须展示“观众原话依据”，避免 AI 结论悬空。
7. 卡片只用于承载独立对象，不做卡片套卡片。

## 9. 视觉规范

1. 全局只保留 4 类容器：页面区块、列表项、结果块、弹窗/抽屉。
2. 卡片圆角统一 8px。
3. 禁止卡片套卡片。
4. 普通页面以白色、中性灰、单一强调色为主。
5. 主要按钮每屏最多 1 个。
6. 次要操作使用文字按钮或轻量描边按钮。
7. 技术诊断、原始输出、模型开销全部收进开发者模式。
8. 移动端步骤导航改为顶部进度条，不横向溢出。

## 11. 范围

P0 必做：

1. 重构导航与主流程。
2. 隐藏普通用户不需要的工程概念。
3. 重写页面文案。
4. 统一卡片和按钮样式。
5. 发布方案、观众反馈、复盘报告三个核心页用户化。
6. 参考案例页去技术化。
7. AI 浮窗改为上下文助手。

P1 可做：

1. 拆分 CreatorWorkspace.vue 大组件。
2. 增加新手样例项目。
3. 增加“复制标题 / 复制简介 / 复制行动清单”。
4. 增加空状态引导图或轻量插画。
5. 增加项目完成度和最近操作记录。

暂不做：

1. B 站账号授权。
2. 自动批量采集。
3. 自动投稿。
4. 后端 Agent 架构重写。
5. 新增复杂权限系统。

## 12. 验收标准

1. 普通模式首屏不出现 Agent、API、Token、RAG、Milvus、Prompt、SSE、评测等词。
2. 用户能按“视频资料 -> 发布方案 -> 观众反馈 -> 复盘报告”完成完整流程。
3. 每一步只有一个明确主按钮。
4. 结果页能直接复制、采用或导出。
5. 卡片样式不超过 4 类，且没有卡片套卡片。
6. 案例库不再暴露检索增强、精排、索引等工程词。
7. 开发者能力仍可通过开发者模式访问。
8. 375px、768px、1440px 宽度下无内容重叠和横向滚动。
