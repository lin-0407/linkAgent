# LinkAgent 前端全链路用户化重构方案

> 文档状态：方案设计，待编码落地。
> 本文只定义前端业务流程、信息架构、文案和验收口径，不改变后端 Agent 架构、数据库 Schema 或现有接口契约。

## 1. 目标结论

本轮前端重构要把当前“开发者验证 Agent 能力的控制台”，改成“业余 B 站 UP 主的视频发布与复盘助手”。

用户进入页面后，只需要理解四件事：

1. 我正在优化哪条视频。
2. 现在该补充什么资料。
3. AI 给了哪些可直接采用的发布或复盘建议。
4. 这些建议依据了哪些评论、弹幕或案例。

普通用户不应该被迫理解 Agent、SSE、RAG、Token、Prompt、Milvus、Rerank 等工程概念。技术信息保留，但统一收进开发者模式。

## 2. 调研启发

本方案参考的是成熟内容创作工具的交互方向，而不是照搬具体页面。

| 产品 / 方法 | 对本项目的启发 | 落到 LinkAgent 的做法 |
|---|---|---|
| YouTube Studio | 以“单个视频”为中心组织标题、简介、评论、可见性等操作，高级设置不抢占主流程。 | 以“视频项目”作为前端核心对象，低频字段放入“更多选项”。 |
| YouTube Analytics | 数据分析要解释“哪里有效、哪里流失、下一步怎么改”，不能只展示指标。 | 反馈分析页先给结论和动作，再展示评论弹幕依据。 |
| Canva AI | 从想法到可编辑产物，AI 给草案，用户保留最终控制权。 | 发布方案、简介、行动清单必须支持复制、编辑、采用。 |
| NotebookLM | 回答应基于用户选择的资料，并给出引用依据。 | 评论、弹幕、案例库结果默认要求展示“依据”。 |
| 渐进披露 | 复杂流程先展示高频关键项，高级项由用户主动展开。 | 技术诊断、模型开销、索引状态、原始输出全部移入高级区。 |

## 3. 目标用户与场景

核心用户是非程序员、非专业运营的中小 UP 主。

| 场景 | 用户问题 | 产品承诺 |
|---|---|---|
| 发布前 | 标题、简介、标签不知道怎么写。 | 给出可直接复制、可解释、可修改的发布方案。 |
| 发布后 | 评论弹幕太散，看不出重点。 | 汇总观众关注、误解、争议和高价值建议。 |
| 复盘 | 下一期做什么主要靠感觉。 | 生成下一期选题、修改动作和互动建议。 |
| 长期创作 | AI 每次都不懂我的风格。 | 沉淀偏好，但允许本期关闭或临时调整风格。 |

## 4. 当前问题诊断

现有页面的主要问题不是功能少，而是信息架构偏开发者。

| 问题 | 现状表现 | 对普通用户的影响 |
|---|---|---|
| 主流程不清晰 | 任务、工作流、发布建议、反馈报告、API 开销并列。 | 用户不知道下一步该点什么。 |
| 技术概念外露 | Agent、SSE、API、Token、RAG、Milvus、Prompt、Rerank、评测直接出现。 | 用户被迫理解工程实现。 |
| 卡片样式过多 | 面板、结果块、流程块、弹窗块、统计块混杂。 | 页面显得碎、重、乱。 |
| 开发入口抢占主界面 | 开发者测试、过程详情、消息流、API 开销在普通路径可见。 | 产品像调试台，不像用户工具。 |
| 案例库过专业 | 查询增强、检索模式、精排、索引状态直接展示。 | 用户不知道这些和创作有什么关系。 |
| 浮窗 AI 仍偏通用 Agent | ReAct、PaE、Multi Agent、推理轨迹等模式可选。 | 用户会误以为要懂 Agent 才能使用。 |

## 5. 产品原则

1. 以“视频项目”为中心，不以 Agent 能力为中心。
2. 页面只呈现用户当前要完成的动作。
3. 技术过程默认隐藏，但可在开发者模式查看。
4. 每一步都有明确输入、主按钮、输出结果和下一步。
5. 结果必须能复制、采用、导出或沉淀为偏好。
6. 评论弹幕分析必须展示“观众原话依据”，避免 AI 结论悬空。
7. 卡片只用于承载独立对象，不做卡片套卡片。

## 6. 信息架构

一级导航调整为：

| 新导航 | 用途 | 备注 |
|---|---|---|
| 创作台 | 当前视频的全链路操作。 | 默认首页。 |
| 参考案例 | 查找可借鉴的视频案例。 | 保留检索能力，但语言用户化。 |
| 项目列表 | 查看历史视频项目。 | 从弹窗或侧栏里独立出来。 |
| 设置 | 账号、模型、开发者模式。 | 普通用户低频访问。 |

创作台主流程：

```text
选择/新建视频
-> 准备发布方案
-> 确认采用建议
-> 导入观众反馈
-> 读懂反馈
-> 生成复盘与下一期行动
```

## 7. 页面需求

### 7.1 首页 / 创作台首屏

首屏只保留两个主操作：

| 操作 | 用户文案 |
|---|---|
| 新建视频项目 | 开始优化一条视频 |
| 继续历史项目 | 继续上次复盘 |

首屏不得出现：开发者测试、API 开销、Token、RAG、Milvus、Prompt、SSE、工作流。

### 7.2 视频项目页

采用左侧步骤导航、中间当前步骤、右侧视频摘要。

步骤固定为：

1. 视频资料
2. 发布方案
3. 观众反馈
4. 复盘报告

每个步骤只展示当前必须填写的内容。高级字段放入“更多选项”。

### 7.3 发布方案页

“发布前优化 Agent”改名为“发布方案”。

输入区：

| 字段 | 用户化文案 |
|---|---|
| 标题草稿 | 现在想到的标题 |
| 简介草稿 | 准备发到简介里的内容 |
| 文稿 / 字幕 | 视频主要内容 |
| 创作目标 | 这期最想让观众记住什么 |
| 风格偏好 | 更稳重 / 更有网感 / 更像教程 / 更像故事 |

输出区：

| 模块 | 要求 |
|---|---|
| 推荐标题 | 每条说明适合谁、为什么能点、风险是什么。 |
| 简介改写 | 可复制，可编辑。 |
| 标签与分区建议 | 只展示少量高置信建议。 |
| 开头 / 内容风险 | 告诉用户发布前最该改哪里。 |
| 采用按钮 | 采用后进入“观众反馈”步骤。 |

### 7.4 观众反馈页

“评论弹幕样例”改名为“观众反馈”。

默认只给三种入口：

| 入口 | 文案 |
|---|---|
| 粘贴视频链接 / BV | 自动读取这条视频的评论和弹幕 |
| 上传文件 | 导入整理好的评论 / 弹幕文件 |
| 手动粘贴 | 我已经复制了一些评论或弹幕 |

数量上限、输出格式、脚本目录等放入“高级采集设置”。

### 7.5 反馈分析结果页

“反馈与复盘结果”拆成两层。

第一层是普通用户先看到的结论：

| 模块 | 内容 |
|---|---|
| 观众最关心什么 | 高频观点和代表评论。 |
| 观众哪里没看懂 | 误解点和来源。 |
| 哪些地方有争议 | 风险和回应边界。 |
| 下一期可以做什么 | 可执行选题和互动动作。 |

第二层由用户点击“查看依据”后展开，展示评论、弹幕、时间点、情绪分类。

### 7.6 复盘报告页

报告必须以行动为核心。

| 模块 | 要求 |
|---|---|
| 本期一句话结论 | 不超过 80 字。 |
| 保留什么 | 下期继续复用的优点。 |
| 修改什么 | 可执行修改清单。 |
| 下一期选题 | 至少 3 条，标注依据。 |
| 互动建议 | 评论区置顶、动态、下期引导语。 |
| 导出 | Markdown 导出、复制摘要。 |

### 7.7 参考案例页

“视频案例库”保留，但语言去技术化。

| 当前文案 | 新文案 / 处理方式 |
|---|---|
| 案例检索 | 找灵感 |
| 查询增强策略 | 普通模式删除，开发者模式保留。 |
| 检索模式 / 精排 / Rerank | 普通模式删除，开发者模式保留。 |
| 命中主题 | 为什么推荐它 |
| 相关评论弹幕 | 观众怎么说 |
| 打开 AI 分析 | 用这个案例帮我改当前视频 |

### 7.8 AI 浮窗

“AI 交互台”改名为“问问 AI”。

普通模式隐藏执行模式按钮：Auto、ReAct、PaE、Multi Agent。

浮窗默认带入当前视频上下文，提示语改为：

> 可以问：这个标题哪里弱？观众可能会误解什么？下一期选题怎么延展？

## 8. 术语替换

| 技术词 | 普通用户词 |
|---|---|
| Agent | AI 助手 |
| 工作流 | 处理流程 |
| 消息流 | 处理记录 |
| SSE 实时连接 | 正在更新 |
| API 开销 | 本次生成消耗 |
| Token | 普通模式隐藏，仅开发者模式显示。 |
| Prompt | 指导规则 |
| RAG / Milvus / Rerank | 普通模式隐藏，仅开发者模式显示。 |
| 证据索引 | 资料整理状态 |
| 开发者测试 | 开发者模式 |

## 9. 视觉与交互规范

1. 全局只保留 4 类容器：页面区块、列表项、结果块、弹窗 / 抽屉。
2. 卡片圆角统一 8px。
3. 禁止卡片套卡片。
4. 普通页面以白色、中性灰和一个强调色为主，避免大面积单一色系堆叠。
5. 主要按钮每屏最多 1 个。
6. 次要操作使用文字按钮或轻量描边按钮。
7. 技术诊断、原始输出、模型开销全部收进开发者模式。
8. 移动端步骤导航改为顶部进度条，不能横向溢出。
9. 所有点击目标在移动端不小于 44px。
10. 375px、768px、1440px 三档宽度必须检查文本重叠和横向滚动。

## 10. 开发者模式

保留现有工程能力，但从普通路径移出。

| 功能 | 新位置 |
|---|---|
| 开发者测试 / 评测样例 | 设置 -> 开发者模式 |
| API 开销统计 | 设置 -> 开发者模式 -> 生成消耗 |
| 工作流消息流 | 结果页 -> 高级 -> 处理记录 |
| 执行步骤、原始输出 | 结果页 -> 高级 -> 诊断详情 |
| RAG / Milvus / Prompt / Token | 仅开发者模式 |

开发者模式只改变可见性，不改变后端返回结构。这样可以避免前端重构时误伤已有调试和演示能力。

## 11. 前端模块影响

| 模块 | 变更方向 | 注意点 |
|---|---|---|
| `src/App.vue` | 调整一级导航和默认首页。 | 普通用户默认进入“创作台”。 |
| `src/components/CreatorWorkspace.vue` | 从功能堆叠改成四步视频项目流程。 | 优先复用现有任务、发布建议、反馈报告接口。 |
| `src/components/KnowledgeWorkspace.vue` | “案例库”去技术化，改成“找灵感”。 | 检索策略、索引状态等移入开发者模式。 |
| `src/components/AgentFloatingWindow.vue` | 改成“问问 AI”。 | 普通模式隐藏执行模式和轨迹入口。 |
| `src/components/SettingsDrawer.vue` | 增加开发者模式入口和可见性开关。 | 设置项不要变成新的主流程。 |
| `src/composables/useAgentChat.ts` | 保持上下文注入能力。 | 前端只传当前视频、当前案例和用户问题，不伪造证据。 |
| `src/styles/theme.css` | 统一容器、按钮、步骤条和响应式规则。 | 避免卡片套卡片和移动端横向滚动。 |

## 12. 前后端边界

1. 本重构优先使用现有接口，不主动新增后端 API。
2. 前端可以改文案、布局、可见性和步骤组织，但不能篡改后端事实来源。
3. 评论、弹幕和案例依据必须来自后端返回或用户主动提供的数据。
4. 普通模式隐藏技术字段，不代表删除字段；开发者模式仍可查看。
5. 如果后续发现“项目列表”需要分页、搜索或归档，再单独设计接口，不在本轮偷加。

## 13. 实施分期

P0 按 4 个切片推进，降低一次性重构风险。

| 切片 | 目标 | 主要改动 | 验收重点 |
|---|---|---|---|
| P0-1 导航与文案去技术化 | 先让普通用户看懂入口。 | 调整导航、首页、术语、开发者模式可见性。 | 首屏不出现工程词。 |
| P0-2 创作台四步流程 | 把核心任务串成视频项目流程。 | 重排视频资料、发布方案、观众反馈、复盘报告。 | 用户能按步骤完成一条视频。 |
| P0-3 参考案例和问问 AI | 让案例库服务当前视频。 | 案例页文案重构，AI 浮窗默认带上下文。 | 用户能用案例辅助当前视频修改。 |
| P0-4 视觉和响应式收口 | 统一页面观感并修移动端问题。 | 统一容器、按钮、结果块、步骤条。 | 三档宽度无重叠和横向滚动。 |

P1 在 P0 稳定后再做：

1. 拆分 `CreatorWorkspace.vue` 大组件。
2. 增加新手样例项目。
3. 增加“复制标题 / 复制简介 / 复制行动清单”细粒度操作。
4. 增加空状态引导图或轻量插画。
5. 增加项目完成度和最近操作记录。

暂不做：

1. B 站账号授权。
2. 自动批量采集。
3. 自动投稿。
4. 后端 Agent 架构重写。
5. 新增复杂权限系统。

## 14. 验收标准

1. 普通模式首屏不出现 Agent、API、Token、RAG、Milvus、Prompt、SSE、评测等词。
2. 用户能按“视频资料 -> 发布方案 -> 观众反馈 -> 复盘报告”完成完整流程。
3. 每一步只有一个明确主按钮。
4. 结果页能直接复制、采用或导出。
5. 卡片样式不超过 4 类，且没有卡片套卡片。
6. 案例库不再向普通用户暴露检索增强、精排、索引等工程词。
7. 开发者能力仍可通过开发者模式访问。
8. 375px、768px、1440px 宽度下无内容重叠和横向滚动。
9. 键盘焦点、表单标签和错误提示清晰可见。
10. 后端未启动或接口失败时，页面给出用户能理解的失败提示。

## 15. 作者验证建议

按项目约定，开发者不执行前端构建、类型检查、运行或启动命令。编码落地后由作者执行：

```powershell
cd E:\linkAgent\linkAgent\link-agent-frontend
npm run type-check
npm run build
npm run dev
```

预期结果：

1. `type-check` 无 TypeScript 类型错误。
2. `build` 正常生成产物。
3. 本地页面在 375px、768px、1440px 三档宽度无横向滚动。
4. 普通模式首屏不出现工程词，开发者模式仍能看到诊断信息。
