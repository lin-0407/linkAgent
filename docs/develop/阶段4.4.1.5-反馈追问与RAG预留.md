# 阶段 4.4.1.5：反馈追问与 RAG 预留

## 需求分析

本轮服务对象是已经完成评论弹幕导入和反馈报告生成的 B 站 UP 主。

要解决的问题是：反馈报告给出“高频观点、争议点、误解点、下一期建议”后，用户经常还会追问“为什么这么判断”“依据是哪几条评论”“下一期应该怎么回应”。如果只能重新生成整份报告，交互成本太高，也不利于展示任务级证据链。

本轮只做：

1. 增加 `POST /api/creator/tasks/{taskId}/feedback/chat` 追问接口。
2. 后端基于当前任务的反馈报告和评论弹幕明细生成回答。
3. 响应返回本次参考的证据明细，为后续 Milvus RAG 保持响应结构。
4. 前端在反馈分析报告弹窗内增加追问输入区和证据展示区。

本轮不做：

1. 不新增聊天历史表。
2. 不接 Milvus，不写向量数据。
3. 不做跨任务检索。
4. 不把前端传来的内容当作证据来源。

## 设计方案

### 后端接口

```text
POST /api/creator/tasks/{taskId}/feedback/chat
```

请求体：

```json
{
  "question": "为什么你认为观众误解了 Agent 工具调用？"
}
```

校验规则：

1. `taskId` 必填，最长 64 个字符。
2. `question` 必填，最长 1000 个字符。
3. 当前任务必须已有反馈报告或评论弹幕明细。

响应核心字段：

```json
{
  "taskId": "creator-task-id",
  "question": "为什么你认为观众误解了 Agent 工具调用？",
  "answer": "基于证据1和证据2...",
  "evidenceItems": [],
  "reportUsed": true,
  "retrievalMode": "MYSQL_REPORT_AND_CLASSIFIED_ITEMS",
  "ragEnabled": false,
  "modelName": "qwen3",
  "promptTokens": 640,
  "completionTokens": 180,
  "totalTokens": 820,
  "elapsedMs": 1300
}
```

### 证据选择策略

第一版不做向量检索，使用 MySQL 中当前任务的明细：

1. 优先读取已保存的反馈报告。
2. 读取当前任务下最近导入的评论弹幕明细。
3. 按问题关键词、问题意图、分类、情绪、点赞和回复量做轻量打分。
4. 最多返回 8 条证据。
5. 没有命中明确证据时，给模型少量最新有效样例，让模型能判断证据不足。

这样做的原因是：现有导入阶段已经把明细、分类和情绪保存到 MySQL，先用这层数据就能完成追问闭环；RAG 后续只需要替换证据检索来源，不必重做前端响应结构。

## 编码实现

后端新增：

```text
CreatorFeedbackChatRequest
CreatorFeedbackChatResponse
```

后端修改：

```text
CreatorFeedbackController
CreatorFeedbackService
```

前端修改：

```text
src/api/creator.ts
src/types/creator.ts
src/components/CreatorWorkspace.vue
src/styles/theme.css
```

关键实现点：

1. 前端只提交问题，不提交报告或证据，避免伪造证据上下文。
2. 后端 prompt 要求回答必须引用证据编号，证据不足时明确说明。
3. 前端追问区放在反馈分析报告弹窗内，不回到评论弹幕输入表单下方展示。
4. 用户重新保存、导入或重新分析反馈时，会清理旧追问结果，避免证据串任务或串版本。
5. 响应返回模型 usage，是为了让追问链路能观察 token 成本和耗时，不再只能靠人工估算。

## 测试验证点

作者本地后端验证：

```bash
cd backend
mvn test
```

作者本地前端验证：

```bash
cd link-agent-frontend
npm run type-check
npm run build
```

联调验收：

1. 先确认发布前建议，再导入评论弹幕样例。
2. 点击“分析反馈”生成反馈报告。
3. 打开“查看分析结果”弹窗。
4. 在“反馈追问”输入问题后点击“追问”。
5. 页面展示回答和证据列表。
6. 没有报告且没有导入明细时，接口返回 400。
7. 重新导入样例后，旧追问结果应清空。

## 后续扩展

1. 接入 Milvus，把有效评论和弹幕写入向量库。
2. `retrievalMode` 从 `MYSQL_REPORT_AND_CLASSIFIED_ITEMS` 扩展为 `MILVUS_VECTOR_SEARCH`。
3. 增加追问历史表，保存用户问题、回答、证据 ID 和模型原始输出。
4. 增加证据相关度评分，帮助用户判断回答可信度。
