# 阶段 4.1：创作任务与稿件输入

## 需求分析

本阶段服务的目标用户是 B 站 UP 主、内容运营者和内容复盘者。

要解决的场景是：在进行标题生成、稿件分析、评论复盘之前，系统需要先有一个稳定的“创作任务”作为业务入口，并能保存用户主动输入的标题草稿、简介草稿、文稿和字幕。

输入数据来源：

1. 用户手动粘贴标题草稿、简介草稿、文稿、字幕。
2. 后续可扩展项目内置样例数据。
3. 本阶段不接入 B 站真实账号，不抓取页面，不自动获取评论或弹幕。

本阶段只做：

1. 创建创作任务。
2. 查询创作任务列表。
3. 查询创作任务详情及其输入材料。
4. 维护对应数据库表结构。

本阶段不做：

1. LLM 稿件分析。
2. 标题简介生成。
3. 评论弹幕分析。
4. 文件上传。
5. 任务删除、归档和复杂状态机。

## 设计方案

### 后端包结构

新增业务包：

```text
com.link.linkagent.creator.task
```

当前只创建 `task` 包，不提前创建 `suggestion`、`feedback`、`report` 等空包，避免过早抽象。

### 数据表

新增 `creator_task`：

```text
保存创作任务主信息，例如 taskId、userId、taskName、status。
```

新增 `creator_material`：

```text
保存任务输入材料，例如 TITLE_DRAFT、DESCRIPTION_DRAFT、MANUSCRIPT、SUBTITLE。
```

任务主表和材料表拆开，是为了让后续阶段可以继续挂载更多材料类型，而不需要频繁修改任务主表字段。

### API

```text
POST /api/creator/tasks
GET  /api/creator/tasks
GET  /api/creator/tasks/{taskId}
```

### 入参校验

所有对外接口使用 Jakarta Validation：

1. `taskName` 最长 128。
2. `titleDraft` 最长 200。
3. `descriptionDraft` 最长 2000。
4. `manuscript` 和 `subtitle` 最长 20000。
5. 标题草稿、简介草稿、文稿、字幕至少填写一项。
6. `limit` 范围是 1 到 100。

### 是否涉及 Agent

本阶段不涉及 Agent、LLM、工具调用、向量库、Redis、SSE。

原因是阶段 4.1 的核心是建立业务数据入口。只有任务和材料先稳定落库，阶段 4.2 的发布前优化 Agent 才有明确的数据来源和业务挂载点。

## 编码实现

本轮新增：

- `CreatorTaskController`：创作任务 REST 接口。
- `CreatorTaskService`：任务创建、列表查询、详情查询。
- `CreatorTaskMapper`：MyBatis 注解 SQL。
- `CreatorTaskRecord`：任务数据库记录。
- `CreatorMaterialRecord`：材料数据库记录。
- `CreatorTaskSummaryRecord`：列表查询记录。
- `CreatorTaskCreateRequest`：创建任务请求。
- `CreatorTaskResponse`：任务详情响应。
- `CreatorTaskSummaryResponse`：任务列表响应。
- `CreatorMaterialResponse`：材料响应。
- `CreatorTaskStatus`：任务状态枚举。
- `CreatorMaterialType`：材料类型枚举。

修改：

- `backend/src/main/resources/sql/init.sql`
  - 新增 `creator_task`
  - 新增 `creator_material`

## 接口示例

### 创建任务

```http
POST /api/creator/tasks
Content-Type: application/json

{
  "userId": "default",
  "taskName": "AI 工具使用经验分享",
  "titleDraft": "我用 AI 写代码的真实体验",
  "descriptionDraft": "分享一次从需求到上线的 AI 辅助开发过程",
  "manuscript": "这里粘贴视频文稿...",
  "subtitle": "这里粘贴字幕文本..."
}
```

### 查询任务列表

```http
GET /api/creator/tasks?userId=default&limit=20
```

### 查询任务详情

```http
GET /api/creator/tasks/{taskId}
```

## 测试验证点

正常路径：

1. 创建任务时填写标题草稿和文稿，返回 `DRAFT` 状态和材料列表。
2. 查询列表时能看到刚创建的任务。
3. 查询详情时能看到任务主信息和材料内容。

边界路径：

1. 四类材料全部为空时，应返回参数校验失败。
2. `limit=0` 或 `limit=101` 时，应返回参数校验失败。
3. `taskId` 不存在时，应返回 404。
4. 超过字段长度限制时，应返回参数校验失败。

作者本地验证命令：

```bash
cd backend
mysql -u root -p < src/main/resources/sql/init.sql
mvn test
```

如果只想先检查编译：

```bash
cd backend
mvn test -DskipTests
```
