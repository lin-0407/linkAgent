# 阶段 4.10 - LLM 用量采集与评测统计口径

## 需求分析

这一轮解决的问题很直接：如果项目只展示“调用大模型返回结果”，简历价值不够；必须能回答 token 怎么统计、评分是不是有依据、Prompt 迭代是否真的可比较。

目标用户是项目作者和面试讲解场景。普通 UP 主不需要看到复杂评测口径，但开发者测试和反馈追问链路需要能说明成本、稳定性和评分依据。

本轮做：

1. 在 `LLMService` 新增 `chatWithUsage`，从 Spring AI `ChatResponse` 中提取模型名称、prompt token、completion token、total token 和耗时。
2. 保留原有 `chat` 方法，避免现有调用方一次性重构。
3. 反馈追问接口返回本次 LLM 调用的 token 与耗时，让真实调用链可以观察成本。
4. Prompt 版本统计从“一个平均分”扩展为成功率、评分样本数、分项均分、token 总量/均值、耗时、评分覆盖率和分数波动。

本轮不做：

1. 不做自动 LLM-as-judge 评分。
2. 不把人工 `accuracyScore` 包装成客观准确率。
3. 不做人民币成本换算，因为不同模型价格和计费口径会变化。
4. 不新增独立 LLM 调用流水表，避免本轮范围扩大。

## 设计方案

### Token 统计

新增返回对象：

```text
LlmCallResult
```

字段：

```text
content
modelName
promptTokens
completionTokens
totalTokens
elapsedMs
```

设计原因：

1. `content` 和 usage 必须绑定在同一次响应上，避免后续统计和模型输出错位。
2. token 缺失时保留 `null`，不伪造为 `0`，因为不同供应商对 usage 返回完整度不一致。
3. Spring AI 的空 usage 可能表现为三个 token 字段都为 `0`，这里统一归一成 `null`，避免把“未知”误统计成“零成本”。
4. `chat` 继续返回字符串，降低改造成本；真正需要统计的调用方改用 `chatWithUsage`。

### 评分统计

评分仍然是人工评测，但不再只看一个均分。Prompt 版本统计增加：

```text
successRatePercent
scoreSampleCount
averageAccuracyScore
averageRelevanceScore
averageCompletenessScore
averageCostScore
averageExplainabilityScore
scoreStandardDeviation
fullScoreCoverageRatePercent
totalTokens
averagePromptTokens
averageCompletionTokens
averageTotalTokens
```

口径说明：

1. 准确性来自 `accuracyScore` 分项，表示人工按评测用例的 `expectedPoints` 和 `scoringRubric` 判断输出是否准确。
2. 合理性不靠单一指标，而是看分项均值、评分覆盖率、人工备注、原始输出和分数波动。
3. 如果某版本均分高但 `scoreStandardDeviation` 高，说明输出不稳定。
4. 如果 `fullScoreCoverageRatePercent` 低，说明样本评分不完整，不能过度解读均分。
5. Prompt 版本统计使用当前评测用例下的全部结果；结果列表接口仍然分页，只服务页面最近结果展示。

## 测试验证

作者本地执行：

```bash
cd backend
mvn test
```

```bash
cd link-agent-frontend
npm run type-check
npm run build
```

验收点：

1. 反馈追问成功后，回答下方能看到模型名称、总 token 和耗时。
2. Prompt 版本对比区能看到成功率、均分、准确性均分、平均 token、评分覆盖率和分数波动。
3. 如果模型供应商没有返回 usage，token 字段应显示为空值，而不是错误显示为 0。
4. 手动记录评测结果时，token 输入不填应保持为空；显式提交 0 会被拒绝或归一为空，只有 prompt token 和 completion token 都存在时才自动推导 total token。
5. 旧的 `LLMService.chat` 调用方仍能正常返回文本。

## 简历表达

可以写成：

```text
补充 LLM 调用用量采集与评测统计口径：基于 Spring AI ChatResponse usage 自动提取 token 与耗时，并按 Prompt 版本聚合成功率、分项评分、评分覆盖率、分数波动和 token 成本，支撑 Prompt 迭代的可观测分析。
```

这比“接入大模型 API”更像 AI 应用工程化能力。
