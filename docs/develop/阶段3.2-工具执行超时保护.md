# 阶段 3.2：工具执行超时保护

## 上下文

阶段 3.1 已经补齐工具注册安全基线。下一步需要处理工具执行边界，因为内置工具、外部 HTTP 工具、后续 MCP 工具都可能失败或阻塞。

如果工具异常和超时直接散落在 `AgentExecutor` 中，ReAct 主循环会逐渐变臃肿，也不利于后续扩展重试、降级和并发执行。

## 本轮目标

新增一个最小工具执行器，把工具查找、异常包装和超时保护集中到工具层。

## 本轮变更

- 新增 `ToolExecutionProperties`：
  - 读取 `agent.tool.execution.timeout-seconds`。
  - 默认工具执行超时为 10 秒。
  - 最小值兜底为 1 秒，避免配置为 0 或负数。
- 新增 `ToolExecutor`：
  - 工具不存在时返回错误 Observation。
  - 工具抛异常时返回错误 Observation。
  - 工具执行超时时返回错误 Observation。
- 修改 `AgentExecutor`：
  - 保留 `ToolRegistry` 用于构建系统提示词。
  - 工具调用改为委托 `ToolExecutor` 执行。
- 修改 `application.yml`：
  - 新增 `TOOL_EXECUTION_TIMEOUT_SECONDS` 环境变量入口。
- 新增 `ToolExecutorTest`：
  - 覆盖正常工具执行。
  - 覆盖工具不存在。
  - 覆盖工具异常。
  - 覆盖工具超时。

## 设计说明

当前版本使用 `CompletableFuture.orTimeout` 做主链路超时保护。它能保证 Agent 不会一直等待工具结果，但不会强制终止底层正在执行的阻塞代码。

这是有意的第一版取舍：先保护 ReAct 主流程的响应边界，后续如果引入代码执行、爬虫、MCP 等重型工具，再单独增加线程池隔离和取消策略。

## 验证方式

本项目约定 Maven 编译和测试由作者执行。本轮建议执行：

```bash
cd backend
mvn test -Dtest=ToolExecutorTest,ToolRegistryTest,AgentExecutorLongTermMemoryTest
```
