# 阶段二：拆 CreatorWorkspace 巨石 — 详细执行方案

> 前置：阶段一（建议卡片/时间轴/状态栏）已完成并验证通过。

## 一、目标与约束

### 目标
把 `frontend/src/components/CreatorWorkspace.vue`（当前 4814 行：script 1-2289，template 2291-4814，无独立 style 块）拆成 1 个主壳 + 6 个子组件 + 1 个工具文件 + 1 个 context 文件。

### 硬约束（违反任一条都算失败）
1. **SSE 必须保持单连接**。`useCreatorWorkflow` 内部建连，`workflowModule` 实例必须全局唯一。
2. **任务恢复/持久化不变**。`creatorStore`（持久化 `selectedTaskId`+`activeStep`）由主壳持有，子组件不碰持久化。
3. **跨 tab 数据共享不变**。feedback/report tab 要读 workflowModule（`hasConfirmedPrePublish`）和 feedbackModule（`feedbackReport`）的数据。
4. **不改 composable 的 return 签名**。composable 现状不变，只在主壳实例化并 provide。
5. **不改 package.json**。
6. **所有注释中文，解释"为什么"不只是"做了什么"**。
7. **样式不动**。CreatorWorkspace 无 `<style>` 块，所有样式在全局 `styles/theme.css`（creator-* 类是全局类）。子组件不写样式，直接用全局类。

### 拆分策略（已与作者确认）
**module 提升 + template 下沉**：所有 composable 在主壳实例化并 `provide`，子组件 `inject` 同一实例。子组件只搬 template + 专属 UI 状态。一次性全拆。

### 步骤 2：创建 context 文件

创建 `composables/creator/useCreatorWorkspaceContext.ts`：

```typescript
import { inject, provide, type InjectionKey } from 'vue'
import type { useCreatorTask } from './useCreatorTask'
import type { useCreatorWorkflow } from './useCreatorWorkflow'
import type { useCreatorFeedback } from './useCreatorFeedback'
import type { useCreatorGuidance } from './useCreatorGuidance'
import type { useCreatorContext } from './useCreatorContext'
import type { useCreatorUsage } from './useCreatorUsage'
import type { useCreatorEvaluation } from './useCreatorEvaluation'
import type { useCreatorFeedbackEvent } from './useCreatorFeedbackEvent'
import type { ResultModalTarget } from './CreatorWorkspace' // 见下文类型导出说明

/**
 * 创作台共享上下文。
 * 主壳实例化所有 composable 后 provide，子组件 inject 同一实例，
 * 保证 SSE 单连接、跨 tab 数据共享、任务恢复逻辑不变。
 */
export interface CreatorWorkspaceContext {
  // 共享 module 实例
  taskModule: ReturnType<typeof useCreatorTask>
  workflowModule: ReturnType<typeof useCreatorWorkflow>
  feedbackModule: ReturnType<typeof useCreatorFeedback>
  guidance: ReturnType<typeof useCreatorGuidance>
  contextModule: ReturnType<typeof useCreatorContext>
  usageModule: ReturnType<typeof useCreatorUsage>
  evaluationModule: ReturnType<typeof useCreatorEvaluation>
  feedbackEvent: ReturnType<typeof useCreatorFeedbackEvent>

  // 跨 tab 共享的 UI 状态与函数
  showDeveloperTools: import('vue').ComputedRef<boolean>
  successMessage: import('vue').Ref<string>
  errorMessage: import('vue').Ref<string>
  openResultModal: (target: ResultModalTarget) => void
  closeResultModal: () => void
  openWorkflowMessageModal: () => void
  openWorkflowProcessModal: () => void
  openFeedbackChatDrawer: () => void
  closeFeedbackChatDrawer: () => void
  toggleFeedbackChatDrawer: () => void
  openDeveloperTest: () => void
  openUsageStats: () => void
  openTaskManager: () => void
}

export const CreatorWorkspaceKey: InjectionKey<CreatorWorkspaceContext> = Symbol('CreatorWorkspace')

export function provideCreatorWorkspace(ctx: CreatorWorkspaceContext) {
  provide(CreatorWorkspaceKey, ctx)
}

export function useCreatorWorkspaceContext(): CreatorWorkspaceContext {
  const ctx = inject(CreatorWorkspaceKey)
  if (!ctx) {
    throw new Error('useCreatorWorkspaceContext 必须在 CreatorWorkspace 主壳内使用')
  }
  return ctx
}
```

**ResultModalTarget 类型**：当前定义在 CreatorWorkspace.vue 第 87 行 `type ResultModalTarget = 'prePublishSuggestion' | 'feedbackDashboard' | 'feedbackReport'`。拆分时把它移到 `types/creator.ts` 导出，或在 context 文件里重新定义并导出。**推荐移到 types/creator.ts**，避免循环依赖。

同步移到 types/creator.ts 的还有：`CreatorActiveStep`（第89行）、`FeedbackChatTurn`（第90-94行，但这个 feedbackModule 可能已内部定义，需确认）。

4. **工具函数无重复**：grep 确认 CreatorWorkspace 不再有 parseJsonArray 等定义（已 import）
5. **SSE 单连接**：workflowModule 只在主壳实例化一次，子组件全是 inject
6. **持久化不动**：creatorStore 只在主壳用

## 五、风险点与应对

| 风险 | 应对 |
|------|------|
| provide 的对象解构后失去响应性 | **不要解构 ref/computed**，子组件里用 `ctx.taskModule.selectedTask` 访问，或解构 module 后通过 module.xxx 访问（module 是普通对象，其属性是 ref，访问 .value 保持响应） |
| inject 拿到 undefined | context 文件的 useCreatorWorkspaceContext 已加守卫抛错，开发期立即暴露 |
| 子组件用到的某个函数没 provide | 自检阶段 grep 每个子组件 template 的所有标识符，对照 context 接口 |
| 工具函数漏搬 | 先建工具文件，CreatorWorkspace 改为 import，grep 确认无残留定义 |
| resultModal 里的 SuggestionCard 依赖 feedbackEvent | feedbackEvent 在主壳实例化并 provide，但 resultModal 在主壳，直接用主壳的 feedbackEvent 即可，不需要 inject |
| usage/evaluation composable 的完整 return 未确认 | 执行前 Read useCreatorEvaluation.ts 229-260 补全 return 签名 |
