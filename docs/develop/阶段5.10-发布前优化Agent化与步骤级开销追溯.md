# 阶段 5.10 - 发布前优化 Agent 化与步骤级开销追溯

## 一、需求分析

本阶段把发布前优化从“单次直连 LLM 生成建议”升级为工作流内的 Agent 推理。

目标用户是 UP 主和内容运营者。他们关心的是稿件哪里要改、标题简介标签怎么改、建议有没有参考依据、模型成本是多少、失败时卡在哪一步。

本阶段做：

- 发布前优化工作流默认走 `AgentExecutor.runTask(...)`。
- Agent 可按需调用 `knowledge_search` 检索视频案例知识库。
- 保留旧直连 LLM 链路作为 Agent 失败后的回退。
- `llm_api_call_log` 增加 workflow session 和 step 归属字段。
- 新增工作流 session 级开销接口，按步骤返回模型调用明细。
- 前端主页面只显示过程摘要，完整步骤、开销和 rawOutput 放进应用内弹窗。

本阶段不做：

- 不做自动投稿。
- 不做批量或定时采集。
- 不把普通 HTTP 请求纳入 token 统计。
- 不重做多 Agent 编排。
- 不引入新的前端路由体系。

## 二、设计方案

### 2.1 后端链路

发布前优化工作流链路：

```text
CreatorWorkflowService.analyzePrePublishWorkflow
  -> LOAD_CONTEXT
  -> AGENT_REASONING
  -> LlmUsageContext.openWorkflowStep(...)
  -> PrePublishSuggestionService.generateSuggestionByAgent(...)
  -> AgentExecutor.runTask(...)
  -> knowledge_search 按需检索案例库
  -> 解析 Agent finalAnswer
  -> 保存 creator_suggestion
  -> SAVE_RESULT
```

Agent 失败时：

```text
AGENT_REASONING 标记失败
  -> 新建 LLM_CALL 回退步骤
  -> PrePublishSuggestionService.generateSuggestion(...)
  -> 保存建议
```

这样做的原因是：用户主流程不能因为 Agent 工具或结构化输出异常完全不可用，但过程弹窗仍能清楚看到 Agent 步骤失败和回退步骤成功。

### 2.2 运行期开关

新增开关：

```text
creator.pre-publish.agent.enabled
```

配置默认值来自：

```text
PRE_PUBLISH_AGENT_ENABLED=true
```

默认开启，设置面板可写入 DB 覆盖值。关闭后发布前优化直接走旧的 `LLM_CALL` 步骤。

### 2.3 数据库字段

`llm_api_call_log` 新增字段：

| 字段 | 说明 |
|---|---|
| `workflow_session_id` | 工作流会话 ID，用于把模型调用归属到一次创作者工作流 |
| `workflow_step_id` | 工作流步骤 ID，用于把模型调用归属到具体执行步骤 |
| `workflow_step_name` | 工作流步骤名称，用于前端展示模型调用发生在哪一步 |
| `workflow_stage` | 工作流阶段，例如 `PRE_PUBLISH`、`FEEDBACK`、`REPORT` |

新增索引：

```sql
KEY idx_llm_api_workflow_step (workflow_session_id, workflow_step_id, create_time)
```

不用时间猜测归属，是因为同一任务可能并发多次模型调用，Embedding 和 Rerank 也可能由工具链内部触发。

### 2.4 用量上下文

新增：

```java
LlmUsageContext.openWorkflowStep(
    taskId,
    workflowSessionId,
    workflowStepId,
    workflowStepName,
    workflowStage,
    scene
)
```

`LlmUsageContext.open(...)` 会继承已有 workflow 字段，避免旧直连方法内部再次打开上下文时把步骤归属覆盖掉。

`ToolExecutor` 会在 `CompletableFuture.supplyAsync(...)` 里恢复 `LlmUsageContext`。这是必要的，因为工具执行会切换线程，`ThreadLocal` 默认不会跨线程传播。

### 2.5 新增接口

```http
GET /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/usage
```

校验规则：

- `taskId` 必填，最大 64 字符。
- `sessionId` 必填，最大 64 字符。

响应按步骤分组：

```json
{
  "taskId": "task-id",
  "sessionId": "session-id",
  "totalCalls": 4,
  "successCalls": 3,
  "failedCalls": 1,
  "skippedCalls": 0,
  "totalTokens": 2381,
  "totalElapsedMs": 3400,
  "steps": []
}
```

### 2.6 前端交互

主页面步骤区改为轻量摘要：

```text
执行过程
3 步完成 · 0 步失败 · API 调用 4 次 · 2381 token · 3.4s
[查看过程]
```

点击“查看过程”打开应用内弹窗。弹窗展示：

- 工作流状态、步骤数、API 调用数、总 token、总耗时。
- 步骤列表、状态、开始时间、输入摘要、输出摘要、错误信息。
- 每个步骤下的模型 API 开销。
- `rawOutput` 默认隐藏，通过按钮展开。

前端开销接口失败时，弹窗仍展示步骤，并显示“开销统计暂不可用”。

发布前优化消息流和材料详情也默认收起。主页面只保留“查看消息流”入口按钮，点击后在应用内弹窗查看消息列表、消息详情和补充要求输入框。

## 三、实现范围

后端：

- `LlmUsageContext` 增加 workflow 字段、`openWorkflowStep(...)` 和异步恢复能力。
- `ToolExecutor` 在异步工具线程恢复 LLM 用量上下文。
- `LlmApiCallRecord`、`LlmApiUsageMapper`、`LlmApiUsageService` 支持 workflow 字段和 session 聚合。
- `CreatorWorkflowController` 增加 `/usage` 接口。
- `CreatorWorkflowService` 接入 Agent 步骤和旧链路回退。
- `PrePublishSuggestionService` 增加 `generateSuggestionByAgent(...)`。
- `RuntimeSettingService` 和 `RuntimeSettingKey` 增加发布前优化 Agent 开关。
- `sql/init.sql` 增加字段、索引和兼容 `ALTER TABLE`。

前端：

- `creator.ts` 增加工作流开销接口。
- `creator.ts` 类型增加 `WorkflowUsageResponse`、`WorkflowStepUsage` 和调用记录 workflow 字段。
- `CreatorWorkspace.vue` 增加过程摘要、过程弹窗、消息流弹窗、rawOutput 展开和步骤调用挂载。
- `theme.css` 增加过程弹窗、消息流弹窗样式和移动端适配。

## 四、验证清单

后端：

- 开启 `PRE_PUBLISH_AGENT_ENABLED=true` 后，发布前优化创建 `AGENT_REASONING` 步骤。
- 知识库 RAG 开启且有数据时，Agent 可调用 `knowledge_search`。
- Agent 输出无法解析时，`AGENT_REASONING` 失败，并创建 `LLM_CALL` 回退步骤。
- `llm_api_call_log` 写入 `workflow_session_id`、`workflow_step_id`、`workflow_step_name`。
- `/usage` 接口能按步骤返回调用明细。
- 统计写入失败不影响主流程。

前端：

- 主页面默认不展开完整步骤。
- 主页面默认不展示消息流和消息详情，只显示“查看消息流”入口。
- 点击“查看过程”打开应用内弹窗。
- 点击“查看消息流”打开应用内弹窗，并能查看消息列表、详情和发送补充要求。
- 弹窗展示步骤、状态、输入摘要、输出摘要和错误信息。
- 每个步骤下展示 API 开销。
- rawOutput 默认隐藏，点击按钮后展开。
- 移动端弹窗不横向溢出。
