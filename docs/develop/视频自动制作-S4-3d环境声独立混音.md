# S4-3d 环境声独立混音

更新时间：2026-10-22。分支 `feature/creator-workspace-s1`，本轮基线 `34a17d4`。上一步见 [S4-3c 时间线调整采纳与重排](视频自动制作-S4-3c时间线调整采纳与重排.md)。

## 1. 为什么单独做一路

S4-3a 只有一路 `backgroundMusic`：它承担配乐，并在对白出现时按实际音轨能量压低。环境声（雨、街道、室内底噪）的用途不同：

| 维度 | 背景音乐 `backgroundMusic` | 环境声 `ambience` |
| --- | --- | --- |
| 作用 | 情绪与节奏 | 空间感与场景连续 |
| 是否随对白压低 | 可选 `ducking` | 固定不压低 |
| 音量 | -36 ~ 0 dB | -36 ~ 0 dB，建议 -24 左右 |
| 淡入淡出 | 0–10 秒 | 0–10 秒 |
| 素材 | `MUSIC` 类型 WAV | 同一 `MUSIC` 类型，但必须是另一份素材 |
| 长度 | 选区 = 全片帧长 | 选区 = 全片帧长 |

把环境声塞进背景音乐会让"对白时压低"作用到本应稳定的底噪上；再加一路则两件事可以独立调节。

## 2. 接口与字段

简报请求新增可选字段 `ambience`：

```json
{
  "expectedWorkspaceRevision": 7,
  "topic": "雨夜散步",
  "targetDurationMs": 60000,
  "dialogueMode": "USER_NARRATION",
  "contentKind": "USER_PROVIDED",
  "assetIds": ["voice-1", "music-1", "rain-1"],
  "constraints": "",
  "backgroundMusic": {
    "assetId": "music-1", "sourceInMs": 0, "sourceOutMs": 60000,
    "gainDb": -18, "fadeInMs": 800, "fadeOutMs": 1200, "ducking": true
  },
  "ambience": {
    "assetId": "rain-1", "sourceInMs": 0, "sourceOutMs": 60000,
    "gainDb": -24, "fadeInMs": 500, "fadeOutMs": 800
  }
}
```

约束：

- `ambience.assetId` 必须在本简报 `assetIds` 内，且素材已 `READY`、类型为 `MUSIC`、内容为 `audio/wav`；
- 区间长度必须等于全片帧长（±1 帧），不循环、不变速；
- 区间终点不得超过素材真实时长；
- 音量 -36 ~ 0 dB；单个淡入或淡出不超过 10 秒，两者合计不超过区间；
- `ambience` 不能与 `backgroundMusic` 引用同一素材；
- 不提供 `ducking` 字段：环境声固定不随对白压低。

未选择 `ambience` 时，简报与旧工程行为完全不变。

## 3. 编译后的 V2 工程

```json
"ambience": {
  "assetId": "rain-1",
  "sourceStartMs": 0,
  "sourceEndMs": 60000,
  "gainDb": -24.0,
  "fadeInMs": 500,
  "fadeOutMs": 800
}
```

字段名与 `backgroundMusic` 保持一致（`sourceStartMs/sourceEndMs`），渲染器按同一套区间读取逻辑处理。环境声素材与音乐素材同属 64 MiB 长音频角色。

## 4. 渲染实现

`renderer/linkagent_renderer/music.py` 抽出 `AudioBed` 基类，`BackgroundMusic` 与 `Ambience` 只差一个"是否允许压低"的开关：

- 区间读取：按源采样率线性插值到 48 kHz，只读选区，不越过 `sourceEndMs`；
- 淡入淡出：按全片时间轴计算，跨场景连续，不因镜头切换重置；
- 压低：只有 `BackgroundMusic` 在 `ducking=true` 时根据**主音轨（原声+旁白）**的 10 ms RMS 判断，环境声不参与也不被影响；
- 混音顺序：原声/旁白 → 背景音乐 → 环境声，最后统一做削波检查。

`contract.py` 在同一层校验 `ambience` 的字段白名单、数值范围、素材 MIME、文件大小和选区范围；`Project.expects_audio` 现在包含环境声，避免"只有环境声"的工程被误判静音。

## 5. 时间线同步

`timeline:apply` 采纳时长提案时，环境声区间与背景音乐走同一规则：

- `sourceInMs` 不变，`sourceOutMs = sourceInMs + 新总时长`；
- 新终点超过素材真实时长时拒绝，要求重新选择区间；
- 淡入淡出总长超过新区间时拒绝；
- 响应 `notes` 分别说明背景音乐与环境声各自从多少毫秒调整到多少毫秒。

`GET /storyboards/{id}/timing` 也会把 `AMB_*` 问题汇总为全片提案。

## 6. 新增受控错误码

| 代码 | 含义 |
| --- | --- |
| `AMB_MISSING` | 环境声引用的素材不在冻结清单、类型不是 `MUSIC` 或不是 `audio/wav` |
| `AMB_DUPLICATE_SOURCE` | 环境声与背景音乐使用同一素材 |
| `AMB_FORMAT_INVALID` | 不是 48 kHz 立体声 PCM16 WAV，或时长不可靠、超过 20 分钟 |
| `AMB_DURATION_MISMATCH` | 选区长度与全片帧长不一致 |
| `AMB_OUT_OF_RANGE` | 选区终点超过素材真实时长 |
| `AMB_MIX_INVALID` | 音量越界，或淡入淡出单项/合计越界 |

这些代码与 `BGM_*` 并列出现在 `timing` 报告的 `proposals` 中，`sceneId` 为空。

## 7. 验证口径

- 编译器单测：合法工程输出 `ambience`、无 `ducking` 字段；缺素材/类型错/区间不匹配/超时长/淡入淡出越界/与音乐同素材/超 64 MiB 分别命中对应错误码；
- 真实 MySQL：简报保存两路音轨且 `ambience` 无 `ducking`；同素材请求被拒绝；采纳时间线后环境声终点随新总时长调整并出现在 `notes`；
- Python 单测：环境声与背景音乐同工程时，对白期间 220 Hz 环境声电平不变、660 Hz 背景音乐下降；区间必须覆盖全片；不能复用音乐素材；V1 拒绝该字段；未知字段被拒绝；音量与淡入淡出严格校验；
- Python 真实编码：`AmbienceNativeTest` 用 FFmpeg 出片 2000ms，解码后验证 220 Hz 环境声在"有对白"与"无对白"两个窗口一致、660 Hz 背景音乐在旁白结束后恢复；
- Java 侧原生渲染本轮未执行：容器环境搭建超时已删除，8 项在宿主跳过；Java 编译器契约与 Python 真实编码分别验证，缺一次端到端串接。

实际命令与结果见 [S4-3d 验证记录](../error/视频环境声S4-3d验证记录.md)。

## 8. 当前边界

- **环境声必须覆盖全片**：不支持"30 秒雨声循环铺 3 分钟"，也不做交叉淡化循环点；需要用户提供足够长的素材或选择更短的全片；
- **只有一路环境声**：多轨环境声（如雨声 + 室内底噪分层）未实现；
- **没有自动音量包络**：不能按场景自动增减，只能固定音量加淡入淡出；
- **素材类型仍叫 `MUSIC`**：环境声复用了长音频素材类型，素材列表不会区分用途，页面标注属 S5-2；
- **页面入口**：本轮只交付后端字段与渲染能力，前端归属另一个 agent。
