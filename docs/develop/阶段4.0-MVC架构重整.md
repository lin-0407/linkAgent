# 阶段 4.0 - MVC 架构重整

> 目标：把后端 Web 相关代码整理成清晰的 MVC 分层，减少“控制器、服务、持久层、传输对象混在一个包里”的情况。

## 1. 本次重整范围

- `controller`：只放 HTTP 接口。
- `service`：只放业务流程和编排。
- `mapper`：只放 MyBatis 数据访问。
- `model`：只放请求、响应、实体、枚举等数据结构。

## 2. 目录结果

```text
com.link.linkagent
├── controller
├── dto
├── creator
│   ├── task
│   │   ├── controller
│   │   ├── service
│   │   ├── mapper
│   │   └── model
│   └── suggestion
│       ├── controller
│       ├── service
│       ├── mapper
│       └── model
├── core
├── memory
├── tool
└── llm
```

## 3. 为什么这样拆

1. HTTP 入参和返回值只属于接口层，不应该和业务实现混在一起。
2. 服务层只负责业务规则，后续新增标题生成、复盘报告时可以直接复用。
3. Mapper 和模型分开后，MyBatis 结果映射更稳定，也更容易定位字段变化。

## 4. 本次不做的事

- 不改现有接口路径。
- 不改数据库表结构。
- 不引入额外的分层框架。
- 不把 Agent 底座能力强行并入普通 MVC 业务层。

## 5. 后续扩展规则

新增创作者业务时，默认沿用以下顺序：

```text
controller -> service -> mapper -> model
```

如果某个模块属于 Agent、Tool、Memory 底座能力，就继续放在独立包里，不硬塞进 Web 分层。
