## 预期效果

### 应该记住

- 用户偏好类问题应写入长期记忆，例如回答风格、示例语言、解释方式。
- 用户身份类问题应写入长期记忆，例如 Java 后端学习者、AI 应用开发方向。
- 项目信息类问题应写入长期记忆，例如作品集定位、技术栈、找工作导向。
- 长期约束类问题应写入长期记忆，例如不要修改 `package.json` 的 node 版本。

### 不应该记住

- 天气、时间、计算、当前代码总结等一次性问题不应写入长期记忆。
- 临时接口报错、短期情绪、普通闲聊不应写入长期记忆。
- 用户明确说“别记住”的内容不应写入长期记忆。

### 边界问题

- “我最近在学 Spring AI，今天想先解决 Redis 连接失败的问题”：理想结果是只保存“用户最近在学 Spring AI”，不保存 Redis 连接失败。
- “这次报错是因为我本地 MySQL 密码没配，记一下以后别忘了”：可以保存“本地 MySQL 需要配置密码”，但不要保存整段报错。
- “我现在在 Windows 上开发，项目路径是 E:\linkAgent”：可以保存开发环境，项目路径是否长期保存后续再根据产品定位决定。

### 连续对话

- 第二轮回答应该能读取第一轮沉淀的长期记忆，推荐方向应明显偏向 Java、Spring AI、AI 应用开发。

## 检查方式

```sql
SELECT user_id, memory_key, content, source_session_id, update_time
FROM t_long_term_memory
WHERE user_id = 'default'
ORDER BY update_time DESC;
```

重点观察：

```text
1. 该记的有没有写入 t_long_term_memory。
2. 不该记的有没有误写入。
3. memory_key 是否稳定、可读，而不是随机、冗长或混乱。
4. 同一类偏好是否覆盖同一个 memory_key，例如 Java 和 C++ 示例语言偏好只能保留一条。
```

当前推荐的稳定 key：

```text
user.preference.example_language
user.preference.explanation_style
user.profile.summary
project.profile.summary
project.constraint.summary
```
