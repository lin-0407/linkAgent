# 阶段 4.5.2：创作任务管理体验优化

## 需求分析

上一阶段工作台已经能创建任务并进入后续分析，但任务入口仍然偏“单点表单”：

1. 任务列表只能浏览，不能快速搜任务。
2. 每个任务没有直接的编辑、删除入口。
3. 创建表单和当前任务预览分离，切换任务时不够顺手。
4. 用户想换一个视频方向时，只能重新创建任务，缺少明确的管理动作。

本轮只解决创作任务的增删改查体验，不扩展到发布前优化、评论弹幕分析和复盘逻辑。

本轮做：

1. 给任务列表增加搜索和状态筛选。
2. 给每条任务增加查看、编辑、删除入口。
3. 把创建表单改成可切换的“创建 / 编辑”双模式。
4. 删除任务采用软删除，保留历史分析产物。

本轮不做：

1. 不做多用户权限系统。
2. 不做任务回收站页面。
3. 不做任务批量删除。
4. 不做跨任务复制。

## 设计方案

### 后端接口

在 `creator_task` 现有业务上补两个接口：

```text
PUT /api/creator/tasks/{taskId}
DELETE /api/creator/tasks/{taskId}
```

编辑接口采用覆盖式更新：

1. 任务名称可更新。
2. 标题草稿、简介草稿、文稿、字幕按表单内容覆盖。
3. 某类材料清空时，对应材料做逻辑删除，避免旧内容继续参与后续 Agent 分析。
4. 只要材料发生变化，任务状态退回 `DRAFT`，提醒用户重新生成建议。

删除接口采用软删除：

1. `creator_task.is_deleted = 1`
2. `creator_material.is_deleted = 1`
3. 状态写成 `ARCHIVED`

这样做是为了保留历史分析、工作流和复盘记录，避免删除任务后把上下游证据一起抹掉。

### 前端交互

任务侧栏改成三块：

1. 顶部管理区：新建、刷新。
2. 中间筛选区：搜索、状态过滤、统计概览。
3. 任务列表区：每条任务直接提供查看、编辑、删除。

右侧任务表单改成双模式：

1. 创建模式：空白表单。
2. 编辑模式：自动载入当前任务内容。

删除动作不直接执行，而是先在侧栏显示确认条，减少误删。

### 视觉收敛

二次优化把任务管理区从偏装饰化的粉色纸面风格收敛到更克制的 SaaS 工作台风格：

1. 背景改为中性浅灰蓝，降低红粉色面积。
2. 面板阴影改为柔和投影，去掉硬边偏拼贴的视觉。
3. 任务卡片以白底、细边框和蓝色左侧激活线表达层级。
4. 删除确认保留危险色，但不再使用大面积高饱和红粉。
5. 主按钮改成深色主操作，普通操作降级为轻量边框按钮。

这样处理是为了让用户扫描任务时先看到标题、状态和材料数量，而不是先被装饰元素吸引。

### 设计取舍

本轮没有把任务做成独立页面，而是继续放在同一工作台里，因为后续分析步骤都依赖 `taskId`，分页面会增加切换成本。

也没有引入复杂的表格组件，原因是任务量不大，当前更需要的是明确入口和稳定的动作顺序，而不是重表格能力。

## 测试验证点

作者本地后端验证：

```bash
cd backend
mvn test
```

作者本地前端验证：

```bash
cd link-agent-frontend
npm run type-check
npm run build
```

联调验收：

1. 任务列表可以按名称、任务 ID 或状态搜索。
2. 每条任务可以直接进入查看、编辑和删除。
3. 编辑任务后，材料变化时任务状态会回到 `DRAFT`。
4. 删除任务后，列表中不再出现该任务。
5. 任务删除后，历史发布前建议和复盘记录不会被物理清空。

## 后续扩展

1. 可以再加任务排序切换，但目前不是刚需。
2. 可以考虑给任务加标签，但要先确认是否会影响现有分析链路。
3. 如果后续任务量继续上升，再考虑分页，而不是一开始就上复杂表格。
