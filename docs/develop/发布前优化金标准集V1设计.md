# 发布前优化金标准集 V1 设计

## 目标

本阶段建立 `PRE_PUBLISH_GOLDEN_V1`，用于评测发布前优化阶段的输出质量。

金标准集不追求唯一标准答案，因为视频创作建议本质上是开放式创意任务。它要沉淀的是可回放的输入、明确的期望能力、不可接受错误和人工评分规则，用来判断模型是否真的能帮助中小 UP 主在发布前完成选题、标题、开头、标签、风险和表达风格优化。

## 需求结论

第一版先做 36 条高质量样例，覆盖中小 UP 主最常见的发布前困境。

本阶段只做评测集设计和样例沉淀，不改发布前优化主流程，不做自动批量评测，不引入新的评测平台。

## 已落地产物

本轮已沉淀机器可读样例文件：`/docs/develop/pre_publish_golden_v1_cases.jsonl`。

该文件包含 36 条 JSONL 样例，每行对应一个发布前优化评测用例。每条样例都保留创作者困境、输入材料、目标观众、人设语境、梗和抽象表达容忍度、期望能力点、不可接受输出和人工评分规则。

配套测试类：`/backend/src/test/java/com/link/linkagent/creator/evaluation/PrePublishAgentGoldenQualityTest.java`。

该测试加载 Spring Boot 测试上下文，使用真实 `AgentExecutor`、`LLMService`、`PromptService` 调用发布前优化 Agent，并使用金标准期望点对输出质量做结构化评测。它评估的是 Agent 输出是否覆盖期望能力点、是否贴合输入材料、是否有灵感质量、是否具备 B 站网感、是否可执行、是否守住风险边界。

该测试会启动 Spring Boot 测试上下文并调用真实 LLM，默认不随普通测试执行。需要显式增加 `-Dlinkagent.golden.prepublish.enabled=true` 才会启用，避免日常单测产生模型调用成本。

可选运行参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `linkagent.golden.prepublish.caseLimit` | `36` | 从 JSONL 前部选取多少条样例 |
| `linkagent.golden.prepublish.caseIds` | 空 | 指定样例 ID，多个用英文逗号分隔 |
| `linkagent.golden.prepublish.minOverallScore` | `4` | 单条样例综合分最低要求 |
| `linkagent.golden.prepublish.minDimensionScore` | `3` | 单项维度最低要求 |

已完成的基础校验：

- 36 行全部是合法 JSON。
- 36 条样例的 `targetStage` 均为 `PRE_PUBLISH`。
- `caseId` 没有重复。
- `caseId`、`userId`、`caseName`、`targetStage`、`taskId`、`tags`、`inputSnapshot`、`expectedPoints`、`scoringRubric` 均无缺失。

## 设计原则

1. **评测创作判断，不评测固定答案。**
   同一个视频可以有多个好标题和多个好角度，所以用期望能力点和负向约束评分，而不是要求输出完全一致。

2. **优先覆盖中小 UP 主的真实痛点。**
   中小 UP 更缺的是选题灵感、表达角度、标题包装、开头留人和平台语境，不是复杂数据分析。

3. **必须纳入当代互联网语境。**
   抽象表达、梗文化、反差、自嘲、弹幕语感和 B 站人群语境会直接影响视频点击和传播。评测集必须测试模型是否有网感，而不是只会输出培训课式建议。

4. **网感不是硬套热梗。**
   金标准集不要求模型机械使用某个流行词，因为梗会过期。它测试的是模型能否判断某个内容适不适合玩梗、适合轻度还是重度抽象、梗是否服务选题和人设。

5. **保留风险边界。**
   涉及严肃科普、法律、健康、财经、争议事件时，模型不能为了网感牺牲准确性、边界感和可信度。

## 复用现有评测能力

现有 `creator_eval_case` 已支持以下字段：

- `caseName`
- `targetStage`
- `taskId`
- `inputSnapshot`
- `expectedPoints`
- `scoringRubric`

第一版直接复用这些字段。结构化内容先以 JSON 文本写入 `inputSnapshot`、`expectedPoints` 和 `scoringRubric`，避免为了评测集过早改表。

## 用例结构

每条金标准样例建议使用以下结构：

```json
{
  "caseId": "prepublish-golden-001",
  "caseName": "数码教程 - 普通功能介绍转成有点击欲的选题",
  "targetStage": "PRE_PUBLISH",
  "videoType": "数码教程",
  "creatorProblem": "作者只会罗列功能，不知道怎么包装成观众想点的视频",
  "inputMaterials": {
    "taskName": "剪映电脑版新功能介绍",
    "titleDraft": "剪映电脑版几个新功能体验",
    "descriptionDraft": "介绍自动字幕、智能抠像、音频降噪等功能",
    "manuscript": "这次更新有几个功能，我分别试了一下……",
    "creatorGoal": "希望视频更有点击欲，适合中小 UP 主和剪辑新手"
  },
  "styleContext": {
    "targetAudience": "B站 18-25 岁，熟悉工具效率类内容和轻度吐槽表达",
    "creatorPersona": "轻松吐槽型，但不低俗",
    "memeTolerance": "medium",
    "avoidStyle": [
      "中老年营销号口吻",
      "强行押韵",
      "过期网络热词",
      "和内容无关的硬蹭梗"
    ]
  },
  "expectedPoints": [
    "不能只罗列功能，要提炼成剪辑效率提升或新手少走弯路的选题角度",
    "标题建议要具体，体现适用人群和结果收益",
    "必须指出功能堆砌会导致完播率低",
    "需要给出开头 15 秒改法",
    "需要给出普通版、网感版、抽象版标题方向"
  ],
  "mustNot": [
    "不能编造官方数据",
    "不能写成夸张标题党",
    "不能只输出泛泛建议",
    "不能为了玩梗牺牲信息清晰度"
  ]
}
```

## 评分规则

现有七项评分继续保留，但评分解释调整为发布前优化语境。

| 字段 | 发布前优化语境下的评分含义 |
|---|---|
| `readabilityScore` | 建议是否清楚好懂，普通创作者能否直接理解 |
| `relevanceScore` | 是否贴合输入材料、视频类型、目标观众和创作者目标 |
| `completenessScore` | 是否覆盖标题、开头、标签、风险、修改计划等关键环节 |
| `accuracyScore` | 是否基于材料，不编造事实、数据、平台规则或不存在的热点 |
| `stabilityScore` | 同类输入下是否稳定输出有用建议，不大幅跑偏 |
| `costScore` | 输出是否克制，不靠堆长文、堆重复建议制造“看起来专业” |
| `explainabilityScore` | 是否说明为什么这样改，能否让创作者学到方法 |

`scoringRubric` 里额外写入两个人工判断项：

| 评分项 | 说明 |
|---|---|
| `inspirationQuality` | 是否给出真正能拍、能点、有差异化的视频角度 |
| `internetSense` | 是否具备 B 站语境下的网感、抽象表达和梗适配能力 |
| `actionability` | 建议是否能直接改标题、改开头、改脚本、改标签 |

这些额外评分项第一版不新增数据库字段，先写进评分说明，避免把评测系统改重。

## V1 覆盖矩阵

| 类型 | 数量 | 评测重点 |
|---|---:|---|
| 灵感枯竭 / 选题角度 | 6 | 能否从普通素材里提炼有传播价值的角度 |
| 标题包装 / 点击动机 | 6 | 能否提升点击欲，但不标题党 |
| 开头与结构优化 | 5 | 能否降低前 30 秒流失风险 |
| 专业内容大众化 | 5 | 能否把硬内容讲给普通观众 |
| 同质化赛道差异化 | 4 | 能否避免“别人都讲过”的平庸角度 |
| 风险与争议边界 | 4 | 能否识别夸大、误导、敏感表达 |
| 标签 / 简介 / 分区 | 3 | 能否做发布包装 |
| 历史反馈转下一期选题 | 3 | 能否把评论弹幕转化成新视频灵感 |

## 导入映射规则

后续如需导入现有评测系统，每条 JSONL 样例可映射到 `POST /api/creator/evaluations/cases`。

| JSONL 字段 | 评测接口字段 | 处理方式 |
|---|---|---|
| `caseName` | `caseName` | 直接写入 |
| `targetStage` | `targetStage` | 直接写入，固定为 `PRE_PUBLISH` |
| `taskId` | `taskId` | 直接写入 |
| `inputSnapshot` | `inputSnapshot` | 序列化为 JSON 字符串后写入 |
| `expectedPoints` | `expectedPoints` | 序列化为 JSON 字符串后写入 |
| `scoringRubric` | `scoringRubric` | 序列化为 JSON 字符串后写入 |

`caseId` 和 `tags` 当前用于数据集维护和人工筛选。如果后续评测表需要原样保留这些信息，可以先放入 `inputSnapshot.datasetMeta`，不要为了第一版样例提前改表。

## 首批 8 条样例草案

### 1. 数码教程：普通功能介绍转成有点击欲的选题

- 视频类型：数码教程
- 创作者困境：素材只是功能罗列，缺少观众为什么要点进来的理由。
- 输入：剪映电脑版自动字幕、智能抠像、音频降噪体验。
- 期望能力：
  - 提炼“剪辑效率提升”“新手少走弯路”等角度。
  - 给出普通版、网感版、抽象版标题。
  - 指出功能堆砌会影响完播。
  - 给出开头 15 秒改法。
- 不可接受：
  - 编造官方数据。
  - 只说“标题要吸引人”。
  - 强行使用和工具内容无关的热梗。

### 2. 游戏内容：高光剪辑缺少差异化

- 视频类型：游戏实况 / 游戏剪辑
- 创作者困境：素材有操作高光，但同类视频太多。
- 输入：一局逆风翻盘，包含几次极限操作和队友语音。
- 期望能力：
  - 找到反差、角色、局势转折或弹幕可参与的包装角度。
  - 能判断是否适合重度抽象标题。
  - 给出标题、开头、封面文案建议。
- 不可接受：
  - 只写“逆风翻盘太燃了”。
  - 使用过度泛化的游戏营销话术。
  - 把操作结果夸大成不存在的段位或战绩。

### 3. 知识科普：专业内容太硬，普通观众看不懂

- 视频类型：知识科普
- 创作者困境：内容正确但表达像课堂，缺少进入门槛低的引子。
- 输入：解释大模型幻觉、上下文窗口和 RAG。
- 期望能力：
  - 用生活化类比降低理解成本。
  - 设计前 30 秒问题钩子。
  - 保留概念准确性。
  - 判断梗表达只能轻度使用。
- 不可接受：
  - 为了网感扭曲概念。
  - 编造技术结论。
  - 输出过度学术化标题。

### 4. 生活 Vlog：日常素材普通，缺少故事线

- 视频类型：生活 Vlog
- 创作者困境：素材真实但平，像流水账。
- 输入：周末整理房间、做饭、剪视频、夜跑。
- 期望能力：
  - 提炼情绪主线，例如自救、恢复能量、普通人的秩序感。
  - 给出不矫情的标题和简介。
  - 给出结构调整建议。
  - 判断是否适合轻度自嘲表达。
- 不可接受：
  - 强行升华到宏大价值。
  - 写成小红书鸡汤。
  - 标题和内容情绪不一致。

### 5. 职场经验：观点容易变成说教

- 视频类型：职场 / 经验分享
- 创作者困境：想讲新人沟通问题，但容易像上级训话。
- 输入：新人汇报工作总是说不到重点。
- 期望能力：
  - 从观众痛点切入，而不是居高临下。
  - 给出可执行沟通模板。
  - 标题要有代入感。
  - 识别“爹味说教”风险。
- 不可接受：
  - 输出职场成功学空话。
  - 鼓励 PUA 式表达。
  - 用过度冒犯的梗攻击新人。

### 6. 影视动漫：同类解读过多，需要新角度

- 视频类型：影视动漫解读
- 创作者困境：热门作品已经很多人讲，担心重复。
- 输入：想做某角色成长线解读。
- 期望能力：
  - 找到细分角度，例如误解、反差、情绪共鸣或二创语境。
  - 给出有弹幕讨论空间的问题式开头。
  - 标题要能区分普通剧情复述。
- 不可接受：
  - 只复述剧情。
  - 编造原作不存在的设定。
  - 用和作品调性冲突的梗。

### 7. 风险边界：热点事件评论容易失真

- 视频类型：热点评论 / 观点表达
- 创作者困境：想蹭热点但不想翻车。
- 输入：围绕争议事件做观点视频，材料只有公开视频和网友讨论。
- 期望能力：
  - 明确区分事实、推测和观点。
  - 给出克制标题。
  - 建议补充来源或降低断言。
  - 判断不适合重度抽象和攻击性梗。
- 不可接受：
  - 编造事实。
  - 鼓励站队辱骂。
  - 用“震惊”“实锤”等高风险词制造误导。

### 8. 历史反馈转下一期：评论区有分歧

- 视频类型：系列内容规划
- 创作者困境：上一期评论有人夸实用，有人嫌太浅，不知道下一期怎么做。
- 输入：评论样例包含“讲得清楚”“太基础”“想看进阶案例”“节奏有点快”。
- 期望能力：
  - 把评论分成受众层次和内容期待。
  - 给出下一期选题方向。
  - 给出标题和开头建议。
  - 保留新手友好，同时安排进阶内容。
- 不可接受：
  - 只总结评论情绪。
  - 忽略分歧。
  - 把所有观众都当成同一种需求。

## 后续推进步骤

1. 先用 `PrePublishAgentGoldenQualityTest` 小样本运行 1 到 3 条样例，确认发布前优化 Agent 的输出质量和评测裁判口径。
2. 小样本稳定后扩大到 36 条完整样例。
3. 人工复核测试失败项，重点标记“无灵感”“网感僵硬”“标题党”“泛泛建议”“风险边界丢失”等失败类型。
4. 根据失败回放调整 Prompt、发布前工作流和必要的上下文输入。
5. 第二轮复测时保留同一批金标准样例，用前后得分变化判断优化是否真实有效。
