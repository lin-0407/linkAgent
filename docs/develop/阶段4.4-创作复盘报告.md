# 阶段 4.4：创作复盘报告

## 需求分析

本阶段服务的目标用户仍然是 B 站 UP 主、内容创作者和内容运营者。

要解决的场景是：单看本视频的稿件、标题建议和评论弹幕，只能做内部复盘，很难判断“优点”和“短板”是否真的成立。真实的视频复盘需要同类型视频作为参照，所以本阶段补充竞品分析，再把发布前优化、评论弹幕分析和竞品分析汇总成完整复盘报告。

输入数据来源：

1. 已保存的创作任务材料。
2. 已保存的发布前优化建议。
3. 已保存的评论弹幕分析报告。
4. 用户主动整理的竞品视频信息。
5. 已保存的竞品分析报告。
6. 用户补充的复盘重点或额外要求。

本阶段只做：

1. 保存用户主动整理的竞品视频信息。
2. 基于本视频材料和竞品视频生成竞品分析报告。
3. 基于发布前建议、评论弹幕分析、竞品分析生成结构化复盘报告。
4. 将竞品分析和复盘报告保存到 MySQL。
5. 支持按 `taskId` 查询竞品视频、竞品分析和复盘报告。
6. 将竞品分析完成后的任务状态更新为 `COMPETITOR_ANALYZED`，复盘完成后更新为 `ANALYZED`。

本阶段不做：

1. 自动抓取同类型视频。
2. 自动校验竞品视频播放量、互动率等平台指标。
3. 复盘报告导出为 PDF 或 Markdown。
4. 复盘报告版本管理。
5. 多人协作批注。

## 设计方案

### 后端包结构

新增业务包：

```text
com.link.linkagent.creator.competitor
```

这个包只负责竞品视频信息和竞品分析，不直接生成最终复盘报告。

继续使用业务包：

```text
com.link.linkagent.creator.report
```

这个包只负责复盘报告汇总，不和任务输入、发布前建议、评论弹幕分析混在一起。

### 数据表

新增 `creator_competitor_sample`：

```text
保存用户主动整理的竞品视频信息。
```

新增 `creator_competitor_report`：

```text
保存本视频相对同类型视频的优势、短板、差距和差异化建议。
```

修改 `creator_report`：

```text
新增 competitor_comparison 字段，保存最终复盘里的竞品对照结论。
```

### API

```text
POST /api/creator/tasks/{taskId}/competitors
GET  /api/creator/tasks/{taskId}/competitors
POST /api/creator/tasks/{taskId}/competitors/analyze
GET  /api/creator/tasks/{taskId}/competitors/report
POST /api/creator/tasks/{taskId}/report/analyze
GET  /api/creator/tasks/{taskId}/report
```

### 入参校验

所有对外接口继续使用 Jakarta Validation：

1. `taskId` 长度不能超过 64。
2. `competitorBvId` 必填，必须是 B 站 BV 号。
3. `competitorVideoName` 必填，最长 200。
4. `competitorSamples` 不能为空，最长 20000。
5. `category` 最长 128。
6. `compareDimension` 和 `extraContext` 最长 500。
7. `customGuidance` 最长 2000。
8. `analysisFocus`、`reviewFocus`、`extraRequirement` 最长 500。

### 是否涉及 Agent

本阶段内部仍然先用同步 LLM 调用完成结构化分析，不直接升级为复杂多 Agent。

原因：

1. 当前阶段要先验证“竞品视频 -> 竞品分析 -> 复盘报告 -> 数据库存档”闭环。
2. 竞品分析的核心是结构化对照，不需要一开始就引入复杂规划器。
3. 后续 SSE 工作流融合可以复用竞品分析结果，不应该把所有复杂度压进 4.4。

## 接口示例

### 保存竞品视频

```http
POST /api/creator/tasks/{taskId}/competitors
Content-Type: application/json

{
  "competitorBvId": "BV1xK4y1a7Bc",
  "competitorVideoName": "竞品视频A",
  "category": "AI 工具教程",
  "competitorSamples": "竞品A：标题突出收益，评论说节奏快。竞品B：封面和标题都强调结果。",
  "compareDimension": "标题、节奏、卖点表达、评论反馈",
  "extraContext": "人工挑选的竞品参考信息"
}
```

### 分析竞品视频

```http
POST /api/creator/tasks/{taskId}/competitors/analyze
Content-Type: application/json

{
  "analysisFocus": "重点对比标题吸引力和内容节奏",
  "extraRequirement": "给出本视频短板"
}
```

### 生成复盘报告

```http
POST /api/creator/tasks/{taskId}/report/analyze
Content-Type: application/json

{
  "customGuidance": "请重点看标题和观众反馈是否一致",
  "reviewFocus": "更关注下一期该怎么调整表达",
  "extraRequirement": "总结尽量短一点"
}
```

## 测试验证点

正常路径：

1. 保存竞品视频后，应能查询到 BV 号、视频名称和分析文本。
2. 竞品视频存在时执行分析，应生成竞品分析报告。
3. 竞品分析完成后，任务状态应更新为 `COMPETITOR_ANALYZED`。
4. 任务存在且已有发布前优化建议、评论弹幕分析报告、竞品分析报告时，应能生成复盘报告。
5. 复盘报告中应包含竞品对照结论。
6. 复盘完成后，任务状态应更新为 `ANALYZED`。

边界路径：

1. 任务不存在时返回 404。
2. 竞品 BV 号为空或格式不对时，参数校验应失败。
3. 竞品视频名称为空时，参数校验应失败。
4. 没有竞品视频时，竞品分析接口返回 400。
5. 没有发布前优化建议时，复盘接口返回 400。
6. 没有评论弹幕分析报告时，复盘接口返回 400。
7. 没有竞品分析报告时，复盘接口返回 400。
8. LLM 输出不是 JSON 时，仍应保存原文并标记为 `RAW_ONLY`。

作者本地验证命令：

```bash
mvn test
```
