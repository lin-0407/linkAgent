# S3c：固定工程后台执行与恢复

日期：2026-10-20。延续 [S3b 产物保存与版本注册](视频自动制作-S3b产物保存与版本注册.md)，实现持久化固定工程从排队到实际渲染、存储和版本登记的后台执行。整体 S3 尚未完成；实际验证见 [记录](../error/固定工程后台执行S3c验证记录.md)。

本轮 322 项回归通过，含 78 项真实隔离 MySQL；Spring 定时调度实际执行 84.167 秒中文工程，完成私有存储登记与同版恢复。实际取消测试观察 Python/FFmpeg 两个进程退出，没有上传或登记成片。未部署，未调用真实付费供应商。

## 本步解决的问题

S3b 已有运行、租约、渲染桥接和产物登记，但需要开发者逐项调用。现在后台可以领取明确冻结的工程，维持租约、执行真实渲染和私有存储登记；执行器退出后依据数据库恢复，旧执行者不能继续采纳结果。

输入仍为后端准备的 RenderInputV1 固定工程，以及已有真实发布方案确认和专属 AI_GENERATION 制作计划。未增加公开启动或文件路径接口，`executionAvailable=false` 保持原语义；没有接入自然语言生成、素材导入页面或付费调用。

## 实现与数据

统一 `init.sql` 新增 `creator_creation_fixed_job`，按 runId 保存任务/归属、源尝试目录 ID 和冻结工程 JSON。源路径由部署配置与可信 ID 拼接，工程只保存相对资产路径和摘要，不保存对象存储或模型密钥。

- `FixedProjectJobFiles.freeze` 在事务外有界读取真实源工程，检查路径、UTF-8、身份和完整输入摘要。
- `FixedProjectJobPersistenceService.attach` 锁任务后核对排队状态、整片授权、故事板/内容摘要及真实制作依据，再保存输入。同一运行同一输入幂等，不覆盖已冻结工程。
- `FixedProjectJobMapper.candidates` 仅返回已附加工程、仍为当前活动运行且可领取的候选；文本、准备和未附加工程的运行不被消费。
- `FixedProjectWorker` 通过已有原子领取及递增代数取得执行权，一个本地执行槽承担媒体工作，独立线程续租。Spring 定时任务只扫描，不占住全局调度线程等待渲染。

当前内部接入顺序是：受理 FULL → 准备该运行的源工程 → freeze/attach → 后台领取。运行受理与工程附加仍为两个明确步骤；未附加输入不会被后台执行，调用方应使用幂等键恢复准备，不能宣称公开制作受理已成为一个完整原子操作。

## 执行与恢复规则

1. 领取时先处理已请求取消的运行，不读取素材或发起存储调用。
2. 已有登记版本时直接恢复事实，不要求原本地目录存在，不重新上传或分配视频版本。
3. 未登记时复核制作依据与基准版本；在独立尝试目录复制资产，逐个核对实际摘要。资产数量、大小和总量沿用 S2 的 64 个、单个 32MiB、合计 256MiB 边界。
4. 新尝试重写运行身份并计算完整输入摘要，保持授权所用内容摘要不变，再调用现有 Python/FFmpeg 渲染和 S3b 保存服务。
5. 默认租约 30 秒、心跳 5 秒，数据库时钟决定是否仍持有执行权。断库、失租或取消会停止本次渲染；失租后不强写 FAILED、CANCELLED 或新版本。
6. 正常关闭停止本执行器线程和其媒体子进程，保留可被租约接管的运行；关闭本身不等于用户取消。
7. 默认允许至多三次未登记的执行领取；超过后不再渲染，记 ATTEMPTS_EXHAUSTED。已有登记事实仍可恢复，不因恢复次数较多而再渲染或失败。
8. 登记成功后等待依赖，dependencyId 指向精确视频版本；状态为 WAITING_DEPENDENCY，不是 FULL 完成。

准备和渲染均发生在数据库事务外。复制后的资产和输出与旧尝试隔离；修改源文件不能改变已复制输入，源摘要不匹配时明确失败。

## 当前完成边界

本步接通到 UPLOADED 版本登记。自动蓝图尚未接入，当前仍须满足已有真实制作计划及步骤门禁，不自动勾选用户步骤。自动原片探测、预处理、完整试映、费用上下文和发布包还需继续连接。

源工程/资产必须在重启后仍存在的专用工作卷中；数据库保存工程元数据不代表保存了所有原始资产。未登记且本地资产丢失时返回错误，不能假装恢复。登记后恢复可以不依赖原目录。

未登记尝试的部分上传对象已有清单可追溯，但统一回收、磁盘保留策略与运行清理尚待收尾；不能把已有正式版本删除能力写成所有失败残留都已回收。
