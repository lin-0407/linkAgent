# linkAgent 前端体验提升方案

> 本文档从原 `linkagent-improvement-plan.md` 拆分而来，聚焦前端交互与视觉。后端支撑方案见 `linkAgent-backend-improvement-plan.md`。

## 当前前端问题

linkAgent 前端有很好的底层基础设施（SSE 状态机、设计令牌系统），但上层体验有三块短板：

| 问题 | 现状 | 用户感受 |
|------|------|---------|
| 单页面巨石 | 所有功能挤在 `HomePage.vue` + `CreatorWorkspace.vue` | 找不到功能入口，来回滚屏 |
| 思考过程不可见 | `ReactTimeline` 只是折叠的原始文本 | "它到底想了什么？可信吗？" |
| 建议展示太简陋 | 标题列表 + 纯文本 | "看着像 API 返回值，不像产品" |
| 只有桌面端 | 无移动适配 | 不能在手机上快速查看分析结果 |
| 无后端状态感知 | 不知道 LLM 服务是否正常 | 出错才知道，等半天白屏 |

---

## 方案一：拆巨石 — Tab 式工作台

### 目标

把 `CreatorWorkspace.vue` 拆成有明确导航的页面结构，用户不用滚动找功能。

### 改造方案

```
├──────────┬───────────────────────────────────────────┤
│          │                                           │
│ 左侧任务  │  右侧内容区（Tab 切换）                      │

│ 任务 A ● │  │ 字幕 / 文稿 / 标题草稿 / 简介草稿    │     │
│ 任务 B   │  └──────────────────────────────────┘     │
│ 任务 C   │                                           │
│          │  ┌─ 发布前优化 ───────────────────────┐    │

│          │                                           │
```

### 不需要路由，用状态驱动

```typescript
// stores/workbenchStore.ts — 替代单文件组件的 reactive()
export const useWorkbenchStore = defineStore('workbench', () => {
  const activeTaskId = ref<string | null>(null)
  const activeTab = ref<'materials' | 'pre-publish' | 'feedback' | 'report'>('materials')
  const tasks = ref<CreatorTask[]>([])

  // 选中任务变化 → 自动加载对应数据
  watch(activeTaskId, (id) => {
    if (id) loadTaskDetail(id)
  })

  return { activeTaskId, activeTab, tasks }
})
```

### 组件拆分

```
components/creator/
  TaskListPanel.vue        ← 左侧列表（当前从 Workspace 抽出来）
  MaterialsTab.vue         ← 材料管理
  PrePublishTab.vue        ← 发布前分析（含策略选择 + 建议卡片）
  FeedbackTab.vue          ← 评论复盘
  ReportTab.vue            ← 复盘报告
  SuggestionCard.vue       ← 可复用的建议卡片（标题/标签/简介通用）
  AnalysisProgress.vue     ← Agent 思考过程时间轴（替代 ReactTimeline）
```

### 用户感知

| 之前 | 之后 |
|------|------|
| 一页上下滚屏找功能 | 左侧选任务，右侧切 Tab，两步到位 |
| 所有任务的信息混在一个大组件 | 每个 Tab 独立，职责清晰 |
| 不知道系统是否正常 | 底部状态栏一目了然 |

## 方案二：Agent 思考过程时间轴

### 目标

把 `ReactTimeline` 从"技术调试面板"升级为"用户可理解的分析进度"。

### 后端依赖

依赖后端 SSE 事件协议中的 `userLabel` / `userDetail` 字段（详见后端方案二）。前端只负责消费标准化事件，不关心 Agent 内部逻辑。

### 当前 vs 改造后

**当前 ReactTimeline（技术视角）：**
```
第 1 步
思考: 需要先提取字幕中的关键词
Action: extractKeywords(字幕内容)
观察: keywordExtractor:["智能家居", "小米生态链"...]
```

**改造后 AnalysisProgress（用户视角）：**
```
┌────────────────────────────────────────────┐
│  分析进度                          [收起]  │
│                                            │
│  ✓ 读取材料                   < 1s        │
│  ├─ 字幕 1,200 字                          │
│  └─ 文稿 800 字                            │
│                                            │
│  ✓ 提取内容要点               2.3s         │
│  └─ 识别到 3 个核心论点                     │
│    · 智能家居趋势                           │
│    · 小米生态链竞争                         │
│    · 用户隐私关注                           │
│                                            │
│  ● 搜索同类视频标题模式       运行中...     │
│  └─ 正在从知识库检索参考案例                │
│                                            │
│  ○ 生成建议                    等待中       │
│  ○ 风格匹配与风险评估          等待中       │
└────────────────────────────────────────────┘
```

### 实现

直接复用现有 `useWorkflowSSE` 的事件流，前端只需要把事件渲染成时间轴：

```typescript
// 后端推送的事件格式（由后端方案二定义）
interface WorkflowStepEvent {
  type: 'step_started' | 'step_completed' | 'step_failed'
  stepId: string
  userLabel: string        // "提取内容要点"
  userDetail?: string      // "识别到 3 个核心论点"
  toolName?: string        // "extractKeywords"
  durationMs?: number      // 2300
}

// 前端只做渲染，不解析业务含义
const steps = ref<TimeLineStep[]>([])

handlers.onStepStarted = (event) => {
  steps.value.push({ status: 'running', ...event })
}
handlers.onStepCompleted = (event) => {
  const step = steps.value.find(s => s.stepId === event.stepId)
  if (step) step.status = 'done'
}
```

时间轴组件用 CSS 动画做进度条和图标过渡，不需要复杂的状态管理。

### 用户感知

| 之前 | 之后 |
|------|------|
| 等待 30 秒，不知道在干什么 | 每步实时显示，知道进度 |
| 出错只能看 console | 哪一步失败了直接标红 |
| 建议没有溯源 | 每个建议可以追溯到哪一步分析得出 |

### 组件设计

`SuggestionCard.vue` 是纯展示 + 事件发射的组件，标题建议、标签建议、简介建议都可以复用，只换 `suggestion.type` 和样式颜色：

```vue
<script setup lang="ts">
const props = defineProps<{
  suggestion: CreatorSuggestion
  rank: number          // 1, 2, 3 用于 ⭐ 标记
  feedbackEnabled: boolean
}>()

const emit = defineEmits<{
  accept: [suggestion: CreatorSuggestion]
  copy: [suggestion: CreatorSuggestion]
  reject: [suggestion: CreatorSuggestion, reason: string]
  tweak: [suggestion: CreatorSuggestion]
}>()

const showRejectPanel = ref(false)

```

反馈提交后调用后端事件记录 API（后端方案五），写入 `creator_event` 表。

## 方案四：运行时状态栏

### 目标

让用户随时知道系统健康状态，不用等到请求失败才发现问题。

### 改造

底部固定状态栏，三个指示灯 + 简要信息：

```
┌──────────────────────────────────────────────────────────────────┐
│  🟢 LLM: DeepSeek  │  🟢 Milvus: 在线  │  🟢 本月: 127次 / ¥3.42 │
└──────────────────────────────────────────────────────────────────┘
```

- **绿色**：服务正常，显示最近一次调用耗时
- **黄色**：有限流/降级，显示原因（"DeepSeek 被限流，已切换到 OpenAI"）
- **红色**：不可用，显示错误（"LLM Key 已过期，请在设置中更新"）

### 实现

后端 `/api/settings/status` 已有，每 30 秒轮询一次，或者复用 SSE 长连接推送：

```typescript
// composables/useSystemStatus.ts
export function useSystemStatus() {
  const llmStatus = ref<'online' | 'degraded' | 'offline'>('online')
  const llmProvider = ref('')
  const monthlyUsage = ref({ calls: 0, cost: 0 })

  // 复用已有 SSE 连接，监听 health 事件
  // 或每 30s 轮询 /api/settings/status
}
```

### 用户感知

| 之前 | 之后 |
|------|------|
| 发起分析 → 等 10 秒 → 报错 | 发起前看到红灯，知道要修 |
| 不知道花了多少钱 | 底部随时显示本月用量 |
| 切换了模型也不知道 | 当前 provider 一目了然 |

## 方案五：移动端 Web

### 目标

让创作者可以在手机上快速查看分析结果、复制标题和标签。

### 改造

不需要重写前端。在 `frontend/` 下加一个 `src/mobile/` 目录，复用同一套 API + composables：

```
frontend/src/mobile/
  MobileApp.vue           ← 入口，底部 Tab 导航
  views/
    TasksView.vue          ← 任务列表
    TaskDetailView.vue     ← 建议卡片 + 复制
    ReportView.vue         ← 报告预览
```

移动端只做**查看 + 复制 + 反馈**，不做复杂编辑。Vite 配置多入口构建：

```typescript
// vite.config.ts
build: {
  rollupOptions: {
    input: {
      main: 'index.html',
      mobile: 'mobile.html',
    }
  }
}
```

访问 `http://localhost:8088/m/` 进入移动端。后端 Nginx 把 `/m/` 路由到移动端入口。

### 用户感知

| 之前 | 之后 |
|------|------|
| 只能电脑操作 | 手机查看分析结果、复制标题 |
| 发布视频时来回切屏 | 手机打开工作台，对照着填 |

## 前端优先级排序

| 优先级 | 改动 | 工作量 | 依赖后端 | 用户感知提升 |
|--------|------|--------|---------|------------|
| **P0** | 拆巨石 — Tab 工作台 | 3 天 | 无 | 导航清晰，不再迷路 |
| **P0** | 建议卡片 + 即时反馈 | 2 天 | 反馈 API（后端方案五） | 从"看文本"到"操作卡片" |
| **P1** | Agent 思考过程时间轴 | 2 天 | SSE 事件协议（后端方案二） | 信任感 + 可观测 |
| **P1** | 运行时状态栏 | 0.5 天 | `/api/settings/status` 已有 | 不用盲等 |
| **P2** | 移动端 Web | 3 天 | 无（复用 API） | 多场景使用 |

P0 两个改动加起来 5 天，前端体验脱胎换骨。

```
第 1 周（P0）
  ├─ Tab 式工作台布局 + 组件拆分

第 2 周（P1）
  ├─ AnalysisProgress 时间轴组件（对接 SSE 事件）
  └─ 运行时状态栏组件

第 3 周（P2）
  └─ 移动端 Web（独立入口 + 查看/复制/反馈）
```
