# 视频素材导入与样片导出补充方案

日期：2026-10-20。关联 [总体方案](面向新手与小UP的视频自动制作与修改方案.md)。

作者要求补齐样片导出、图片/音频/视频片段导入，使创作者可以使用自己的素材完成作品。本文件扩展首发产品范围；下面的交互、格式白名单和数据契约是具体设计建议，尚未编码、部署或验收。当前已实现边界仍以 S2、S3a、S3b、S3c 阶段记录和源码为准。

## 1. 用户最终能完成什么

新增交付目标是：**上传自己的素材 → 按场景安排内容 → 试看短样片 → 制作整片 → 修改指定场景 → 导出投稿文件**。

| 场景 | 用户提供 | 平台完成 | 用户拿到 |
| --- | --- | --- | --- |
| 录屏讲解 | 操作录屏、要点、可选口播 | 选取片段、安排讲解、配字幕和轻量包装 | 可投稿的演示视频与字幕 |
| 照片配音 | 多张图片、文稿或录好的声音 | 图片排序、适配画幅、配音/录音、字幕和音乐 | 图文成片、封面和投稿材料 |
| 原声片段组合 | 多段实拍/录屏、有对白的片段、可选 BGM | 截取和排序、保留选定原声、补充说明画面、字幕与混音 | 使用自有素材的新视频版本 |

三种场景使用同一套任务、素材、场景和视频版本体系。独立生成标题/简介、原有整条成片上传试映、人工发布/BV/反馈/复盘继续保留。

首发提供场景列表、素材选择和简单截取，不建设无限轨道时间线、专业调色、人物抠像、任意视频特效或自动搬运素材。

## 2. 明确新增范围

| 能力 | 补充后的交付要求 |
| --- | --- |
| 短样片 | 从已确认故事板选择一段，生成约 10–15 秒可播放 MP4，支持独立下载 |
| 图片 | 上传、预览、排序、指定场景、替换；支持适配画幅和有限平移/缩放 |
| 配音 | 用户录音可直接作为旁白；也可使用已配置 TTS，按场景选择来源 |
| 背景音乐 | 上传音乐，选择截取范围、音量、淡入淡出和旁白期间压低音乐 |
| 视频片段 | 上传、探测、截取、排序、选择原声处理方式，组合进新成片 |
| 局部修改 | 换图、换录音、换片段、改截取范围、改顺序、改字幕、改 BGM；生成新版 |
| 导出 | 样片 MP4、制作预览 MP4、SRT、封面；完整试映后的精确版本发布 ZIP |

“导入视频片段”和“上传完整成片”是两个入口。前者产生素材和可编辑场景；后者直接产生待试映的视频版本。把完整 MP4 上传成功不能算作片段导入完成。

## 3. 用户操作流程

### 3.1 新建与准备

1. 新建任务，输入主题、文稿或现有视频制作需求，选择目标时长。
2. 在素材区上传图片、录音、音乐或视频片段；显示上传进度、真实时长/尺寸、探测状态和可用原因。
3. 系统读取 READY 素材形成候选场景；用户也可手动选择素材和顺序。模型建议的片段要能定位到素材的真实时间范围。
4. 通过真实发布方向确认，查看故事板与制作提案；本次制作授权明确包含素材用途、时长、声音方案和费用上限。

上传文件本身不代表授权 ASR、生图或 TTS。需要调用收费服务时，先在相应准备/制作确认中说明并计入现有任务预算。

### 3.2 场景卡片

每张卡片只显示创作者需要的选项：场景缩略图、顺序、画面素材、开始/结束位置、旁白或原声、字幕和预计时长。

- 图片：选择图片、完整显示或裁切铺满；裁切时可预览位置。
- 视频：在播放器里选入点/出点，预览所选片段；显示源时长与选中时长。
- 声音：显式选择“生成配音 / 使用我的录音 / 使用片段原声 / 无对白”。
- 有配音时，片段音轨可选择静音或作为环境声保留；不自动把两路人声叠在一起。
- 全片设置一个 BGM，提供音量、截取和旁白压低开关。首发不开放任意数量的音乐轨。

完整显示画面作为建议默认值；保留原声、裁切铺满、重复片段、定格补时和音乐循环均应让用户可见并明确选择。具体音量数值作为经实测的模板参数，不让用户理解滤镜命令。

### 3.3 试看与完成

确认后可选“先看短样片”或“直接制作整片”。样片不是强制额外审批。样片页展示所取场景、实际时长、声音来源和未完成事项，提供播放、下载、修改和继续整片入口。

修改后的故事板保存为新修订。只更新受影响素材和字幕，再生成新 MP4；旧视频、报告和发布包保持原归属。

## 4. 素材接入与处理规则

以下是首发格式建议，实施时通过部署中的实际解码能力验证；不能仅看扩展名通过。

| 类型 | 建议接受范围 | 进入制作前的处理 |
| --- | --- | --- |
| 图片 | PNG、JPEG | 解码、方向修正、尺寸/大小校验、缩略图；适配输出画幅 |
| 录音/音乐 | WAV、MP3、M4A/AAC 常见音频 | 真实探测、解码，生成受控 PCM 工作音轨；记录原始与规范化元数据 |
| 视频片段 | MP4、MOV 中已验证可解码的 H.264/HEVC 与常见音轨 | 探测方向、时长、时间基准、画幅和音轨；按部署支持范围生成规范化工作素材 |
| 字幕 | UTF-8 SRT | 校验 cue 顺序、时长范围和文本；不执行样式脚本或读取外部资源 |

首发成片沿用当前渲染器的 16:9、720p/1080p、受控帧率和 H.264/AAC 设计，不代表用户入口已经部署。竖屏源可以导入并在横屏画幅中完整显示或由用户选择裁切；竖屏成片输出另行验收。

HDR、特殊编码、多音轨、异常时间戳和不支持的媒体先明确返回原因及可行转换建议。不能丢掉原声、静默改变颜色或选错音轨后声称素材已正确导入。

### 4.1 上传、探测与存储

- 复用现有 ObjectStorageService、分片存储能力和私有读取签名；小图片可使用既有设计的 Java 转存路径，较大音视频使用可恢复分片上传。
- 素材上传会话关联 assetId，不创建 DraftVideo、不占完整视频版本号、不切换当前成片。现有成片分片上传服务包含视频版本业务，不能直接当作通用素材接口使用。
- 持久化会话、分片、校验指纹和失败信息，刷新可恢复。同键不同实际文件拒绝；不能只按文件名判断重复。
- 实际文件大小、完整性、可解码性和探测结果通过后才进入 READY；PREPARING、FAILED、DELETED 素材不能进入已确认工程。
- 原始素材保留独立身份；转码、截取、混音和缩略图是派生资产，不能覆盖原文件。
- 文件大小、媒体总时长、解码尺寸和本地磁盘需要按部署给出运行前检查。素材上传限制与现有完整成片上传限制分开，不在本次方案里偷偷修改原上传上限。

### 4.2 截取与时间线

视频、录音和音乐使用 `sourceInMs/sourceOutMs`，区间为左闭右开。必须满足 `0 <= in < out <= 实测源时长`，并校验对应解码范围可用。

首发按正常速度使用片段。变速、倒放或自动循环另行提案，不能为满足总时长偷偷加速人声、截掉句尾或重复画面。

可变帧率、旋转元数据和非零起始时间要在素材准备阶段规范化；剪切采用真实时间基准，最终按输出帧率量化，验收画面范围和总时长在约定帧级容差内。不能用“按关键帧复制成功”代替精确截取验证。

建议提供“固定总时长”和“按内容自适应”两个明确选择。固定时长不能容纳语音/片段时，给出删减、改稿或延长的具体提案。素材不足时提供缩短场景、补图、重复或定格选项，用户选择后才执行。默认 60–90 秒只是建议，不替代用户指定值和当前渲染器实际边界。

### 4.3 声音和字幕

- 使用用户录音的场景不再生成同段 TTS；换图、换 BGM、放大字幕不能重复购买不变旁白。
- 保留片段原声时，声音随同一源截取范围同步处理；替换配音时记录原声静音或环境声方案。
- 采用一个主对白来源，加可选环境声和全片 BGM 的受控混音；记录音量和淡入淡出。对白期间压低 BGM，检查输出峰值、削波、静音和完整音轨。
- TTS 字幕基于实际生成音频；用户录音和片段对白可使用经校验的 SRT 或已授权 ASR 结果。ASR 缺失、失败或时间证据不足时明确展示待处理，不能把按字数估算当成准确字幕。
- 整条录音分配到多个场景需要用户提供范围或确认候选切分；不能把整段录音简单复制给每个场景。
- 片段内已有烧录字幕不会被自动擦除。预览时提示与新增字幕可能重叠，允许关闭新增字幕或调整样式；开启的字幕仍需真实时间范围和内容依据。
- 无对白或明确关闭新增字幕的场景不强制伪造字幕；V2 清单需记录字幕不适用及原因。整片无对白、无音乐时，是否保留静音 AAC 轨由受控输出配置决定，本地检查按已选声音方案验收。

## 5. 样片与导出是正式业务对象

### 5.1 SAMPLE 的边界

样片对应一个 SAMPLE 运行和产物资产，绑定不可变故事板、场景范围、声音方案、渲染配置及输入摘要。通常生成约 10–15 秒、720p 的 MP4；目标段落较短时展示真实时长，不填充成虚假试片。

优先选择完整旁白和真实场景边界，不直接截断句子。指定片段无法在建议长度内形成完整预览时，展示可选场景或拆分提案。

样片完成条件为：真实编码、整片解码、声音/字幕范围和存储内容校验通过。它不占完整视频版本序号，不切换当前成片，不满足正式发布门禁，不代替整片试映。界面、文件名和 sample-manifest 都明确标记样片。

### 5.2 从样片继续整片

确认和预算上限分别绑定其实际范围；只授权样片不能自动开始整片。用户已明确授权直接整片时，也不能强制他先做样片。

素材探测、源文件、录音、适用的 TTS 和字幕证据可以按准确内容摘要复用。720p 样片编码与 1080p 整片编码不同，需要重新编码的部分如实执行，不能把样片视频文件冒充整片缓存。

### 5.3 四种下载

| 下载内容 | 条件与标识 |
| --- | --- |
| 样片 MP4 | SAMPLE 产物完整且可用；明确“样片”，不要求完整视频版本 |
| 制作预览 MP4 | 完整视频文件已保存并通过本地检查；标记试映进度与检查未完成事项 |
| SRT / 封面 | 归属所选样片或具体视频版本；显示实际对应对象 |
| 投稿发布 ZIP | 精确视频版本、完整媒体处理/试映及发布包齐全；包含 MP4、字幕、封面、文案、来源和清单 |

下载通过后端校验后的短时私有地址；过期后可刷新，不能暴露永久公开链接。重复下载不重做 TTS、ASR 或视频。只有需要新打包时才创建相应的零新增供应商费用 PACKAGE 运行，仍记录真实存储相关事实和预算边界。

导出和用户实际发布分开。下载预览或 ZIP 都不会自动写已发布、BV 或真实观众反馈。

## 6. 数据、API 与渲染契约补充

以下为设计契约，实施时复核实际表和接口，统一维护 init.sql；本轮不创建空表或新接口。

### 6.1 数据引用

沿用总体方案的 `creator_creation_asset`，补齐实际类型 IMAGE、NARRATION、MUSIC、VIDEO_CLIP、SUBTITLE 及原始/规范化媒体元数据。素材会话、派生关系和缓存关联 assetId；复用分片协议实现，按需要增加素材会话持久化，不能混入成片上传会话。

故事板场景引用 `visual.assetId`、源截取范围、fit/crop、音频模式、旁白资产和字幕来源；全片引用可选音乐及截取、音量、淡入淡出和压低配置。用户输入的是受校验数据，不是 URL、本地路径或命令。

同一素材可被多个场景和历史版本引用，引用关系必须可查询。素材从当前素材区移除与实际删除文件分开；物理删除前说明受影响工程和重制能力，不静默破坏历史引用。最终 MP4 删除责任仍由视频版本媒体管理统一承担。

### 6.2 建议接口职责

| 接口范围 | 必要职责 |
| --- | --- |
| `/assets` 与素材上传会话 | 创建/完成/取消/恢复上传；素材列表、探测状态和失败原因 |
| `/assets/{assetId}:read-url` | 按用途预览或下载，检查归属、对象可用性和短签期限 |
| 场景编辑与修改提案 | 选择素材、截取、声音、字幕和顺序；验证工程/工作区预期版本 |
| `/runs` 的 SAMPLE / FULL / REVISION | 独立授权、有限预算、真实持久化调度与精确产物关联 |
| `/release-packages` 与产物下载 | 区分样片/预览/正式包，冻结准确版本和清单，幂等打包 |

对外请求使用现有 Jakarta Validation；上传内容还需真实格式、探测和业务校验。具体路径以总体接口表及实际开发评审为准，不把本表写成已上线 API。

### 6.3 RenderInputV2

当前严格的 RenderInputV1 仅支持图片和 PCM WAV，不直接塞入未定义视频/BGM 字段。新增版本化契约，扩展受控视频画面、源区间、音轨模式和音乐混音，保持一个 Python/FFmpeg 渲染引擎和共享校验/编码实现；旧工程继续按原契约读取。

Java 校验资产 READY 和摘要，下载并准备本地规范化媒体，再生成确定性渲染输入。renderer 保持离线，不读取数据库或 OSS/模型密钥，不接受任意 FFmpeg 命令。视频帧解码与图片绘制都采用有界处理，不能把多个完整片段全部放入内存。

输入、产物清单、缓存键和本地验收同步升级并覆盖契约测试。相同字幕文字由屏幕和 SRT 共用；素材范围、声音方案、分辨率或渲染器变化都进入失效判断。

## 7. 局部修改与版本规则

补充 `SET_CLIP_RANGE`、`SET_SCENE_AUDIO`、`SET_MUSIC`、`SET_VISUAL_FIT` 等受限修改，与现有换素材、改顺序、换旁白和字幕样式操作配合。字段、目标场景和可用资产均校验，不接受任意 JSON 路径。

| 修改 | 应重做 | 应保留 |
| --- | --- | --- |
| 单场景换图 | 该画面、新全片编码及必要封面 | 未变的旁白、其他素材和历史视频 |
| 换原声视频片段 | 对应画面/原声音轨、相关字幕与时间线 | 未涉及的场景录音和素材 |
| 换配音录音 | 对应字幕、音轨和必要的时间安排 | 原图及未变旁白 |
| 换 BGM / 音量 | 混音与输出编码 | 旁白资产、字幕内容和时间依据 |
| 调整顺序 | 全局时间线、字幕偏移和合成 | 可以复用的场景局部资产 |

操作产生新的故事板修订和视频版本。AI 分析的是新视频对应的内容；旧报告保留原时间点。已发布或绑定 BV 的任务仍按现有边界新建修订任务，不直接替换已发布作品。

## 8. 交付顺序与验收门槛

保持已有阶段，不把 S3b 写成这些新功能已完成。补充实现按依赖推进：

1. **S3 收尾**：持久化 worker、自动蓝图、精确媒体子任务、完整试映、发布包及费用上下文。
2. **S4 素材/工程**：素材上传与探测、用户音频/视频准备、RenderInputV2、真实字幕来源和受控混音；再接模型生成与 TTS，素材可复用。
3. **S5 用户闭环**：素材区、场景卡片、截取播放器、声音选择、样片播放/下载和整片/发布包导出。样片和导出必须列为验收项，不能只交后台命令。
4. **S6 修改闭环**：指定场景改素材/声音/范围、版本对比和缓存/费用复用，回归原上传覆盖入口。
5. **S7–S8 实用验收**：三类真实制作场景、资源约束、失败恢复、正式包一致性和用户体验。

| 编号 | 验收案例 | 必须观察到 |
| --- | --- | --- |
| M01 | 图片、WAV/MP3、MP4/MOV 正常导入 | 实际可解码、元数据准确、刷新后素材仍在，文件类型名不能代替行为 |
