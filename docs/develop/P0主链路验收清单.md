# P0 主链路验收清单

## 目标

本清单用于验收 LinkAgent 是否已经形成面向 B 站内容创作者的最小可用闭环。
它只覆盖 P0 主链路，不评价高级 RAG、Multi Agent、竞品分析等扩展能力。

验收结论必须回答一个问题：UP 主能不能从一个创作想法出发，完成发布前优化、绑定已发布视频、查看复盘结论，并把偏好沉淀到下一次创作中。

## 验收范围

本轮只验收以下主链路：

1. 创意输入
2. AI 生成 3 个创意方案
3. 用户选择创意方向
4. 发布前优化 AI 交互台
5. 发布方案确认
6. BV 号与 B 站 UID 绑定
7. 视频分析页展示已绑定视频
8. 评论弹幕样例分析与复盘报告
9. 创作者偏好沉淀

暂不验收：

- 自动投稿。
- 批量或定时采集 B 站数据。
- 平台推荐算法模拟。
- 高级知识库 RAG 精排效果。
- 多用户权限体系。

## 主链路检查表

| 步骤 | 用户动作 | 预期输出 | 后端接口或模块 | 前端入口 | 数据落点 | 必验失败态 |
|---|---|---|---|---|---|---|
| 1. 创意输入 | 输入创作想法、视频类型和背景资料 | 创建创作任务与交互会话 | `CreatorInteractiveController` / `CreatorInteractiveService` | 创作工作台 AI 创意入口 | `creator_task`、`creator_interactive_session` | 想法为空、长度不足、文件过大 |
| 2. 生成方案 | 点击生成创意方案 | 返回 3 个结构化创意卡片 | `CreatorInteractiveService` | 创意方案卡片区 | `creator_idea_option` | LLM 调用失败、JSON 解析失败、只保存原文兜底 |
| 3. 选择方向 | 选择一个创意卡片 | 标记已选方案并进入发布前优化 | `confirmCreativeOption` 相关链路 | 创意卡片确认按钮 | `creator_idea_option.selected`、`creator_material` | optionId 不存在、重复确认 |

## 契约验收点

### API 入参

- 所有对外 JSON 请求体必须使用 Jakarta Validation 校验。
- 所有路径变量中的 `taskId`、`sessionId`、`optionId`、`userId` 必须限制长度。
- BV 号、UID 等平台标识必须做格式校验。
- 文件上传必须同时校验文件大小、文件名和可解析文本长度。

### SSE 事件

- 工作流启动后，前端必须能收到连接成功事件。
- 分析过程中必须能看到步骤状态变化。
- LLM 失败时必须返回可展示的失败事件，而不是让前端一直等待。
- 浏览器刷新后，前端必须能重新拉取历史消息和步骤。

### LLM 输出

- 创意卡片、发布前建议、反馈复盘报告必须保存原始输出。
- 结构化解析失败时必须保存 `RAW_ONLY` 或对应失败状态。
- 前端展示必须能处理部分字段为空的情况。
- 失败回放必须能定位到模型、场景、任务和工作流步骤。

### 数据库

- `backend/src/main/resources/sql/init.sql` 必须能在空库初始化。
- 已有库升级时，兼容补丁不能重复报错。
- 新增字段必须有中文 `COMMENT`。
- 种子提示词更新必须使用幂等写法，避免重复插入。

### 前端状态

- 切换任务后，工作台展示的材料、建议、工作流消息必须属于当前任务。
- SSE 断开后，页面不能残留“永远分析中”的状态。
- 用户刷新页面后，选中的任务和阶段恢复不能覆盖服务端真实状态。
- 本地 `localStorage` 只保存界面偏好和轻量状态，不保存模型密钥或大量素材。

## 作者手动验收建议

开发者不能执行编译、测试、构建、运行或启动命令。
需要作者在本机执行以下验证，并反馈结果。

### 后端

```bash
cd backend
mvn test
```

预期结果：

- 单元测试通过。
- 如果失败，优先查看失败用例是否与 LLM Mock、Redis Testcontainers 或数据库初始化有关。

### 前端

```bash
cd frontend
npm run type-check
npm run build
```

预期结果：

- TypeScript 类型检查通过。
- Vite 构建成功。
- 如果失败，优先检查 API 类型定义、组件 props、Pinia store 字段是否与后端 DTO 不一致。

### 演示环境

```bash
docker compose up -d --build
docker compose logs -f backend
docker compose logs -f frontend
```

预期结果：

- MySQL、Redis、后端和前端容器健康启动。
- 访问 `http://localhost:8088` 能进入工作台。
- 没有配置 `LLM_API_KEY` 时，页面仍能展示基础样例或可控失败提示。
