# 阶段 3.6：MCP 客户端接入配置骨架

## 上下文

阶段 3.5 已经完成 Spring AI `ToolCallback` 到项目内部 `Tool` 的适配。Spring AI 1.1.4 的 MCP 客户端自动配置已经提供了 `SyncMcpToolCallbackProvider` 和 `AsyncMcpToolCallbackProvider`，这意味着项目只要把客户端配置和 `ToolRegistry` 接起来，就能把外部 MCP Server 暴露的工具统一纳入工具池。

本轮不连接真实 MCP Server，只补最小配置骨架和接入说明，避免把服务端配置、协议调试和业务工具混在同一轮里。

## 本轮目标

把 MCP 客户端接入路径固定下来，让后续只需要补服务器地址和连接参数，就能直接让外部 MCP 工具进入 `ToolRegistry`。

## 本轮变更

- 说明 Spring AI 1.1.4 已内置 MCP 客户端自动配置：
  - `McpClientAutoConfiguration`
  - `McpToolCallbackAutoConfiguration`
  - `SyncMcpToolCallbackProvider`
- 说明项目当前已具备接入前提：
  - `spring-ai-starter-mcp-client`
  - `ToolCallbackProvider -> ToolRegistry -> ToolExecutor`
- 补充接入骨架思路：
  - 通过 Spring Boot 配置声明 MCP Server
  - 由 Spring AI 自动生成 `ToolCallbackProvider`
  - 再由 `ToolRegistry` 统一注册为内部 `Tool`

## 设计说明

这一轮不写死具体 MCP Server 配置，是因为当前项目还没有明确要接哪个外部服务。MCP 的价值在于“把外部能力标准化暴露给 Agent”，而不是先把某个 server 的配置写死在代码里。先把自动配置链路确认清楚，等接入真实 server 时再落配置更稳。

## 验证方式

本轮没有新增运行态代码，建议作者后续在接真实 MCP Server 时再执行：

```bash
cd backend
mvn test
```
