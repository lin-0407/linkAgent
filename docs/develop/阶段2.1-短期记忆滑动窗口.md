# 阶段 2.1：短期记忆滑动窗口

## 上下文

阶段 1 已经完成 ReAct 最小闭环，但每次 `/api/agent/chat` 调用都是孤立的。阶段 2 的完整目标包含短期记忆、摘要记忆、长期记忆和向量检索；本轮只做最小可验证的短期记忆，不引入 Redis / MySQL 写入链路。

目标：同一个 `sessionId` 下，Agent 能在下一轮调用时看到最近几轮 Human / AI 对话。

---

## 本轮变更

- 新增 `memory/MemoryMessage.java`：表示一条短期记忆消息。
- 新增 `memory/ShortTermMemory.java`：进程内滑动窗口记忆，按 `sessionId` 保存最近 10 条消息。
- 修改 `AgentChatRequest`：新增可选 `sessionId`，最大长度 64。
- 修改 `AgentChatResponse`：返回最终使用的 `sessionId`，便于前端继续传入。
- 修改 `AgentController`：把 `sessionId` 传入 `AgentExecutor`。
- 修改 `AgentExecutor`：调用 LLM 前拼接最近对话；成功得到 `Final Answer` 后写入 Human / AI 两条记忆。
- 新增 `ShortTermMemoryTest`：验证写入顺序和滑动窗口淘汰。

---

## 关键设计

### 1. 先用进程内 Map

当前实现：

```java
Map<String, Deque<MemoryMessage>>
```

这是阶段 2 的最小实现，用于验证会话语义和 prompt 拼接方式。它的限制也很明确：

- 应用重启后记忆丢失。
- 多实例部署时不同实例之间不共享。
- 不适合生产环境。

后续进入 Redis 短期记忆时，可以保留 `ShortTermMemory` 的调用入口，只替换内部存储。

### 2. 滑动窗口按消息数裁剪

本轮使用 `MAX_MESSAGES_PER_SESSION = 10`，每次追加后超过上限就从队头删除最旧消息。

这里暂不做 token 级裁剪，因为 token 估算和摘要触发策略属于阶段 2 的关键学习点，后续应由作者亲手实现。

### 3. Prompt 拼接位置

`AgentExecutor` 在当前 Human 输入前拼接：

```text
Recent conversation:
Human:...
AI:...

Human:当前问题
```

这样 LLM 可以先看到上下文，再处理当前问题。当前仍然保持经典 ReAct 文本格式，不引入 Spring AI 原生 memory。

## 验证方式

### 单元测试

由作者在本地执行：

```bash
cd backend
mvn test -Dtest=ShortTermMemoryTest
```

### 接口验证

第一次请求不传 `sessionId`，响应会返回一个新的 `sessionId`：

```bash
curl -X POST http://localhost:8080/api/agent/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"我叫 Link，记住这个名字"}'
```

第二次请求带上返回的 `sessionId`：

```bash
curl -X POST http://localhost:8080/api/agent/chat \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"上一步返回的sessionId","message":"我叫什么？"}'
```

预期：模型能参考最近对话回答用户名字。
