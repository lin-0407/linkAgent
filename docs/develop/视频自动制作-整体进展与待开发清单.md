# 视频自动制作：整体进展与待开发清单

更新时间：2026-10-20。实现核对基线：`feature/creator-workspace-s1`，提交 `1cb6a7cf19ab3b8b1493a95eda446d370f238e69`，已推送。

本任务包括面向新手与小 UP 的视频自动制作、素材导入与样片导出、可选 AI 视频生成，以及局部修改。本文汇总当前状态和后续交付条件；详细业务规则仍以 [总体方案](面向新手与小UP的视频自动制作与修改方案.md)、[素材与样片补充方案](视频素材导入与样片导出补充方案.md)、[AI 视频生成补充方案](AI视频生成制作方式补充方案.md) 为准。

本次只整理文档并静态核对实现，没有重新执行测试或增加业务功能。测试数字引用最近一次实际回归，不把历史各轮数字相加。

## 1. 当前结论

**S3e 已完成，完整 S3 尚未完成；S4a 的视频片段合成基础也已完成，完整 S4 尚未完成。**

当前已经能从准备好的结构化工程，真实生成视频，并由后台完成保存、版本登记和原片探测。尚不能在产品页面从一句想法或用户素材自动完成样片、整片、局部修改和正式包导出。

当前内部链路：

```text
真实发布方案确认 + 制作授权 + 已准备的冻结工程
    → 后台领取、心跳、取消及恢复
    → Python/FFmpeg 实际渲染
    → 私有存储与八对象内容校验
    → 自动蓝图按真实产物完成步骤
    → 登记独立视频版本
    → 自动 FFprobe，保存原片实际元信息
    → READY_FOR_REVIEW
    → FULL 等待该精确版本的完整媒体依赖
```

`READY_FOR_REVIEW` 只表示原片已可进入试映。完整制作运行仍为 `WAITING_DEPENDENCY`，不能写成完整试映通过或整次制作完成。

运行快照仍返回 `executionAvailable=false`、`budgetScope=CREATION_RUNTIME_ONLY`。内部 worker 已存在；公开启动/重试入口、新手制作页面和完整任务总预算尚未开放或闭环。本轮成果未部署，浏览器全链路与真实视频模型未验收。

另一个 agent 正在优化前端，相关未提交改动独立保留。页面优化的存在不代表自动制作交互已交付。

| 导入图片、录音、视频片段 | renderer 已能使用准备好的本地可信图片/音频/视频资产 | 独立素材上传会话、持久化、真实探测/规范化、私有预览、故事板引用与页面 |

| 样片制作及下载 | 已有真实整片渲染和产物保存基础 | SAMPLE 的独立授权、范围、调度、标识、播放/下载及继续整片复用；通常 10–15 秒仅为设计目标 |
| 成片与正式包导出 | MP4、SRT、封面与清单能够实际生成和保存 | 区分样片/制作预览/正式包的用户入口、精确版本打包、文案与来源清单、短签刷新 |
| AI 视频生成方式 | 镜头混用、全片快捷选择的业务方向已确认；生成片段可复用现有 VIDEO_CLIP 基础 | 用户模型配置、能力查询、异步任务、费用、结果持久化与真实模型验收；已有枚举不代表已接生视频模型 |
| 修改指定片段 | 目前只有可供后续复用的片段合成与版本基础 | 真正的修改提案和执行、精确影响范围、未变资产复用及新版本；不能宣传已能自然语言局部改片 |
| 独立选题/标题/简介 | 既有发布方案和助手能力可复用 | 与新制作运行一致的独立入口及恢复，不因只改标题就启动整片 |
| 总预算控制 | 已有授权、费用预留、已知/未知费用和结算基础 | 现有媒体/试映及后续生成调用全面归并；当前不是所有任务入口的严格总账 |

局部修改的目标是只重新生成受影响的素材、配音或 AI 镜头，再合成为新视频。最终 MP4 仍可能整片重新编码；不应把“修改一个镜头”承诺成“输出文件只编码那几秒”。

## 4. S3 剩余的三块工作

以下编号用于后续拆任务，不表示这些工作已经实现，也不预先固定新的 API、Schema 或子阶段名称。

### S3-1 自动媒体处理与完整试映

目的：让已经生成的准确视频，自动进入原媒体链路，并能可靠等待、恢复和收尾。

- 在系统原片探测后接入已有预处理、完整试映服务，保存精确的运行、视频版本、处理任务及试映任务关系。
- 活动 FULL 不能被普通人工入口抢占；内部受理需核对该运行授权、版本、执行代数及租约，不全局放宽现有冲突门禁。
- 等待依赖期间保留活动运行；重启、重复扫描和恢复不重复创建媒体任务或重复付费。
- 跟踪成功、失败、待用户处理和取消；不能把旧版/旧代结果用于当前制作，也不能自动替用户确认试映问题。
- 外部调用在事务外执行；真实试映调用前接相应费用授权与预留。S3-1 与 S3-3 需配套，未接费用时只能验证无付费的部分。

完成条件：真实固定工程由后台进入预处理与完整试映，准确关联子任务；刷新/重启/取消不乱版、不重复付费。若没有执行真实供应商试映，只能报告本地或协议验证，不能标记整条链路已通过。

接入位置：`FixedProjectWorker`、`CreationRuntimeService`、`MediaProcessingService`、`PreflightReviewService` 及相关持久化/测试。既有媒体处理与试映能力已经存在，本项主要补自动制作的协调与受控接入。

### S3-2 最小发布包与完整运行收尾

目的：让运行最终交付用户能够定位、下载和自行投稿的结果。

- 精确冻结本次视频版本、字幕、封面、投稿文案、来源和清单，生成最小真实发布包。
- 打包可幂等恢复；重复查询/下载不重做视频或模型任务。制作预览和正式发布包显示各自真实条件。
- 仅当规定的媒体处理、试映和发布包条件真实满足后，FULL 才进入 COMPLETED 并正确释放活动位置。
- 导出不写成已发布；实际投稿、BV 绑定、观众反馈和复盘仍按原流程进行。

完成条件：同一精确版本的媒体、试映、文案和包一致；缺失或失败明确拒绝；恢复不重复生成版本或产物。最小发布包属于 S3，不能全部推迟到 S7。

### S3-3 媒体调用费用接入

目的：将 S1 的记账基础接到真正收费的消费者上。

- 将当前媒体处理、ASR、视频理解、观众试映等实际调用接入制作授权、预留、发送标记、日志归并与结算。
- 区分已知、预留和未知费用；响应丢失、取消、失租与迟到结算不得漏账或重复扣记。
- 取消不能承诺供应商退款；无法核实的调用保留 UNKNOWN，不能按零费用释放后盲目重试。
- 保持任务限额与本次授权范围；后续 S4 的生成/TTS 接入复用同一规则，不把预算初始化当成消费授权。

完成条件：一次真实媒体/试映链路的物理调用、运行和费用可相互核对；重复结果不叠加；取消或响应不明仍有真实账务依据。S1 的费用基础测试不能代替本项消费者验收。

| S6-2 | 依赖失效与资产复用 | 仅重做受影响的资产/配音/生成镜头；未变资产摘要和费用可复查；时间线、字幕及混音随真实变化重建 | S6-1、资产与调用缓存 |
| S6-3 | 新版本与对比 | 修改产生新故事板和视频版本；旧片/旧报告保留；并发冲突明确；已发布/BV 任务遵守现有限制 | 版本基础、修改执行、试映与发布包 |
| S7-1 | 试映可信度收口 | 事实、模型观察、假想观众分开；无关证据不自动补位；确认问题及片段复核依据准确；不是伪造真实观众反馈 | 自动试映接入和对应媒体证据 |
| S7-2 | 发布包、兼容及资源回收 | 原上传/已有成片、V1/V2、删除、选版、BV/复盘不回退；检查失败未登记对象和历史素材引用的清理，包与版本始终一致 | 各条制作和修改路径 |
| S8-1 | 三类实际制作与浏览器验收 | 录屏讲解、照片配音、原声片段组合，在页面完成上传→场景→样片→整片→修改→导出，并核对文件和持久化事实 | S3–S7 |
| S8-2 | 真实新手、投稿与复盘验证 | 记录独立完成、中断、实际费用和失败；用户实际投稿后再验 BV、反馈、复盘；无真实数据的部分保持未验证 | 可用部署、用户与实际作品 |

AI 配置入口和共用功能不等待作者先选具体模型。后续需要实现一个经过实际核对的兼容协议；不能承诺任意服务地址填入后都可用。真正供应商输出与费用必须单独验收，模拟异步任务不算生视频交付。

样片是推荐路径，继续保留直接整片；“全片采用 AI”只改变画面来源提案，不自动改变用户选择的声音，也不等于一次请求生成任意长度整片。只授权样片不能自动扩成整片付费范围。

## 6. 后续顺序与完成门槛

建议继续按依赖推进，不并行启动所有阶段：

1. 先实现 S3-1，并在收费调用前接 S3-3；再完成 S3-2，收尾固定工程业务链路。
2. 继续 S4 的素材/故事板/声音服务及 AI 配置接入，共用能力无需等具体模型选型。
3. 接 S5 页面与样片、下载、公开受理和恢复；与当前前端优化 agent 明确文件归属后再改页面。
4. 完成 S6 修改与资产复用，再做 S7 可信度/兼容收口和 S8 实际用户验收。
