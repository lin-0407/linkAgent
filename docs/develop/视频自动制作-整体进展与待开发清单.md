## 1. 当前结论

**S3 的本地闭环与复查修复已交付，真实供应商试映、账单和部署验收仍未通过。S4a、S4-1、S4-2、S4-3a 与 S4-3b 后端已实现，完整 S4 尚未完成。**

当前已经能从准备好的结构化工程，真实生成视频，并由后台自动完成保存、版本登记、原片探测、媒体预处理、完整试映协调和最小发布包，最后在包通过对象校验时结束整片运行。尚不能在产品页面从一句想法或用户素材自动完成样片、整片、局部修改和正式投稿。

当前内部链路：

```text
用户真实简报/任务材料 + 已准备素材
    → 独立费用估算 → 明确准备授权 → PREPARE 模型候选
    → 保存不可变故事板/来源/素材摘要 → 检查缺素材、配音或时长问题
    → 仅对 TTS 场景：估算/授权 → 配音合成 → 私有音频复核与 READY 登记
                      → 实际音频转写 → 文稿核对 → 保存 ASR_ALIGNED 新故事板
    → 可制作工程编译（配音或 AI_VIDEO 未准备时不得假装完成）

真实发布方案确认 + 制作授权 + 已准备的冻结工程
    → 后台领取、心跳、取消及恢复
    → Python/FFmpeg 实际渲染
    → 私有存储与八对象内容校验
    → 自动蓝图按真实产物完成步骤
    → 登记独立视频版本
    → 自动 FFprobe，保存原片实际元信息
    → 内部受理媒体预处理（精确 jobId，重启只恢复不重建）
    → 内部受理完整试映（精确 reviewId，人工入口门禁未放宽）
    → 打包发布包并 HEAD 校验（video/srt/封面/帧/清单 + 投稿文案）
    → FULL → COMPLETED 并释放活动位置
```

`COMPLETED` 表示该精确版本已完成预处理、完整试映和最小发布包；**不代表已投稿、已发布或试映问题已被作者确认**。包清单固定写入 `published=false`。

运行快照仍返回 `executionAvailable=false`、`budgetScope=CREATION_RUNTIME_ONLY`。公开启动/重试入口、新手制作页面和完整任务总预算尚未开放或闭环。本轮成果未部署，真实视频模型与真实供应商试映未验收。

另一个 agent 正在优化前端，相关未提交改动独立保留；本轮没有修改前端。页面优化的存在不代表自动制作交互已交付。

## 4. S3 三块工作的实现与验证（本轮完成）

### S3-1 自动媒体处理与完整试映

目的：让已经生成的准确视频，自动进入原媒体链路，并能可靠等待、恢复和收尾。

本轮结果：已实现。`FixedProjectWorker` 在探测通过后把运行交给 `CreationMediaService`（闭环记录与等待依赖同事务），`CreationMediaWorker` 按 `creator_creation_media_link` 的阶段推进：内部受理预处理 → 等 job COMPLETED → 内部受理完整试映 → 等 review COMPLETED。内部受理走 `InternalMediaAcceptance`，核对活动运行、活租约、整片授权与 `REGISTERED` 版本；人工入口的“有活动运行即拒绝”保持原样。预处理或试映失败时运行留在活动位置（`stage=MEDIA_BLOCKED`）并要求作者处理，不自动继续付费。

- 在系统原片探测后接入已有预处理、完整试映服务，保存精确的运行、视频版本、处理任务及试映任务关系。
- 活动 FULL 不能被普通人工入口抢占；内部受理需核对该运行授权、版本、执行代数及租约，不全局放宽现有冲突门禁。
- 等待依赖期间保留活动运行；重启、重复扫描和恢复不重复创建媒体任务或重复付费。
- 跟踪成功、失败、待用户处理和取消；不能把旧版/旧代结果用于当前制作，也不能自动替用户确认试映问题。
- 外部调用在事务外执行；真实试映调用前接相应费用授权与预留。S3-1 与 S3-3 需配套，未接费用时只能验证无付费的部分。

完成条件：真实固定工程由后台进入预处理与完整试映，准确关联子任务；刷新/重启/取消不乱版、不重复付费。若没有执行真实供应商试映，只能报告本地或协议验证，不能标记整条链路已通过。

本轮验证：真实隔离 MySQL 下验证了闭环登记、同一运行重复受理只有一条记录、旧租约被拒绝、其他版本不能冒充、失败保留运行；调度器单测验证子任务不重复创建、取消先停试映再确认。真实供应商试映未执行，因此本项按“代码完成、真实供应商未验收”记录。

接入位置：`FixedProjectWorker`、`CreationMediaService`、`CreationMediaWorker`、`CreationRuntimeService`、`MediaProcessingService`、`PreflightReviewService` 及相关持久化/测试。既有媒体处理与试映能力已经存在，本项只补自动制作的协调与受控接入。

### S3-2 最小发布包与完整运行收尾

目的：让运行最终交付用户能够定位、下载和自行投稿的结果。

本轮结果：已实现。`CreationPackageService` 只打包登记清单里的八个对象，逐个校验字节数与 SHA-256，追加 `publishing.md`（候选标题、简介、目标观众、核心信息、成片事实、试映摘要、来源标识）与 `package-manifest.json`（版本/运行/尝试标识、逐文件摘要、试映问题数、`published=false`）。上传后 `HeadObject` 字节数必须等于本地包大小才登记 READY；已 READY 的包不再重建。`CreationRuntimeService.completeProduction` 只认与闭环版本一致的 READY 包，随后 FULL 进入 COMPLETED 并释放活动位置。

- 精确冻结本次视频版本、字幕、封面、投稿文案、来源和清单，生成最小真实发布包。
- 打包可幂等恢复；重复查询/下载不重做视频或模型任务。制作预览和正式发布包显示各自真实条件。
- 仅当规定的媒体处理、试映和发布包条件真实满足后，FULL 才进入 COMPLETED 并正确释放活动位置。
- 导出不写成已发布；实际投稿、BV 绑定、观众反馈和复盘仍按原流程进行。

完成条件：同一精确版本的媒体、试映、文案和包一致；缺失或失败明确拒绝；恢复不重复生成版本或产物。最小发布包属于 S3，不能全部推迟到 S7。

本轮验证：发布包单测真实生成 ZIP，断言 10 个条目、文案与清单内容；篡改任一产物后明确拒绝且不上传；包对象大小与本地不一致时拒绝登记；无包或包未 READY 时 `completeProduction` 拒绝结束运行。真实隔离 MySQL 验证了闭环版本与包版本一致性约束。

### S3-3 媒体调用费用接入

目的：将 S1 的记账基础接到真正收费的消费者上。

本轮结果：已实现。新增 `MediaCallChargeGate` 窄接口与 `CreationMediaBilling` 实现，把 ASR、全片视频理解、重点片段复核、观众试映四类真实调用接到 `creator_creation_cost_entry`：发送前预留、发送前 `markSent`、拿到用量后按美元单价结算，缺失用量记 UNKNOWN；同一调用标识只允许发送一次。台账按人民币记账，美元按配置折算率换算，折算率与美元上界写入价格快照。人工试映没有运行归属，闸门为空实现。

- 将当前媒体处理、ASR、视频理解、观众试映等实际调用接入制作授权、预留、发送标记、日志归并与结算。
- 区分已知、预留和未知费用；响应丢失、取消、失租与迟到结算不得漏账或重复扣记。
- 取消不能承诺供应商退款；无法核实的调用保留 UNKNOWN，不能按零费用释放后盲目重试。
- 保持任务限额与本次授权范围；后续 S4 的生成/TTS 接入复用同一规则，不把预算初始化当成消费授权。

完成条件：一次真实媒体/试映链路的物理调用、运行和费用可相互核对；重复结果不叠加；取消或响应不明仍有真实账务依据。S1 的费用基础测试不能代替本项消费者验收。

本轮验证：真实隔离 MySQL 验证了依赖阶段的预留、重复预留幂等、金额不一致被拒绝、发送标记只生效一次、结算后预算从预留转为已知费用；单测验证美元换算与折算率快照、缺失实付记 UNKNOWN、人工试映不记账。真实供应商账单未核对，`UNKNOWN` 暂停新增付费调用的规则未在生产流量中验证。
