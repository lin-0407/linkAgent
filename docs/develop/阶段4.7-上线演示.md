# 阶段 4.7 - 上线演示

## 需求分析

阶段 4.6 已经把评测样例和失败回放补齐，但项目还缺一个真正能给面试官看的演示环境。本阶段只解决“能一键起起来、能看到首页、能连到后端、能带着初始化数据跑”的问题，不去做公网部署、HTTPS、CI/CD 或多环境编排。

本轮做：

1. 把后端容器化。
2. 把前端打包成静态站点并交给 Nginx 托管。
3. 用 Docker Compose 串起 MySQL、Redis、后端和前端。
4. 让初始化 SQL 自动注入可直接展示的演示数据。
5. 补一份面向作者的根目录 README。

本轮不做：

1. 不做域名和证书。
2. 不做云服务器脚本。
3. 不做 CI/CD。
4. 不做额外的部署平台适配。

说明：如果 `LLM_API_KEY` 为空，容器仍然可以启动，但只能验证页面、数据库、Redis 和反向代理的连通性，不能算完整的创作分析演示。

## 设计方案

### 部署拓扑

```text
浏览器
  -> 前端 Nginx
  -> 后端 Spring Boot
  -> MySQL / Redis
```

### 关键文件

```text
docker-compose.yml
backend/Dockerfile
backend/.dockerignore
link-agent-frontend/Dockerfile
link-agent-frontend/.dockerignore
link-agent-frontend/deploy/nginx/default.conf
README.md
```

### 设计原因

1. 前端和后端分开打镜像，演示时更接近真实部署。
2. 前端容器直接代理 `/api`，浏览器同源访问更省事。
3. MySQL 启动时挂载 `init.sql`，可以直接带出评测样例和工作台演示数据。
4. Compose 只保留一个对外入口，避免用户在演示时来回切端口。
5. 演示库名固定为 `link_agent`，因为初始化脚本本身会创建并切换到这个库，继续暴露可变库名会制造配置分叉。

## 编码实现

### 后端容器

后端镜像使用多阶段构建：

1. 第一阶段用 Maven 编译。
2. 第二阶段只保留 JRE。
3. 运行时通过环境变量注入数据库、Redis 和 LLM 配置。

### 前端容器

前端镜像先执行 `npm ci` 和 `npm run build`，再用 Nginx 承载静态文件。
Nginx 同时负责：

1. SPA 路由兜底。
2. `/api` 反向代理。
3. SSE 流式输出的 buffering 关闭。

### Compose 编排

Compose 服务包括：

1. `mysql`
2. `redis`
3. `backend`
4. `frontend`

其中 `frontend` 容器对外暴露 `8088`，作为演示入口。

## 测试验证

这轮由作者本地执行以下命令验证：

```bash
cd linkAgent
docker compose up -d --build
```

判断标准：

1. `http://localhost:8088` 可以打开首页。
2. 前端请求 `/api` 能到后端。
3. MySQL 首次启动后能看到 `init.sql` 的演示数据。
4. 任务列表默认能看到发布前、反馈分析、完整复盘三类样例任务。
5. 打开最新的完整复盘样例时，可以看到已确认的发布前工作流、评论弹幕仪表盘和评测结果样例。
6. SSE 页面能继续看到流式过程，而不是被 Nginx 缓冲住。
