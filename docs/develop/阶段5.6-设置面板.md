# 阶段 5.6 - 设置面板

> 承接路线：内核结构化输出（5.4） → 提示词 DB 热更（5.5） → **设置面板（5.6）** → 回 5.3b 发布前优化 Agent 化。
>
> 本阶段定位：把运行期开关、启动期配置状态、基础设施连通性检测、知识库索引运维集中进一个全局设置弹窗。设置面板服务开发者 / 运维者 / 演示者，不改变创作者主流程。

---

## 一、需求分析

### 1. 背景与痛点

- 前端目前只有两个顶层 surface：创作工作台和案例库。设置能力不应该作为第三个工作台出现。
- 案例库里混放了 4 个索引运维面板，日常查看案例时信息层级过重。
- 后端已有多组功能开关，但前端看不到“现在到底开了什么”。
- 部分开关适合运行期动态调整，例如 LLM 成本保护、摘要记忆、rerank、反馈追问 RAG。
- 部分开关不适合运行期调整，因为它们决定 Spring 启动时创建哪个 Bean，运行期改值不会自动重装配。
- 排查问题时还需要知道 Redis、MySQL、Milvus、Embedding、ChatModel 是否可用。

### 2. 目标用户

- 项目作者本人。
- 本地演示和排查时需要快速确认系统状态的人。

### 3. 本阶段做什么

1. 新增全局设置入口，固定放在页面左上角。
2. 新增居中设置弹窗，使用 `Teleport to="body"`，不打断当前工作台。
3. 新增 5 个可写动态开关：
   - `agent.llm.guard.enabled`
   - `agent.memory.summary.enabled`
   - `agent.kernel.structured.enabled`
   - `knowledge.rag.rerank.enabled`
   - `creator.feedback.rag.enabled`
4. 保留 3 个启动期配置为只读状态：
   - `knowledge.rag.enabled`
   - `knowledge.rag.hybrid.enabled`
   - `agent.memory.short-term.store-type`
5. 新增连通性检测按钮，按需检测 MySQL、Redis、知识库向量库、hybrid 向量库、Embedding Bean、ChatModel Bean。
6. 把案例库里的 4 个索引运维面板迁入设置弹窗。
7. 案例库页面不保留索引入口。

### 4. 本阶段不做什么

- 不做 `knowledge.rag.enabled` 动态切换，因为它影响 `KnowledgeSearchTool` 是否创建。
- 不做 `knowledge.rag.hybrid.enabled` 动态切换，因为 hybrid 客户端和集合连接在启动期初始化。
- 不做 `agent.memory.short-term.store-type` 动态切换，因为 `memory / redis` 是启动期 Bean 二选一。
- 不做真实 LLM 调用或 Embedding 试算作为连通性检测，避免设置页本身产生模型成本。
- 不引入 router、Pinia 或新的 UI 组件库。

## 二、技术设计

### 2.1 后端模块

新增设置模块：

| 类 / 文件 | 职责 |
|---|---|
| `RuntimeSettingMapper` | MyBatis 注解式访问运行期设置表 |
| `RuntimeSettingRecord` | 运行期设置表映射对象 |
| `RuntimeSettingKey` | 服务端白名单，限定哪些 key 允许动态修改 |
| `RuntimeSettingService` | 聚合配置默认值、DB 覆盖值、动态写入 |
| `SettingsConnectivityService` | 执行轻量连通性检测 |
| `SettingsController` | 暴露设置状态、动态开关修改、连通性检测 API |

为什么要建表：动态开关如果只存在内存里，后端重启后会丢。写入 MySQL 后，下一次启动仍能读到上次设置，符合设置面板的直觉。

表里只保存用户在设置面板改过的覆盖值。没有覆盖值时，后端继续使用 `application.yml` 或环境变量里的默认值，避免初始化脚本把真实部署配置改掉。

### 2.2 数据库表

数据库 Schema 仍维护在 `backend/src/main/resources/sql/init.sql`。

```sql
CREATE TABLE IF NOT EXISTS app_runtime_setting
(
    id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY COMMENT '主键',
    setting_key   VARCHAR(128) NOT NULL COMMENT '设置键，只允许服务端白名单内的运行期开关',
    setting_value VARCHAR(64)  NOT NULL COMMENT '设置值，布尔开关统一保存 true 或 false',
    description   VARCHAR(255) NOT NULL COMMENT '中文说明，帮助后续维护者理解这个开关影响什么能力',
    create_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    is_deleted    TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除：0=正常，1=已删除',
    UNIQUE KEY uk_runtime_setting_key (setting_key)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COMMENT = '运行期设置表';
```

动态开关的默认值来自当前配置：

| key | 默认值 |
|---|---|
| `agent.llm.guard.enabled` | `true` |
| `agent.memory.summary.enabled` | `false` |
| `agent.kernel.structured.enabled` | `true` |
| `knowledge.rag.rerank.enabled` | `false` |
| `creator.feedback.rag.enabled` | `false` |

### 2.3 API 设计

#### 查询设置状态

```http
GET /api/settings/status
```

返回：

```json
{
  "dynamicToggles": [
    {
      "key": "agent.llm.guard.enabled",
      "name": "LLM 成本保护",
      "enabled": true,
      "description": "限制单次模型输入规模，避免演示环境成本失控"
    }
  ],
  "readonlySettings": [
    {
      "key": "knowledge.rag.enabled",
      "name": "知识库 RAG 主开关",
      "value": "false",
      "description": "启动期装配开关，修改配置后需重启"
    }
  ]
}
```

#### 修改动态开关

```http
PUT /api/settings/toggles/{settingKey}
Content-Type: application/json

{
  "enabled": true
}
```

校验规则：

- `enabled` 必填。
- `settingKey` 必须是服务端白名单中的 4 个 key。
- 不允许前端传未知 key。

#### 连通性检测

```http
POST /api/settings/connectivity/check
```

返回：

```json
{
  "items": [
    {
      "key": "mysql",
      "name": "MySQL",
      "status": "UP",
      "message": "连接正常"
    }
  ]
}
```

状态枚举：

| 状态 | 含义 |
|---|---|
| `UP` | 可用 |
| `DOWN` | 不可用 |
| `DISABLED` | 当前配置关闭或 Bean 不存在 |
| `UNKNOWN` | 无法确认 |

### 2.4 动态开关接入点

| 开关 | 接入位置 | 说明 |
|---|---|---|
| `agent.llm.guard.enabled` | `LLMService.validatePromptLength` | 每次模型调用前读运行期设置 |
| `agent.memory.summary.enabled` | `SummaryMemory` | 每次摘要读取、判断、保存前读运行期设置 |
| `knowledge.rag.rerank.enabled` | `KnowledgeReferenceRetrievalService` 与 `KnowledgeRerankClient` | 每次案例检索和精排调用前读运行期设置 |
| `creator.feedback.rag.enabled` | `CreatorFeedbackEvidenceRetrievalService` 与 `CreatorFeedbackEvidenceIndexService` | 每次反馈证据检索和索引前读运行期设置 |

动态开关只覆盖“是否启用”这一层。其他参数，例如 topK、候选池、字符上限，仍从原配置类读取。

### 2.5 连通性检测设计

| 检测项 | 实现方式 |
|---|---|
| MySQL | `DataSource.getConnection().isValid(2)` |
| Redis | `StringRedisTemplate.execute(connection -> connection.serverCommands().info())` |
| 知识库父/子向量库 | `KnowledgeVectorStore.isReady()` / `isChildReady()` |
| hybrid 向量库 | `KnowledgeHybridStore.isReady()` |
| Embedding Bean | `ObjectProvider<EmbeddingModel>.getIfAvailable()` 是否存在 |
| ChatModel Bean | `ObjectProvider<ChatModel>.getIfAvailable()` 是否存在 |

注意：LLM 和 Embedding 不做真实请求。原因是设置页应该是排查工具，不应该自己产生模型费用。

### 2.6 前端模块

新增：

| 文件 | 职责 |
|---|---|
| `types/settings.ts` | 设置状态、开关、连通性检测类型 |
| `api/settings.ts` | 设置相关 API 客户端 |
| `components/SettingsDrawer.vue` | 设置弹窗壳、运行期开关、只读状态、连通性检测 |
| `components/KnowledgeIndexPanels.vue` | 从案例库迁出的 4 个索引面板 |

改动：

| 文件 | 改动 |
|---|---|
| `App.vue` | 新增左上角固定设置按钮与 `SettingsDrawer` |
| `KnowledgeWorkspace.vue` | 删除 4 个索引面板及其状态、方法、导入、onMounted 调用 |

### 2.7 前端交互

- `⚙` 固定在页面左上角。
- 点击后打开居中设置弹窗。
- 首次打开弹窗时加载设置状态。
- 动态开关切换后调用 `PUT`，成功后刷新状态。
- 连通性检测必须由用户点击按钮触发。
- 索引面板只在设置弹窗里出现。

## 四、风险与约束

- 动态开关只改运行期判断，不改启动期 Bean 装配。
- `knowledge.rag.enabled=false` 启动时，知识库向量能力不会因为设置页动态开关而被打开。
- `creator.feedback.rag.enabled=true` 动态打开后，如果基础 VectorStore Bean 不存在，仍会降级 SQL。
- 连通性检测只报告当前状态，不负责自动修复外部依赖。
- 所有编译、测试、运行命令由作者执行。

## 五、验证清单

后端：

- `GET /api/settings/status` 返回 5 个动态开关和 3 个只读状态。
- `PUT /api/settings/toggles/agent.llm.guard.enabled` 可切换。
- 传未知 key 返回 400。
- `POST /api/settings/connectivity/check` 返回各依赖状态，异常时不导致接口整体 500。

前端：

- 左上角 `⚙` 可打开设置弹窗。
- 动态开关切换成功后 UI 状态同步。
- 接口失败时显示错误，不白屏。
- 案例库页面没有索引运维面板。
- 设置弹窗内 4 个索引面板刷新 / 重建行为与迁移前一致。
