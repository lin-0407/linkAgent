# 阶段 5.6 - 设置面板

> 承接 5.5（提示词 DB 化）。把散落的「可调项」收进一个统一的 ⚙ 设置入口：提示词在线改、功能开关在线开关、知识库索引在一处管理。编码、测试由作者执行。

## 1. 需求（解决什么）

- **提示词**：5.5 已把提示词搬进库、给了读写接口，但没前端。设置面板补上「列出 → 编辑 → 保存即时生效」。
- **开关**：现在所有开关只能改 `application.yml`/环境变量再重启。设置面板让能安全运行时切的开关在页面上点一下就生效；依赖 Milvus 的开关给出「怎么开」的指引（作者接受重启）。
- **索引管理**：4 个知识库索引面板现在挤在「案例库」主区，和日常浏览混在一起。挪进设置面板，案例库主区回归采集 + 浏览。

## 2. 范围（做 / 不做）

**做**：① 提示词编辑 ② 开关管理（可改的 Toggle 即时生效 + 依赖 Milvus 的展示状态 + 开启指引）③ 知识库 4 索引面板收拢。

**不做**：
- **检索框不搬**：留在案例库主区（作者 2026-06-11 拍板，后续展示要用）。
- **消息流 / ReAct 回放不碰**：它是 `MessageBubble` 里的对话内展示（`ReactTimeline`），属于对话、非配置。
- 不做开关的版本 / 审计 / 多租户；不强行让依赖 Milvus 的开关运行时热切（改完重启）。

## 4. 设计

### 4.1 后端

- **新表 `system_flag`**（`init.sql` 末尾新分节，范式照搬 `llm_prompt_template`）：`flag_key / enabled / scene / description` + `id/create_time/update_time/is_deleted`。种子 = 3 个可改开关，`enabled` 默认 0（与现 yml 默认一致 → 零回归）。
- **`SystemFlagService`**（照搬 `PromptService` 不缓存范式）：`isEnabled(key)` 每次查库、`setEnabled(key,bool)` 写库、`listAll()`。
- **`SystemFlagController`**：`GET /api/system/flags`（列表）、`PUT /api/system/flags/{key}`（@Valid 改一项，key 不存在 404）。
- **切 3 个读取点**到 `SystemFlagService`（逻辑等价、默认值不变）。`AgentExecutor` 那处去掉 `final` 字段、改每次查库——单独成刀、重点回归 `/agent/chat`。
- **基础设施只读状态**：`GET /api/system/infra-status` 聚合返回 RAG/hybrid/feedback/embedding/vectorstore 的当前值（从现有 Properties 读，纯只读）。
- **提示词**：零改（`GET /api/prompt-templates`、`PUT /{key}` 已就绪）。
- 顺手修 `PromptTemplateController:58` 过时的「缓存」注释。

### 4.2 前端

- `App.vue`：加 `const settingsOpen = ref(false)` + 顶栏 ⚙ 按钮。
- **`SettingsDrawer.vue`**：右侧滑入浮层，**沿用 `AgentFloatingWindow` 的 `position:fixed` 写法、不引入 Teleport**（少一个新概念）。复用全局 `creator-*` 设计系统。分三区：
  1. **提示词**：`GET` 列表按 `scene` 分组 → 选一条 → `<textarea>` 改 → `PUT` 保存。
  2. **开关**：3 个可改开关用 Toggle（`PUT` 即时生效）；依赖 Milvus 的展示只读状态 + 一张「**如何开启知识库 RAG**」指引卡片（见 §5）。
  3. **索引管理**：抽 **`IndexPanel.vue` 子组件**（4 个索引面板现在几乎同形），各传标题 / 说明 / status 函数 / rebuild 函数，从 `KnowledgeWorkspace` 迁入。
- **`KnowledgeWorkspace.vue`**：删掉 4 个索引 `section`（向量/子条目/父hybrid/子hybrid）及其 ref/函数，**留**采集导入、案例检索、案例列表。
- 新增 `api/system.ts` + `types/system.ts`；索引相关复用现成 `api/knowledge.ts`（函数不动）。

## 5. 「如何开启知识库 RAG」指引卡片内容

面板里直接展示给用户（作者 docker 部署在 Linux 虚拟机）：

1. **起 Milvus**：在虚拟机上 `docker compose up -d`（Milvus standalone：etcd + minio + milvus，暴露 `19530`）。确认容器健康。
2. **配后端 `.env`**：`KNOWLEDGE_RAG_ENABLED=true`、`EMBEDDING_MODEL_TYPE=openai`、`LLM_EMBEDDING_MODEL=text-embedding-v4`、`LLM_EMBEDDING_DIMENSIONS=1024`、`LLM_EMBEDDING_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`、`LLM_EMBEDDING_API_KEY=<DashScope Key>`、`MILVUS_HOST=<虚拟机IP>`、`MILVUS_PORT=19530`、首次加 `MILVUS_INITIALIZE_SCHEMA=true` 与 `KNOWLEDGE_RAG_INITIALIZE_SCHEMA=true`。
3. **重启后端** → 设置面板的只读状态应变「RAG 已启用 / 向量库就绪」。
4. 首次建好集合后把 `*_INITIALIZE_SCHEMA` 改回 `false`，避免每次启动重建。
5. hybrid 额外需 Milvus 服务端 ≥2.5 + `KNOWLEDGE_RAG_HYBRID_ENABLED=true`，再在「索引管理」点「重建 hybrid 索引」。

> 具体 compose 文件以作者虚拟机上现有 Milvus 部署为准；此处给标准 standalone 步骤作参照。

## 7. 测试点（命令由作者执行）

- **零回归**：3 个开关种子默认关 → 后端行为与今天字节级一致（结构化走文本路、不 rerank、不摘要）。
- 提示词：`PUT` 改一条 → 下次模型调用即用新值，不重启。
- 开关：Toggle `structured` → `/agent/chat` 立即走结构化路；关回去立即走文本路。
- 索引迁移：4 面板在设置抽屉里功能与原案例库一致；案例库主区采集/检索/列表照常。
- `infra-status`：RAG 关时显示未就绪、按指引开启 + 重启后显示就绪。

## 8. 决策

- **开关三档**：纯逻辑（3 个）运行时切；依赖 Milvus（RAG/hybrid/feedback）重启 + 面板给开启指引；作者 2026-06-11 拍板「开关都要能用、Milvus 类给 docker 指引」。
- **不用 Teleport**：随现有 `fixed` 浮层惯例，简单优先。
- **检索框留案例库主区**：作者拍板，后续展示用；设置面板不重复做检索台。
- **消息流 / 回放不进设置**：它是 `MessageBubble` 内的 `ReactTimeline` 对话内展示，非配置项。
