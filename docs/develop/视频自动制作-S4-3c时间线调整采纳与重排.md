# S4-3c 时间线调整采纳与完整重排

更新时间：2026-10-21。分支 `feature/creator-workspace-s1`，本轮基线 `ce38d97`。上一阶段见 [S4-3b 配音与自动字幕对齐](视频自动制作-S4-3b配音与自动字幕对齐.md)。

## 1. 这一步解决什么问题

S4-3a/S4-3b 只给出**只读**时长建议：真实录音或配音比场景长时返回 `EXTEND_SCENE`，比场景短时返回 `SHORTEN_SCENE`，但作者没有入口把这些建议真正落到工程里。结果是配音已经付费生成、音频事实也齐全，工程却始终卡在 `AUDIO_OVERFLOW`，只能重新录制或重新生成配音。

S4-3c 增加**显式采纳**：作者选择某条时长提案后，后端把场景时长改成提案给出的真实值，同步视频截取区间、重算整片时间线、随总时长调整背景音乐区间，并保存新的简报版本与故事板版本。旧版本全部保留。

## 2. 关键设计决定

### 2.1 采纳必须新建简报版本

简报里的 `targetDurationMs` 是用户明确指定的总时长，属于不可变意图。场景延长后总帧长变化，如果只在故事板里改时长，编译器会以 `TARGET_DURATION_MISMATCH` 拒绝；如果偷偷放宽编译器，就违背了"用户指定 1–180 秒"这条已确认规则。

因此采纳同时做两件事：

1. 复制原简报文档，把 `targetDurationMs` 改成调整后场景帧长对应的毫秒数，写入**新简报版本**（`revision+1`）；
2. 用新简报 + 调整后场景写入**新故事板版本**（`parent_storyboard_id` 指回原故事板）。

原简报与原故事板的 `document_json`、`source_json`、素材快照都不改写。版本链因此可审计：能看到"用户最初要 5 秒，采纳延长后把目标改为 6 秒"。

### 2.2 只采纳能靠改时长解决的提案

| 提案 | 是否可采纳 | 原因 |
| --- | --- | --- |
| `EXTEND_SCENE` | 是 | 音频完整保留，场景与可同步的视频区间一起延长 |
| `SHORTEN_SCENE` | 是 | 缩短场景到实际音频长度，或保留尾部画面的选择中的一种 |
| `RECORD_AGAIN` | 否 | 需要重新录制或重新生成配音，不是时间线问题 |
| `SUPPLY_MORE_VIDEO` | 否 | 需要补充画面素材 |
| `SUPPLY_RECORDING` / `PREPARE_REAL_AUDIO` | 否 | 还没有真实音频 |
| `CONFIRM_SOURCE_SILENCE` / `CONFIRM_TOTAL_DURATION` | 否 | 需要作者确认语义，不是机械改时长 |
| `TTS_TEXT_MISMATCH` / `VOICE_SCRIPT_CONFIRM` | 否 | 文稿与音频不一致，必须重新生成 |

请求里的 `durationMs` 必须**等于服务端当前报告中该场景该提案的 `proposedDurationMs`**。这样作者不能传一个任意毫秒数绕过素材、音频和帧量化约束；同一场景在一次请求里也不能重复出现。

### 2.3 视频选区随场景同步

`VIDEO_CLIP` 场景的截取区间必须与场景帧长一致（渲染器不循环、不变速）。采纳时保持 `sourceInMs` 不变，把 `sourceOutMs` 改为 `sourceInMs + round(frames(newDuration) * 1000 / 30)`：

- 延展前再次核对素材真实画面时长，超出时拒绝并提示补充视频；
- 缩短只减小终点，不会越过素材尾部。

### 2.4 背景音乐区间随总时长调整

背景音乐选区的业务语义是"这段音乐覆盖整片"，长度必须与全片帧长一致。总时长变化时：

- 起点 `sourceInMs` 不变，终点改为 `sourceInMs + 新总时长`；
- 新终点超过音乐素材真实时长时**拒绝**，要求作者重新选择区间，绝不循环或读取选区外音频；
- 淡入淡出总长超过新区间时拒绝；
- 响应 `notes` 明确写出区间从多少毫秒改成多少毫秒，便于作者核对。

这不是静默改写用户选择：区间与整片绑定是已有规则，调整结果和原因都在响应里可见。

### 2.5 字幕全局时间由编译器重算

场景 `cues` 保存的是**相对本场景音轨**的时间，没有改动。编译器按新的场景起点重算全局字幕时间，因此第二个场景的 SRT 时间会随前面的延长整体后移。原生测试直接断言了这一点（`00:00:02,000 --> 00:00:02,900`）。

本轮同时修正了编译器的一处精度问题：原来全局起点用 `Math.round` 取整、片尾用未取整值比较，场景起点帧为 `k ≡ 2 (mod 3)` 时会把恰好在音轨末尾的字幕误判越界。采纳产生的场景时长来自"音频向上取整到帧"，更容易命中这类起点，因此改为统一使用未取整的起点，并对音轨末尾和片尾比较保留 1 毫秒量化容差。

## 3. 接口

`POST /api/creator/tasks/{taskId}/creation/storyboards/{storyboardId}/timeline:apply`

请求头需要 `Idempotency-Key`（最多 128 字符）。

```json
{
  "expectedWorkspaceRevision": 7,
  "adjustments": [
    { "sceneId": "opening", "proposalCode": "EXTEND_SCENE", "durationMs": 5134 }
  ]
}
```

响应包含新故事板视图（含 `check`）、新简报版本号、新目标时长、实际生效的调整和说明：

```json
{
  "board": { "storyboardId": "...", "revision": 3, "briefId": "...", "check": { "renderable": true } },
  "briefRevision": 2,
  "targetDurationMs": 6133,
  "applied": [
    { "sceneId": "opening", "proposalCode": "EXTEND_SCENE", "previousDurationMs": 5000, "durationMs": 5134 }
  ],
  "notes": ["背景音乐区间终点已随总时长从 5000ms 调整为 6134ms"]
}
```

规则：

- 幂等键作用域是故事板 + 请求体摘要；同键同请求返回原版本，同键不同请求 409；
- `expectedWorkspaceRevision` 必须等于当前工作区修订，且工作区没有活动运行或其他活动制作；
- 故事板必须基于**当前最新简报**，否则 409（避免基于过期依据改时长）；
- 调整后总帧长必须在 30–5400 帧（1–180 秒），单场景仍在 1–30000 毫秒、900 帧以内；
- 采纳不要求故事板整体已可渲染：其他场景缺配音或缺字幕仍然保留，`check` 会如实返回剩余问题。

## 4. 与配音运行的关系

正确顺序是**先生成配音，再采纳时间线**：

1. `audioMode=TTS` 的场景先走 S4-3b：估算 → 授权 → 合成 → 转写 → `ASR_ALIGNED` 新故事板；
2. 对这份新故事板查询 `timing`，得到基于真实配音时长的 `EXTEND_SCENE`；
3. 采纳后生成更新的简报与故事板版本。

反过来先采纳再配音也可以，但配音运行会以旧简报为依据，保存结果时会被"配音依据已变化"拒绝。这不是缺陷：音频长度未知时无法确定时间线，先定时间线等于猜测。

采纳时保留原故事板的素材快照，包括系统生成的 TTS 配音素材；这些素材不在简报 `assetIds` 里，但作为本链路实际产出的配音继续被新版本引用，不会被当成用户上传素材，也不能用于 `NARRATION` 场景。

## 5. 事务与并发

- 提案校验、场景重算、简报文档构造在 `StoryboardAudioService` 完成；
- 新简报、新故事板、素材引用和任务行锁在 `StoryboardPersistence.saveTimeline` 的单个事务内提交；
- 写入前重新核对活动运行、活租约、工作区修订和简报版本，避免校验与写入之间的竞态；
- 外部调用为零：采纳只读写数据库，不调用模型、不调用供应商、不产生费用。

## 6. 验证口径

- 真实隔离 MySQL：新增 8 项，覆盖新简报/新故事板/旧版本保留、幂等重放、音乐区间延展、音乐超界拒绝、视频选区同步、过期简报拒绝、帧边界字幕判断、未准备场景不阻塞采纳；
- 单元测试：任意毫秒数拒绝、不支持提案代码拒绝、重复场景拒绝、幂等键冲突；
- 控制器测试：缺修订、非法提案代码在进入服务前被拒绝，成功响应 `no-store`；
- 原生渲染（容器内 FFmpeg/Python）：延展到 3 秒的工程真实出片 90 帧，断言第二段字幕全局时间后移、音乐覆盖到片尾。

完整命令与结果见 [S4-3c 验证记录](../error/视频时间线S4-3c验证记录.md)。

## 7. 当前边界

本阶段完成"按真实提案调整单个场景时长并重排整片"，以下仍未实现：

- **环境声独立混音**：`creator_creation_asset` 只有 `MUSIC` 一类长音频，V2 工程只有一路 `backgroundMusic`；环境声是下一子阶段；
- **任意手动微调**：只能采纳服务端给出的量化值，页面拖拽或输入任意时长属于 S5/S6；
- **多场景批量联动**：一次请求可以调多个场景，但每个都必须各自命中真实提案，不做"整体拉伸到目标时长"；
- **跨场景重排顺序**：场景顺序、素材替换、复制删除仍是 S5-2/S6 范围；
- **页面入口**：本轮只交付后端接口，前端归属另一个 agent。
