# 阶段 3.3：工具执行重试保护

## 上下文

阶段 3.2 已经把工具执行超时和异常边界收进 `ToolExecutor`。但真实工具场景里，很多失败不是永久错误，而是瞬时网络抖动、下游短暂不可用或临时超时。

如果这类问题直接返回给 `AgentExecutor`，ReAct 主循环会把“临时失败”误当成“任务失败”，导致模型过早放弃。

## 本轮目标

在工具层增加一个最小、统一的重试策略，让短暂失败有一次或多次恢复机会。

## 本轮变更

- 新增 `agent.tool.execution.max-retries` 配置：
  - 默认值为 `0`。
  - 最小值兜底为 `0`，避免负数配置。
- 修改 `ToolExecutor`：
  - 仅对工具实际执行失败做重试。
  - `tool not found` 不重试，因为这是配置问题，不是瞬时故障。
  - 重试耗尽后返回最后一次错误信息。
- 修改 `ToolExecutorTest`：
  - 覆盖“首次失败、重试后成功”。
  - 覆盖“重试耗尽仍失败”。

## 设计说明

当前版本只做统一重试次数，不区分异常类型，也不引入退避算法。原因很简单：阶段 3 的重点是把工具执行边界先收紧，先验证“能恢复的失败”这一类场景，别一开始就把重试策略做复杂。

后续如果接入外部 HTTP 工具、MCP 工具或并发执行，再根据工具类型细分重试条件、退避时长和幂等约束。

## 验证方式

本项目约定 Maven 编译和测试由作者执行。本轮建议执行：

```bash
cd backend
mvn test -Dtest=ToolExecutorTest,ToolRegistryTest
```
