# S4-2 简报、故事板与工程生成

日期：2026-10-21。承接 [S4-1 独立素材导入](视频自动制作-S4-1独立素材导入.md)。本轮把用户意图、真实材料和已准备素材连接为可保存、可检查的业务工程；接口说明见[简报故事板与工程接口说明](../reference/简报故事板与工程接口说明.md)。

本文保留 S4-2 的交付范围；后续已增加用户背景音乐、SRT 导入和真实时长提案，见[S4-3a 记录](视频自动制作-S4-3a音乐字幕与时长建议.md)。下面“尚未交付”和素材限制按本阶段时点理解，当前能力以总进度及最新阶段记录为准。

## 需求与交付边界

创作者先明确主题、核心信息、观众、目标时长和对白方式，再选择本任务已 READY 的素材。可以人工保存故事板，也可以先估算、明确授权金额，再调用当前部署的文本模型生成候选。每次保存得到独立版本，可以查询历史依据及素材引用，不覆盖旧版本。

准备运行的种类为 `PREPARE`，结果是业务故事板。准备完成既不代表已经制作视频，也不构成 `FULL` 整片授权。故事板存在未完成的配音、AI 画面或真实字幕对齐时仍能作为候选保存，但 `check.renderable=false`，不能编译成渲染工程。

本轮增加已授权 FULL 运行的内部工程桥接，继续要求真实发布方案确认、专属制作计划、精确故事板和内容摘要。没有新增公开的通用整片启动 API，准备接口始终返回 `fullProductionAvailable=false`，原制作运行快照的 `executionAvailable=false` 未被改成公开可执行。

业务主线仍为发布方案确认 → 制作蓝图 → 成片试映/媒体处理 → 用户实际发布 → BV 绑定 → 反馈与复盘。准备阶段可以先整理简报与候选，不因此跳过制作授权或成片试映。

## 数据与不可变版本

新增 `creator.creation.storyboard` 模块，复用 S1 的工作区修订、运行、租约、预算和费用流水，不为故事板另建一套执行状态机。四张表直接维护在统一 `backend/src/main/resources/sql/init.sql`：

| 表 | 保存的事实 |
| --- | --- |
| `creator_creation_brief` | 任务内递增的简报版本、幂等请求摘要、用户意图和保存当时的真实来源快照 |
| `creator_creation_storyboard` | 故事板版本、明确父版本、对应简报、准备运行、业务内容摘要和不可变素材快照 |
| `creator_creation_storyboard_asset` | 故事板与冻结素材的历史引用关系，支持反查影响 |
| `creator_creation_storyboard_job` | PREPARE 运行对应的简报、原始受理摘要和唯一结果故事板 |

简报保存时读取实际任务材料，保留 `material:编号`、类型、正文和正文 SHA-256；用户本次简报使用 `brief:user` 作为来源标识。若当前存在符合门禁的已确认发布建议，保存其会话/结果身份；没有确认依据时不伪造确认事实。

故事板来源必须属于对应简报。`USER_PROVIDED` 的每个场景都需要真实来源引用；`FICTION` 表示明确虚构，也不能伪造外部材料标识。来源标识用于追溯，并不等于自动完成事实核查。

仅能冻结本任务的 READY 素材，使用持久化桶、NORMALIZED 对象键、完整 SHA-256、实际字节数、类型及原始/规范化元数据，不保存短签。保存时会冻结简报选择的整个素材集合并登记历史引用；实际渲染只下载场景用到的素材。引用查询因此包含已冻结但某场景未使用的素材，不能作为精确到镜头的剪辑影响分析。

`requestHash` 校验同一幂等键是否对应同一原请求；`documentHash` 标识业务故事板正文；`renderContentHash` 标识实际受控渲染内容，排除运行和尝试身份。工程的 `inputHash` 则包含本次运行/尝试，用于验收具体输入。不同哈希用途不能相互替代。

修改通过新版本和可选 `parentStoryboardId` 表达；不提供原地覆盖接口。工作区修订、空闲状态和任务归属在任务行锁内复核。同键同请求重放返回原结果，同键换内容拒绝。新保存与新准备必须使用当前简报；历史版本保留查询能力。

## 准备运行与费用

推荐顺序：读取工作区 → 保存简报 → 重新读取工作区 → `storyboards:estimate` → 用户明确本次最高金额 → `storyboards:generate` 返回 202 → 查询准备运行 → 查询结果故事板和 `check`。人工保存故事板不触发模型调用。

`estimate` 与 `generate` 使用同一套实际提示词、冻结上下文和部署价格进行估算：

```text
输入 token 保守上界 = 系统提示词 UTF-8 字节数 + 实际 context UTF-8 字节数 + 4096
输出 token 上限 = 4096
人民币预留 = CEILING_6((输入上界 × 输入美元单价 + 4096 × 输出美元单价) × 折算率 / 1,000,000)
最低非零预留 = 0.000001 元
```

这是基于配置的估算，不是模型 tokenizer 的精确计数、实时单价、实时汇率或供应商实付账单。来源快照限制 48 KiB，包含资产快照的准备请求限制 60 KiB；超过限制明确拒绝，不截断材料后继续调用。

`maxAdditionalCostCny` 是用户显式授权上限。低于当前估算、授权超过任务总预算、工作区修订变化或任务仍有活动制作时，拒绝受理。剩余可用预算及 UNKNOWN 在后台发送前的 reserve 再检查，因此可能出现已受理后因余额或未知费用而失败，但不会因此发送付费请求。估算接口不消耗修订、不创建运行、不发模型请求；它不是锁定价格的授权。生成受理时重新计算并冻结模型名、单价、折算率、token 上界和预留金额；估算后配置变化可能需要重新确认。

后台先在账本预留，登记真实发送标记，再发起单次文本请求。专用模型实例关闭 Spring 重试，使用 JDK HTTP 传输避免传输层在 429/503 后自动重发 POST；不启用工具执行或多候选续调。异常、超时、旧调用结果不明以及租约接管均不能自动再次计费请求。

模型返回后先按已冻结单价与折算率登记 `USAGE_ESTIMATE`，再解析和校验候选。已产生用量的无效 JSON、错误来源或非法业务字段，不会因没生成故事板而被当成免费失败。结算金额按实际返回 token 估算，使用六位小数 HALF_UP；预留上界使用 CEILING，两者用途不同。

缺少任一侧 usage 时登记 `UNKNOWN`，不把缺失值补成零。如果候选有效，可以保存候选并结束准备运行，但未知费用继续占用预留并阻止后续付费调用。重启后发现既有发送/预留事实时停止自动模型重发；在途请求取消后仍可能晚到并产生费用，晚结果不能覆盖被取消运行，但已知 usage 仍须结算。取消不保证供应商退款。

## 业务检查与受控工程

业务故事板有 1 至 48 个场景，每场景提供稳定 ID、布局、标题、正文、旁白文稿、时长、素材身份、声音方案、真实字幕及来源。模型候选禁止额外字段、命令、URL、路径和伪造字幕时间；模型输出的 `cues` 必须为空。人工保存的相对音轨字幕标为 `USER_PROVIDED`，模型候选标为 `NOT_PROVIDED`。

| 布局 | 当前工程行为 |
| --- | --- |
| `TITLE_CARD` | 固定文字构图，不引用画面素材 |
| `IMAGE_CARD` | 使用真实冻结图片，正文必须为空以避免遮挡 |
| `SPLIT_CARD` | 固定图文分区，必须引用真实图片 |
| `COMPARE_CARD` | 两项正文对比，不接受图片 |
| `VIDEO_CLIP` | 使用真实视频区间，CONTAIN 或 COVER，正文为空 |
| `AI_VIDEO` | 可作为待准备意图保存；未接供应商时明确不可渲染 |

编译固定使用 renderer V2：1280×720、30 fps、H.264、48 kHz 音频、固定字体标识和深色背景，不允许模型拼接命令或滤镜。单场景最多 30 秒，总长为 1 至 180 秒。每场景毫秒时长量化为整数帧，量化后的总时长与目标最多相差一帧；不在后台悄悄改成另一种时长。

视频 source 区间须在规范化视频的真实时长内，长度与量化后的场景相符；不循环素材、不定格补齐、不自动变速。场景声音分别为无对白、原声、用户录音或待 TTS。原声必须有实际可听区间，不能同时绑定旁白；视频使用用户录音时原声静音，不隐式 MIX。对白选择还要符合简报策略：USER_NARRATION 对应 NARRATION，SOURCE 视频对应 ORIGINAL，SOURCE 图文过场可以 NO_DIALOGUE，TTS 保留为待配音。

用户录音必须是 READY 的 NORMALIZED PCM16 WAV，真实时长不超过 30 秒且完整容纳于场景；超出时拒绝，不截音、不加速。旁白场景需要用户提供相对录音的真实字幕时间；编译只平移至整片时间轴，不宣称做了 ASR 对齐。无对白可无字幕；原声也可明确无字幕。已有字幕必须按序、无重叠、处于真实音轨和场景范围内，整片最多 200 条。

本轮保持现有 renderer 的素材上限：单个 32 MiB、引用合计 256 MiB、图片/视频解码尺寸不超过 800 万像素。S4-1 可以准备的源素材范围更大，READY 不代表必然能直接进入此渲染器；超限会要求先裁剪或压缩后导入，不擅自扩大引擎边界。纯文字无对白工程会写一个程序内固定 1×1 PNG，明确标识为系统占位，不作为场景画面或配音。

## 已授权 FULL 内部桥接与文件生命周期

`StoryboardProductionBridge.attachToRun` 只接受已存在的 FULL 运行：故事板 ID、`renderContentHash`、活动运行、QUEUED 状态、ACTIVE/PRODUCTION 授权及输入指纹必须一致。它复用已有整片门禁和 `FixedProjectJobPersistenceService`，没有把 PREPARE 授权升级成 FULL。

工程资产文件名固定为 `assets/{assetId}.{ext}`，只从冻结桶下载。落盘前核对 HEAD，下载后复核完整字节数与 SHA-256；工作目录必须为受控 `root/runId/attemptId`，不得覆盖旧尝试或通过符号链接越界。

准备文件失败会清理本次新建目录；明确冻结失败可以按输入身份和摘要撤回该尝试。桥接提交响应异常时，先核实持久化结果：本尝试实际已登记则复用，另一尝试已占据运行则清理本尝试。提交结果仍不明确时保留文件，不能删除可能刚被数据库采纳的工程。任务全局的孤立工作目录、包对象与历史资源回收仍需 S7 统一收口。

## 验证口径与后续工作

本轮测试覆盖简报/故事板真实数据库事务、幂等、版本、来源、预算预留与结算、发送不明接管、取消晚结果、桥接以及受控工程文件边界；具体执行结果以本轮最终测试输出和总进度记录为准，此处不把测试设计当成通过结果。

三主题原生测试用固定受控 Candidate 与测试媒体，存储接口把 fixture 对象复制到本地，再通过同一 Java 编译器、文件边界、Python renderer 和 FFmpeg 真实出片，检查时长、字幕和实际画面差异。这证明本地工程渲染行为，不代表真实 LLM 故事板质量、真实 OSS 上传下载、浏览器操作或端到端供应商验收；候选直接进入编译器的技术测试也不代替公开 API 的完整业务策略验证。

尚未交付 TTS/AI 视频真实供应商生成、ASR 字幕自动对齐、BGM、SAMPLE 样片入口、局部修改与缓存复用、故事板/素材页面或通用公开整片制作入口。整个 S3 的真实供应商试映、实际账单、部署与用户完整操作验收仍须单独完成。
