# 阶段 2.4：摘要后短期记忆裁剪

## 上下文

阶段 2.3 已经可以在短期消息超过阈值后生成摘要，但摘要生成后短期窗口仍保留原始消息。这样会导致后续 Prompt 同时包含摘要和原文，浪费 Token，也可能反复摘要同一批内容。

## 本轮目标

本轮只解决一个问题：摘要成功后，短期记忆只保留最近少量消息，让摘要负责承接更早的上下文。

## 本轮变更

- `SummaryMemoryProperties` 新增 `retained-message-count` 配置，默认保留 2 条最近消息。
- `SummaryMemory` 暴露 `getRetainedMessageCount()`，统一兜底负数配置。
- `ShortTermMemoryStore` 新增 `replaceMessages()`，用于替换某个 session 的短期消息。
- `InMemoryShortTermMemoryStore` 和 `RedisShortTermMemoryStore` 实现替换能力。
- `ShortTermMemory` 新增 `keepRecentMessages()`，封装短期记忆裁剪逻辑。
- `AgentExecutor` 在摘要成功后调用裁剪逻辑。

## 设计说明

`retained-message-count` 默认是 2，因为当前一次完整问答通常会追加 `Human` 和 `AI` 两条消息。摘要负责保存更早内容，最近一轮原文继续保留，可以让下一轮对话衔接更自然。

当前阶段没有引入复杂的摘要版本、消息游标或数据库持久化。原因是项目还在记忆系统早期，先跑通“摘要 + 裁剪”的最小闭环，比提前设计复杂状态更重要。

## 验证方式

```bash
cd backend
mvn test -Dtest=SummaryMemoryTest,ShortTermMemoryTest,InMemoryShortTermMemoryStoreTest
```

Redis 版本可按需执行：

```bash
cd backend
mvn test -Dtest=RedisShortTermMemoryStoreTest
```
