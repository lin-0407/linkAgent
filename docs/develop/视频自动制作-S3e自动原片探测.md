# S3e：系统成片自动原片探测

日期：2026-10-20。承接 S3c/S3d 和 S4a；本步先修复整体复查的问题，再将后台执行从成片登记推进到真实原片探测。公开制作入口仍关闭，`executionAvailable=false`，没有新增前端制作页面、HTTP API、表结构或供应商调用。

## 需求与边界

原固定工程 worker 登记 UPLOADED 成片后直接等待依赖，原片探测仍须另行调用。用户最终的一键制作需要自动连接原媒体链路，但探测成功不能代替预处理、完整试映、发布包或用户实际发布。

本步输入仍为真实发布方案确认、专属制作授权和冻结工程。输出是本运行精确登记视频的实际 FFprobe 元信息与 `READY_FOR_REVIEW` 状态；FULL 继续停在 `WAITING_DEPENDENCY`，等待后续完整媒体工作。

## 复查修复

| 问题 | 修复方式 |
| --- | --- |
| 删除任务后运行与费用无法收尾 | 删除先取得制作受理共用的任务行锁；有活动运行或 RESERVED/UNKNOWN 费用时拒绝删除，结算和取消完成后仍可正常删除 |
| 取消后系统蓝图遮住原人工计划 | 终态收尾仅把未完成、未登记的专属自动蓝图置为 STALE；保留步骤证据、原成片和已完成人工蓝图 |
| Java/Python 小数摘要差异 | 两端统一浮点摘要 token；实际工程仍为 JSON，非有限值在序列化前拒绝，Java 按真实 JSON round-trip 数值计算 |
| 目标时长未与工程核对 | 工程附加时读取本 run 精确自动蓝图，使用整数帧公式检查一帧容差；旧人工计划目标不新增硬限制 |
| 旧请求清空新任务上传状态 | 仅在原上传状态机的迟到 404/410 分支补操作代数检查，不改其他 agent 正在优化的界面、样式或文案 |
| 视频元数据标题误走画面检查 | VIDEO_CLIP 标题不参加可见文字的字形/布局检查，真实字幕仍检查 |
| COVER 中间画面膨胀 | 按 SAR 直接计算目标框或在源内裁切，移除整帧 SAR 预放大与先放大再裁切 |

取消回退的边界：原任务有已完成的人工制作依据时，可以恢复该依据上传自己的新成片；首次自动制作若没有人工蓝图，取消后仍须按原业务规则建立制作依据，不放宽上传门禁，也不伪造自动步骤完成。

渲染器版本为 0.2.1。浮点摘要 token 是 `f64:` 加 16 位小写 IEEE 754 双精度大端十六进制，只有摘要流使用裸 token，文件中的数字不变。纯整数工程摘要不变；旧浮点工程需重新准备和授权，不能自动改旧授权来通过。细节见 renderer README。

## 自动探测链路

```text
真实渲染和八对象校验
  → 精确登记 UPLOADED
  → 本运行领取原片探测，阶段 SOURCE_PROBING
  → 事务外签名并用 FFprobe 读取私有原片
  → 版本/token/代数/活租约复核及工程元信息比对
  → READY_FOR_REVIEW，阶段 SOURCE_PROBED
  → FULL 等待同一 versionId 的完整媒体依赖
```

新增 `GeneratedDraftProbeService` 协调签名和 FFprobe；其外部调用禁止包在数据库事务中。`GeneratedDraftProbePersistenceService` 分别以短事务领取、采纳或记录失败。仍复用原媒体状态、元信息字段、`probe_attempt_id` 和创建运行租约，没有复制另一套媒体状态表。

领取必须找到本 run 的 REGISTERED 尝试及精确 versionId。READY 且元信息符合冻结工程时直接复用，不签名、不重新探测。UPLOADED/PROBE_FAILED 可以领取；旧代数 PROBING 可以以原状态和 token CAS 接管，同代数重复领取拒绝。

实际元信息须符合冻结工程的内容摘要、分辨率、帧率、H.264/AAC 及按帧计算的时长，封装时长容差为 65ms。静音 V2 仍有静音 AAC 音轨；`hasAudio=true` 不表示存在人声。

## 取消、失租与并发

成功和失败均先复核制作执行权及版本，再按精确探测 token 写入。写完后另一次 SQL 检查数据库当前时间和活租约；事务中途过期会使媒体状态与元信息整体回滚。

手工探测领取及 GET 懒恢复，在对应生成运行活动期间避开该 run 精确登记的版本；其他人工视频仍按原规则处理。运行终态后可以恢复手工操作。取消/失败由当前权威执行者收尾时，只清理本 run 版本上的自动 PROBING，不改人工 token 或其他版本。

FFprobe 复用原有并发槽、输出上限和签名 URL 保护，增加取消供应器。进程等待和输出读取共同遵守截止时间；取消、中断和超时均有界回收自身进程和观察到的后代。旧单参数 `probe(url)` 保留原手工调用方式。

登记后或 READY 提交后重启，仍恢复同一视频版本。原工作目录已删除时不重新渲染、上传或分配版本。探测失败保留已经登记的成片与自动步骤事实，不能把网络失败改写成渲染从未发生。

## 验证与下一步

正式回归覆盖七项修复、跨语言实际冻结/重写/编码，以及探测的旧代迟到、手工恢复互斥、取消接管和元信息写入中途到期回滚。原生链路由 Spring 调度真实制作 V1/V2 的中文工程，通过私有存储自动探测，再删除原工作目录恢复同一版本，仍校验后续完整试映门禁。
