# 阶段 3.1：工具注册安全基线

## 上下文

阶段 1 已经实现了 ReAct 主循环和基础工具调用，阶段 2 完成了记忆系统。进入阶段 3 后，工具数量会继续增加，并且后续还会接入 MCP、动态工具和并发工具调用。

如果工具注册中心仍然只做简单 Map 写入，两个问题会变得很难排查：

- 工具名重复时后注册的工具会覆盖前一个工具。
- 工具名为空时模型可能拿到不可调用的工具说明。
- 工具列表顺序不稳定时，系统提示词、日志和测试结果不容易复现。

## 本轮目标

先补工具注册的安全基线，不引入额外抽象，不提前实现 SPI、MCP 或并发调用。

## 本轮变更

- 修改 `ToolRegistry`：
  - 启动期校验工具名不能为空。
  - 启动期校验工具名不能重复。
  - 按工具名稳定排序后注册工具。
  - `getAllTools()` 返回注册后的工具集合，保证顺序与实际注册表一致。
- 新增 `ToolRegistryTest`：
  - 覆盖正常注册。
  - 覆盖重复工具名。
  - 覆盖空工具名。
  - 覆盖工具集合稳定排序。

## 设计说明

工具注册属于基础设施，最重要的是“失败要早”。如果等 Agent 运行到某个工具调用步骤才暴露问题，排查成本会明显变高。

当前没有引入自定义注解或 SPI，是因为现阶段 Spring Bean 自动注入 `List<Tool>` 已经足够。后续当工具来源变多时，再扩展注册来源会更自然。

## 验证方式

本项目约定 Maven 编译和测试由作者执行。本轮建议执行：

```bash
cd backend
mvn test -Dtest=ToolRegistryTest
```
