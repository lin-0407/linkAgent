## 1. 本轮结论

固定工程运行在登记系统成片并通过原片探测后，不再停在 `WAITING_DEPENDENCY`：后台按已落库的阶段自动创建媒体预处理任务、完整试映任务，构建最小发布包，最后只在包通过对象校验时把 FULL 推进到 `COMPLETED` 并释放活动槽。

三块工作的实际边界：

| 编号 | 当前实现 | 未验收部分 |
| --- | --- | --- |
| S3-1 | 内部受理媒体预处理与完整试映，精确关联运行/版本/子任务/执行代数，失败保留运行待作者处理 | 未调用真实供应商试映（无部署密钥），只做协议与真实数据库验证 |
| S3-2 | 精确版本打包 video/subtitles/cover/frames/render.log/manifest + 投稿文案 + 包清单，对象 HEAD 校验后登记 | 页面下载入口属 S5-4，本轮只提供内部事实与接口路径 |
| S3-3 | ASR、全片视频理解、重点片段复核、观众试映四类真实调用接入预留/发送/结算/未知 | 未与真实供应商账单核对；文本单价为配置上界 |

公开制作入口仍未开放，`executionAvailable=false`；本轮不改变前端。

## 2. 数据模型

统一维护在 `backend/src/main/resources/sql/init.sql`，只新增两张表，不改既有表。

### 2.1 `creator_creation_media_link`

一条整片运行只允许一个精确成片版本进入媒体闭环。

| 字段 | 含义 |
| --- | --- |
| `run_id` | 主键，整片运行 |
| `version_id` | 本运行 `REGISTERED` 的唯一成片版本，唯一键防重 |
| `stage` | `MEDIA_PENDING` → `MEDIA_RUNNING` → `PREFLIGHT_RUNNING` → `PACKAGE_PENDING` → `PACKAGE_READY` → `COMPLETED`，异常为 `FAILED`，取消为 `CANCELLED` |
| `processing_job_id` | 内部受理的预处理任务，恢复时按此复用 |
| `preflight_review_id` | 内部受理的完整试映任务，恢复时按此复用 |
| `lease_generation` | 最近一次推进的执行代数 |
| `failure_code` | 受控失败原因 |

### 2.2 `creator_creation_package`

| 字段 | 含义 |
| --- | --- |
| `run_id` | 主键 |
| `status` | `BUILDING` / `READY` / `FAILED`；`READY` 不会被重复扫描重建 |
| `object_key`、`bytes`、`sha256` | 真实上传后的事实；字节数来自 `HeadObject` |
| `manifest_json` | 冻结的版本、文案、来源、试映摘要与文件清单 |
| `lease_generation` | 构建代数，失租结果不能登记 |

## 3. 状态机与调度

`CreationMediaWorker` 以数据库阶段为唯一事实，每次只推进一个可持久化边界：

```text
登记并探测 READY
  → MEDIA_PENDING   领取租约，内部受理预处理，写回 jobId，等待依赖
  → MEDIA_RUNNING   预处理 COMPLETED 后受理完整试映，写回 reviewId，等待依赖
  → PREFLIGHT_RUNNING 试映 COMPLETED 后推进待打包并释放租约
  → PACKAGE_PENDING 独立领取并构建包，写回 READY 后等待依赖
  → PACKAGE_READY   复核包事实，FULL 进入 COMPLETED，释放活动槽
```

关键约束：

- 等待依赖时释放租约，`status=WAITING_DEPENDENCY`；重启后按已落库的 `jobId`/`reviewId` 继续，不重复创建。
- 预处理或试映 `FAILED` 时把运行留在活动位置，`stage=MEDIA_BLOCKED`、`error_code` 记录受控原因，不自动继续付费，也不自动替作者确认问题。
- 取消请求由调度器领取后请求停止试映并确认取消；取消不承诺供应商退款，已发送调用保留费用流水。
- 包已 `READY` 时重复扫描只复核完成条件，不重新下载、不重新打包。
- 同阶段最多领取 `max-attempts` 次，含首次；成功推进才重置。正常完整流程可有六次领取，不能用整片累计次数判断阶段失败。
- 已交接运行的 QUEUED/过期 RUNNING 由媒体 worker 接回；固定 worker 在候选与任务锁内均拒绝抢回，活 RUNNING 不抢占。暂停后的取消仍能收尾。

## 4. 内部受理与现有门禁

人工入口的规则没有放宽：`MediaProcessingService.createJob` 与 `PreflightReviewService.create` 仍拒绝“有活动制作运行”的人工请求。

新增的内部重载接受 `InternalMediaAcceptance`，由 `CreationMediaAcceptance` 实现：

1. 运行必须是当前活动运行，执行租约仍然有效，整片授权未撤销，输入指纹一致；
2. 目标版本必须是本运行 `REGISTERED` 的版本；
3. 其余前置条件（成片 READY、预处理 COMPLETED、Provider 配置）保持不变。

因此“自动运行不能被人工入口抢占”和“内部受理不能全局放宽门禁”两条同时成立。

## 5. 最小发布包

包内文件：

| 文件 | 来源 |
| --- | --- |
| `video.mp4`、`subtitles.srt`、`cover.png`、三张画面帧、`render.log`、`manifest.json` | 登记清单中的八个私有对象，逐个校验字节数与 SHA-256 |
| `publishing.md` | 冻结的候选标题、简介、目标观众、核心信息、成片事实、试映摘要、来源标识 |
| `package-manifest.json` | 版本/运行/尝试标识、输入与清单摘要、逐文件摘要、试映问题数与阻断数、`published=false` |

构建规则：

- 任一对象缺失或摘要不一致 → 明确拒绝并标记 `PACKAGE_BUILD_FAILED`，不会用不完整素材打包。
- 视频按存储方式写入 ZIP，不重新编码；文本与清单压缩。
- 上传后 `HeadObject` 字节数必须等于本地包大小，才登记 `READY`。
- 包只代表导出结果，`published=false` 固定写入清单；实际投稿、BV 绑定与反馈仍走原流程。
- 已 READY 的包直接复用，恢复和重复扫描不产生第二次上传。

## 6. 费用接入（S3-3）

`MediaCallChargeGate` 是媒体侧的窄接口，`CreationMediaBilling` 是唯一实现：

| 能力 | 预留口径 | 结算口径 |
| --- | --- | --- |
| `MEDIA_ASR` | 音频秒数 × 每秒单价 | Provider 返回的计费用秒 |
| `MEDIA_VIDEO` | 预处理预估，缺失时用配置上界 | 实际输入/输出 token × Plus 单价 |
| `MEDIA_SEGMENT` | 每次调用一个保守上界 | 实际 token |
| `MEDIA_TEXT_SCREENING` | 每次调用一个保守上界 | 实际 token × 配置单价；token 缺失记 `UNKNOWN` |

规则：

- 发送前必须先预留并 `markSent`；同一调用标识只能发送一次，重放不会二次提交。
- 响应丢失、失败或取消时保留 `UNKNOWN`，不按零费用释放后盲目重试；存在 `UNKNOWN` 时暂停该任务的新增付费调用。
- 台账按人民币记账，美元用量按配置折算率换算，折算率、美元上界与价格依据写入 `price_snapshot_json`。
- 人工试映没有制作运行归属，闸门为空实现，行为与之前一致。

## 7. 配置

```yaml
creator:
  creation:
    media:
      enabled: ${CREATOR_CREATION_MEDIA_ENABLED:false}
      poll-interval-ms: 5000
      lease-seconds: 60
      heartbeat-seconds: 15
      max-attempts: 3
      frame-interval-seconds: 10
      resolution: P720
      model-plan: FLASH_PLUS_REVIEW
      include-asr: true
    billing:
      usd-to-cny: 7.20
      video-usd-upper-bound: 0.30
      segment-review-usd-upper-bound: 0.05
      text-screening-usd-upper-bound: 0.05
      text-input-usd-per-million-tokens: 0.20
      text-output-usd-per-million-tokens: 0.80
```

`creator.creation.media.enabled` 必须与 `creator.media.enabled`、`creator.creation.renderer.enabled` 同时为 `true` 才会加载调度器；否则运行停留在等待依赖，和之前一致。
