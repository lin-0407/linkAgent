# 阶段 4.4.1.4：结果独立弹窗展示

## 需求分析

本轮服务对象是使用创作工作台完成发布前优化、评论弹幕导入和反馈复盘的 B 站 UP 主。

要解决的问题是：AI 生成结果和脚本解析结果不应该直接铺在表单下方。输入区用于填写材料和触发动作，结果区用于阅读、确认和复盘，两者混在同一屏会让页面失焦。

本轮只做：

1. 发布前优化建议改为通过发布前阶段内的“查看建议 / 查看并确认”按钮打开独立弹窗。
2. 评论弹幕脚本导入和文件导入后的仪表盘改为通过“查看导入结果”按钮打开独立弹窗。
3. 评论弹幕 AI 分析报告改为通过“查看分析结果”按钮打开独立弹窗。
4. 生成建议、导入结果、生成反馈报告成功后自动打开对应弹窗。

本轮不做：

1. 不新增后端接口。
2. 不新增路由页面。
3. 不调整数据库表结构。
4. 不改变已有 LLM 分析和脚本采集逻辑。

## 设计方案

前端新增 `resultModalTarget` 作为结果弹窗状态：

```text
prePublishSuggestion -> 发布前优化建议
feedbackDashboard    -> 评论弹幕导入仪表盘
feedbackReport       -> 反馈分析报告
```

每个 `resultModalTarget` 只展示当前阶段对应的结果，不做跨阶段 tab 切换。选择弹窗而不是新页面的原因：

1. 当前创作工作台仍是单页 MVP，路由还没有承载多页面工作流。
2. 结果数据已经存在于 `CreatorWorkspace.vue` 状态中，弹窗可以复用现有 API 返回值。
3. 弹窗能保留当前任务上下文，用户关闭后仍回到原来的输入阶段。

## 编码实现

修改文件：

```text
link-agent-frontend/src/components/CreatorWorkspace.vue
link-agent-frontend/src/styles/theme.css
```

关键实现点：

1. `openResultModal` 只允许打开已有结果，避免空弹窗误导用户。
2. 切换任务、创建新任务或重新保存评论弹幕样例时会清理弹窗状态，避免旧结果串到新任务。
3. 原先表单下方的大块 `creator-result-grid` 迁移到 `creator-result-modal` 内部。
4. 页面主体只保留阶段内结果入口按钮和轻量状态提示。
5. 发布前建议生成后，发布前区域会出现“发布前 AI 分析结果已生成”入口卡片，避免用户不知道结果在哪里。

## 测试验证点

作者本地前端检查：

```bash
cd link-agent-frontend
npm run type-check
npm run build
```

联调验收：

1. 点击“生成建议”后，应自动弹出发布前优化建议弹窗。
2. 关闭弹窗后，发布前优化区应显示“发布前 AI 分析结果已生成”入口卡片，不再在下方铺开结果明细。
3. 点击“拉取并导入”或“导入文件”后，应自动弹出评论弹幕导入结果弹窗。
4. 评论弹幕页不再直接铺开仪表盘，只通过“查看导入结果”进入。
5. 点击“分析反馈”后，应自动弹出反馈分析报告弹窗。
6. 切换任务后，旧任务的结果弹窗不应继续停留在页面上。
