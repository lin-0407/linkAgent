# 阶段 6.4 - 发布前优化证据化建议链路

## 一、需求分析

目标用户是 B 站 UP 主和内容运营者。

本阶段解决的问题是：发布前优化建议不能只给结论，还要能回到任务材料、创作者偏好、视频类型语境和同类案例，说明为什么这样建议。

本阶段做：

- 在发布前优化生成前收集证据。
- 证据来源包括任务材料、手动偏好、历史偏好与类型语境、同类案例检索结果。
- 直连 LLM 路径和 Agent 路径共用同一份证据包。
- 保存 `evidence_refs`、`missing_info`、`generation_mode`、`quality_status` 到 `creator_suggestion`。
- 要求标题建议和高优先级修改计划尽量输出 `evidenceIds`、`confidence`、`assumption`。

本阶段不做：

- 不新增发布前建议审查器。
- 不做用户反馈闭环。
- 不新增前端证据展示 UI，只先扩展响应字段和类型。
- 不重构 Multi Agent 编排。

## 二、设计方案

新增 `PrePublishEvidenceCollector`，在建议生成前完成证据收集：

```text
PrePublishSuggestionService
  -> buildPreferencePromptContext
  -> PrePublishEvidenceCollector.collect
  -> buildUserPrompt / buildAgentTaskPrompt
  -> buildSuggestionRecord
  -> creator_suggestion.evidence_refs
```

证据对象使用 `PrePublishEvidenceRef`：

| 字段 | 说明 |
|---|---|
| `evidenceId` | 给模型引用的证据编号，例如 E1 |
| `type` | 证据类型，例如 TASK_MATERIAL、CREATOR_PREFERENCE、REFERENCE_CASE |
| `sourceName` | 人类可读来源名 |
| `sourceRef` | 可回查来源标识 |
| `quote` | 原文摘录 |
| `summary` | 为什么这条证据可用 |
| `confidence` | 证据置信度 |

## 三、数据库字段

`creator_suggestion` 新增：

| 字段 | 说明 |
|---|---|
| `evidence_refs` | 发布前优化可引用证据 JSON |
| `missing_info` | 影响建议准确性但当前缺失的信息 JSON |
| `generation_mode` | 生成模式，区分直连模型证据化和 Agent 证据化 |
| `quality_status` | 质量状态，本阶段为 EVIDENCE_COLLECTED |

已有本地库通过 `init.sql` 末尾的条件式 `ALTER TABLE` 补字段。

## 四、验证点

作者执行后端编译时，应确认：

- `PrePublishSuggestionService` 构造器注入正常。
- `CreatorSuggestionResponse` 参数数量和 `toResponse` 对齐。
- `creator_suggestion` 表字段存在。
- 发布前优化响应里有 `evidenceRefs`、`generationMode`、`qualityStatus`。
