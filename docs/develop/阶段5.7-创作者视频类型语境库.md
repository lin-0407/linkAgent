# 阶段 5.7 - 创作者视频类型语境库

> 承接路线：RAG 案例库检索（5.1/5.2） → 设置面板（5.6） → **创作者视频类型语境库（5.7）**。
>
> 本阶段定位：把“不同类型视频应该怎么表达”沉淀成创作者私有语境库，并在发布前优化时自动注入提示词。它不是全网热梗爬虫，也不是替代评论弹幕证据的 RAG。

---

## 一、需求分析

### 1. 背景与痛点

- 只靠通用 RAG 案例库，会给出“别人的优质视频怎么做”，但不一定符合当前创作者自己的表达习惯。
- 不同视频类型的关键词、黑话、标题套路和慎用表达不一样，统一塞进一个偏好记忆会互相污染。
- 用户不应该每次手动复制“这个赛道常用词”和“这个赛道不能说的话”。
- 联网抓热梗太细，也容易引入无关内容。更适合 MVP 的做法是让用户在真实使用中逐步保存、采纳、降权。

### 2. 目标用户

- 做多个内容类型的 B 站 UP 主。
- 需要复用过往有效表达方式的创作者。
- 希望发布前优化更贴近自己账号语气和赛道语境的用户。

### 3. 本阶段做什么

1. 创作任务增加 `videoType`，作为语境库隔离维度。
2. 新增创作者语境词条表，保存关键词、黑话、梗、标题套路、观众关注点和慎用表达。
3. 新增语境词条 API，支持保存、查询、禁用、接受和拒绝反馈。
4. 发布前优化在“沿用历史偏好”时自动加载当前视频类型语境。
5. 前端创作工作台增加视频类型选择、语境库预览、语境管理弹窗。
6. 前端支持把发布前优化结果中的受众判断、标题建议、标签建议保存为当前类型语境。

### 4. 本阶段不做什么

- 不做全网热梗自动采集。
- 不做后台定时采集。
- 不把语境库当作事实证据库。
- 不把评论弹幕自动抽取语境做成强流程。
- 不引入新的向量库或检索链路。

## 二、设计方案

### 2.1 数据结构

`creator_task` 增加字段：

| 字段 | 说明 |
|---|---|
| `video_type` | 视频类型，用于按创作赛道加载对应语境库 |

新增表：`creator_context_term`

| 字段 | 说明 |
|---|---|
| `term_id` | 词条唯一 ID |
| `user_id` | 创作者隔离维度 |
| `video_type` | 视频类型，`GLOBAL` 表示全局通用 |
| `term` | 展示文本 |
| `normalized_term` | 归一化文本，用于去重 |
| `term_type` | `KEYWORD`、`SLANG`、`MEME`、`TABOO`、`TITLE_PATTERN`、`AUDIENCE_CONCERN` |
| `polarity` | `POSITIVE`、`NEGATIVE`、`NEUTRAL` |
| `source_type` | `USER_SAVE`、`AI_ACCEPTED`、`COMMENT_EXTRACTED`、`USER_REJECTED`、`VIDEO_SUCCESS` |
| `evidence_text` | 为什么保存这个词条 |
| `weight` | 注入提示词时的排序权重 |
| `usage_count` / `accept_count` / `reject_count` | 后续权重闭环依据 |
| `enabled` | 是否参与提示词注入 |

### 2.2 后端模块

| 类 / 文件 | 职责 |
|---|---|
| `CreatorContextController` | 语境库 HTTP API |
| `CreatorContextService` | 词条保存、查询、权重反馈和提示词摘要生成 |
| `CreatorContextMapper` | MyBatis 注解 SQL |
| `CreatorContextTermRecord` | 表记录映射 |
| `CreatorContextTermCreateRequest` | 保存词条入参 |
| `CreatorContextTermFeedbackRequest` | 接受 / 拒绝反馈入参 |
| `CreatorContextTermResponse` | 词条响应 |
| `CreatorContextBundleResponse` | 语境包响应，用于前端或 Agent 调试 |

### 2.3 API 设计

#### 保存词条

```http
POST /api/creator/context/terms
Content-Type: application/json
```

```json
{
  "userId": "default",
  "videoType": "知识科普",
  "term": "避坑",
  "termType": "KEYWORD",
  "polarity": "POSITIVE",
  "sourceType": "USER_SAVE",
  "sourceTaskId": "task-id",
  "evidenceText": "这个词适合当前类型的标题表达"
}
```

同一用户、同一视频类型、同一归一化词条、同一词条类型会走 upsert，不重复插入。

#### 查询词条

```http
GET /api/creator/context/terms?userId=default&videoType=知识科普&includeDisabled=false&limit=50
```

#### 获取提示词语境包

```http
GET /api/creator/context/bundle?userId=default&videoType=知识科普&scene=PRE_PUBLISH
```

#### 禁用词条

```http
DELETE /api/creator/context/terms/{termId}
```

#### 反馈词条

```http
POST /api/creator/context/terms/{termId}/feedback
Content-Type: application/json

{
  "accepted": true
}
```

### 2.4 发布前优化接入

`PrePublishSuggestionService` 在构建用户提示词时读取两类长期上下文：

- `CreatorPreferenceService.buildPromptContext(userId)`：创作者历史偏好。
- `CreatorContextService.buildPromptContext(userId, videoType, "PRE_PUBLISH")`：当前视频类型语境。

偏好模式规则：

| 模式 | 语境库处理 |
|---|---|
| `USE_HISTORY` | 历史偏好和视频类型语境都正常注入 |
| `IGNORE_HISTORY` | 不注入历史偏好，也不注入视频类型语境 |
| `EXPERIMENT` | 注入，但提示 LLM 只作为避坑参考 |

### 2.5 前端接入

| 位置 | 行为 |
|---|---|
| 任务表单 | 新增视频类型选择 |
| 任务列表 | 展示视频类型 |
| 发布前优化面板 | 展示当前类型语境词条预览 |
| 结果弹窗 | 标题建议、标签建议、受众判断可保存为语境词条 |
| 语境库弹窗 | 支持手动新增、提高权重、降低权重、禁用 |

### 2.6 为什么不用混合检索

这批数据不是大规模文档，也不是需要向量语义召回的案例库。

它更像“创作者自己的表达规则表”。第一版直接用 MySQL 按 `userId + videoType + weight` 排序就够了。

后续如果语境词条变多，可以再做：

- 按场景过滤。
- 按词条类型配额。
- 从评论弹幕候选中半自动抽取。
- 失败复盘后自动降权。

## 三、编码实现范围

### 3.1 后端

- 新增 `com.link.linkagent.creator.context` 包。
- `creator_task` 增加 `videoType` 字段传输和持久化。

### 3.2 前端

- `types/creator.ts` 增加任务视频类型和语境库类型。
- `api/creator.ts` 增加语境库接口客户端。
- `CreatorWorkspace.vue` 增加视频类型选择、语境库预览、语境管理弹窗和从建议保存语境的按钮。
- `theme.css` 增加语境库相关样式。

## 四、验证清单

后端：

- 创建任务时可保存 `videoType`。
- 更新任务视频类型后任务状态回到 `DRAFT`。
- 保存同一词条不会重复插入，会提升权重。
- 禁用词条后不再进入 `bundle`。
- 接受词条会加权，拒绝词条会降权，低权重会禁用。
- 发布前优化 `USE_HISTORY` 会注入当前视频类型语境。
- 发布前优化 `IGNORE_HISTORY` 不注入语境库。

前端：

- 新建 / 编辑任务时可选择视频类型。
- 切换任务后语境库预览跟随当前视频类型刷新。
- 手动新增词条后列表刷新。
- 从标题、标签、受众判断保存词条后能在语境库看到。
- 提高权重、降低权重、禁用按钮能调用后端并刷新。
