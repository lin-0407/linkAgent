# 阶段 4.4.1.1：发布前优化消息流

## 需求分析

本轮服务对象是已经创建创作任务的 B 站 UP 主和内容运营者。

要解决的具体问题是：发布前优化不能再只是“点按钮后等 LLM 结果”，用户需要先看到系统已经读取了哪些任务材料，并且可以在正式生成建议前追加自己的补充要求。

输入数据来源：

1. 用户在阶段 4.1 主动创建的创作任务。
2. 用户主动输入的标题草稿、简介草稿、文稿和字幕。
3. 用户在工作流输入框中主动补充的发布前优化要求。

本轮只做：

1. 新增发布前优化工作流会话。
2. 将任务材料装载成消息流。
3. 支持查询历史消息。
4. 支持用户发送补充要求消息。
5. 前端展示消息流、材料详情和底部输入框。

本轮不做：

1. 不接 SSE。
2. 不把 LLM 分析步骤写入消息流。
3. 不做发布前建议确认。
4. 不做附件上传。
5. 不做评论弹幕导入、仪表盘和追问。

## 设计方案

### 后端模块

新增包：

```text
com.link.linkagent.creator.workflow
├── controller
├── service
├── mapper
└── model
```

核心类：

| 类 | 说明 |
|---|---|
| `CreatorWorkflowController` | 工作流 HTTP 接口 |
| `CreatorWorkflowService` | 会话创建、材料消息装载、用户消息保存 |
| `CreatorWorkflowMapper` | 工作流会话与消息表访问 |
| `CreatorWorkflowSessionRecord` | 会话表记录 |
| `CreatorWorkflowMessageRecord` | 消息表记录 |
| `CreatorWorkflowSessionResponse` | 会话响应，包含当前消息列表 |
| `CreatorWorkflowMessageResponse` | 消息响应 |

### 数据表

新增：

```text
creator_workflow_session
creator_workflow_message
```

为什么先只建会话和消息表：

1. 工作流消息必须先能持久化，SSE 才有断线恢复基础。
2. 发布前建议确认需要依赖会话状态，不能只存在前端内存里。
3. 第一轮不需要附件表和 step 表，避免提前做空结构。

### API

```text
POST /api/creator/tasks/{taskId}/workflow/pre-publish/start
GET  /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/messages
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/messages
```

入参校验：

1. `taskId` 必填，最长 64。
2. `sessionId` 必填，最长 64。
3. `userId` 可选，最长 64；当前单人工作台前端不传。
4. `content` 必填，最长 2000。

### 前端接入

修改：

```text
src/types/creator.ts
src/api/creator.ts
src/components/CreatorWorkspace.vue
src/styles/theme.css
```

交互流程：

```text
用户选择任务
  -> 前端调用 start 接口
  -> 后端创建或恢复 PRE_PUBLISH 会话
  -> 后端按顺序写入系统消息、材料摘要消息、Agent 提示消息
  -> 前端展示消息流
  -> 用户点击材料消息查看完整材料
  -> 用户在底部输入框发送补充要求
  -> 后端保存 USER 消息
```

## 测试验证点

正常路径：

1. 创建创作任务后进入发布前优化页，应自动创建工作流会话。
2. 消息流中应出现进入阶段、读取任务、加载材料、Agent 准备分析等消息。
3. 点击材料摘要消息，右侧应显示完整材料内容。
4. 输入补充要求并发送，应新增一条 `USER` 消息。
5. 刷新消息后，历史消息应仍然存在。

边界路径：

1. 任务不存在时返回 404。
2. 任务没有材料时返回 400。
3. `content` 为空时参数校验失败。
4. `content` 超过 2000 字时参数校验失败。
5. 会话不存在时返回 404。
6. 会话状态为 `FAILED` 或 `CANCELLED` 时不允许继续发送消息。

cd backend

```

```
