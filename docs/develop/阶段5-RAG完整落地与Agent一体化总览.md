# 阶段 5 - RAG 完整落地与通用 Agent 一体化（总览）

> 承接阶段 4（UP 主智能工作台）。阶段 5 把 RAG 从“反馈专用、默认关的最小闭环”升级为产品级能力，并把通用 ReAct Agent 内核与创作工作台合并为一体。本文件是阶段 5 的真相来源，并**细化刷新**阶段 4 大纲中的平台数据边界（见 §3）。

## 1. 四个方向决策（作者已拍板）

| 维度 | 决策 | 含义 |
|---|---|---|
| 一体化 | 后端以 Agent 为核心 | 通用 ReAct 内核 + ToolRegistry 成为工作台编排大脑，创作能力封装成 Agent 工具 |
| RAG 知识范围 | 跨分区「优品 + 竞品」视频案例库 | 给 Agent 注入高质量领域知识，而不是只检索创作者自己的历史 |
| 检索亮点 | 全做 | 混合检索 + RRF、查询改写/多查询/HyDE、分块 + 父子召回 + 富元数据、Rerank |
| 基础设施 | 可提供但保持开关 | 默认可关，关掉时优雅降级到 SQL，演示成本可控 |

## 3. 数据边界刷新（重要）

- 阶段 4 红线「**部署后端不做批量 / 定时后台采集**」**继续有效**。
- 阶段 5 新增：知识库语料通过 `scripts/` 下的**离线采集脚本**获取——作者本地用系统 cron 运行天 / 周 / 月榜 top-N 或定向 BV，产出标准 JSON，再经导入接口**合规入库**（AI 清洗 + 质量打分）。
- 即：采集只发生在**离线脚本**、由作者运行；**部署的演示后端零采集**。这样既拿到高质量语料，又保住合规与“AI 应用工程化”的简历叙事。

## 4. 可讲述的技术亮点（简历主线）

- **存储策略**：跨分区案例库、父子分块（small-to-big 打底）、富元数据、MySQL 事实源 + 向量副本、专用 Milvus 集合隔离、批次受限的成本可控索引、分区归一化质量打分。
- **检索策略**：查询改写 / 多查询 / HyDE、向量 + 关键词混合 + RRF 融合、Rerank 重排序、父子召回、“向量 → 事实回查 → SQL 兜底”的分层优雅降级。
- **一体化**：ReAct 内核 + 工具注册表编排创作能力，RAG 作为 Agent 工具注入领域知识，消灭“通用 Agent / 工作台两座孤岛”。
