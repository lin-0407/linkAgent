# S4a：视频片段合成基础

日期：2026-10-20。作者明确暂缓具体视频模型选型，先实现功能，后续通过配置入口自行添加模型。本步落实自有视频与生成片段共用的确定性合成基础；S3 的完整试映调度、发布包等工作仍未完成，不以此越过原门禁。

## 需求与范围

创作者的一条作品可以混用图文、录屏/实拍或以后模型返回的片段。需要按真实区间截取画面，明确选择是否保留原声，并与已有旁白、字幕、视频版本和恢复链路一起工作。

本步实现 RenderInputV2 的 VIDEO_CLIP、区间、显示和声音处理，并接入既有 Java 固定工程、自动蓝图、存储与版本登记。输入由后端准备为本地可信工程；没有新增公开文件路径接口、业务表、前端页面、Agent 或供应商调用。

## 受控工程契约

V1 严格按原协议读取，未知字段仍拒绝。V2 保留原顶层结构，新增以下受控内容：

- 资产：`video/mp4` 的 `.mp4` 或 `video/quicktime` 的 `.mov`；实际固定以 MP4/MOV 解复用器探测，画面 H.264/HEVC、单视频流、至多一条音轨。源文件继续受单个 32MiB、总计 256MiB 约束。
- 场景：`layout=VIDEO_CLIP`，`clip` 精确包含 `assetId/sourceStartMs/sourceEndMs/fit/audioMode/gainDb`，不接受自由滤镜或命令。元数据标题不会覆盖视频画面，正文必须为空；字幕仍单独绘制。
- 区间：毫秒整数、结束不包含，长度须对应场景帧数，允许整数毫秒到帧的量化误差至多 1ms。实际探测再次核对源视频时长；不靠加速、循环或定格补齐不足片段。
- 显示：`CONTAIN` 完整显示并留边，`COVER` 居中裁切铺满，由工程明确选择。FFmpeg 读取方向及像素比例，按原时间戳转换至目标帧率。
- 声音：`MUTE` 不取原声，可单独叠旁白；`ORIGINAL` 只保留原声，旁白必须为 null；`MIX` 明确叠加原声与旁白，旁白必须存在。两路衰减范围均沿用 −24～0dB，混音超过峰值范围时拒绝，不静默改变用户音量。
- V2 的 `voice=null` 表示该场景没有旁白。显式全片无声音可输出静音 AAC；原 V1 的静音异常检查保持原规则。
- 有旁白的场景仍必须提供绑定实际音频的字幕。原声可以引用片段资产的已核实字幕，也可没有对白字幕；原声 cue 还需处于实际音轨覆盖的截取范围。渲染器不生成 ASR，不把测试音当作对白转写。

完整示例见 [接入说明](../reference/视频片段合成接入说明.md)。这是当前已实现的 V2 子集，尚未包括独立音乐/BGM 字段、上传与规范化服务或完整故事板编辑 API。

## 合成与一致性

`clips.py` 使用现有受控子进程执行器实际探测、裁剪和逐帧解码，始终限制为本地 file/pipe 协议。只持有当前视频帧和一个场景音轨，工具输出有上限；所有子进程共用超时、取消和部署环境隔离。HDR、异常元数据、过大画面等明确要求先规范化。

画面与原声使用同一个视频时间原点，保留真实音轨延迟。范围内完全没有原声时不假装保留成功；原声音轨结束后不拉伸对白。封面和抽帧来自实际输出，视频场景不使用静态标题卡冒充画面。

输出清单仍为版本 1；V2 输入额外记录 `inputSchemaVersion=2` 和 `clipSources` 的实际源时长、时间原点及适用原声范围。Java 冻结服务接受 V1/V2，产物验收检查对应输入版本。静音只依据逐场景明确选择判定，不信任清单自报“静音”标记。

片段区间、声音选择及来源摘要进入已有内容指纹。后台重试仍只改运行/尝试身份，沿用独立工作目录、实际摘要检查、六步自动蓝图和 PUT/HEAD/GET 内容核验。没有取消原制作、完整试映或发布门禁。

## 验证与边界

使用自制红/绿/蓝视频和已知频率音轨检查实际截取画面、原声、旁白与混音，另检查方向、竖屏显示、非零时间原点、音轨延迟、缺原声、原声范围、静音、非法区间及实际取消。旧图文渲染测试同时执行。

Java 原生测试接收实际原声/静音片段；真实隔离 MySQL/RustFS 调度测试分别用 V1 和含 V2 视频场景的 84.167 秒中文工程完成自动蓝图、存储登记、同版恢复、原 FFprobe 与删除。发布确认仍通过数据库夹具准备，不能视为真实页面验收。

最终命令、计数与未验证项见 [验证记录](../error/视频片段合成S4a验证记录.md)。尚未实现素材上传页面、完整素材库、用户模型配置入口、真实生视频调用、短样片业务运行/下载及局部编辑页面，公开执行入口仍关闭，未部署。具体模型选型不作为继续开发这些共用能力的前置。
