# 阶段 4.11：创作者语境与建议质量升级

## 需求分析

本阶段服务的目标用户是正在准备发布视频的 B 站 UP 主，以及用本项目做作品集演示的作者。

用户反馈的核心问题是：AI 给出的回答和建议太宽泛，缺少对当下内容创作者真实决策压力的理解，结果看起来像通用文案助手，不能指导下一步修改。

本阶段先解决发布前优化建议质量，不直接开始 RAG。

原因：

1. RAG 解决的是“证据从哪里来”，当前更大的问题是“分析框架太浅”。
2. 如果结构仍然只要求摘要、标题、标签，即使接入外部材料，模型也可能只是把空泛建议换成带证据的空泛建议。
3. 发布前优化是工作台最先被用户感知的结果，先把这里做深，后续反馈追问和 RAG 才有稳定承接点。

本阶段做：

1. 在发布前优化结果中新增创作者困境、观众钩子、内容定位和可执行修改计划。
2. 升级标题建议结构，让每个标题解释观众心理、点击理由、信任风险和适用场景。
3. 前端结果弹窗展示这些高信号字段。
4. 复盘和竞品阶段读取新增字段，让后续分析继续沿用创作者语境。

本阶段不做：

1. 不接入向量库。
2. 不抓取或批量采集平台数据。
3. 不模拟 B 站推荐算法。
4. 不新增复杂多 Agent 编排。

## 设计方案

### 数据结构

`creator_suggestion` 新增字段：

| 字段 | 说明 |
|---|---|
| `creator_dilemma` | 本期创作者最可能纠结或做错的表达问题 |
| `audience_hook` | 观众愿意点击、继续观看、收藏或评论的核心动机 |
| `content_positioning` | 本期内容定位和差异化方向 |
| `actionable_revision_plan` | 可执行修改计划 JSON |

标题建议仍保存在 `title_suggestions`，但对象结构增强：

```json
{
  "title": "标题",
  "viewerPsychology": "对应的观众心理",
  "clickReason": "为什么会点",
  "trustRisk": "可能损伤信任的点",
  "bestScenario": "最适合的使用场景",
  "reason": "推荐理由",
  "risk": "风险提醒"
}
```

### 为什么不拆子表

当前每个任务仍只保留一份最新发布前建议。新增字段属于同一个分析结果的一部分，先放在 `creator_suggestion` 中最简单。

等后续出现标题版本对比、人工批注、多人协作，再拆标题建议子表或建议版本表。

### Prompt 质量约束

发布前优化 Prompt 增加三类硬约束：

1. 必须围绕创作者困境、观众点击动机、内容差异化、标题信任感和下一步动作。
2. 禁止只写“更吸引人”“提升互动”“优化表达”等空泛话术。
3. 每条建议都要说明为什么当前材料会让观众点击、跳出、怀疑或收藏。

## 编码实现

后端修改：

- `PrePublishSuggestionService`
  - 解析新增 JSON 字段。
  - 升级系统 Prompt 和标题建议结构。
- `CreatorSuggestionRecord`
  - 新增 4 个字段及 getter/setter。
- `CreatorSuggestionResponse`
  - 响应新增 4 个字段。
- `CreatorSuggestionMapper`
  - insert、update、select、result map 补齐新列。
- `CreatorCompetitorService`、`CreatorReportService`
  - 发布前建议上下文补充创作者困境、观众钩子、内容定位和可执行修改计划。
- `init.sql`
  - `creator_suggestion` 建表字段新增。
  - 为已有本地库补充条件式 `ALTER TABLE`。
  - 样例数据补充高信号字段。

前端修改：

- `src/types/creator.ts`
  - `CreatorSuggestion` 类型补齐新增字段。
- `CreatorWorkspace.vue`
  - 发布前结果弹窗新增创作者困境、观众钩子、内容定位和可执行修改计划。
  - 标题建议展示观众心理、点击理由、信任风险和适用场景。

## 测试验证点

作者本地验证命令：

```bash
cd E:\linkAgent\linkAgent\backend
mysql -u root -p < src/main/resources/sql/init.sql
mvn test
```

```bash
cd E:\linkAgent\linkAgent\link-agent-frontend
npm run type-check
npm run build
```

重点检查：

1. 旧任务已有发布前建议时，执行 `init.sql` 后不应出现未知列错误。
2. 新生成建议时，响应中应包含 `creatorDilemma`、`audienceHook`、`contentPositioning`、`actionableRevisionPlan`。
3. LLM 输出缺少新字段时，旧字段仍能正常解析，新增字段为空。
4. 前端弹窗在新增字段为空时显示兜底文案，不影响旧数据查看。
5. 复盘报告和竞品分析仍能读取发布前建议上下文。

## 后续扩展

下一步建议继续做“反馈分析质量升级”，让评论弹幕分析也输出创作者焦虑、观众误解来源、互动回应策略和下一期动作。

RAG 可以放在质量结构稳定后接入，用于给反馈追问补充证据来源，而不是替代分析框架。
