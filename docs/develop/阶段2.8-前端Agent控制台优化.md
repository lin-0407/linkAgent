# 阶段 2.8 - 前端 Agent 控制台优化

## 本阶段目标

在不改动后端接口契约、不引入额外 UI 组件库的前提下，优化现有 Vue3 单页控制台，让它更适合作为作品集项目中的 Agent 调试入口。

## 优化范围

- 优化侧边栏会话区，保留当前 session、会话列表、新会话入口。
- 增加运行状态、会话数、消息数、最新 ReAct 步数指标。
- 增加空态快捷提示词，用于快速验证短期记忆、工具调用和多步推理。
- 优化 ReAct steps 展示结构，让 Thought、Action、Observation 更容易阅读。
- 优化输入区，增加字符数反馈。
- 调整整体视觉风格为偏工程控制台的深色界面，减少普通聊天页的弱业务感。
- 增强移动端布局，让顶部统计、消息区和输入区在窄屏下仍然可用。

## 当前实现位置

- 前端入口页面：`link-agent-frontend/src/App.vue`

## 设计取舍

1. 本阶段没有拆分组件。
   当前前端规模仍然很小，过早拆分会增加文件跳转成本。等后续出现记忆管理页、工具管理页、Trace 页面时，再按业务边界拆分组件更合适。

2. 本阶段没有引入 UI 库。
   项目目标是先跑通企业级 Agent 框架主链路，前端只需要具备清晰、稳定、可展示的控制台体验。组件库会带来额外样式覆盖和依赖维护成本。

3. 本阶段没有改后端接口。
   页面优化只依赖已有 `/api/agent/chat`、`/api/agent/sessions`、`/api/agent/sessions/{sessionId}` 接口，避免把 UI 优化和后端行为变更混在一起。

## 二次优化：设计美感与人性化

本轮根据页面观感反馈，继续调整了前端体验：

- 将偏冷、偏硬的控制台风格调整为更温和的 Agent Studio 风格。
- 增加品牌标识 `LA`，让页面第一眼有明确识别点。
- 将英文按钮和状态文案替换为更贴近中文用户的表达。
- 空态区域增加柔和主视觉和更自然的引导文案，减少“空页面”的冷启动压力。
- 快捷提示词增加“试试”标签，让用户知道这些内容可以直接点击。
- 消息气泡、输入框、按钮统一为轻质卡片风格，提升阅读舒适度。
- 保留 ReAct 调试能力，但展示方式更克制，不让技术细节压过主对话。

## 四次优化：前端结构工程化

本轮将单文件页面拆成更接近真实项目的结构，为后续 SSE、记忆管理页和工具管理页预留扩展空间。

### 新增目录与职责

- `src/types/agent.ts`
  统一维护 Agent 前端类型，例如 `AgentStep`、`ChatMessage`、`SessionListItem`。

- `src/api/agent.ts`
  统一封装 `/api/agent/chat`、`/api/agent/sessions`、`/api/agent/sessions/{sessionId}` 调用。

- `src/composables/useAgentChat.ts`
  维护聊天页状态、发送消息、加载会话、打开历史会话、滚动到底部等业务逻辑。

- `src/components/AgentSidebar.vue`
  负责品牌区、会话列表、状态指标。

- `src/components/TopBar.vue`
  负责顶部标题和消息统计。

- `src/components/MessageList.vue`
  负责消息列表、空态和加载态。

- `src/components/MessageBubble.vue`
  负责单条消息和 Markdown 渲染。

- `src/components/ReactTimeline.vue`
  负责 ReAct steps 时间线展示。

- `src/components/ChatComposer.vue`
  负责输入框、自适应高度、发送按钮。

- `src/components/ErrorNotice.vue`
  负责错误状态展示和排查提示。

### 设计取舍

1. CSS 暂时仍保留在 `App.vue` 的全局 `<style>` 中。
   当前页面视觉样式高度耦合，先拆逻辑和组件更有收益。等后续页面增加后，再把样式按 `styles/` 或组件局部样式拆分，避免现在过度拆分导致查样式成本变高。

2. 没有引入 Pinia。
   当前只有一个聊天工作台页面，`useAgentChat` 已经足够表达状态边界。等出现多页面共享状态，例如长期记忆页和工具管理页共用会话状态时，再考虑 Pinia。

3. 没有改变后端接口。
   本轮是前端结构优化，只把原有 `fetch` 调用集中到 API 层，没有调整请求路径和响应结构。

## 三次优化：产品体验补齐

本轮继续补齐前端细节，让页面从“能看”进一步接近“可用的 Agent 工作台”：

- 消息区阅读宽度收敛，用户消息和 Agent 消息分别使用不同最大宽度，减少长文压迫感。
- Markdown 补充表格、分割线、列表、代码块等样式，提升复杂回答的阅读稳定性。
- ReAct steps 改为时间线结构，用“第 N 步、思考、行动、观察”的层级帮助理解 Agent 推理过程。
- 空态增加能力标签，直接展示当前页面支持短期记忆、工具调用、ReAct 轨迹、Markdown/公式。
- 会话列表增加当前会话标识、preview 省略和“继续这个会话”提示。
- 错误状态改为说明型错误卡片，保留原始错误码，同时给出排查方向。
- 输入框支持自动增高，增加 `Enter 发送，Shift + Enter 换行` 提示。
- 发送按钮 hover 仅在可用状态触发，避免禁用态也出现交互反馈。

