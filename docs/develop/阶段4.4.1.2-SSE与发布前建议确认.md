# 阶段 4.4.1.2：SSE 与发布前建议确认

## 需求分析

本轮服务对象是已经进入发布前优化阶段的 B 站 UP 主和内容运营者。

阶段 4.4.1.1 已经能把任务材料装载成消息流，但“生成建议”仍然更像一次普通表单提交。本轮要解决的问题是：

```text
让发布前优化具备可实时展示、可回放步骤、必须用户确认后才能推进阶段的工作流能力。
```

输入数据来源仍然只允许：

1. 用户主动创建的创作任务和材料。
2. 用户在工作流消息框中主动输入的补充要求。
3. 用户在发布前优化表单中主动填写的创作者偏好、标题风格和额外要求。

本轮不做：

1. 不做评论弹幕文件导入。
2. 不做附件上传。
3. 不做复杂多 Agent 协作。
4. 不做建议版本对比。
5. 不自动推进到评论弹幕阶段。

## 设计方案

### 后端接口

新增接口：

```text
GET  /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/events
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/pre-publish/analyze
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/pre-publish/confirm
```

保留旧同步接口：

```text
POST /api/creator/tasks/{taskId}/pre-publish/analyze
```

旧接口继续用于简单联调；工作流页面改走新接口。

### 表结构

新增：

```text
creator_workflow_step
```

用途：

1. 记录 `LOAD_CONTEXT`：读取任务材料。
2. 记录 `LLM_CALL`：调用发布前优化 Agent。
3. 记录 `SAVE_RESULT`：保存结果消息。
4. 记录 `CONFIRM_RESULT`：用户确认建议。

### 状态流转

```text
WAITING_USER_INPUT
  -> RUNNING
  -> WAITING_CONFIRMATION
  -> CONFIRMED
```

失败时：

```text
RUNNING -> FAILED
```

失败后允许用户补充消息并重新触发分析。

### 为什么要拆开生成与确认

阶段 4.2 的 `PrePublishSuggestionService.analyze` 会在生成建议后直接把任务状态更新为 `PRE_PUBLISH_ANALYZED`。

工作流模式不能这样做，因为用户还没有确认建议。处理方式是：

1. 抽出 `generateSuggestion`，只生成并保存建议。
2. 工作流分析调用 `generateSuggestion`，会话进入 `WAITING_CONFIRMATION`。
3. 用户调用 confirm 接口后，才把任务状态更新为 `PRE_PUBLISH_ANALYZED`。

### 后端修改

```text
CreatorWorkflowController

CreatorWorkflowMapper
CreatorSuggestionMapper
PrePublishSuggestionService
backend/src/main/resources/sql/init.sql
```

关键点：

1. SSE 事件只负责实时通知，不作为唯一状态来源。
2. 每条消息仍然先落库，再发布 `message_created` 事件。
3. 工作流分析会合并用户在消息流中主动输入的补充要求。
4. `confirm` 接口校验建议必须属于当前任务。

### 前端修改

```text
src/api/creator.ts
src/types/creator.ts
src/components/CreatorWorkspace.vue
src/styles/theme.css
```

关键点：

1. `EventSource` 订阅工作流事件。
2. 消息按 `messageId` 去重，避免本机 POST 返回和 SSE 推送造成重复显示。
3. 生成建议后停留在发布前优化页。
4. 点击“采用本轮建议”后才开放评论弹幕阶段。

## 测试验证点

### 正常路径

1. 创建任务后自动创建发布前优化工作流。
2. 前端显示 SSE 状态为“实时连接”。
3. 发送补充要求后，消息流新增用户消息且刷新后仍存在。
4. 点击“生成建议”后，消息流出现分析过程和结果消息。
5. 后端写入 `creator_workflow_step`。
6. 生成建议后会话状态为 `WAITING_CONFIRMATION`。
7. 点击“采用本轮建议”后会话状态为 `CONFIRMED`。
8. 任务状态更新为 `PRE_PUBLISH_ANALYZED`。
9. 评论弹幕阶段在确认前不可进入，确认后可进入。

### 边界路径

1. 任务不存在返回 404。
2. 会话不存在返回 404。
3. 任务没有材料时不允许分析。
4. 运行中重复点击生成建议返回 400。
5. 已确认会话不允许再次生成建议。
6. suggestionId 不属于当前任务时不允许确认。
7. LLM 调用失败时写入错误消息，会话状态变为 `FAILED`。
8. `FAILED` 后允许补充要求并重新触发分析。
9. SSE 断开后仍可通过刷新消息恢复历史消息。
