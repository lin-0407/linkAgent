# S4-3a 音乐、字幕与时长建议

日期：2026-10-21。承接 [S4-2 简报与故事板](视频自动制作-S4-2简报故事板与工程生成.md)，接口和示例见[使用说明](../reference/音乐字幕与时长建议接口说明.md)。本阶段只交付用户已有音乐、用户 SRT 和真实媒体时长建议，不能据此将完整 S4-3 标为完成。

## 需求与当前边界

创作者已经导入录音、音乐和视频片段后，需要把自己的背景音乐放入工程、把已有 SRT 绑定到实际音轨，并知道“录音比镜头长”该怎样处理。本阶段使用 S4-1 的 READY 素材和 S4-2 的不可变简报、故事板，不引入另一套制作状态机。

新增三项能力：

- 简报可明确选择一段已导入音乐，设置增益、淡入淡出和主音轨有声音时压低音乐。
- 把用户提供的相对音轨 SRT 导入指定场景，生成子故事板，保留旧版和原始请求身份。
- 查询真实录音、视频选段和量化场景的时长差，返回需用户选择的处理提案。

这些操作不发起音乐下载、文本模型、TTS 或 ASR 调用，不生成付费请求。普通文本模型故事板准备仍使用 S4-2 原有的显式估算和费用授权流程。业务主线继续为发布方案确认 → 制作蓝图 → 成片试映/媒体处理 → 实际发布 → BV 绑定 → 反馈与复盘；本阶段没有放开通用公开 FULL 制作入口。

## 简报音乐与不可变素材

`BriefInput` 增加可空的 `backgroundMusic`。未选择音乐时该字段不参与 JSON 序列化，原无音乐请求的摘要保持不变，同键重放仍可识别原简报。已保存简报不原地覆盖；更换音乐或参数需要新简报，再明确保存相应故事板。

背景音乐必须属于本简报 `assetIds` 选择范围、与任务归属一致，且 READY 素材的 `kind=MUSIC`。保存时沿用原素材快照和引用关系，后续工程从持久化私有对象、完整摘要和真实技术元数据恢复，不依赖短签。模型只能读取上下文中的受控目录，不能代替用户改写简报中的音乐设置。

音乐字段包括 `assetId/sourceInMs/sourceOutMs/gainDb/fadeInMs/fadeOutMs/ducking`。区间由用户选择，增益为 -36 至 0 dB，最多一位小数；淡入和淡出分别为 0 至 10000 毫秒，合计不能超过选区。`ducking` 必须明确提供布尔值。

保存简报只确认素材身份与基础字段，不等于音乐已经可渲染。编译器还要核对 NORMALIZED 文件确实为 48 kHz、双声道 PCM16 WAV，有可靠真实时长，选区未越界，且长度与全片帧长一致，最多允许一帧误差。当前 S4-1 音乐素材时长上限为 20 分钟；API 字段范围不能代替真实媒体上限。

## V2 音乐渲染

对应 renderer 版本为 `0.3.0`。V2 工程增加可选 `backgroundMusic`，V1 不接受该字段；不选音乐的已有工程继续使用原行为。

| 项目 | 受控行为 |
| --- | --- |
| 音乐范围 | 使用用户明确的源区间，从全片起点播放；不循环、不变速、不自动找歌或扩展选区 |
| 帧量化 | Java 工程固定 30 fps；音乐选区与全片允许最多一帧差，尾部容差不构成无限补齐 |
| 淡入淡出 | 在全片时间线上施加，不在每个镜头切换时重新开始 |
| 主音轨压低 | 对实际录音/原声主音轨的能量做检测，有声音时压低音乐，跨镜头保留包络状态 |
| 能力含义 | 能量压低不是语音识别、人物识别或 ASR，不区分人声与环境声 |
| 资产上限 | 音乐独占背景音乐角色时可至 64 MiB；其他单资产仍至 32 MiB，工程引用总量仍至 256 MiB |
| 来源验收 | 下载和渲染继续复核真实字节数、完整摘要、WAV 参数及选区边界 |

背景音乐不能借同一资产身份兼作旁白/视频音轨而套用较大上限。音乐参数进入实际工程内容摘要，修改音乐后必须重新确认相应制作范围，不能沿用旧内容指纹。

## SRT 导入与版本保存

新增 `StoryboardAudioModels.SubtitleImport` 和 `StoryboardAudioService`。接口收到目标故事板、场景和用户 SRT 后，读取该故事板的不可变简报与冻结素材，校验实际音轨，再复用 `StoryboardPersistence.saveWithRequestHash` 保存新版本。

SRT 必须是有效 UTF-8 文本，原文至多 64 KiB。支持开头 BOM、CRLF 和多行字幕正文；每条需要正整数且不重复的编号、`hh:mm:ss,mmm --> hh:mm:ss,mmm` 时间和非空正文。每场景最多 100 条，每条正文最多 120 字符；按序、不重叠，结束时间晚于开始时间。正文不能包含换行以外的控制字符。

只接受 `NARRATION` 和 `ORIGINAL` 场景：

- 用户录音字幕相对本场景所用录音起点。
- 视频原声字幕相对所选视频区间起点，仍须落在区间里真实存在的音轨范围内。原声晚于画面开始时，字幕不能提前到静音部分。

导入替换该场景的整个 `cues` 数组，其他场景保持不变。编译器检查目标场景的真实素材、声音和字幕范围，并检查全片 200 条字幕上限；其他场景尚缺录音或字幕，不妨碍逐场景补齐。返回的完整 `BoardView.check` 仍可能说明其他待准备问题，不能将导入成功显示为整片已制作完成。

保存的 `parentStoryboardId` 指向导入前版本，字幕时间来源标为 `USER_PROVIDED`。工作区修订、最新简报、活动制作互斥和任务归属仍由原持久化事务复核。不会覆盖旧故事板、当前成片或已有试映报告。

字幕导入使用稳定的作用域幂等键；摘要包含父故事板、场景、修订及 SRT 原文。即使两段文本经 BOM/换行规范化得到相同 cue，同键换原文也会拒绝。同键同请求重放返回原子版本；更换目标或内容应使用新的幂等键。

## 真实时长建议

`GET /storyboards/{storyboardId}/timing` 只读取冻结元数据和用户场景设置，不创建版本、运行或费用。场景按 30 fps 量化；旁白依据真实规范化 WAV 时长，原声依据所选视频与音轨的实际交集，全片依据总帧数。没有实际 TTS 音频时，返回“待生成”，不按中文字数虚构秒数。

背景音乐缺失、选区不足或越界也通过 `BGM_` 提案返回，要求重新选择区间、补充素材或明确修改全片时长；不会因场景对白足够长就忽略音乐不足。

例如场景为 2 秒、录音为 3 秒，报告返回 +1000 毫秒差异，并给出“延长镜头并重新确认全片时长”或“保持镜头、重新录音”的提案。录音较短时，可建议缩短场景或明确保留画面留白；视频不足时要求重新截取、缩短或补素材。超过单场景 30 秒的录音需拆分或重新录制。

提案不会自动执行。改变目标总长需要新简报，改变场景需要新故事板；之后继续通过当前工程检查与独立制作授权。报告中的 `requiresUserDecision` 只表示有需要处理或确认的提案，不是制作授权。

## 数据与验证口径

本阶段沿用现有简报、故事板及资产 JSON 和引用表，不增加数据库表或迁移框架。前端文件不属于本阶段实现范围。

最终验证：Java 完整 `clean test` 26 套件 441 项，439 通过、零失败/错误、2 项旧 S3 原生用例未开启；Python 渲染器 87 项全部通过。真实 MySQL 验证来源/引用/幂等和只读建议，原生音乐用例实际经过冻结、恢复、FFmpeg 和 Java 验收。完整命令、发现的问题及未验证部分见[审查与验证记录](../error/视频声音S4-3a审查与验证记录.md)。
