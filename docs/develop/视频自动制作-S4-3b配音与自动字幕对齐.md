# S4-3b 配音生成与自动字幕对齐

日期：2026-10-21。承接 [S4-3a 音乐、字幕与时长建议](视频自动制作-S4-3a音乐字幕与时长建议.md)，接口与示例见[接口说明](../reference/配音与自动字幕对齐接口说明.md)，实际命令与问题见[验证记录](../error/视频配音S4-3b验证记录.md)。

本阶段只交付“用户选择 TTS 的场景生成配音，并用实际音频转写时间生成字幕”的后端准备链路。它仍属于 S4-3 的一部分：完整时间线重排、环境声独立混音、用户采纳流程以及真实供应商验收都还没有完成。

## 需求与边界

新手往往没有录音设备。S4-2 的故事板可以明确选择 `TTS`，但当时只要出现 TTS 场景就整体拒绝，因为没有真实音频就不能渲染，也不能伪造字幕时间。本阶段补上中间那一段：

- 只对故事板里 `audioMode=TTS` 的场景生成配音；用户录音 `NARRATION`、视频原声 `ORIGINAL` 和无对白场景不会被改成配音。
- 生成音频保存为独立私有素材，记录供应商、模型、音色、请求标识、文稿摘要、真实音频摘要和时长。
- 字幕时间只来自对实际音频的转写；文稿与转写文本做确定性比对，低于阈值不生成新版本。
- 音频放不进镜头时返回延长场景或缩短文稿后重新生成的提案，不截断、不加速、不自动改片。
- 复用已有 PREPARE 运行、明确授权、费用预留/结算、租约与私有资产机制，不另建预算状态机。
- 没有真实密钥时完成协议适配与本地替身验证，保留“真实供应商未验收”的结论。

本阶段不发起文本模型调用，不下载音乐，不做 AI 视频生成，也不开放通用公开 FULL 入口。`executionAvailable` 仍为 `false`。

## 数据与状态机

新增两张表，沿用现有 `creator_creation_run`、`creator_creation_cost_entry` 和 `creator_creation_asset`：

`creator_creation_voice_job`：一条准备运行的配音归属，保存简报、来源故事板、幂等键与请求摘要，以及成功后保存的新故事板标识。

`creator_creation_voice`：每个场景一行，主键 `(run_id, scene_id)`，包含：

| 字段组 | 记录的事实 |
| --- | --- |
| 输入 | 场景顺序、用户确认文稿、文稿摘要、字符数、发起时的场景帧长 |
| 供应商 | provider、model、voice、合成请求标识、转写任务标识 |
| 音频 | 素材标识、规范化音频摘要/字节数/实际时长 |
| 对齐 | 转写段落、文稿相似度、待作者确认的提案、受控错误码 |

场景状态：`QUEUED → SYNTHESIZING → SYNTHESIZED → TRANSCRIBING → ALIGNED`，异常分支为 `NEEDS_REVIEW`、`FAILED`、`CANCELLED`。运行结束后仍有中间态时，由扫描按运行终态统一收口为取消或失败，不会长期显示“排队中”。

## 受理、授权与费用

接口先 `GET .../voice:estimate` 再 `POST .../voice`。估算只读，返回待配音场景、字符数、按配置单价的保守上界和阻断原因；`POST` 必须带 `Idempotency-Key`、当前工作区修订和 `maxAdditionalCostCny`。

受理使用 `CreationRuntimeService.startPreparation`：生成 `PREPARE` 运行和独立 `PREPARATION` 授权，运行、授权、任务行和场景行在同一事务内提交。同键重放返回原运行；同键改故事板、修订或金额会被拒绝。

费用按两类物理调用记账：

| 能力 | 计费依据 | 预留 | 结算 |
| --- | --- | --- | --- |
| `VOICE_TTS` | 提交的字符数 | 字符数 × 配置的每百万字符美元上界，按记账汇率折人民币 | 供应商回报字符数优先，缺失时用实际提交字符数 |
| `VOICE_ASR` | 实际音频秒数 | 音频时长 × 媒体 ASR 每秒单价 | 供应商回报用量；缺失记 `UNKNOWN` |

调用标识固定为 `voice-tts-<runId>-<sceneId>` 与 `voice-asr-<runId>-<sceneId>`，同一场景同一能力只允许一次物理发送。价格快照写入模型、音色、字符数或秒数、单价和汇率，只表示配置估算，不是供应商账单。

接管执行时会释放未发送的预留。只有 `sent_at` 为空、能够证明从未发送的预留才允许重新占用；已发送但结果不明的调用记为 `UNKNOWN`，不自动重发，并暂停后续新增付费调用，等待作者处理。

## 合成与私有资产

`SpeechSynthesisProvider` 是窄接口；`DashScopeCosyVoiceProvider` 按 DashScope 多模态生成协议提交 `model/input{text,voice,format,sample_rate}`，读取 `output.audio.url`（兼容 Base64 返回）和 `usage.characters`。密钥沿用媒体模块的 DashScope 配置，不新增第二份密钥。

真实调用在事务外执行，结果按以下顺序处理：

1. 校验返回字节为 WAV（`RIFF/WAVE` 头），否则明确失败，不把未知格式当成可用音频。
2. 用 `AssetMediaPreparer` 完整解码并规范化为 48 kHz 双声道 PCM16 WAV，取真实时长；编码、声道、采样率或时长不合格直接失败。
3. 原始音频与规范化音频分别上传到私有对象存储，`HEAD` 核对字节数，再下载规范化文件按 SHA-256 复核。
4. 短事务内写入 `creator_creation_asset`（`kind=NARRATION`、`status=READY`）和场景音频事实；场景更新带运行租约围栏，失败整笔回滚。

生成素材的 `metadata_json` 含 `original`、`normalized` 和 `generated{kind=TTS,provider,model,voice,format,sampleRate,textSha256,characters,runId,sceneId,storyboardId}`。故事板冻结快照引用的是规范化文件的对象键、字节数和摘要，不保存短签。

这样 S4-1 的素材页、引用历史和后续删除影响分析都能识别这段音频；但它没有浏览器上传过程，不能作为用户上传免检入口复用。

## 转写、字幕与文稿核对

转写直接复用 `SpeechRecognitionProvider`：对规范化音频生成 ASR 原生短签，提交后先保存供应商任务标识，再轮询。重启或接管后只按已保存的任务标识续查，不会重复提交；超过等待上限时把费用记为未知并失败，保留任务标识供作者核对。

拿到段落后：

- 只使用供应商给出的 `startMs/endMs`，按顺序裁剪到音频与场景范围；紧邻且合并后不超过 120 字符的片段会合并，间隔超过 400 毫秒不合并。
- 单场景超过 100 条或单条超过 120 字符时返回提案，不删词、不挪时间。
- 文稿与转写文本先去掉标点空白再做编辑距离比对，相似度低于配置阈值（默认 0.85）时标记 `VOICE_SCRIPT_MISMATCH`，保留音频但不生成字幕。
- 无人声、音频超出镜头、字幕超限同样进入 `NEEDS_REVIEW`，附带可执行的提案。

相似度是确定性算法结果，不是模型评分，也不能证明每个字都被正确念出；页面需要同时展示文稿与转写原文供作者确认。

## 新故事板版本与工程编译

所有场景 `ALIGNED` 时，才保存新故事板：

- `parentStoryboardId` 指向发起配音的版本，旧版本、旧字幕、已有成片和试映报告都不覆盖。
- `subtitleTimingSource=ASR_ALIGNED`，字幕来自实际音频。
- 冻结素材 = 简报选择素材 + 本运行生成的配音素材；引用表同步记录，供后续影响分析。
- 保存前用同一 `StoryboardCompiler` 重新检查：文稿摘要、音频格式、时长、字幕范围和全片帧长都通过才落库；失败则运行失败，不写入不可渲染版本。

编译器对声音来源做了双向约束：

| 场景声音 | 允许的音频 | 拒绝情况 |
| --- | --- | --- |
| `TTS` | `metadata.generated.kind=TTS` 且 `textSha256` 等于当前文稿摘要 | 缺音频、旧文稿音频、格式/时长不合格、缺字幕时间、超出场景 |
| `NARRATION` | 用户上传的 READY 录音 | 引用系统生成音频，防止用户录音被悄悄替换 |
| `ORIGINAL` | 视频区间内的真实原声 | 无音轨或区间无交集 |

`StoryboardCodec.policy` 也同步收紧：生成素材只能用于 TTS 场景，且不计入简报 `assetIds` 范围校验；其他场景引用会被拒绝。

## 时长报告的变化

`GET /storyboards/{id}/timing` 对已生成配音的 TTS 场景改用真实音频时长，`timingSource=NORMALIZED_MEDIA`，并与录音场景共用延长、缩短、拆分提案。未生成时仍返回 `NOT_GENERATED`，不按字数估算。文稿与音频不一致时，报告额外返回 `TTS_TEXT_MISMATCH` 提案。

## 取消、失租、重启与迟到结果

- 每个外部调用前检查执行权；调用后写结果前再次由 SQL 核对 `RUNNING`、租约所有者、代数与到期时间。
- 取消后迟到的音频不会落库，已产生的已知费用仍按字符数结算；ASR 结果无法确认时记未知。
- 接管执行不会重发已发送请求；合成结果缺失时场景失败、运行失败，费用保持未知。
- 转写阶段重启只续查任务，不重复提交。
- 取消或失败运行遗留的场景行由独立扫描收口。

## 验证口径

最终 Java 选定 29 个套件 452 项，421 通过、零失败/错误、31 项需要原生开关的用例未在宿主执行；其中真实隔离 MySQL 46 项（配音 11 项、故事板 35 项）。容器内用真实 FFmpeg 规范化配音并渲染出片，Python 渲染器 87 项在项目既有镜像中全部通过。完整命令、环境差异和未验证范围见[验证记录](../error/视频配音S4-3b验证记录.md)。

## 当前边界

本阶段没有真实 DashScope 密钥，也没有调用真实 TTS/ASR。协议字段、费用口径、私有音频、字幕时间与版本保存均用本地替身和真实 MySQL/FFmpeg 验证；真实模型音质、真实账单、供应商限流与失败码仍需在可用部署中验收。

仍未完成：完整时间线重排与用户采纳流程、环境声独立可调混音、多音色/多语言选择、页面与 SAMPLE 样片、S4-4 AI 视频生成、S6 局部修改及 S7/S8 收口。不要因为本阶段能用 TTS 出片，就把“一键制作”标成完成。
