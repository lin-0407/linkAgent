## 本轮做了什么

按原文档方案推进，但**纠正了文档对现状的几处失真判断**，避免做无用功：

### 改动二：建议卡片化 + 完整反馈面板（P0）

**问题**：发布前优化的标题建议、标签建议原本是朴素 `<section>` 列表，没有"采纳/复制/反馈"操作，用户无法表达对建议的偏好，画像无法增量更新。

**改了什么**：
- `types/creator.ts`：新增 `CreatorEventType`（事件类型枚举，对齐后端 `creator_event.event_type` 注释）、`CreatorRejectReason`（拒绝原因预设值）、`CreatorFeedbackEventPayload`（提交载荷）。
- `api/creator.ts`：新增 `recordCreatorEvent()`，对接后端**已就绪**的 `POST /api/creator/profile/events`。
- `composables/creator/useCreatorFeedbackEvent.ts`：新建，统一封装反馈事件上报（去重防连点、loading 态、成功/失败 toast），复用 CreatorWorkspace 现有 toast 通道。
- `components/creator/SuggestionCard.vue`：新建可复用建议卡片，支持 type（title/tag/desc）切样式，含采纳/复制/不太好按钮 + 推荐角标 + 已采纳态。二级操作通过 slot 注入（保留"保存为标题套路"）。
- `components/creator/SuggestionRejectPanel.vue`：新建"不太好"展开的原因单选面板，6 个预设原因 + 其他自定义。
- `CreatorWorkspace.vue`：标题建议、标签建议渲染区从朴素列表替换为 SuggestionCard 卡片网格；新增 `titleSuggestionCards`/`tagSuggestionCards` computed 做数据解析，`onAcceptSuggestion`/`onCopySuggestion`/`onRejectSuggestion` 桥接反馈事件。
- `styles/theme.css`：新增 `.suggestion-card-grid` 响应式网格样式。

**为什么这么做**：卡片化让用户一眼看到推荐理由和元信息（观众心理/点击理由/风险），并能把"采纳/拒绝"信号写回 `creator_event` 表，触发创作者画像增量更新——这是原文档方案三的核心价值。反馈面板用预设原因而非自由文本，是为了让画像更新能稳定聚类用户的排斥倾向。

**解决的痛点**：建议从"看着像 API 返回值"变成"可操作的产品卡片"；用户反馈有记忆，影响下次建议。

---

### 改动三：Agent 思考过程时间轴（P1）

**问题**：后端 SSE 已推送 `userLabel`/`userDetail`/`durationMs` 字段（`CreatorWorkflowService.buildStepPayload`），但前端 `useWorkflowSSE` 的 step 事件 handler 是无参 `() => void`，**这些字段被完全丢弃**。用户分析时只看到"生成中..."，不知道 Agent 在干什么。

**改了什么**：
- `composables/useWorkflowSSE.ts`：新增 `WorkflowStepEvent` 类型；三个 step handler（`onStepStarted/Completed/Failed`）签名从 `() => void` 改为 `(event: WorkflowStepEvent) => void`；新增 `toStepEvent()` 工具函数解析 payload。
- `components/creator/AnalysisProgress.vue`：新建用户友好的时间轴组件，渲染 ✓完成/●运行中(脉冲)/○等待/✗失败 + 步骤名 + 耗时 + 可折叠详情。数据源是 `workflowSteps`（HTTP 全量），SSE 增量字段已透传供实时刷新。
- `CreatorWorkspace.vue`：在发布方案 tab 分析区挂载 AnalysisProgress（分析进行中或有步骤时显示），面向所有用户，不再仅限开发者。

**为什么这么做**：后端字段已就绪，前端只差消费。时间轴让用户知道"它在提取要点、在搜同类视频、在生成建议"，建立信任感。步骤数据通过 `listWorkflowSteps` HTTP 全量拉取（SSE 事件触发刷新），即使前端不消费事件 payload 也能完整工作，SSE 字段是"实时增量高亮"的锦上添花。

**解决的痛点**：等待 30 秒不再盲等；哪步失败直接标红，不用翻 console。

---

### 改动四：运行时状态栏（P1）

**问题**：用户发起分析后才在报错中发现 LLM 挂了，白等半天。

**改了什么**：
- `composables/useSystemStatus.ts`：新建，轮询 `POST /api/settings/connectivity/check`（60s 一次），归一化 7 项基础设施状态为三色灯，复用 `workflowStore` 的 SSE 连接状态。
- `components/SystemStatusBar.vue`：新建底部固定状态栏，三组指示灯（LLM/向量库/实时通道）+ 摘要文字，点击可手动刷新。
- `App.vue`：挂载 SystemStatusBar。
- `styles/theme.css`：`.surface-root` 加 `padding-bottom: 40px` 避免状态栏遮挡内容。

**主动纠正文档**：原文档方案四写"显示本月调用 127 次 / ¥3.42"，但后端**没有**跨任务的"本月用量汇总"接口（只有单任务粒度 `getTaskLlmUsageSummary`）。本实现**不展示这类数据**，避免编造假数字。状态栏只展示真实可探测的基础设施健康 + SSE 连接状态。

**解决的痛点**：发起分析前就能看到红灯，知道要修；切了模型/降级了一目了然。

## 验证清单（需作者执行）

> 遵守 AGENTS.md"开发者不跑构建命令"约束，以下命令由作者执行。

### 1. 类型检查
```bash
cd frontend && npm run type-check
```
**预期**：无 TS 报错。重点排查拆分时的类型问题。
**失败优先排查**：`useWorkflowSSE.ts` 的 `WorkflowStepEvent` 字段类型；`CreatorWorkspace.vue` 里 `feedbackEvent.isReporting` 的参数类型；SuggestionCard 的 props 类型。

### 2. 启动开发服务器
```bash
cd frontend && npm run dev
```
访问 `http://localhost:8088/`，逐项验证：

**建议卡片（改动二）**：
- 进入创作台 → 新建/选择任务 → 发布方案 tab → 生成发布方案 → 点"查看并确认"。
- 标题建议区应是卡片网格（不再是列表），第 1 张有"⭐ 推荐"角标。
- 点"复制" → 2 秒内显示"已复制"，剪贴板有内容。
- 点"采纳" → 卡片变"已采纳"态，顶部出现成功 toast。
- 点"不太好 ▾" → 展开原因单选，选一项 + 提交 → toast 提示已记录。
- 开 DevTools Network：采纳/拒绝时应看到 `POST /api/creator/profile/events` 返回 200。
- 查数据库 `creator_event` 表有新记录，event_type 对应 TITLE_ACCEPTED/TITLE_REJECTED。
- 标签建议区同样是卡片，"存为关键词"二级操作可用。

**分析时间轴（改动三）**：
- 发布方案 tab 触发分析时，"分析进度"时间轴实时出现。
- 每步显示中文名（读取上下文/Agent 推理等）+ 状态标签 + 用时。
- 运行中的步骤有脉冲动画，失败的标红显示错误信息。
- 点步骤可展开看输入/输出摘要。

**状态栏（改动四）**：
- 页面底部出现状态栏，三个指示灯（LLM/向量库/实时通道）。
- 服务正常时全绿；手动停掉 Redis/某服务，60s 内（或点击状态栏立即刷新）对应灯变红。
- 状态栏不遮挡页面内容（底部有 40px 留白）。

### 3. 失败优先排查
- 卡片不显示：检查 `titleSuggestionCards` computed 是否正确解析（看 `parseJsonArray`/`getRecordText` 是否被正确引用）。
- 时间轴不出现：检查 `workflowSteps` 是否在分析后有数据（可能 SSE 未触发 `refreshPrePublishWorkflowSteps`）。
- 状态栏一直显示离线：`/api/settings/connectivity/check` 接口可能需要后端 Bean 就绪，看 Network 返回。
