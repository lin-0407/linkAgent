# 阶段 1.1：配置安全基线

## 背景

项目已经完成最简 LLM 调用链路和 ReAct 最小闭环。继续开发记忆、RAG、MCP 前，需要先把运行配置从代码仓库中剥离出来，避免数据库密码、模型 API Key 等敏感信息进入版本管理。

## 本轮变更

- `backend/src/main/resources/application.yml` 改为使用环境变量占位符。
- 新增 `.env.example`，只保留配置项名称和本地默认示例，不包含真实密钥。
- 保留本地 `.env` 作为开发机私有配置，依赖 `.gitignore` 避免提交；注意 Spring Boot 不会自动读取 `.env`，需要由 IDE、Shell、Docker Compose 或部署平台注入。
- 默认关闭 Vector Store 自动配置，避免在尚未开发 RAG 时强制连接 Milvus。

## 关键决策

### 1. application.yml 保留默认值，但默认值不能是秘密

`application.yml` 是应用的公开配置模板，适合放端口、默认模型名、localhost 连接信息等非敏感配置。

不适合放：

- 真实 API Key
- 线上数据库地址
- 数据库密码
- Langfuse secret key

### 2. .env.example 只表达契约

`.env.example` 的价值不是让应用直接运行，而是告诉开发者和部署环境需要准备哪些变量。

真实值应该由以下来源提供：

- 本地 `.env`
- IDE Run Configuration
- Docker Compose environment
- CI/CD Secret
- 云服务器环境变量

如果使用 IntelliJ IDEA，可以在 Run Configuration 的 Environment variables 中填入这些变量；如果使用 Docker Compose，则通过 `env_file` 或 `environment` 注入。

## 涉及知识点

- Spring Boot 配置占位符：`${ENV_NAME:defaultValue}`
- 配置与秘密分离：config 可以进仓库，secret 不应该进仓库
- Spring AI 自动配置：引入 starter 后可能自动创建外部资源客户端，需要用配置明确控制启停
- 简历项目的工程可信度：安全基线、部署契约、可复现配置都比单纯功能堆叠更重要

## 踩坑记录

如果 `mvn test` 出现：

```text
MilvusServiceClient.<init>
DEADLINE_EXCEEDED: deadline exceeded
```

原因是项目引入了 `spring-ai-starter-vector-store-milvus`，Spring AI 1.1.4 在未指定 `spring.ai.vectorstore.type` 时会默认尝试创建 Milvus 客户端。当前阶段还没有启动 Milvus，所以连接超时。

本项目默认设置：

```yaml
spring:
  ai:
    vectorstore:
      type: ${VECTOR_STORE_TYPE:none}
```

后续进入 RAG 阶段并准备好 Milvus 后，再将 `VECTOR_STORE_TYPE` 改为 `milvus`。

## 验证方式

启动前确认本地环境变量或 `.env` 中存在：

```bash
LLM_API_KEY=你的模型服务密钥
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

然后启动后端，调用：

```bash
curl -X POST http://localhost:8080/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"你好，用一句话介绍你自己"}'
```
