# 提示词模板资产治理与初始化乱码修复

## 1. 需求结论

本轮治理对象是数据库表 `llm_prompt_template` 中的提示词模板，不限定为 Agent 提示词。

目标用户是维护 LinkAgent 的开发者和内容工作台配置者。业务场景是 UP 主创作链路中的发布前优化、反馈分析、竞品分析、复盘报告、通用 Agent、画像和字段补全。

本轮只做资产盘点、初始化乱码修复和维护文档，不重新设计提示词热更新架构，不新增模板引擎，不物理删除任何提示词。

## 2. 设计方案

涉及模块：

| 模块 | 处理 |
|---|---|
| `backend/src/main/resources/sql/init.sql` | 增加 `SET NAMES utf8mb4`，并让重复种子在发现乱码指纹时才覆盖 `content` |
| `.env.example` | 把 JDBC 示例编码统一为 `characterEncoding=UTF-8` |
| `frontend/src/components/SettingsDrawer.vue` | 将前端提示词管理文案从 Agent Prompt 收口为提示词模板 |
| `docs/reference/提示词模板资产治理说明.md` | 记录全量模板资产、调用处、状态和处理建议 |
| `docs/error/提示词模板初始化乱码修复记录.md` | 记录乱码成因、修复策略和回滚方式 |

为什么不直接覆盖所有 `content`：

提示词支持 DB 热更新，开发者可能已经在设置面板里调优正文。如果初始化脚本每次启动都覆盖正文，会破坏热更新和可回滚能力。因此本轮只在已有 `content` 命中乱码指纹时，用种子里的 UTF-8 正文修复。

## 3. 编码实现

`init.sql` 的重复种子更新策略变为：

这段逻辑只处理明显乱码或问号占位的历史脏数据。正常中文、英文和人工调优过的正文不会被种子覆盖。

## 4. 验证方案

开发者不执行构建、测试、启动命令。作者可按参考文档中的 SQL 验证：

1. 查询提示词总数应为 30 条未删除模板。
2. 查询乱码指纹应返回 0 行。
3. 前端设置面板能看到 30 条模板并按场景分组。
4. 修改任意一条提示词后，再次读取能看到新正文。
5. 主链路调用不出现缺 key 或占位符未替换。
