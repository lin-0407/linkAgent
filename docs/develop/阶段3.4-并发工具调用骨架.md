# 阶段 3.4：并发工具调用骨架

## 上下文

阶段 3.1 到 3.3 已经完成工具注册、超时保护和重试保护。当前 `AgentExecutor` 仍然遵循最小 ReAct 闭环，一轮只解析并执行一个工具。

但后续进入 MCP、Planner 或模型原生 parallel tool use 时，工具层必须支持一次接收多个 `ToolCall` 并返回多个 `Observation`。

## 本轮目标

在不改动 ReAct 主循环的前提下，先给 `ToolExecutor` 增加批量执行入口，为后续并发工具调用打基础。

## 本轮变更

- 修改 `ToolExecutor`：
  - 保留原有 `execute(ToolCall)` 单工具入口。
  - 新增 `executeAll(List<ToolCall>)` 批量工具入口。
  - 批量执行时使用 `CompletableFuture` 并发启动工具调用。
  - 返回结果顺序与输入 `ToolCall` 顺序保持一致。
- 修改 `ToolExecutorTest`：
  - 覆盖多个工具批量执行。
  - 覆盖一个工具失败时，其他工具结果仍然保留。

## 设计说明

当前阶段只扩展工具执行器，不修改 `AgentExecutor` 的 ReAct 文本解析。原因是现有 Prompt 明确要求“每次只使用一个工具”，直接改主循环会同时牵涉 Prompt、解析器、前端步骤展示和模型行为，不适合一步完成。

本轮先把工具层能力补齐，后续再做 ReAct 多工具解析或 MCP 适配时，只需要复用 `executeAll`，不会再重写工具执行边界。

## 验证方式

本项目约定 Maven 编译和测试由作者执行。本轮建议执行：

```bash
cd backend
mvn test -Dtest=ToolExecutorTest
```
