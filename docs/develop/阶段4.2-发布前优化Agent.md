# 阶段 4.2：发布前优化 Agent

## 需求分析

本阶段服务的目标用户仍然是 B 站 UP 主、内容运营者和内容复盘者。

要解决的场景是：任务已经有了标题草稿、简介草稿、文稿或字幕之后，系统需要帮助用户在发布前快速得到标题、简介、标签、分区和风险建议。

输入数据来源：

1. 阶段 4.1 已保存的创作任务和材料。
2. 用户本次可选补充的创作者偏好、标题风格和额外要求。
3. 本阶段不接入 B 站真实数据，不抓取评论，不做自动投稿。

本阶段只做同步分析基线：

1. 基于任务材料生成发布前优化建议。
2. 将建议保存到数据库。
3. 支持按 `taskId` 查询建议。
4. 将任务状态更新为 `PRE_PUBLISH_ANALYZED`。

本阶段暂不做，后续由阶段 4.4.1 承接：

1. SSE 流式过程展示和工作流消息落库。
2. 复杂多 Agent 协作。
3. 标题质量打分模型。
4. 分区规则引擎。
5. 历史版本管理。
6. 用户确认后再推进下一阶段。

## 设计方案

### 后端包结构

新增业务包：

```text
com.link.linkagent.creator.suggestion
```

这个包只负责发布前优化建议，不把评论弹幕、复盘报告混进来，避免一个包塞太多职责。

### 数据表

新增 `creator_suggestion`：

```text
保存一轮发布前优化结果，包括摘要、受众判断、卖点、风险、标题建议、简介建议、标签建议和分区建议。
```

为了便于失败回放和人工检查，保留 `raw_output` 字段。

### API

```text
POST /api/creator/tasks/{taskId}/pre-publish/analyze
GET  /api/creator/tasks/{taskId}/pre-publish/suggestions
```

### 入参校验

所有对外接口继续使用 Jakarta Validation：

1. `taskId` 长度不能超过 64。
2. `creatorPreference` 长度不能超过 500。
3. `titleStyle` 长度不能超过 100。
4. `extraRequirement` 长度不能超过 500。

### 是否涉及 Agent

本阶段逻辑对外叫“发布前优化 Agent”，但内部先用一次 LLM 调用完成建议生成，不先接 ReAct 工具链。

原因很直接：

1. 当前阶段主要验证业务闭环，不验证多轮工具规划。
2. 标题、简介、标签建议更适合先调 Prompt 和 JSON 输出格式。
3. 等后面加入标签规则、分区规则和偏好记忆时，再把它演进成真正的可观测 Agent。

### 与阶段 4.4.1 的关系

阶段 4.2 是已完成的同步 LLM 基线，职责是验证“任务材料 -> 发布前建议 -> 数据库存档”这条主链路。

阶段 4.4.1 会在此基础上做增量升级：

1. 保留 `creator_suggestion` 作为发布前建议结果表。
2. 新增工作流会话、消息和步骤表，用于展示 Agent 如何读取材料和生成建议。
3. 新增 SSE 事件流，前端逐条展示上下文装载、分析步骤和结果消息。
4. 新增建议确认机制，只有用户确认后才允许业务正式进入评论弹幕分析阶段。
5. 后续如需重新生成或继续调整，应新建一轮工作流消息和建议版本，不直接覆盖用户已确认结果。

## 编码实现

本轮新增：

- `PrePublishSuggestionController`：发布前优化接口。
- `PrePublishSuggestionService`：读取任务材料、调用 LLM、保存建议。
- `PrePublishAnalyzeRequest`：发布前优化请求。
- `CreatorSuggestionRecord`：建议数据库记录。
- `CreatorSuggestionResponse`：建议响应。
- `CreatorSuggestionMapper`：MyBatis 访问层。

修改：

- `CreatorTaskMapper`
  - 新增任务状态更新方法
- `CreatorTaskStatus`
  - 新增 `PRE_PUBLISH_ANALYZED`
- `backend/src/main/resources/sql/init.sql`
  - 新增 `creator_suggestion`

## 接口示例

### 发布前分析

```http
POST /api/creator/tasks/{taskId}/pre-publish/analyze
Content-Type: application/json

{
  "creatorPreference": "偏好理性一点的表达，不要太夸张",
  "titleStyle": "偏经验分享和结果导向",
  "extraRequirement": "标题尽量短，简介要清楚"
}
```

### 查询建议

```http
GET /api/creator/tasks/{taskId}/pre-publish/suggestions
```

## 测试验证点

正常路径：

1. 任务存在且材料不为空时，应生成建议并保存。
2. 再次查询同一个 `taskId` 时，应返回最新建议。
3. 任务状态应更新为 `PRE_PUBLISH_ANALYZED`。

边界路径：

1. 任务不存在时返回 404。
2. 任务存在但没有材料时返回 400。
3. `taskId` 超过长度限制时返回参数校验失败。
4. LLM 输出不包含 JSON 时，仍应保存原文并标记为 `RAW_ONLY`。

作者本地验证命令：

```bash
cd backend
mysql -u root -p < src/main/resources/sql/init.sql
mvn test
```

如果只想先检查编译：

```bash
cd backend
mvn test -DskipTests
```
