# 阶段 3.5：MCP 工具适配骨架

## 上下文

阶段 3.1 到 3.4 已经完成工具注册、超时保护、重试保护和批量执行入口。下一步进入工具生态的重点能力：把外部 MCP Server 暴露的工具接入项目统一工具池。

本轮先不连接真实 MCP Server，只做 Spring AI `ToolCallback` 到项目内部 `Tool` 的适配。这样可以先把注册链路打通，避免一上来就把协议、网络、启动配置和工具执行混在一起。

## 本轮目标

让 MCP 工具和本地工具使用同一套 `ToolRegistry`、`ToolExecutor` 和系统提示词生成逻辑。

## 本轮变更

- 新增 `SpringAiToolCallbackAdapter`：
  - 将 Spring AI `ToolCallback` 适配成内部 `Tool`。
  - 复用外部工具的名称、描述和输入调用逻辑。
- 修改 `ToolRegistry`：
  - 增加 `ToolCallbackProvider` 注入入口。
  - 启动时把 provider 暴露的工具一并注册进内部工具池。
- 修改 `ToolRegistryTest`：
  - 覆盖 MCP 风格 `ToolCallback` 的注册和调用。

## 设计说明

当前只做适配，不做 MCP Server 连接器，是因为项目现阶段最需要先统一“工具如何被看见、如何被调用”的内部抽象。真正连接外部 MCP Server 时，最容易出问题的是协议对象和内部工具模型的边界；这一步先把边界压平，后续接服务器时改动会更小。

## 验证方式

本项目约定 Maven 编译和测试由作者执行。本轮建议执行：

```bash
cd backend
mvn test -Dtest=ToolRegistryTest,ToolExecutorTest
```
