# S1：版本上下文、发布资料与历史选版闭环

2026-10-19。作者要求先自审、再继续，并合并推进相关功能。本轮围绕“旧版可以安全选回且不污染正式发布资料”完成一组闭环，不进入真实自动渲染或供应商调用。

## 自审与方案

上轮精确版本绑定保护了媒体身份，但门禁仍读取最新确认，正式标题/简介仍读取可变缓存。这两个缺口必须在开放选版前解决。

- 新上传在任务锁内核对真实确认及蓝图就绪，冻结版本的来源、确认 ID、方案 ID、蓝图和材料快照；已有成片只继承当时显式跳过事实。旧版依据不被新候选改变。
- 新绑定在首次归属核验通过时冻结 B 站公开标题/简介等资料；未读取到的字段保持未知，既不冒充用户实际投稿文案，也不回填历史绑定。后续指标仍按最新同步时间展示。
- 新增 `GET /api/creator/tasks/{taskId}/creation`、`GET /versions?page=1&pageSize=20`、`POST /versions/{versionId}:select`，选版正文包含 `expectedWorkspaceRevision`，使用 Jakarta Validation。响应不包含桶、对象键或签名。
- 选版先校验归属、活动工作、版本上下文和完整试映，再在事务外 HEAD 实际存储对象；短事务复核任务锁、版本锁和修订号后切换指针。查询不自动创建工作区，也不产生付费调用。
- 无法确认历史上下文的旧版可以查询；不能用最新任务内容反推历史后直接选回。旧 V1 原有手动链路保留。

统一 SQL 维护新上下文表及绑定快照字段。版本上下文不可覆盖，选择只切换指针，不复制旧材料覆盖任务资料。工作区响应提供所选版本的冻结内容供编辑基线读取。

## 已实现的边界

`MediaUploadPersistenceService` 在分配版本和保存上传的同一事务中捕获上下文；不满足真实确认/蓝图条件则整体回滚，序号与上传记录均不残留。已开始上传的续传、登记和确认使用该上传版本的上下文。发布后门禁以及精确版本校验读取其冻结依据；尚无快照的旧任务仍走原门禁。

历史列表按版本号降序分页，包含已完成上传的视频与媒体删除后的历史，不包含失败上传占位；分别返回媒体可用性、上下文是否已保存、完整试映是否就绪、是否当前、是否正式绑定。单次最多 100 条，读取不会创建工作区。工作区与列表读取使用只读事务；选版响应带新的修订号和选中版冻结资料。

选版同时检查活动上传、预处理和试映；对象 HEAD 使用历史记录的桶与对象键，避免部署默认桶变化后读错文件。HEAD 在事务外，实际切换在任务锁、版本锁与修订号检查之后；在 HEAD 期间发生重新定位、删除或另一次选择时，旧请求被拒绝。重复选择同一当前版本不重复递增修订号。

`CreatorBilibiliMapper` 在新绑定直接 BOUND 或延迟同步首次转 BOUND 时保存公开资料白名单，标题/简介/分区/标签不随缓存刷新改写。公开指标仍使用匹配 BV/UID 的最新缓存并保留同步时间。`CreatorPublishedVideoContextService` 给竞品、总体复盘和本轮新增接入的反馈分析读取相同口径；没有匹配冻结快照的新模式绑定明确返回未知，不拿新草稿补造。

首次 BOUND 同时在精确视频上保存永久 `published_flag`，后续 UID/视频查询异常只影响当前核验状态，不清除已发布事实；重新定位继续被阻止，重复绑定保留原 BV、版本及异常状态。同步按稳定顺序先锁定全部待处理任务/绑定，再写视频缓存，避免与显式绑定冻结快照形成反向锁等待。

发生后续核验异常后，发布后媒体门禁仍按永久发布事实读原精确版本，不能因编辑页选了另一个版本就回退。已有匹配冻结资料可作为历史依据读取，同时明确当前异常状态；实时缓存归属/BV 冲突时，实时指标标为未知，不污染冻结文案。

试映页新增 `VideoVersionHistory`：分页查看历史、说明不可选原因、切换后重载所选版本的媒体/处理/试映；冲突后刷新真实状态。未存在发布事实时提供“上传新版本”，用户显式点击才清除已完成的本地续传指针；新视频完成前，后端旧指针不变。前端复用当前布局，仅静态核对，未作为浏览器行为验收。

版本上下文目前只覆盖真实 `UPLOAD` 来源；自动渲染的工程、故事板与执行授权尚未开发，不能继承任务级跳过事实。完整自动制作编辑器也尚未实现；返回冻结资料不等于已有可视化工程编辑能力。
