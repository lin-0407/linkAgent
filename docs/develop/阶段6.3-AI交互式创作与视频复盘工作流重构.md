# 阶段 6.3 - AI 交互式创作与视频复盘工作流重构

> 文档状态：整体方案已审查，P0-1「AI 创意方案入口」与 P0-2「发布前优化 AI 交互台」已完成编码，待作者验证。
> 本文继续作为阶段 6.3 的总方案文档；已落地范围以 `/docs/reference/AI交互式创意方案入口说明.md` 和 `/docs/reference/发布前优化AI交互台说明.md` 为准。

## 1. 需求结论

本阶段要把当前“用户手动填表驱动流程”的创作工作台，改成“用户输入想法，AI 主动推进任务”的交互式工作台。

核心变化是：

1. 用户不再先填写一组固定表单，而是在 AI 交互台输入自己的创作想法。
2. AI 先生成 3 个最贴近用户想法的创意卡片，卡片必须包含标题大纲、内容大纲和简介大纲。
3. 用户选择其中一个创意卡片后，系统自动进入发布前优化阶段。
4. 发布前优化阶段仍然是 AI 交互台形态，由 AI 主动提醒用户还需要补充什么。
5. 用户确认发布方案后，任务进入“等待绑定 BV 号”状态。
6. 绑定 BV 号并完成 B 站 UID 绑定后，第三阶段进入独立的视频分析页面。
7. 视频分析页面只展示已经和平台任务绑定的视频卡片，不展示用户账号下全部视频。
8. 视频分析阶段自动采集、清洗、分析评论弹幕和基础指标，输出完整页面级分析结果。
9. 原“评论弹幕分析”和“复盘报告”合并进视频分析阶段，分析完成后即可导出。
10. 开销统计不再作为任务阶段，而是全局入口，并同时提供全局任务统计和单任务统计。

本文中“简介大纲”按 B 站发布语境理解为视频简介大纲。用户原文里的“简历大纲”如果确实不是笔误，需要在审查时改名并重新定义字段。

## 2. 本阶段解决的问题

当前工作台的问题不是缺少功能，而是交互方式不像 Agent。

| 问题 | 当前表现 | 本阶段改法 |
|---|---|---|
| 输入过于手动 | 用户需要自己理解标题、简介、文稿、指导词等字段。 | 用户只输入自然语言想法，AI 主动拆解并追问。 |
| AI 没有主动感 | 用户点一个按钮得到一次结果。 | AI 按阶段主动给方案、问缺口、推进状态。 |
| 阶段可随意切换 | 左侧竖向进度更像 Tab。 | 进度条只展示状态，不能手动跳阶段。 |
| 视频分析和任务脱节 | 评论弹幕导入依赖用户手动脚本或文件。 | 任务确认后绑定 BV，后续自动围绕 BV 拉取和分析。 |
| 复盘和评论弹幕割裂 | 评论弹幕分析、复盘报告是两个阶段。 | 统一成视频分析与复盘页面。 |
| 开销统计抢占主流程 | 开销统计在任务进度栏里像一个阶段。 | 改成全局任务统计和单任务统计，不影响创作流程。 |

## 3. 关键假设与需要作者审查的点

这些点不是最终定论，需要作者审查：

1. “实时同步用户的视频数据”第一版建议定义为准实时同步，也就是进入视频分析页、绑定 BV、点击刷新或定时轮询时同步。原因是 B 站并不一定提供适合本项目的实时推送能力。
2. UID 绑定不是账号授权。第一版只通过用户提供的公开 UID 同步公开视频信息，不读取私密数据，不保存 Cookie，不绕过平台权限。
3. 如果后续要做真正账号授权、定时后台同步或更完整的视频数据读取，需要单独确认 B 站官方能力和合规边界。
4. 任务和实际视频的硬关联使用 BV 号。UID 只用于确认“这个 BV 是否属于当前创作者的视频列表”以及展示视频主页式卡片。
5. 未绑定 BV 的任务不进入视频分析页卡片列表。它只停留在第二阶段后的“等待绑定 BV”状态。
6. 第三阶段不是弹窗，也不是当前创作台里的一个小结果区，而是完整页面。
7. 现有评论弹幕采集脚本和 `/feedback/fetch` 能力可以作为第一版自动采集底座，但编码前必须再次核对脚本入参、输出结构和 B 站侧可用性。

## 4. 新主流程

推荐主流程如下：

```text
用户输入创作想法
  -> AI 生成 3 个创意卡片
  -> 用户选择并确认一个创意卡片
  -> AI 进入发布前优化，主动追问缺失信息
  -> AI 生成发布方案
  -> 用户确认发布方案
  -> 任务进入等待绑定 BV 号
  -> 用户绑定 B 站 UID 和任务 BV 号
  -> 视频分析页同步账号视频
  -> 只展示已和任务绑定的公开视频卡片
  -> 用户选择视频卡片
  -> 自动采集评论、弹幕和基础指标
  -> LLM 生成初步视频分析完整页面
  -> 用户可追问 AI
  -> 导出视频分析与复盘报告
```

## 5. 阶段定义

左侧竖向进度条保留，但它不再是可点击 Tab。

| 阶段 | 页面形态 | 用户动作 | AI / 系统动作 | 可否手动切换 |
|---|---|---|---|---|
| 1. 创意方案 | AI 交互台 | 输入想法，选择创意卡片。 | 生成 3 个创意方向。 | 否 |
| 2. 发布前优化 | AI 交互台 | 补充需求，确认发布方案，绑定 BV。 | 主动追问缺口，生成发布前方案。 | 否 |
| 3. 视频分析与复盘 | 独立完整页面 | 选择已绑定视频，追问 AI，导出。 | 同步视频数据，自动采集并分析。 | 否 |

开销统计从阶段里移除，放到全局入口和任务详情高级区。

## 6. 第一阶段：创意方案 AI 交互台

### 6.1 用户入口

首屏应是 AI 输入台，而不是任务表单。

示例文案：

```text
把你这期视频的想法告诉我。
可以只写一句话，也可以写素材、目标观众、想表达的观点。
```

用户可以输入：

```text
我想做一期讲 Spring AI Agent 工作流的视频，面向会 Java 但没接触过 Agent 的人，希望别太学术。
```

### 6.2 AI 输出

AI 必须返回 3 个创意卡片，每张卡片结构一致。

| 字段 | 说明 |
|---|---|
| 创意名称 | 一句话概括这个方向。 |
| 适合人群 | 说明这个方向更适合哪类观众。 |
| 标题大纲 | 不是最终标题，而是标题表达方向和可选标题骨架。 |
| 内容大纲 | 视频主体结构，至少包含开头、主体段落、结尾。 |
| 简介大纲 | B 站简介写法，包括核心卖点、关键词和引导语。 |
| 亮点 | 为什么这个方向贴合用户想法。 |
| 风险 | 可能跑偏、过度承诺或观众误解的地方。 |
| AI 建议 | AI 推荐用户优先选择的理由。 |

### 6.3 创意卡片交互

卡片按钮建议：

| 按钮 | 作用 |
|---|---|
| 选择这个方向 | 确认该卡片并进入第二阶段。 |
| 让 AI 微调 | 用户输入补充要求，基于当前三张卡片再改。 |
| 重新生成 | 保留用户原始想法，重新生成三张卡片。 |

确认后，系统保存：

1. 用户原始想法。
2. 三张候选创意卡片。
3. 用户选择的卡片。
4. 选择时的补充要求。

### 6.4 第一阶段状态

建议状态：

| 状态 | 含义 |
|---|---|
| `IDEA_INPUT` | 用户正在输入想法。 |
| `CREATIVE_GENERATING` | AI 正在生成创意卡片。 |
| `CREATIVE_OPTIONS_READY` | 三张卡片已生成，等待用户选择。 |
| `CREATIVE_CONFIRMED` | 用户已确认创意方向。 |

## 7. 第二阶段：发布前优化 AI 交互台

### 7.1 阶段入口

用户确认创意卡片后自动进入发布前优化。

AI 第一条消息不应该继续让用户填表，而是基于已选卡片主动提示缺口。

示例：

```text
我已经按你选的方向整理了发布方案雏形。
现在还缺 3 类信息：视频大概时长、是否已有字幕或文稿、标题风格边界。
如果你没有字幕或文稿，我可以先根据已选方向补一版草稿，你也可以继续提供更完整的素材。
```

### 7.2 AI 主动追问

AI 需要把“固定表单字段”转成自然语言追问。

| 当前字段 | 新交互方式 |
|---|---|
| 标题草稿 | AI 从创意卡片推导标题方向，用户只补充禁忌或偏好。 |
| 简介草稿 | AI 先给简介结构，用户补充链接、资料、互动引导。 |
| 文稿 / 字幕 | 用户可粘贴完整内容，也可以只补充素材摘要；如果没有，AI 先询问用户是否继续提供，用户选择不提供时再补一版可编辑草稿。 |
| 创作目标 | 第一阶段想法中自动提取，不足时 AI 追问。 |
| 风格偏好 | AI 根据用户表达推断，用户可以纠正。 |
| 额外要求 | 由对话消息承载，不再要求用户理解字段名。 |

### 7.2.1 文稿 / 字幕补充策略

第二阶段允许用户没有现成字幕或文稿。

处理规则：

1. AI 检测到用户没有提供文稿或字幕时，先询问用户是否要继续补充已有素材。
2. 用户可以选择粘贴完整文稿、字幕、素材摘要、拍摄提纲或口播要点。
3. 如果用户明确表示没有，AI 基于第一阶段创意卡片、用户补充需求和发布目标生成一版可编辑文稿草稿。
4. AI 生成的文稿草稿必须标记为“AI 草稿”，不能当作用户已完成脚本。
5. 用户确认或修改草稿后，发布前优化再基于这版内容生成标题、简介、标签和发布检查清单。

这样做的原因是：用户没有文稿时，Agent 应该先帮用户把想法落成可修改内容，而不是把流程卡死在材料缺失上。

### 7.3 发布方案输出

AI 生成发布方案后，仍然用弹窗或页面级确认层让用户选择。

方案内容建议：

| 模块 | 内容 |
|---|---|
| 最终标题建议 | 至少 3 条，说明适用场景和风险。 |
| 简介正文 | 可复制、可编辑。 |
| 内容结构建议 | 告诉用户开头、中段、结尾怎么调整。 |
| 标签和分区 | 少量高置信建议。 |
| 发布前风险 | 标题夸张、信息缺口、观众误解点。 |
| 发布检查清单 | 用户发布前需要自己确认的事项。 |

确认层按钮：

| 按钮 | 作用 |
|---|---|
| 采用这个方案 | 保存方案，进入等待绑定 BV 状态。 |
| 再修改一下 | 用户继续输入要求，AI 基于上一版修改。 |
| 重新生成 | 基于当前上下文生成另一版方案。 |

### 7.4 BV 绑定门槛

用户采用发布方案后，任务不能直接进入视频分析。

它必须进入：

```text
WAITING_BV_BINDING
```

页面提示：

```text
发布后把这条视频的 BV 号填回来。
绑定后，我会在视频分析页同步这条视频的数据并生成复盘。
```

绑定规则：

1. BV 号必须符合 B 站 BV 格式。
2. 一个任务第一版只绑定一个 BV。
3. 同一个 BV 不建议绑定多个任务；如果确实要支持，需要弹出冲突确认。
4. 未绑定 BV 的任务不出现在视频分析页。
5. 如果用户还没绑定 UID，可以先保存 BV，但视频分析页会要求绑定 UID 后再同步。

### 7.5 第二阶段状态

建议状态：

| 状态 | 含义 |
|---|---|
| `PRE_PUBLISH_GUIDING` | AI 正在追问发布前缺口。 |
| `PRE_PUBLISH_GENERATING` | AI 正在生成发布方案。 |
| `PRE_PUBLISH_READY` | 发布方案已生成，等待用户确认。 |
| `PRE_PUBLISH_CONFIRMED` | 用户已确认发布方案。 |
| `WAITING_BV_BINDING` | 等待用户填回已发布视频 BV。 |
| `BV_BOUND` | 任务已经绑定 BV。 |

## 8. 第三阶段：视频分析与复盘完整页面

### 8.1 页面定位

第三阶段是独立页面，不复用 AI 交互台作为主体。

原因是这一阶段用户关注的是已经发布的视频表现、评论弹幕证据和复盘结论，需要信息密度更高的分析页面。

页面主要区域：

```text
顶部：B 站 UID 绑定状态、同步按钮、最近同步时间
主体：已绑定任务视频卡片列表
右侧或下方：当前选中视频的任务上下文摘要
详情页：完整视频分析报告、证据列表、追问入口、导出入口
```

### 8.2 UID 绑定

用户需要提供 B 站 UID。

第一版绑定含义：

1. 记录当前创作者的 B 站公开 UID。
2. 用 UID 同步公开视频列表和基础公开信息。
3. 用 UID 校验绑定 BV 是否属于该创作者公开列表。

### 8.3 视频同步口径

用户账号下可能有 `n` 个视频，但视频分析页只显示其中 `x` 个和平台任务关联的视频。

筛选规则：

```text
B 站 UID 下的公开视频列表
  JOIN creator_task_video_binding
  ON bvid = bound_bvid
  WHERE binding_status = 'BOUND'
```

也就是说：

1. 用户账号下没绑定任务的视频不显示。
2. 平台任务没填 BV 的视频不显示。
3. 平台任务填了 BV 但该 BV 不属于当前 UID 时，显示为绑定异常，不进入正常卡片列表。

### 8.4 视频卡片

视频卡片可以参考 B 站个人主页视频列表，但只做业务需要的字段。

| 字段 | 说明 |
|---|---|
| 封面 | 来自 B 站公开视频信息。 |
| 标题 | 视频真实标题。 |
| BV 号 | 用于任务关联和排错。 |
| 发布时间 | 用于判断评论弹幕成熟度。 |
| 播放 / 点赞 / 投币 / 收藏 | 能同步到则展示，同步不到给空状态。 |
| 任务名称 | 平台内创作任务名称。 |
| 分析状态 | 未分析、同步中、分析中、已完成、失败。 |

卡片点击后进入完整视频分析页，并自动带入：

1. 第一阶段的原始想法。
2. 用户选择的创意卡片。
3. 第二阶段确认的发布方案。
4. 当前视频的公开信息。
5. 已采集的评论、弹幕和指标。

## 9. 自动采集与初步分析

### 9.1 触发时机

以下动作会触发或准备触发采集分析：

1. 用户绑定 BV 后，系统可以创建待分析任务。
2. 用户进入视频分析页并点击视频卡片后，系统检查是否已有有效数据。
3. 如果没有数据或数据过期，页面展示加载状态，并自动执行采集分析。

### 9.2 加载步骤展示

加载不是弹窗，而是完整页面中的状态区。

建议展示步骤：

```text
正在同步视频基础信息
正在采集评论样例
正在采集弹幕样例
正在清洗无效内容
正在归类观众反馈
正在生成初步视频分析
正在整理可导出的复盘报告
```

用户不需要看到脚本路径、命令参数或本地文件目录。

### 9.3 采集边界

第一版建议继续沿用“限量样例采集”思路，避免把产品做成无限制爬取器。

建议默认上限：

| 数据 |        默认上限 | 说明 |
|---|------------:|---|
| 评论 |   0 - 300 条 | 优先热评和较新评论，具体策略编码前确认。 |
| 评论回复 | 每条 0 - 15 条 | 防止回复树过大。 |
| 弹幕 |   0 - 500 条 | 足够支撑趋势判断，避免成本失控。 |

如果同步失败，页面必须说明失败原因，并允许用户重试或上传样例文件兜底。

## 10. 初步视频分析页面

视频分析结果不是弹窗，而是完整页面。

建议模块：

| 模块         | 内容 |
|------------|---|
| 一句话复盘      | 不超过 80 字，说明这条视频当前最重要结论。 |
| 发布方案兑现情况   | 对比第二阶段确认方案，说明哪些做到了，哪些偏离了。 |
| 观众最关心什么    | 高频评论弹幕观点和代表证据。 |
| 观众哪里没看懂    | 误解点、来源和可能原因。 |
| 争议与风险      | 争议点、风险等级和回应建议。 |
| 数据表现摘要     | 播放、点赞、投币、收藏等公开指标，缺失则隐藏。 |
| 弹幕时间段观察    | 如果有时间戳，展示情绪高峰或疑问集中点。 |
| 下期行动清单（可选） | 标题、内容结构、互动和选题建议。 |
| 证据列表       | 可展开查看评论、弹幕、时间点和分类理由。 |
| 追问 AI      | 用户围绕当前视频继续问。 |
| 导出         | 导出 Markdown 复盘报告。 |

## 11. 视频追问 AI

视频分析页保留追问 AI 入口，但它不是主页面形态。

追问必须带入当前任务上下文：

1. 创作想法。
2. 已选创意卡片。
3. 发布前确认方案。
4. 视频基础信息。
5. 评论弹幕分类结果。
6. 初步视频分析报告。
7. 可用时带入 RAG 证据检索结果。

回答要求：

1. 能引用证据就引用评论或弹幕。
2. 证据不足时明确说不足。
3. 不编造播放量、点赞量或观众观点。
4. 不直接替用户做平台操作。

## 12. 合并复盘报告与评论弹幕分析

第三阶段完成后，任务就可以认为完成。

新阶段不再拆成：

```text
观众反馈
复盘报告
```

而是统一为：

```text
视频分析与复盘
```

后端可以先保留原有 `CreatorFeedbackReport` 和 `CreatorReport` 能力，但前端普通用户只看到一个统一报告。

统一报告需要覆盖：

1. 评论弹幕分类。
2. 观众核心关注。
3. 误解和争议。
4. 本期内容复盘。
5. 下一期行动建议。
6. 可导出的 Markdown。

## 13. 开销统计全局化

开销统计不再是创作任务的一个阶段，但需要同时支持全局统计和单任务统计。

推荐入口：

| 入口 | 说明 |
|---|---|
| 顶部导航“开销” | 面向作者和演示，查看所有任务的总调用、总 token、总耗时和失败次数。 |
| 设置 -> 开发者模式 -> 生成消耗 | 保留技术细节和原始调用记录。 |
| 任务详情高级区 | 查看当前任务自己的调用、token、耗时、失败记录和工作流归属，不在左侧阶段进度里展示。 |

左侧阶段进度只保留业务阶段：

```text
创意方案
发布前优化
视频分析与复盘
```

统计口径：

| 统计层级 | 用途 | 需要展示 |
|---|---|---|
| 全局任务统计 | 让作者看到整个系统最近消耗情况。 | 总任务数、总调用次数、总 token、总耗时、失败次数、按模型类型分组、按日期趋势。 |
| 单任务统计 | 让用户或作者定位某个任务的成本和失败点。 | 当前任务总调用、总 token、总耗时、阶段分布、工作流步骤分布、失败调用明细。 |

全局统计用于看整体成本，单任务统计用于排查某条视频为什么贵或为什么失败。两者都不能回到任务阶段栏里。

## 15. API 草案

所有对外 API 入参都必须使用 Spring Boot 自带的 Jakarta Validation / Hibernate Validator。

### 15.1 创建交互式创作任务并生成创意卡片

```http
POST /api/creator/interactive/tasks
Content-Type: application/json
```

请求：

```json
{
  "userId": "default",
  "idea": "我想做一期讲 Spring AI Agent 工作流的视频",
  "videoType": "技术分享"
}
```

响应：

```json
{
  "taskId": "task-id",
  "sessionId": "workflow-session-id",
  "status": "CREATIVE_OPTIONS_READY",
  "options": []
}
```

校验：

1. `idea` 必填，长度建议 10 到 3000 字。
2. `userId` 可选，最长 64 字符。
3. `videoType` 可选，最长 100 字符。

### 15.2 重新生成或微调创意卡片

```http
POST /api/creator/interactive/tasks/{taskId}/creative-options/regenerate
```

请求：

```json
{
  "extraRequirement": "更适合新手，标题别太像教程课"
}
```

### 15.3 确认创意卡片

```http
POST /api/creator/interactive/tasks/{taskId}/creative-options/{optionId}/confirm
```

响应进入 `CREATIVE_CONFIRMED`，并自动准备发布前优化会话。

### 15.4 发布前优化对话

可以复用现有工作流消息接口：

```http
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/messages
```

区别是前端不再展示为“消息流调试”，而是展示为 AI 交互台。

### 15.4.1 生成可编辑文稿草稿

P0-2 新增：

```http
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/pre-publish/manuscript-draft
Content-Type: application/json
```

请求：

```json
{
  "extraRequirement": "口播更自然，适合 5 分钟以内的视频"
}
```

规则：

1. 只在发布前优化会话中可用。
2. 当前会话运行中、已确认或已取消时不可触发。
3. 已有较完整文稿或字幕时不覆盖，让用户直接生成发布方案。
4. 生成结果写回 `creator_material.MANUSCRIPT`，并追加工作流消息。
5. 本次 LLM 调用纳入工作流步骤级开销记录。

### 15.5 生成发布方案

```http
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/pre-publish/analyze
```

返回发布方案，并进入 `PRE_PUBLISH_READY`。

### 15.6 确认发布方案

```http
POST /api/creator/tasks/{taskId}/workflow/sessions/{sessionId}/pre-publish/confirm
```

确认后进入 `WAITING_BV_BINDING`。

P0-2 编码阶段暂时仍沿用现有 `CONFIRMED` / `PRE_PUBLISH_ANALYZED` 状态；`WAITING_BV_BINDING` 需要和 BV 绑定表、校验接口、前端绑定入口在 P0-3 一起落地。

响应：

  "taskId": "task-id",
  "bvid": "BV1xx411c7mD",
  "bindingStatus": "WAITING_VERIFY",

## 18. 验收标准

产品验收：

1. 用户只输入一句创作想法，也能得到 3 张结构完整的创意卡片。
2. 每张创意卡片都包含标题大纲、内容大纲、简介大纲、亮点和风险。
3. 用户选择任一卡片后，系统自动进入发布前优化阶段。
4. 发布前优化阶段由 AI 主动追问缺失信息，而不是要求用户填固定表单。
5. 发布方案确认后，任务进入等待绑定 BV 状态。
6. 未绑定 BV 的任务不会出现在视频分析页。
7. 绑定 UID 后，视频分析页只展示和任务绑定的视频卡片，不展示账号下所有视频。
8. 点击视频卡片后，页面自动同步、采集、分析并展示完整页面级结果。
9. 视频分析页可以追问 AI，回答必须基于当前视频上下文和证据。
10. 评论弹幕分析和复盘报告在普通用户路径中合并为统一视频分析报告。
11. 分析完成后可以导出 Markdown。
12. 开销统计不在左侧任务阶段栏中出现，但全局任务统计和单任务统计都可以访问。

技术验收：

1. 所有新增 API 使用 Jakarta Validation 校验入参，相关代码需要写清楚中文注释。
2. 新增表结构维护在 `backend/src/main/resources/sql/init.sql`。
3. 所有新增表字段注释使用中文。
4. 自动采集失败不影响任务上下文和已确认发布方案。
5. LLM 失败时保留错误状态，允许用户重试。
6. UID 同步失败时给出明确原因，不能静默显示空列表。
7. BV 与 UID 不匹配时进入绑定异常状态，不能误展示为正常视频。
8. 视频分析追问不能编造证据。
9. 开销统计仍能按任务、工作流、全局维度追溯。

8. 进入视频分析页。
9. 同步视频并确认只展示已绑定任务的视频。
10. 点击视频卡片并等待自动分析完成。
11. 追问 AI。
12. 导出 Markdown。



## 21. 主要风险

| 风险 | 影响 | 应对                    |
|---|---|-----------------------|
| B 站公开视频同步能力不稳定 | 视频卡片和指标可能同步失败。 | 第一版可以添加一个刷新按钮。        |
| “实时同步”理解过重 | 容易变成后台定时任务和平台授权问题。 | 第一版定义为准实时同步，后续再扩展。    |
| AI 交互过于自由 | 用户可能不知道下一步是否完成。 | 由任务状态和只读进度条约束推进。      |
| 创意卡片质量不稳定 | 第一阶段体验会直接受影响。 | 结构化输出、评测样例和失败回放必须同步补。 |
| 自动采集成本上升 | 评论弹幕和 LLM 调用可能变贵。 | 限量采集、开销全局追踪、失败可重试。    |
| UID 与 BV 不匹配 | 可能把别人的视频关联到任务。 | 绑定状态必须显式校验和展示异常。      |
