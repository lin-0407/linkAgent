## 1. 产品目标：替用户交付一条作品

### 1.1 作者已经明确的方向

LinkAgent 面向两类创作者：

1. 没有做过视频、缺乏制作技能，但愿意表达一个想法的人。
2. 会做一些视频、资源有限，希望减少策划和重复制作的小 UP。

作者希望尽可能自动帮助他们实现视频想法、创意、标题、简介或者视频内容。专业 UP 的复杂工程、精细导演控制和团队协作不是当前服务对象。

产品仍是个人自托管的 B 站创作者工作台，通常一套部署服务一位创作者。`linkagent.cloud` 是演示、联调地址，不能由此推导公开 SaaS 需求。

### 1.2 核心承诺

**用户表达一个想法，LinkAgent 在清楚说明制作方式和费用后，交付一条能观看、能修改、能导出的初稿，以及与这条视频一致的投稿材料。**

“自动”必须落实为实际媒体产物和可验证的修改。输出分镜、制作步骤或建议不能代替交付视频。

支持独立的小任务。用户只要标题、简介或选题时，只交付相应结果，不强制生成整条视频，不强制走成片试映。

### 1.3 衡量价值的三个问题

- 零剪辑经验的用户能否在部署已经配置好的条件下得到第一条可观看初稿？
- 用户换一个主题，开发者是否无需修改渲染源代码就能制作下一条？
- 用户说“把结尾改得轻松一点，字幕大一点”，系统是否确实修改对应内容，并保留可回看的旧版？

任何阶段若只让表单更丰富、报告更多，却没有推进这三个问题，不应作为本方案的主要成果。

### 1.4 不承诺的结果

不承诺爆款、涨粉、收益、影视级人物表演、任意素材的专业剪辑或一次生成即满意。试映中的 AI 观众是推测，不是真实观众，不构成传播效果保证。

## 2. 现状与差距：以真实证据为起点

本节保留 2026-10-18 初始设计时的证据基线。后续 S1–S3d 进展以 [文档索引](../README.md) 和阶段实现记录为准；不能用本节代替最新源码与测试核对。

### 2.1 当前已存在的能力

| 能力 | 当前事实 | 在新方案中的用途 |
|---|---|---|
| 创作任务、材料和发布前工作流 | 已有任务、想法对齐、方案生成与确认 | 保留业务事实和确认记录，减少重复输入 |
| 制作蓝图 | 已有制作方式、步骤、前置门禁和步骤完成状态 | 自动制作时成为执行计划的业务映射 |
| 私有媒体上传、探测和预处理 | 已有 OSS 分片上传、FFprobe、FFmpeg、音轨和关键画面 | 复用；不是新建第二套媒体后端 |
| 发布前试映 | 已有 ASR、时间轴、画面分析、片段复核、三类观众和修改清单 | 对真实生成的版本继续试映 |
| 用户发布后链路 | 已有 BV 绑定、反馈、复盘及门禁 | 使用用户真实发布后的数据 |
| 平台操作助手 | 已有查询、操作提案、计划确认与连续执行 | 新制作操作接业务服务，不由聊天伪造完成 |
| Python Agent | 已有迁移设计、服务骨架和协议基线 | 遵循迁移边界，不假定业务已全部迁移 |

### 2.2 本次真实作品证明了什么

本次《月亮维修员》实际输出了 75 秒、1920×1080、24fps、H.264/AAC 的原创程序动画、旁白、音乐音效、字幕、封面和发布文案，随后通过当前项目上传、预处理并完成试映。

关键边界：**连续画面和声音由工作台外部的 AI 编程制作，不是当前 LinkAgent 自动制作功能的产物。** 平台中的 V1 对应制作目录中的本地 V2；两个版本命名体系不能混用。

可复用的原型位于 `export/first-video-20261018/`，其中 `produce.py`、`graphics.py`、`film_content.json`、`timeline.json` 展示了制作路径。但画面逻辑含月亮、机器人和具体剧情，不能通过改标题就声称它是通用渲染器。

已有真实证据覆盖上传、媒体处理、试映、浏览器整片播放等。尚未覆盖产品内自动生成、自然语言修改后再导出、用户真实发布后的反馈和复盘。本方案要补的是这些能力，不能用既有成功记录替代新能力验收。

### 2.3 体验暴露的关键问题

| 问题 | 深层原因 | 本方案的响应 |
|---|---|---|
| 用户拿到制作清单后仍不会做 | 系统把制作执行留给了目标用户 | 增加实际渲染与导出 |
| 反复填写相同信息 | 各阶段独立收集定位，没有稳定任务简报 | 任务级简报和自动继承 |
| 外部专家需要持续救场 | 运行状态、环境错误、恢复路径对新手不可理解 | 异步任务、可恢复状态、明确部署检查 |
| 高置信度试映也会说错 | 模型观察、计算事实、观众推测混在一起 | 分层证据、代码计算、冲突复核 |
| 修改建议难以变成新视频 | 没有结构化可编辑工程与依赖关系 | 稳定场景 ID、受限修改和版本重渲染 |
| 一次成功不能自然复制 | 原型与具体故事绑定 | 内容数据和渲染代码分离，跨主题验收 |
| 费用看不到完整任务 | 文本、音频、视频调用分散，失败调用可能未知 | 统一任务费用视图和保留未知预留 |

## 3. 首个版本的范围与取舍

### 3.1 首发采用受控的素材组合制作

首发从 `ILLUSTRATED_NARRATION` 图文配音基线扩展为**自有图片、录音、音乐和视频片段的场景化组合**，覆盖录屏讲解、照片配音、原声片段组合。建议时长仍为 60–90 秒，用户可在部署实际支持范围内指定总时长；不能把建议值当成统一限制。

当前 S2 / RenderInputV1 仍只支持图片与 PCM WAV。新增素材组合须通过版本化渲染契约、媒体准备和真实验收后开放，继续使用同一个受控 Python/FFmpeg 引擎。

| 项目 | 首发设计值 | 说明 |
|---|---|---|
| 画幅 | 16:9 | 后续扩展竖屏不混入首轮 |
| 成片 | 1920×1080、24fps | H.264、AAC、48kHz，具体编码参数记录快照 |
| 试片 | 约 10–15 秒、720p，可独立下载 | 来自已确认故事板的一段，不占整片版本号，不能冒充整片 |
| 语言 | 简体中文旁白和字幕 | 英文混排须有字体回退 |
| 画面 | 用户图片、视频片段、内置图形和排版、可选生成图片 | 可按场景选取、排序和替换，不强制增加付费生图供应商 |
| 运动 | 平移、缩放、淡入淡出、有限图形动画 | 使用受控参数；不执行模型生成的代码 |
| 音频 | 已配置 TTS、用户录音、选定片段原声、用户提供的音乐 | 明确对白来源，支持受控混音；不默认克隆真实个人声音 |
| 素材操作 | 场景绑定、截取范围、排序、替换、画幅适配 | 不开放无限轨道；素材不足和时长冲突需可见处理 |
| 导出 | 样片/制作预览 MP4、SRT、封面；完整试映后的投稿发布包 | 样片绑定 SAMPLE 资产，整片和正式包绑定精确视频版本 |

这些数值是首个制作配置，不得覆盖已有上传功能的全局时长、格式或文件大小限制。现有用户仍可上传符合原规则的其他视频。

这类作品适合短知识解释、录屏演示、照片讲解、轻故事和原声片段整理。不能把它宣传成与连续人物表演等价的动画。素材、声音、截取、样片和下载的完整规则见 [补充方案](视频素材导入与样片导出补充方案.md)。

### 3.2 首发必须提供的结果

1. 一句话想法可转成有限、可制作的简报与故事板。
2. 用户确认方向后可直接生成整片，也可先看并下载短样片。
3. 系统完成配音、时间轴、画面、字幕、封面及初版投稿文案。
4. 成片自动接入原有探测、预处理和完整试映，用户不必手动下载再上传。
5. 用户能用自然语言或场景卡片修改旁白、字幕样式、图片/视频素材、截取范围、声音来源和局部节奏。
6. 修改生成新的不可变版本；旧版仍可回看和选择。
7. 可以导出与选定版本一致的发布包，实际投稿由用户操作。
8. 标题、简介、选题可单独生成，不被整片流程绑架。
9. 用户自己的图片、录音、音乐和视频片段能实际进入工程；上传状态、选取范围、声音选择和导出结果可在页面核对。

### 3.3 首发明确排除

- 影视级连续角色动画、口型同步、任意机位、多角色一致性生成。
- 在服务器上执行模型临时生成的 Python、JavaScript、Shell、FFmpeg 命令串。
- 通用时间线剪辑器、无限轨道、专业调色和插件市场。
- 自动搬运网络视频、绕过登录获取素材或默认下载不明授权素材。
- 自动向 B 站投稿、代用户登录、模拟真实评论或播放量。
- 自动重写已绑定 BV 的作品并把旧反馈当作新版反馈。
- 同时上线多个渲染引擎、复杂分布式调度平台、GPU 集群。
- 为本功能重新实现 RAG、长期记忆或通用多 Agent 框架。

按场景选择素材、简单截取、排序和声音处理属于此次首发补充，不能因排除通用剪辑器而一并排除。

### 3.4 为什么不先做任意视频

任意视频需要不同的素材组织、时序控制、视觉规范和验证方法。先把有限场景和受控素材组合做到内容可变、修改可控、失败可恢复，再根据实际创作需求扩展。

不采用“每个新主题由 AI 写一个新程序”的运行模式。开发 AI 可以在研发阶段编写稳定渲染器，普通用户使用阶段只能提交数据和受限修改。

## 4. 用户体验与意图分流

### 4.1 三个主要入口

| 用户说的话 | 意图 | 交付 |
|---|---|---|
| “帮我想几个适合新手的选题” | `IDEAS` | 少量有差异的选题与制作可行性 |
| “给这段稿子起标题／写简介” | `TITLES` / `DESCRIPTION` | 对应文案，标明依据和缺失信息 |
| “把这个点子做成视频” | `CREATE_VIDEO` | 简报、试片或整片、可修改工程和发布包 |
| “第三幕换张图，字幕大一点” | `REVISE_VIDEO` | 指定版本的修改提案和新版 |
| “我已经有成片了” | 原有已有成片入口 | 保留显式跳过策划后进入试映的路径 |

意图识别不可靠时，先提供简短选择。不能因为出现“视频”就触发付费制作。

### 4.2 新手创建视频的主流程

1. 输入想法并选择目标时长。可选提供图片、已有文稿、录音、音乐、视频片段或参考描述。
2. 系统返回一屏简报：准备讲什么、给谁看、怎样制作、预计时长、主要限制、费用范围。
3. 对明显影响作品的缺失信息最多集中问一轮；非关键风格采用可修改默认值。不要连续询问十几个专业术语。
4. 用户确认方向与费用范围。系统保存对应的发布方案确认记录及制作授权。
5. 用户可选“先看一段”或“直接生成初稿”；两者是明确的执行动作。样片可单独播放、下载，再决定修改或继续整片。
6. 制作时展示真实阶段和已完成镜头，可离开页面再回来。
7. 完成后首先展示可播放视频，其次展示需要注意的事项、场景修改和下载入口；制作预览与完整试映后的正式发布包明确区分。
8. 用户用一句话提出修改，查看修改范围和新增费用，再按已授予的范围执行。
9. 系统完成实际版本的试映并组织发布包。用户自己投稿，再提供真实 BV。

样片不是强制第三次审批。已经明确选择直接生成整片的用户，不应被强制停在样片确认；但不能用这种简化取消发布方案确认、费用授权或真实发布门禁。

### 4.3 小 UP 的使用方式

小 UP 可以提供自己的稿件、图片、录音、音乐和视频片段，完成录屏讲解、照片配音或原声片段组合，也可只补选题、改标题、改简介或调整已有本系统工程。保留原有成片上传试映路径。

首发的场景修改依赖本系统结构化工程。外部 MP4 可以作为素材导入、截取并组成新工程，但不会自动恢复原始字幕层、配音层和分镜。整条成片上传试映与素材片段导入分别提供，不能把前者当作后者已经完成。

### 4.4 控制输入负担

- 创作者画像是默认偏好，任务简报是本条视频的事实，二者分开。
- 自动继承已填写的受众、语气、时长、禁止事项，不跨页面再问同一问题。
- 标题、简介和标签基于实际成片更新；不得与剧本未落地的内容保持错误一致。
- 任务显示名称与已确认材料分开。改列表名称不能使成片、试映和复盘失效。
- 原 `video_type` 的 B 站分区含义与 `renderProfile` 的制作形式分开，不把“图文动画”直接塞进分区枚举。
- 未配置 OSS/TTS/字体属于部署者任务，日常创作者页面说明受影响能力并给出可恢复状态，不要求新手理解端口和请求头。

### 4.5 授权的产品含义

发布方案确认、执行制作、增加费用、实际投稿是不同动作。可在同一张确认卡上合并前两者的用户操作，但后端必须保存各自的事实。

一次明确制作授权可允许其范围内的配音、渲染、私有媒体写入、自动试映与有限重试；不能扩张为无限付费、发布到外部平台、克隆声音或改动另一条任务。模型不能代替用户点击确认。

## 5. 总体技术结构与职责

### 5.1 主链路

```text
用户意图与已有材料
  -> 任务简报 / 文案请求
  -> 受约束的脚本和故事板
  -> 发布方案确认 + 范围明确的执行授权
  -> Java 持久化制作任务
  -> 素材准备 / TTS / 实测时间轴
  -> Python 确定性渲染器 CLI
  -> 本地产物校验 / 私有 OSS 入库
  -> 真实完成制作蓝图的制作步骤
  -> 注册新的成片版本
  -> 原有 FFprobe / 媒体预处理 / 完整试映
  -> 版本对应的发布包
  -> 用户实际投稿 / BV 绑定 / 真实反馈 / 复盘
```

### 5.2 模块边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| Vue 创作界面 | 输入、确认、播放、修改预览、任务恢复和导出 | 不存密钥，不拼 FFmpeg 命令，不推测任务成功 |
| Java 创作业务 | 归属、简报版本、授权、任务状态、预算、事务、门禁、版本指针 | 不把长模型调用放在数据库事务里 |
| Agent / 结构化模型调用 | 意图、脚本、故事板候选、文案、修改提案 | 不直接写 `creator_*` 业务表，不自行授权付费 |
| 素材与 TTS 适配 | 在已授权任务下调用供应商，保存真实用量和资产 | 不绕过预算，不由渲染器读取 `.env` 发请求 |
| Python 渲染 CLI | 读取已校验的本地工程，生成确定性媒体和清单 | 不访问业务库、OSS、外网或用户密钥 |
| 既有媒体服务 | 上传与私有读取、探测、预处理、试映、删除和读取签名 | 不承担任意创意代码执行 |
| 既有发布后服务 | 校验真实 BV、反馈和复盘 | 不制造发布事实或沿用错误版本的分析 |

### 5.3 与 Python Agent 迁移并行

当前 Java Agent 业务与 Python 迁移工作可能并行。实现时以最新阶段说明为准：不能根据 Python 骨架存在就假定业务已切换。

- 模型业务先接入届时实际使用的调用边界；没有完成切换时，复用现有 Java `LLMService` 等入口。
- 迁移后的 Agent 请求继续遵循 `payload + usageContext + invocationId` 信封和现有用量语义，缺失用量为未知而不是 0。
- Java 保有创作业务表、门禁、媒体任务和执行租约的写入责任。
- Python 渲染 CLI 是有固定输入输出的本地媒体工具，与 Python Agent 服务是两种职责。可以共享语言和环境，不共享数据库写权限。
- ASR/视觉/TTS 的供应商协议按已确认迁移边界接入，Java 保存业务结果。不要复制第二套重试、计费或 HTTP 客户端。
- 不以“等整个 Agent 迁完”为自动制作的前置条件，也不为此抢先迁移无关模块。

### 5.4 首发技术选择

复用实际原型中 Pillow/NumPy/FFmpeg 的可行路径，但提取成受控模板、资产和时间线。先实现一个渲染引擎，不引入通用渲染插件层。

Remotion 可以作为未来经过实测的替代选择。本轮不同时实现它。若后续选用，要重新核对部署、资源占用、许可证及授权条件，不能默认所有使用场景均免费。

## 6. 结构化输入、工程和资产

### 6.1 任务简报 `CreationBriefV1`

简报是当前任务意图的结构化快照，不是长期记忆，不用聊天历史全文替代。

| 字段 | 类型 / 规则 |
|---|---|
| `briefRevision` | 正整数，由服务端分配 |
| `intent` | `CREATE_VIDEO` 或独立文案意图 |
| `topic` / `coreMessage` | 主题、观众应记住的一个核心信息 |
| `audience` | 普通语言受众描述；可采用默认值并标注 |
| `targetDurationSec` | 默认建议 60–90；允许在部署支持范围内指定，固定时长与按内容自适应需明确；实际成片以实测为准 |
| `renderProfile` | 采用已部署的受控配置；图文基线扩展素材组合前须完成 RenderInputV2 与真实媒体验收 |
| `tone` / `visualStyleId` / `voiceId` | 从支持列表中选，保存实际配置快照 |
| `providedAssetIds` | 仅本任务有权限的资产 ID |
| `constraints` | 不想出现的内容、隐私和表达限制 |
| `factSources` | 用户材料或检索到的具体来源；虚构故事标明虚构 |
| `assumptions` / `openQuestions` | 默认值和仍影响制作的缺口 |
| `platformCategory` | 可空的 B 站分区意向，与制作形式分开 |

简报、故事板及渲染工程保留 `schemaVersion`。不把未经验证的历史聊天、案例库描述或记忆自动升级为用户事实。

### 6.3 必须由代码校验的规则

- 场景 ID 唯一、非空、稳定；调序不改变 ID。场景数和单场景文字长度设明确上限。
- `layoutId`、`motion.type`、字体、配色和音色全部来自受控注册表。
- 模型不能提供绝对路径、URL、脚本、表达式、FFmpeg filter 字符串或任意模板源码。
- 图片/视频尺寸、MIME、资源大小、源时长、截取范围、字体可用性、文本框范围由真实资产或渲染结果验证。
- 建议时长不等于实测时长。按实际 TTS、用户录音、片段及留白和转场重叠重算；不能只靠字数估算承诺固定时长。
- 使用十进制或整数毫秒计算时间；帧时间按有理数转换，不逐帧累积浮点误差。
- 标注为事实的可核查断言必须有来源，缺来源时调整表达或请用户提供依据。不能补一个无关引用凑字段。
- 首发不让 LLM 输出逐字字幕时间。字幕来自实际音频与对齐结果；模型只能建议分句。
- 严格结构化输出之后仍做业务校验，不能把 JSON 可解析等同于工程可渲染。

### 6.4 资产的四类来源

| 来源 | 首发处理 |
|---|---|
| `BUILTIN` | 项目提供且来源明确的图形、字体、声音、模板 |
| `UPLOAD` | 用户主动上传的图片、录音、音乐、视频片段和受支持字幕；校验真实格式、归属和限制 |
| `GENERATED` | 已授权的 TTS 或可选生成图片；保存供应商、调用和来源说明 |
| `DERIVED` | 裁切、混音、镜头片段、字幕、封面、清单等派生产物 |

首发补充用户 PNG/JPEG 图片、常见音频、可解码 MP4/MOV 片段和经校验字幕；具体白名单及探测、规范化、声音处理见 [素材接入规则](视频素材导入与样片导出补充方案.md#4-素材接入与处理规则)。不直接接受带脚本的 SVG、HTML 或可执行工程。素材上传不创建完整视频版本，已有成片上传继续走原有规则和入口。

私有资产保存桶和对象键、摘要、来源和归属，不持久化短签 URL。浏览器预览临时签名，过期后重新获取。模型输入引用资产 ID 或业务事实，不接触 OSS 密钥。

### 6.5 素材和内容来源

发布包列出素材来源、内置或生成标识、用户提供标识，以及实际调用的模型信息。不能给出未经确认的“完全无版权风险”保证。

案例库用于结构与表达参考，不默认下载原视频或复用其画面。风格参考应转成抽象描述，不复制对方完整脚本、商标或人物身份。

## 7. 领域对象、版本与状态机

### 7.1 不要把所有状态塞进任务状态

| 对象 | 表达什么 | 不能替代什么 |
|---|---|---|
| 原 `CreatorTask` | 任务归属和既有业务生命周期 | 不承担每一帧制作进度 |
| 原发布前工作流 | 用户对发布方向的确认事实 | 不代表媒体已生成 |
| 创作工作区 | 当前简报、选中工程、选中视频和活动制作任务 | 不覆盖历史产物 |
| 故事板版本 | 一份不可变的可编辑内容工程 | 不代表 TTS 和视频已完成 |
| 制作运行 `CreationRun` | 一次有授权、有预算、可恢复的执行 | 不与旧工作流 session 状态混用 |
| 成片版本 `DraftVideo` | 实际存在的一个完整视频对象 | 样片不是完整成片版本 |
| 媒体处理与试映任务 | 对某视频及某次预处理结果的分析 | 不能复用于不同视频字节 |
| 发布绑定 | 一个真实 BV 与实际发布版本的关系 | 不随编辑页选择新版自动变化 |

工作区的“待确认、可看样片、正在制作、初稿就绪、待修改、可导出”等展示状态，从持久化对象推导。不要再维护一套可能与后台脱节的前端真值。

### 7.2 故事板版本

- 创建时分配 `storyboardId`、递增 `storyboardRevision`、`documentHash` 和父版本。
- 文档一旦保存为版本就不可原地修改；调整文字也生成新的故事板版本。
- 是否被批准由授权快照引用决定，不需要不断修改故事板 JSON 的 `approved` 字段。
- 尚未执行的新候选不自动替换当前成片。界面明确区分“候选工程”“当前视频”“已发布视频”。
- 每个产物记录实际使用的故事板、模板、字体、配音、渲染器版本与输入摘要。

### 7.3 制作运行类型

| `kind` | 输入与输出 | 是否注册完整成片 |
|---|---|---|
| `TEXT` | 选题、标题、简介请求 -> 文案结果 | 否 |
| `PREPARE` | 简报、材料 -> 故事板候选、发布方案候选、估算 | 否 |
| `SAMPLE` | 已授权故事板 -> 10–15 秒样片和复用资产 | 否 |
| `FULL` | 已授权故事板 -> 完整成片、处理、试映和发布包 | 是 |
| `REVISION` | 基准成片、已接受的修改 -> 新故事板和新版全链路 | 是 |
| `PACKAGE` | 已就绪成片与选定文案 -> 重建发布包 | 否；不重做视频 |

自然语言修改的解释与候选差异由 `PREPARE` 的 `purpose=CHANGE_PROPOSAL` 产出；真正改视频是随后有授权的 `REVISION`。不要为提案和执行分别复制一整套工作流框架。

### 7.4 制作运行状态

```text
QUEUED -> RUNNING -> COMPLETED
              |-> WAITING_DEPENDENCY -> RUNNING
              |-> FAILED
QUEUED / RUNNING / WAITING_DEPENDENCY
              -> CANCEL_REQUESTED -> CANCELLED
```

- `WAITING_DEPENDENCY` 表示等待已经登记的媒体子任务或供应商异步任务，不表示继续占着工作线程轮询。
- 等待用户确认时不创建假运行中的制作任务。提案运行可以 `COMPLETED`，工作区展示“待你确认”。
- 预算不足、输入已变、依赖不可恢复等以明确错误结束，保留可用产物。
- 显式重试创建关联原运行的新 `runId`，复用已验证资产；不清空失败历史。
- 自动重试仅适用于第 10 节允许的情况，保留本运行的尝试计数和物理调用费用。
- `COMPLETED` 按类型定义：`SAMPLE` 须完成样片编码、本地检查和存储校验；`FULL/REVISION` 必须完成实际媒体处理、完整试映和发布包。
- 渲染成功、对象上传成功只是阶段里程碑，不能提前将 `FULL` 标为 `COMPLETED`。

### 7.5 单任务活动运行与并发

P0 同一工作区只允许一个活动运行，包含 `TEXT/PREPARE/SAMPLE/FULL/REVISION/PACKAGE`。只读聊天、查看旧版本和播放不受限制。用数据库工作区行锁和 `active_run_id` 实现，不引入分布式工作流平台。

`QUEUED/RUNNING/WAITING_DEPENDENCY/CANCEL_REQUESTED` 占用活动位置；终态释放。依赖等待释放 worker 租约，保留工作区活动位置，防止另一轮修改覆盖工程。

运行保存 `expectedWorkspaceRevision`、输入指纹、故事板 ID、基准视频版本及授权快照。外部调用回来后必须再次核对租约代数和输入指纹，旧结果可以保留为资产和计费证据，不能覆盖新选择。

启动时的预期工作区版本用于受理请求的 CAS，不能在 worker 保存时机械地再次比较原数值，因为运行自己也会推进工作区版本。worker 以活动运行身份、租约代数和内容指纹为依据；注册时再校验选版前值，恢复时允许已经登记的同一输出版本。

P0 活动运行期间拒绝修改简报、工程选择、当前视频和执行授权，用户先取消再改。显示别名可单独修改，预算可按费用约束调整；这些操作不改变视频内容指纹，也不自动扩大已有执行授权。

### 7.6 完整成片版本

当前 `creator_draft_video` 已有 `(task_id, version_no)` 唯一键，可存不同版本号。问题是部分查询和上传行为固定 V1，而不是必须重建版本表。

采用以下语义：

1. `versionId` 是不变身份，`versionNo` 是任务内展示序号，序号允许有空洞。
2. 工作区 `current_video_version_id` 是用户当前选中的完整版本，不通过 `MAX(version_no)` 隐式决定。
3. 在完整 MP4 通过本地校验、私有存储校验且制作门禁满足后，注册 `UPLOADED` 版本，并在短事务中切换当前指针。
4. 新版仍需探测、处理和试映。期间显示“新版检查中”，原版可回看；不得沿用旧版试映放行新版。
5. 样片、中间镜头和失败产物不占完整版本序号，不写成 `READY_FOR_REVIEW`。
6. 用户显式选择旧版时，校验归属、媒体存在和对应试映就绪；不存在的对象不能被重新选为可发布版。
7. 重传只允许恢复属于该上传会话的未完成版本，不能重置另一个完整历史版本。

显式选版同时恢复该版本对应的编辑基准，并使不匹配的新执行授权失效。未执行候选保留在工程历史中，不暗中丢弃；后续修改不能仍基于之前选中的另一版。

### 7.7 发布后的版本冻结

- P0 不在已绑定 BV 的同一任务继续自动制作并替换发布作品；需要继续创作时新建任务，可显式复用素材。
- 用户绑定 BV 时，保存 `published_version_id` 和正式标题简介快照，并再次校验当时实际选中版本的门禁。
- 发布版本以原 BV 绑定记录为唯一业务真值；工作区查询可返回这个字段，但不再维护一个独立可写的发布指针。
- BV 绑定后的反馈、复盘读取发布快照，不跟随 `current_video_version_id`。
- 存量绑定若没有足够信息确认对应版本，保留“历史绑定版本未记录”，不能按最大版本补造事实。
- 本地导出和是否在 B 站发布是不同事实。下载 ZIP 不能自动把任务标成已发布。

## 8. 数据模型建议

### 8.1 设计原则

新增数据围绕本功能，不创建通用低代码工作流或企业审计系统。下述七张表是完整方案的建议，按阶段增量创建；不是要求第一天一次建完所有空表。

统一维护 `backend/src/main/resources/sql/init.sql`，遵循现有 ID、时间、软删除和 MyBatis 风格，数据库字段注释用中文。业务引用沿用当前项目的一致性方式，不顺便引入迁移框架。

本文字段类型是设计基线；落地前核对现有 DTO、字段长度和索引限制，重要变更需要作者确认，局部命名采用仓库惯例。

### 8.2 `creator_creation_workspace`

一条任务最多一条工作区记录。任务归属仍以现有 `creator_task` 为业务依据。

| 字段 | 建议类型 | 语义 |
|---|---|---|
| `id` | `BIGINT` | 主键 |
| `task_id` / `owner_id` | `VARCHAR(64)` | 任务与现有媒体归属 |
| `mode` | `VARCHAR(32)` | `LEGACY` / `AUTO_CREATION` |
| `display_name` | `VARCHAR(128)` | 不触发内容失效的工作区显示名 |
| `workspace_revision` | `BIGINT` | 业务写入的乐观锁版本 |
| `brief_revision` | `INT` | 当前简报版本 |
| `brief_json` | `LONGTEXT` | 受校验的简报快照 |
| `current_storyboard_id` | `VARCHAR(64)` 可空 | 选定工程，不等于已渲染视频 |
| `current_video_version_id` | `VARCHAR(64)` 可空 | 当前完整视频 |
| `active_run_id` | `VARCHAR(64)` 可空 | 当前唯一活动运行 |
| `current_approval_id` | `VARCHAR(64)` 可空 | 当前制作授权；历史授权保留在授权表 |
| `next_version_no` | `INT` | 下一完整成片序号，事务内递增 |
| `budget_limit_cny` | `DECIMAL(18,6)` | 当前任务预算，有限正数 |
| 创建、更新时间、软删除字段 | 与现有表一致 | 不新增账号体系 |

唯一键 `task_id`，索引 `active_run_id`。预算消耗不另存可随意覆盖的累计数，按费用流水汇总；有性能需要再添加可校验缓存。

`workspace_revision` 只在简报、授权、工程选择、视频选择、预算和活动运行变更时递增。逐帧进度、心跳不更新此值，避免用户确认因无关进度频繁冲突。

### 8.3 `creator_storyboard`

| 字段 | 建议类型 | 语义 |
|---|---|---|
| `id` | `BIGINT` | 主键 |
| `storyboard_id` | `VARCHAR(64)` | 唯一外部 ID |
| `task_id` / `owner_id` | `VARCHAR(64)` | 归属 |
| `storyboard_revision` | `INT` | 任务内递增工程版本 |
| `parent_storyboard_id` | `VARCHAR(64)` 可空 | 修改来源 |
| `brief_revision` | `INT` | 对应简报 |
| `schema_version` / `template_version` | `VARCHAR(64)` | 工程和模板契约 |
| `document_json` | `LONGTEXT` | 不可变故事板 |
| `document_hash` | `CHAR(64)` | 规范化 JSON 的 SHA-256 |
| `source_run_id` | `VARCHAR(64)` | 生成或修改运行 |
| `change_summary_json` | `LONGTEXT` 可空 | 场景差异及解释，不放私密思考链 |
| 创建时间、软删除字段 | 与现有表一致 | 内容不原地编辑 |

唯一键 `storyboard_id`、`(task_id, storyboard_revision)`。文档哈希包含实际渲染内容；规范化方法固定并测试，不依赖随机 JSON 键顺序。

哈希规范由 Java 一处实现：解析并校验后按固定键顺序、固定数字表示和 UTF-8 无 BOM 序列化，统一换行规则；不含临时签名、时间戳和进度。Python 消费同一规范化内容与摘要，不自行发明另一种哈希算法；用固定样例测试两端传输没有改变实际内容。

### 8.4 `creator_creation_asset`

| 字段组 | 建议字段 | 语义 |
|---|---|---|
| 身份 | `asset_id`、`task_id`、`owner_id` | 业务引用用 ID |
| 分类 | `asset_kind`、`source_kind`、`scene_id` | 图片、TTS、音乐、片段、SRT、封面、清单、发布 ZIP 等 |
| 版本 | `storyboard_id`、`source_run_id`、`source_step_id` | 来自哪一次真实执行 |
| 存储 | `bucket_name`、`object_key` 或 `builtin_ref` | 对象与内置资产二选一 |
| 文件 | `content_type`、`file_size`、`sha256` | 真实检测值，摘要为 `CHAR(64)` |
| 媒体 | `duration_ms`、`width`、`height`、`metadata_json` | 实测；无此属性时为空 |
| 复用 | `cache_key`、`renderer_version` | 有效复用的输入依据 |
| 来源 | `provenance_json`、`provider_call_ref` | 来源、供应商与费用关联 |
| 上传幂等 | `upload_idempotency_key`、`upload_request_hash` | 用户上传时保存，派生资产可空 |
| 生命周期 | `status`、创建时间、软删除字段 | `PREPARING/READY/FAILED/DELETED` |

唯一键 `asset_id`。`cache_key` 建普通索引，不在软删除/并发情况下错误设置全局唯一；命中时校验归属、完整性和引用关系。

另建 `(owner_id,task_id,upload_idempotency_key)` 唯一键，上传请求摘要包含实际文件摘要和受校验的元数据。同键不同文件拒绝，不能只靠原文件名防重。

最终 MP4 的对外版本身份仍是 `creator_draft_video`。若资产表记录其摘要或渲染来源，必须指向同一对象，不能形成两个独立删除责任方。

### 8.5 `creator_creation_run`

| 字段组 | 建议字段 | 语义 |
|---|---|---|
| 身份 | `run_id`、`task_id`、`owner_id`、`kind`、`purpose` | 运行与业务类型 |
| 幂等 | `idempotency_key`、`request_hash` | 同键不同请求返回冲突 |
| 输入 | `input_fingerprint`、`storyboard_id`、`base_version_id`、`brief_revision` | 不可变输入 |
| 授权 | `authorization_snapshot_json`、`budget_snapshot_json` | 启动时真实授权和限额 |
| 关联 | `parent_run_id`、`publishing_session_id`、`publishing_result_id`、`production_plan_id`、`created_video_version_id`、`processing_job_id`、`preflight_review_id` | 精确关联，不能取任意最新方案或子任务 |
| 状态 | `status`、`stage`、`run_revision`、`progress_json` | 阶段进度；不承诺准确剩余秒数 |
| 里程碑 | `artifact_ready_at`、`artifact_manifest_asset_id` | 媒体产物就绪，不等于全链路完成 |
| 调度 | `next_run_at`、`lease_owner`、`lease_expires_at`、`lease_generation`、`attempt_count` | 持久化恢复和旧 worker 隔离 |
| 结果 | `result_json`、`error_code`、`error_message` | 脱敏结果、可恢复动作 |
| 时间 | 排队、开始、完成、创建、更新时间 | 用于真实耗时统计 |

唯一键 `run_id`、`(owner_id, task_id, idempotency_key)`。领取索引覆盖 `status/next_run_at/lease_expires_at`，查询执行计划在隔离库验证。

### 8.6 `creator_creation_step`

| 字段组 | 建议字段 | 语义 |
|---|---|---|
| 身份 | `step_id`、`run_id`、`step_code`、`scope_key` | `scope_key` 为稳定场景 ID 或固定 `GLOBAL`，非空 |
| 输入输出 | `input_hash`、`output_asset_ids_json`、`output_json` | 断点恢复和可核查产物 |
| 状态 | `status`、`attempt_count`、`cache_hit` | `PENDING/RUNNING/COMPLETED/FAILED/SKIPPED/CANCELLED` |
| 供应商 | `provider_request_id`、`cost_entry_ids_json` | 查询异步请求和真实调用次数 |
| 错误时间 | `error_code`、脱敏错误、开始完成时间 | 不记录密钥或短签 URL |

唯一键 `step_id`、`(run_id, step_code, scope_key)`。租约由运行统一管理，步骤写入同时核对运行租约代数；不要引入第二套互相竞争的步骤租约。

自动执行固定代码中的依赖图，不能让 LLM 发明任意 `step_code` 来驱动业务。

### 8.7 `creator_creation_cost_entry`

| 字段组 | 建议字段 | 语义 |
|---|---|---|
| 身份 | `entry_id`、`task_id`、`owner_id`、`run_id`、`step_id`、`authorization_id` | 任务预算、跨运行授权余额和调用关联 |
| 去重 | `charge_key` | 一次物理外部调用的唯一记账身份，发送前生成 |
| 来源 | `provider`、`model`、`capability`、`source_log_refs_json` | 可关联全局和媒体用量记录，同次不重复加总 |
| 估算 | `reserved_cny`、`price_snapshot_json`、`exchange_rate_snapshot` | 发起前保守预留 |
| 结算 | `known_cost_cny`、`native_currency`、`native_cost`、`usage_json` | 供应商返回或根据真实用量估算 |
| 语义 | `status`、`settlement_kind` | `RESERVED/SETTLED/UNKNOWN/RELEASED`；估算与账单分开 |
| 关联时间 | `provider_request_id`、创建更新时间 | 失败不删除费用依据 |

唯一键 `charge_key`。`settlement_kind` 至少区分 `USAGE_ESTIMATE` 与 `PROVIDER_REPORTED`，两者都不自动等于供应商月度结算账单。

费用表是预算预留与统一视图，不再次调用模型，不复制原始响应全文。已有日志仍负责各自用量事实，归并规则见第 16 节。

### 8.8 `creator_creation_approval`

授权必须可持久恢复和引用，不能仅存一份会被覆盖的工作区 JSON。这里保存业务执行依据，不是新增账号权限或企业审计系统。

| 字段 | 建议类型 | 语义 |
|---|---|---|
| `id` / `approval_id` | `BIGINT` / `VARCHAR(64)` | 主键与唯一外部 ID |
| `task_id` / `owner_id` | `VARCHAR(64)` | 归属 |
| `approval_kind` | `VARCHAR(32)` | `PREPARATION/PRODUCTION/REVISION` |
| `prepared_run_id` | `VARCHAR(64)` 可空 | 依据哪个已完成准备结果 |
| `brief_revision` / `storyboard_id` / `storyboard_hash` | 整数 / ID / `CHAR(64)` | 精确绑定工程，准备阶段工程可空 |
| `publishing_session_id` / `publishing_result_id` | `VARCHAR(64)` 可空 | 已有真实发布方向确认；准备授权不伪造此记录 |
| `scope_json` / `budget_snapshot_json` | `LONGTEXT` | 允许动作、修改范围、金额和次数 |
| `max_additional_cost_cny` | `DECIMAL(18,6)` | 整个授权合计可增加费用，不按运行重置 |
| `idempotency_key` / `request_hash` | 与运行幂等字段相同 | 确认超时重试可返回原授权 |
| `status` | `VARCHAR(32)` | `ACTIVE/SUPERSEDED/REVOKED` |
| `approved_at` / `revoked_at` | 与现有时间类型一致 | 用户动作事实 |

唯一键 `approval_id`、`(owner_id,task_id,idempotency_key)`。批准内容和原始依据不可变，仅允许状态失效；运行仍保存启动时快照。

`TEXT/PREPARE` 请求在同一短事务保存准备授权和排队运行。准备授权不替换当前制作授权，不把“允许花一元准备”解释为“已确认整片方向”。

无模型调用的 `PACKAGE` 可由用户明确导出请求直接形成零付费执行快照，不必创建伪发布确认或新增授权种类。

### 8.9 现有表的增量调整

| 现有对象 | 建议调整 | 禁止的捷径 |
|---|---|---|
| `creator_draft_video` | 增加生成来源、`creation_run_id`、`storyboard_id`、`parent_version_id`，以及发布确认和制作计划关联；旧记录默认上传来源 | 删除已有 `(task_id,version_no)` 唯一键 |
| `creator_task_video_binding` | 增加可空 `published_version_id` 和必要正式发布快照关联 | 将历史绑定随当前版本覆盖 |
| 原上传会话 | 创建时分配独立目标版本，续传始终绑定同一版本 | 每次上传重用并清空 V1 |
| 原费用记录 | 必要时新增 `TTS/IMAGE` 能力与运行关联，更新枚举、查询和 UI | 把 TTS 伪装成 ASR 或漏计失败调用 |
| 原制作计划与步骤 | 增加系统制作来源、运行和产物证据的最少关联 | 把所有步骤一次性勾成完成 |
| 原预处理/试映任务 | 保存可恢复的 `creation_run_id/authorization_id` 等预算上下文 | 只在线程变量里带费用上下文，worker 重启后丢失 |
| 原任务显示名 | 提供只改显示名的窄入口或统一读取工作区别名 | 放开冻结材料的整个更新接口 |

`LONGTEXT` 中的 JSON 在服务层严格校验，是否改用原生 JSON 类型沿用现有项目风格，不在此轮顺便切换全库。

### 8.10 通用字段与幂等存储约束

- 对外 ID、归属、场景 ID、关联 ID 默认沿用现有 `VARCHAR(64)`；操作类型/状态默认 `VARCHAR(32)`，哈希为 `CHAR(64)`。
- JSON 快照沿用 `LONGTEXT`；文件大小、时长、运行修订和租约代数为 `BIGINT`，尺寸和步骤计数为 `INT`；费用统一 `DECIMAL(18,6)`。
- 对象键、MIME、文件名等沿用现有媒体字段长度，不把 1000 字符对象键直接建超长复合唯一索引。
- 时间与软删除字段沿用仓库现有约定。明确哪些是必填、哪些是阶段尚未发生；未开始/未知时不填写假时间和 0 用量。
- 幂等键建议有界 `VARCHAR(128)`，请求摘要为规范化内容的 SHA-256；与实际仓库已有约定不同时统一现有约定。
- 工作区初始化额外保存初始化幂等键和请求摘要，一条任务只初始化一次。重复初始化不同正文不得改写已存在工作区。
- 运行创建/重试/发布包以运行表保存幂等；授权以授权表保存；小文件素材上传以资产表保存，大文件还需持久化独立素材会话和分片身份。不要承诺幂等，却找不到持久化其身份的位置。
- 取消是对指定运行的单调状态操作；选版、改名、改预算等以预期业务版本避免覆盖。不为这些本地操作新建通用幂等平台。
- 各表引用用现有项目方式校验；所有跨任务 ID 查询都同时限定归属，不能仅凭 UUID 长得随机就当安全校验。

## 9. 渲染器契约与实际制作

### 9.1 从原型提取，而不是复制一份故事

研发阶段把 `export/first-video-20261018/produce.py` 的时间线、音频合成、逐帧生成和 FFmpeg 编码经验提取为稳定模块。故事内容、角色图形、场景布置从代码移到受校验数据与内置资产。

原型中读取 `.env` 和调用 TTS 的部分不能照搬进渲染器。生产供应商调用受预算和统一日志控制，渲染器只接收已下载并校验的本地资产。

建议新增目录 `renderer/`，包含固定入口、受控布局、字体及依赖清单；具体包结构按实际实现规模确定，不先搭插件框架。

### 9.2 CLI 输入输出

建议调用形态：

```text
python -m linkagent_renderer render --input <validated-local-manifest> --output-dir <run-attempt-dir>
```

Java 使用参数数组和 `ProcessBuilder` 等现有惯例启动，不经 Shell 拼接。Python 解释器、模块名和路径由部署配置决定，不接收用户自定义命令。

当前图片/PCM 音频基线输入为后端生成的本地 `RenderInputV1`，与面向模型的故事板分开，包含：

- 不可变故事板和配置摘要。
- 已实测的场景起止、字幕 cue、转场、音频增益和实际帧数。
- 后端解析后的本地资产路径、预期 SHA-256 和 MIME。
- 受控模板、字体、输出编码配置、随机种子。
- `runId/attemptId/inputHash`，用于核对结果归属。

本次素材组合通过 [RenderInputV2 设计](视频素材导入与样片导出补充方案.md#63-renderinputv2) 增加视频源区间、声音方案和受控混音；输入、清单、Java 验收和缓存键同步升级。V1 严格契约不能直接接收新字段，也不能因总方案出现视频素材就声称当前渲染器已支持。

输出固定包括 `manifest.json`、MP4、SRT、封面和必要日志。清单记录实际文件名、大小、SHA-256、媒体参数、渲染器版本、耗时和告警。只允许相对于本次输出目录的文件名。

退出码建议：`0` 成功、`2` 契约或资产不合法、`3` 字体或环境缺失、`4` 编码失败；取消和超时由 Java 记录为业务错误。实现时把枚举和测试同步，不靠解析随意的中文日志判断成功。

### 9.3 文件与进程边界

- 工作目录由服务端生成，例如 `<workRoot>/<runId>/<attemptId>/`；解析真实绝对路径后确认落在配置根目录内。
- 拒绝路径穿越、越界软链接、压缩包内绝对路径和未声明输出。
- 渲染进程不需要业务数据库、OSS 凭据或模型密钥；不自动加载仓库 `.env`。
- 模板不能主动访问网络。生产容器条件允许时限制渲染进程出网；不能仅靠提示词声明“不要联网”。
- 原始 Shell 和 FFmpeg 参数不可由用户或模型直接输入。
- 设置实际超时、帧数、尺寸、资产解码尺寸和磁盘空间边界；超限产生可读错误。
- 取消只终止本次记录的子进程及其派生进程，核对 PID 与启动身份，不能 `kill` 全部 Python/FFmpeg。
- 成功后先验证清单和文件，再进入对象上传；失败部分文件不注册为完整成片。

### 9.4 时间线和字幕

1. 先确定场景对白来源；仅 TTS 场景生成配音，用户录音和选定原声采用实际媒体探测与规范化结果。
2. 依据实际语音、视频/音频截取范围、明确留白和转场计算场景范围。
3. 将全部 cue 统一成整数毫秒，渲染时转换到帧边界。
4. 重新计算全片时长，检查是否符合用户确认的目标、固定/自适应选择及部署能力。
5. 超出目标时给出缩稿、删减或延长的具体提案；素材不足时给出缩短、补图、循环或定格选项。需要用户选择的操作不能静默执行。
6. 字幕只描述真实说出的文本。TTS 改词、漏读时标记冲突，不能拿预计文本冒充实测转写。
7. 由真实时间线生成 SRT 和烧录字幕，两者来自同一 cue 集合。
8. 修改旁白后重算后续时间轴，不能保留失效的旧绝对时间戳。
9. 用户录音或原声字幕使用已授权 ASR 或经校验 SRT；缺乏真实时间证据时保持待处理，不按字数伪造对齐。无对白场景不凭空生成字幕。
10. BGM 与对白/环境声按受控音轨方案混合；声音随片段同范围截取，不因添加配音意外叠加两路人声。

总时长等于场景时长之和减转场重叠，加独立片头片尾。实现时明确重叠是否被计入场景，固定一个公式并用有重叠的样例验证，不能由模型心算。

校验区分时间线、视频帧时长、音轨时长和容器时长；帧量化与编码补齐允许有明确的小容差。具体容差用实际编码样例固定并测试，不能用宽泛容差隐藏字幕越界或几秒音画偏移。

### 9.5 视觉与音频基本质量

- 首发提供至少若干构图变化，如全屏图、图文并排、关键词卡、对比图，避免全片同一张模板轮播。
- 单场景只承载一个主要信息，旁白、画面和大字应互相支持，不逐字堆满屏幕。
- 字体随部署明确提供或确认存在，覆盖常用中文、标点和必要英文；缺字能检测并报错。
- 字幕默认大字、最多两行、稳定安全边距。首发可从 1080p 下约 48–56px 试验，最终以真实缩图验证，不把像素建议当成通用质量证明。
- 文本按真实字体宽度换行和测量，不按字符数假设等宽；溢出不能静默裁掉。
- 画面和字幕内容分层，避免遮挡主要对象；对比度不足提供实际可见的底板或描边。
- 音量、峰值、削波、声道、采样率由音频工具检测。背景音乐随旁白压低，不能由无音轨视觉模型判断声音问题。
- BGM 可先采用来源明确的内置或程序合成音频。没有可用音乐时使用干净旁白，不下载不明音乐凑结果。
- 镜头片段流式编码或逐段合成，内存不同时装下整片 1080p 原始帧。

### 9.6 本地质量检查

对最终文件至少做：真实 FFprobe、FFmpeg 整片解码、帧数/时长检查、字幕范围检查、字体缺字与溢出检查、音频存在性/峰值检查、首中尾抽帧和资产摘要校验。

这些属于确定性制作检查，与原有发布前试映并存。不得因为本地检查通过就写出“观众一定觉得好”，也不能因为模型说“很好”而跳过解码。

## 10. 持久化执行、恢复和取消

### 10.1 固定执行阶段

| 阶段 | 主要动作 | 完成证据 |
|---|---|---|
| `VALIDATE_INPUT` | 校验归属、简报、故事板、授权和环境 | 指纹、配置快照、有效授权 |
| `PREPARE_ASSETS` | 内置及用户图片、音视频探测与规范化，可选授权生图 | READY 资产、源/派生摘要、实测参数和来源 |
| `SYNTHESIZE_AUDIO` | 仅需要时生成 TTS，复用用户录音或提取所选原声 | 音频对象、实际时长、字幕依据、真实调用流水 |
| `BUILD_TIMELINE` | 排列场景、字幕、留白和转场 | 实测时间线 JSON |
| `RENDER` | 样片或完整渲染 | 受校验的输出清单 |
| `LOCAL_QA` | 解码、文本、音量、字幕等检查 | 检查结果和抽帧 |
| `STORE_ARTIFACTS` | 上传并验证私有对象 | HEAD/读取校验和文件摘要 |
| `COMPLETE_PRODUCTION` | 逐项更新自动制作步骤 | 对应步骤的真实产物引用 |
| `REGISTER_DRAFT` | 注册完整成片并切换指针 | 不可变 `versionId` |
| `PROBE` | 接原探测服务 | 同版本探测结果 |
| `PROCESS_MEDIA` | 接原预处理任务 | 精确 `processingJobId` |
| `PREFLIGHT` | 接原完整试映 | 精确 `preflightReviewId` |
| `BUILD_RELEASE_PACKAGE` | 依据实际版本组织投稿材料 | 清单、封面、文案、ZIP |

不同运行只选所需子图。例如 `SAMPLE` 在保存样片后结束，不走 `REGISTER_DRAFT`；`TEXT/PREPARE` 不启动渲染；`PACKAGE` 不重做 TTS 和视频。

`SKIPPED` 只能表示该步骤确实不适用，记录原因。例如无 BGM 可不混音乐。不能把本应执行的试映步骤标成跳过以缩短流程。

### 10.2 工作领取与租约

复用现有媒体 worker 的数据库领取思路。建议初始配置为制作并发 1、租约约 120 秒、心跳约 20 秒，实际数值通过本地机器实测调整，不另建消息中间件。

领取候选包括排队任务、到期的依赖等待、租约过期的运行以及待处理取消；取消不能因为不是 `RUNNING` 就永远无人消费。

处理顺序：

1. 短事务领取到期运行，递增 `lease_generation`，记录 worker 与到期时间。
2. 查询本阶段是否已有完整、输入指纹匹配的产物或供应商任务 ID。
3. 如需付费，先在另一短事务预留费用，再调用外部服务。
4. 外部调用、下载、TTS、渲染和上传均在数据库事务外执行。
5. 保存前复核租约代数、输入指纹、取消状态和授权范围。
6. 用短事务保存资产引用、费用结果、步骤结果与下一阶段。
7. 等待异步依赖时保存准确子任务 ID 与 `next_run_at`，进入 `WAITING_DEPENDENCY` 并释放 worker 线程。

长渲染期间由受控心跳任务续约。旧 worker 即使后来返回，也不能更新当前进度和版本指针；它产生的真实费用仍必须入账。

### 10.3 幂等与重复提交

- 有副作用的创建、执行、批准、重试和导出操作要求 `Idempotency-Key`，遵循现有接口惯例。
- 同一键和相同规范化请求返回原结果；同一键不同正文返回 `409 IDEMPOTENCY_CONFLICT`。
- 持久化运行后才能返回已接受；前端收到超时先查询原运行，不能立即换键再付费执行。
- 渲染对象键包含任务、运行与尝试身份；重启先检查已保存清单，不能盲目覆盖完整视频。
- 调用原媒体服务时使用稳定子键，并复用同一指纹已有的处理/试映任务。不要每次调度都创建一个新子任务。
- 异步供应商提交成功但本地响应丢失时，优先用已保存请求身份查询。无法确认是否扣费时进入 `UNKNOWN`，不无限重提。

### 10.4 重试边界

| 失败类型 | 默认处理 |
|---|---|
| 本地暂时 I/O、已知可恢复网络失败 | 有限自动重试，退避并记录次数 |
| 结构化输出无法解析或业务校验失败 | 在原授权和剩余预算允许下最多一次修复性调用；否则让用户处理 |
| 供应商模型不存在、凭据错误、配置缺失 | 立即失败，不重复撞同一配置 |
| 已提交且费用未知的供应商请求 | 不自动再次付费；查询或保留未知预留 |
| FFmpeg 输入非法、字体缺失 | 输出具体错误，修复输入/环境后显式重试 |
| 用户改变工程或选中版本 | 旧结果不覆盖；新运行使用新指纹 |
| 旧版试映已完成，新版待检查 | 只推进新版，不将旧报告重命名套用 |

底层 HTTP 客户端与业务层重试要合并计数。不能外层重试 2 次、模型层重试 3 次，界面却只显示“调用一次”。

### 10.5 取消语义

- 取消请求持久化为 `CANCEL_REQUESTED`，界面立即显示正在停止，不承诺供应商退款。
- 不再提交新的付费调用、注册成片或切换当前版本。
- 本地进程停止后核对归属并清理本次未引用的临时文件。
- 已提交供应商请求若无法撤销，查询并结算真实费用；未知费用继续保留预留。
- 已经完成并被历史版本引用的产物保留。取消新版不删除原版。
- 若已经注册新版但试映未完成，保留“检查未完成”的事实；用户可以显式切回已就绪旧版，不能伪造新版成功。

### 10.6 崩溃恢复

重启后依据数据库阶段、租约、资产摘要和子任务身份恢复，不依据浏览器缓存。断电发生在上传完成、数据库登记前时，检查本运行命名空间下对象和清单，验证后补登记或标记待清理；不能扫描并删除整个桶。

临时文件、未引用对象和失败资产使用本功能范围内的清理策略。清理前核对实际绝对目录、对象前缀、引用关系和活动运行，禁止影响作者原有数据。

## 11. 自然语言修改与依赖失效

### 11.1 一次修改必须回答的问题

- 基于哪一个 `baseVersionId` 和 `storyboardId`？
- 具体改哪些稳定场景、文本、素材或全局样式？
- 哪些镜头、音频、字幕、时间线和封面需要重建？
- 预计新增多少费用，是否仍在授权范围？
- 用户看到的新版与原版有何可验证差异？

修改结果不能只是一段“已经改好”的聊天消息。

### 11.2 受限修改操作

建议 `CreationPatchV1` 支持下列白名单，不开放任意根路径 JSON Patch：

| 操作 | 目标 | 主要失效范围 |
|---|---|---|
| `REPLACE_NARRATION` | 某场景旁白 | 该场景 TTS、字幕、片段；全局时间线和合成 |
| `SET_ONSCREEN_TEXT` | 某场景某文字角色 | 该场景片段；全局合成，必要时封面 |
| `SET_SUBTITLE_STYLE` | 全局或指定场景 | 涉及的全部字幕画面；不重做不变 TTS |
| `REPLACE_VISUAL_ASSET` | 某场景的实际资产 ID | 该场景片段；来源清单和合成 |
| `SET_CLIP_RANGE` | 场景及合法的源入点/出点 | 对应画面/原声、字幕、时间线和合成 |
| `SET_SCENE_AUDIO` | 生成配音/用户录音/原声/无对白及受控参数 | 对应音轨、字幕、时序和必要画面 |
| `SET_MUSIC` | 音乐资产、范围、音量及压低/淡入淡出 | 混音和输出编码，不重做未变旁白 |
| `SET_VISUAL_FIT` | 完整显示/裁切铺满及合法裁切位置 | 对应画面和合成，不重做音频 |
| `SET_SCENE_TIMING` | 受限留白或转场 | 时间线、字幕偏移、受影响片段和合成 |
| `REORDER_SCENES` | 明确的场景 ID 顺序 | 全局时间线、字幕和合成；可复用场景内素材 |
| `REMOVE_SCENE` | 明确场景 ID | 时间线、成片、文案和来源清单 |
| `SET_PALETTE` | 受控配色 ID | 涉及画面与封面；不重做音频 |
| `REPLACE_RELEASE_COPY` | 标题、简介等 | 新发布包；不改视频字节 |

首发不支持的操作明确返回可选替代，不把“让机器人跳舞”默默变成一张图片并说完成。

### 11.3 修改提案示例

```json
{
  "schemaVersion": "creation-patch.v1",
  "baseVersionId": "video_example_v1",
  "baseStoryboardId": "sb_example_001",
  "expectedWorkspaceRevision": 8,
  "operations": [
    {
      "op": "REPLACE_NARRATION",
      "sceneId": "scene_ending",
      "text": "今晚先休息，明天再一起把它做好。"
    },
    {
      "op": "SET_SUBTITLE_STYLE",
      "scope": "GLOBAL",
      "styleId": "larger-two-line"
    }
  ],
  "summary": "修改结尾旁白，并放大全片字幕",
  "requiresNewDirectionApproval": false
}
```

`requiresNewDirectionApproval` 是模型建议，服务端根据允许字段、简报变更、权限和预算重新判定，不能信任模型直接放行。

### 11.4 明确指令与含糊指令

“字幕大一点”可映射到已部署的字号档位，并在结果中说明采用哪一档；“做得更高级”不能直接触发重做整片，要给出少量具体选项或短试片。

用户点击“发送并修改”且当前授权明确允许相应局部修改时，可以连续执行，不额外要求逐镜头批准。扩大主题、加入新事实主张、改音色身份、增加付费供应商、突破预算时，先产生具体提案，等待明确授权。

### 11.5 依赖图与缓存键

```text
场景旁白 + 音色 + 模型参数 -> TTS 音频 -> 实测时长
用户录音/片段原声 + 源范围 + 音轨选择 -> 实际对白/环境声音轨
场景图片/视频/图形 + 源范围 + fit/crop + 布局 + 时间线局部 -> 场景画面
对白/片段实测时长 + 场景顺序 + 留白 + 转场 -> 全局时间线
真实字幕证据 + 时间线 + 字体样式 -> SRT / 烧录字幕
对白/环境声 + BGM/范围 + 音量/淡入淡出/压低 -> 混音
场景画面 + 混音 + 字幕 -> 最终 MP4
最终 MP4 + 选定文案 + 封面 + 来源 -> 发布包
最终 MP4 -> 探测 -> 预处理 -> 试映
```

缓存键包含相关内容、资产 SHA-256、模板/字体/渲染器版本、随机种子、供应商模型与影响结果的参数。计费日志 ID、创建时间和无关显示名称不应使媒体缓存失效。

场景随机性由全局种子和稳定场景 ID 派生，不按当前序号分配；场景片段优先使用局部 cue，最后合成再换算全局时间。这样调整顺序不会无理由改变原场景画面或使全部音频失效。

必须按依赖项判断复用，不简单地“修改了场景 3，所以只替换旧 MP4 的第 10–15 秒”。旁白长度变化会让后续绝对时间全部移动。

对未受影响的配音、图片和无字幕场景片段，验收应看到真实哈希复用及没有再次付费的证据。全片字幕样式变化重渲染全部画面是合理的，但不能因此再次生成所有音频。

### 11.6 版本对比

对比包括旧/新版并排或切换播放、场景级文字差异、实际时长变化、修改执行结果和新增费用。旧时间点到新版的定位由场景 ID 映射，不凭相同秒数假设内容没变。

若试映建议转成修改任务，保存 `issueId -> patch -> newStoryboardId -> newVersionId` 关系。只有新媒体真的生成并核对后才能把修改任务标成完成。

## 12. 接入原工作流的门禁与防循环设计

### 12.1 必须保留的现有门禁

当前需要重点核对：

- `ProductionPlanGateService.ensurePrePublishConfirmed`：发布前工作流真实确认，确认结果与当前方案对应。
- `ProductionPlanGateService.ensureReadyForPreflight`：制作计划已就绪，必需制作步骤完成；保留已有成片的显式跳过分支。
- `ProductionPlanApplicationService` 的就绪判断：计划 `READY` 且未完成步骤数为 0。
- `CreatorMediaWorkflowGateService.ensureReadyForPostPublish`：当前成片可试映，匹配的预处理及完整试映已经完成。

本文要求隐藏专业细节，不要求取消这些事实。开发不能通过直接改数据库状态或让模型回复“已确认”绕过门禁。

### 12.2 自动制作的发布方案确认

`PREPARE` 运行产生可读简报、故事板和当前业务可识别的发布方案候选，保存真实方案 ID 与输入快照。优先复用现有方案生成与持久化能力，避免为了填不同页面重复调用同一模型。

用户确认时，通过现有业务服务确认正确的工作流和方案；不能自行插入一条含糊的 `CONFIRMED` 记录。新增确认卡可以整合 UI，但必须保留原来的归属、当前方案一致性与状态校验。

确认服务只做数据库业务操作。若需要补充模型生成，先单独异步准备，准备结束后再让用户确认，不能把长模型调用藏进确认事务。

### 12.3 自动制作蓝图如何完成

自动制作采用已有 `ProductionMethod.AI_GENERATION`，具体渲染形式另存 `renderProfile`。不新增意义重复的制作方式枚举。每次 `FULL/REVISION` 分配自己的制作计划并关联运行；`SAMPLE` 不把整片计划的步骤标成完成。

建议自动蓝图采用少量确定性阶段，并由产物逐项完成：

| 蓝图步骤 | 完成依据 |
|---|---|
| 内容与工程已确认 | 用户确认快照、故事板哈希 |
| 素材已准备 | 实际图片、音视频、图形等 READY 资产及规范化清单 |
| 配音和时间线就绪 | 音频对象、实测时长、时间线 |
| 成片和字幕生成 | MP4、SRT、渲染清单 |
| 本地质量检查通过 | 解码、字体、音频、字幕等检查 |
| 私有成片与初版发布素材已保存 | 对象验证、封面、初版文案和来源说明 |

上述步骤不包含平台试映、真实发布、BV 绑定、反馈或复盘。阶段是代码确定的执行映射，不让蓝图模型重新发明一套可能循环的前置关系。

自动步骤由实际产物证据驱动；失败、未执行、用户取消都不能勾选完成。原手动蓝图流程继续保留，人工步骤不能被新 worker 无差别改写。

S3d 已实现固定工程 FULL 的专属自动蓝图与真实证据写入，见 [阶段说明](视频自动制作-S3d真实产物驱动自动蓝图.md)。当前最后一步只证明现有八个产物已保存，不包括尚未生成的投稿文案或最终发布包；SAMPLE、REVISION、素材导入和完整试映调度不能据此标成已完成。

### 12.4 正确的无环依赖

```text
发布方向确认
  -> 本次整片运行专属的自动蓝图建立
  -> 本地制作、校验、上传真实对象
  -> 自动蓝图制作步骤逐项完成
  -> artifact_ready 里程碑
  -> 通过原制作门禁，注册并探测成片
  -> 预处理完成
  -> 完整试映完成
  -> 最终发布包完成
  -> FULL/REVISION 运行完成
```

`artifact_ready` 是阶段里程碑，必须独立于 `FULL/REVISION.COMPLETED`。媒体注册不能要求整条制作运行已经完成，否则又会形成循环。

发布包的最终整理在试映后完成，但蓝图制作步骤只要求初版发布素材实际存在，不能让“最终发布包”阻塞进入试映。

### 12.5 系统成片进入媒体服务

新增内部业务方法，例如 `registerGeneratedDraft`，复用原有对象校验、归属与探测逻辑。方法接收已验证资产/运行引用，不接收模型提供的任意桶名或对象键。

对象已经由 Java 上传并验证，因此无需让浏览器下载后再走一遍分片上传。内部登记仍执行原制作门禁，注册为 `UPLOADED`，随后真实探测；不能直接写 `READY_FOR_REVIEW`。

已有 `ObjectStorageService` 的 `putObject/downloadObject/headObject`、私有读取签名等能力优先复用。ASR 原生签名与浏览器短签可能使用不同入口，不能混成一个永不过期 URL。

### 12.6 完整试映与建议的含义

- 首发继续执行现有完整试映流程，保留各步骤现有的适用/跳过规则。
- 不为了加快演示，把三类观众、ASR 或重点片段复核批量标成完成。
- 按规则没有复核候选可以如实 `SKIPPED`，要展示原因。
- 当前发布后门禁不要求用户采纳全部 AI 建议，本文也不新增“高置信度建议必须修完”的封锁。
- 可选建议可以保留、忽略或转修改任务。确定性技术失败与模型审美意见必须分开。
- 未来若要增加轻量试映模式，必须另行定义报告完整性和发布门禁，不能在本方案实施时偷偷替代现有完整流程。

### 12.7 修改与原冻结材料

渲染工程、版本文案和旧 `creator_material` 不是同一存储对象。局部修改通过新故事板、新视频和发布快照表达，不反复改写被冻结的任务原材料。

在既有发布方向内的局部修订引用原确认记录，并取得本次执行授权。需要改变简报或发布方向时，生成新候选并明确再次确认，不在确认前破坏原媒体和报告。

若现有重新定位操作会使下游失效，必须新增针对版本的失效范围和历史保留逻辑后再接入，不能直接复用破坏性重置方法。旧版报告依然标明其真实版本，不能被新版覆盖。

### 12.8 当前版本查询改造

`MediaUploadMapper.findDraftVideo` 当前有固定 `version_no = 1`。实施多版本前必须枚举所有调用方：上传、当前媒体读取、探测、处理估算、试映、删除、发布绑定、页面恢复。

新查询优先读工作区明确指针；精确版本接口始终按 `versionId + owner`。旧任务没有工作区时继续读取原有效 V1，显式启用自动制作时在事务内采纳旧版本并分配 `next_version_no = MAX(version_no)+1`。

不得只改一个 `ORDER BY version_no DESC` 就宣称支持多版本。原片删除、续传、当前试映和绑定都会受影响，需要端到端覆盖。

### 12.9 新候选不能堵死或污染旧版本

多版本不仅是多个 MP4。现有部分门禁读取任务最新方案/最新计划；若直接照搬，新计划未完成时会连旧版一起阻塞，取消后也可能无法恢复。

自动模式必须把以下关系作为不可变版本上下文保存：

```text
CreationRun / DraftVideo
  -> publishingSessionId + publishingResultId
  -> productionPlanId
  -> storyboardId + briefRevision
```

- 原手动任务继续使用原门禁路径。
- 新模式为门禁增加明确版本上下文的内部入口，复用原归属、真实确认、计划就绪和步骤完成校验，不能使用 `force=true` 跳过。
- 新成片注册前按本运行专属计划检查；版本已存在后按该版本引用的确认与计划检查，不读取另一个候选的最新记录。
- 初次确认仍要求当时的当前方案与确认结果匹配。自动模式确认后的会话/结果不被新候选原地改写；大方向变化创建新的确认上下文。
- 若原确认服务会清理下游，先提取共用校验与确认保存逻辑，为自动模式保留历史引用；不调用会删除旧媒体的重置分支。
- 取消新运行后，显式选回旧版应能使用旧版已完成的真实确认、制作和试映事实。不能要求先把已取消的新计划手工勾完。
- 原新建任务的已有成片跳过分支保留，不作为系统生成视频规避确认的手段。
- BV 绑定前按选中版本校验；绑定后的反馈和复盘按绑定的 `publishedVersionId` 校验，不能因为编辑页正在查看旧版就换一份视频的事实。历史绑定无法定位版本时保持明确的存量处理边界。

首次采纳旧 V1 时，在新候选产生前核对其原有确认和制作上下文，只对有依据的关系补充引用。原本未就绪的旧版不会因启用工作区自动变就绪。

已有成片的跳过事实还必须与版本来源对应：由原显式上传分支取得的 `UPLOAD` 版本可保留当时的跳过上下文；`SYSTEM_RENDER` 版本始终需要真实发布确认和制作计划，即使该任务过去的全局 `planning_skipped` 为真。必要时给旧成片补充有依据的跳过快照，不以一个任务布尔值永久放行所有未来视频。

这是必要的版本语义调整，需要在 S1/S3 一起实现和回归。只增加版本下拉框而不改门禁上下文，不满足本方案。

## 13. 新接口契约建议

### 13.1 通用约定

以下均为**拟新增接口**，不是现有接口清单。根路径：

```text
/api/creator/tasks/{taskId}/creation
```

- 复用项目现有响应封装、异常格式、归属解析和 Jakarta Validation，不另加校验库。
- 示例 JSON 仅展示业务数据。错误码名称为建议，落地时映射到现有错误契约并同步前端。
- 涉及业务写入传 `expectedWorkspaceRevision`。并发冲突返回当前版本，不能静默覆盖。
- 非空字符串、枚举、长度、场景数量、资产归属和金额范围在入口校验，跨对象一致性由服务层校验。
- 执行型接口持久化任务后返回 `202`，不让 HTTP 连接等待完整制作。
- 查询和订阅不触发模型、不扣费、不自动确认、不隐式重试。
- 所有引用 ID 校验属于同一任务和实际 owner，不信任客户端传入的桶、路径、价格或用量。

### 13.2 路由表

| 方法 | 相对路径 | 请求重点 | 返回 / 行为 |
|---|---|---|---|
| `GET` | 空路径 | 无 | 工作区快照、能力、预算、当前工程/视频和活动运行；未启用时只读返回未启用状态 |
| `POST` | 空路径 | `mode`、初始简报、任务预算、幂等键 | 显式启用工作区，`201`；不自动付费 |
| `PATCH` | `/brief` | 预期版本、简报字段 | 新简报版本；必要时使未执行授权失效 |
| `PATCH` | `/display-name` | 预期版本、显示名 | 仅改显示名，不触发材料失效 |
| `POST` | `/assets` | 有限大小 `multipart/form-data` 图片 | 后端验证并写私有对象，返回资产元数据 |
| `GET` | `/assets` | 类型、状态、分页 | 任务素材区及真实元数据，不自动调用模型 |
| `POST` | `/assets/uploads` 及会话子路由 | 类型、文件指纹、大小、分片和幂等身份 | 创建/恢复/签分片/完成/取消素材上传；不分配成片版本，具体职责见补充方案 |
| `POST` | `/requests` | 意图、用户文本、资产、预期版本、准备阶段费用授权 | 创建 `TEXT/PREPARE` 运行，返回 `202` |
| `GET` | `/storyboards/{storyboardId}` | 精确工程 ID | 不可变工程、来源和差异 |
| `POST` | `/approvals` | 准备结果、工程哈希、范围、预算、预期版本 | 保存真实确认与当前执行授权，`201` |
| `GET` | `/approvals/{approvalId}` | 精确授权 ID | 只读授权范围、来源、状态与已用金额 |
| `POST` | `/runs` | 类型、授权 ID、工程、基准版本、预期版本 | 创建 `SAMPLE/FULL/REVISION/PACKAGE`，`202` |
| `GET` | `/runs/current` | 无 | 当前活动运行，没有则为空 |
| `GET` | `/runs/{runId}` | 精确运行 ID | 状态、阶段、步骤、结果、费用和可用动作 |
| `GET` | `/runs/{runId}/events` | 现有 SSE 约定 | 只读进度提示；快照仍为权威 |
| `POST` | `/runs/{runId}:cancel` | 指定运行，无扩展副作用正文 | 请求取消，重复调用返回实际状态 |
| `POST` | `/runs/{runId}:retry` | 当前授权、预期版本、幂等键 | 新运行，引用旧运行并复用有效产物 |
| `GET` | `/versions` | 分页 | 完整视频历史，不把样片混入 V 序列 |
| `POST` | `/versions/{versionId}:select` | 预期版本 | 显式选择可用旧版；活动制作中拒绝切换 |
| `POST` | `/assets/{assetId}:read-url` | 具体用途 | 复用私有短签读取，不泄露密钥 |
| `POST` | `/release-packages` | 精确版本、选定文案、预期版本、幂等键 | 创建 `PACKAGE` 运行，返回 `202` |
| `PATCH` | `/budget` | 新限额、预期版本、明确用户动作 | 调整任务预算；不能低于已占用金额 |

小图片继续采用 Java 转存，实际解码和本功能大小上限仍需校验；较大音视频采用复用存储协议的独立素材分片会话。会话关联 assetId，不借用含完整视频业务的上传会话创建假成片。统一复用现有存储实现，不另建媒体存储服务，也不把图片上限施加到已有 MP4 上传。字段、恢复和真实内容校验见 [补充方案](视频素材导入与样片导出补充方案.md#6-数据api-与渲染契约补充)。

```json
{
  "intent": "CREATE_VIDEO",
  "purpose": "INITIAL_PREPARATION",
  "text": "做一条温暖的小故事，告诉大家忙的时候也可以休息。",
  "assetIds": [],
  "expectedWorkspaceRevision": 2,
  "preparationAuthorization": {
    "maxAdditionalCostCny": "1.00",

```

`preparationAuthorization` 来自页面明确显示的准备动作，不由模型补填。准备阶段也可能花钱，不能等到 TTS 才开始计费。

```json
  "kind": "PREPARE",
  "status": "QUEUED",
  "workspaceRevision": 3,

```

### 13.4 确认与授权快照

授权至少绑定：`approvalId`、任务、简报版本、故事板 ID/哈希、发布方案/确认记录、制作形式、允许动作、允许的局部修改类型、额外费用上限、任务总预算、重试边界、用户操作时间和请求摘要。

```json
{
  "preparedRunId": "run_prepare_example",
  "storyboardId": "sb_example_001",
  "storyboardHash": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "expectedWorkspaceRevision": 4,
  "confirmPublishingDirection": true,
  "executionScope": {
    "allowedKinds": ["SAMPLE", "FULL", "REVISION"],
    "allowedLocalChanges": ["SET_SUBTITLE_STYLE", "SET_PALETTE"],
    "maxAdditionalCostCny": "15.00",
    "allowAutomaticPreflight": true,
    "maxPaidRepairAttempts": 1
  }
}
```

哈希示例是占位说明；真实字段必须为后端提供的 SHA-256。服务端从已完成准备运行解析对应的真实方案，不允许客户端自由指定另一个已确认方案来混配工程。

授权原文存授权表，工作区只指向当前制作授权，执行时复制完整快照到运行。替换授权前已有运行留存原快照；未执行且已被替换的授权 ID 不能继续启动任务。确认超时用原幂等键取得同一授权，不重复确认和重复创建计划。

只批准样片时不能随后自动做整片。批准了样片及整片且用户点击“生成初稿”时，可直接启动整片，无需再次确认同一方向。

上述示例还允许有限局部修改；界面必须把这一范围明确展示，用户可以不授予。`REVISION` 只能在真实基准成片产生后启动，并限制为已允许操作和剩余授权金额，不能被解释成无限重做。

### 13.5 启动整片或修改

```json
{
  "kind": "FULL",
  "storyboardId": "sb_example_001",
  "approvalId": "approval_example_001",
  "baseVersionId": null,
  "expectedWorkspaceRevision": 5
}
```

`REVISION` 必须有真实 `baseVersionId`、已接受的修改提案及新故事板。样片转整片复用未改变的 TTS 与资产，但重新计算全片时间线。

`PACKAGE` 或 `/release-packages` 只接受已经就绪、属于本任务的精确视频版本。重复导出相同版本和文案可以返回现有包，不重新调用模型。

### 13.6 运行快照重点字段

返回至少包括身份、类型、状态、当前阶段、已完成场景数、总场景数、`runRevision`、真实开始时间、预估耗时范围、当前工程、基准/输出版本、子任务 ID、已完成资产、告警、错误、可恢复动作及费用分项。

没有可靠 ETA 时不返回虚构倒计时。阶段未开始不能显示 100%；已返回 MP4 但试映未完成时，可播放并说明“正在检查”，不能显示全链路成功。

### 13.7 主要业务错误

| HTTP / 业务码 | 语义与用户动作 |
|---|---|
| `400 INVALID_CREATION_INPUT` | 字段非法，指出可修改项 |
| `404 CREATION_RESOURCE_NOT_FOUND` | 任务、工程、版本或资产不存在/不可见 |
| `409 WORKSPACE_REVISION_CONFLICT` | 页面已过时，刷新快照后重试确认 |
| `409 CREATION_RUN_ACTIVE` | 已有活动任务，提供其链接，不能重复启动 |
| `409 IDEMPOTENCY_CONFLICT` | 同键不同请求，不执行新操作 |
| `409 BASE_VERSION_CHANGED` | 修改所基于的版本已变化 |
| `409 DIRECTION_APPROVAL_REQUIRED` | 需要确认具体新方向或执行范围 |
| `409 MEDIA_NOT_READY` | 指向实际缺失的探测/处理/试映阶段 |
| `422 UNSUPPORTED_RENDER_OPERATION` | 形式或修改不支持，提供可行替代 |
| `422 UNRENDERABLE_STORYBOARD` | 工程无法制作，返回场景级原因 |
| `422 BUDGET_APPROVAL_REQUIRED` | 预留后将超预算，保留现有成果 |
| `503 CREATION_DEPENDENCY_UNAVAILABLE` | 字体、FFmpeg、存储或供应商配置不可用 |

若仓库已有同义错误码，优先复用，不为了本文命名制造不兼容的平行错误体系。

### 13.8 原接口继续有效

下面是现有入口的主要路径形态，实施时以 Controller 为准：

- 发布前流程：`/api/creator/tasks/{taskId}/workflow/...`。
- 上传会话：`/api/creator/tasks/{taskId}/draft-video/uploads`，注意 `draft-video` 是单数。
- 成片读取、探测与媒体处理：`/api/creator/tasks/{taskId}/draft-videos/...`，此处为复数。
- 试映：`/api/creator/tasks/{taskId}/preflight-jobs/...`。

新增编排服务内部调用领域服务，不让后端用 HTTP 请求自己的 Controller，也不废弃旧版前端仍在使用的接口。

## 14. 试映可信度与事实边界

### 14.1 不能只加一句提示词

现有提示词已经包含事实约束，真实体验仍出现了静音段数量/总时长、字幕底板、起声时间及不存在工具的误判。多个人设还可能重复同一错误。

因此需要修改数据契约、计算责任、冲突处理和界面表述，而不是只补一句“不要幻觉”。这项工作可与渲染开发并行推进，但首发宣传前必须完成最低可信度修复。

### 14.2 三类信息分别保存

| 类型 | 示例 | 允许的表述与校验 |
|---|---|---|
| `DETERMINISTIC_FACT` | 时长、分辨率、静音段区间、像素框、音量峰值 | 工具直接测量；数量/合计由代码算 |
| `MODEL_OBSERVATION` | 某时段可能出现文字遮挡、叙事跳跃 | 绑定实际帧或片段；可被人工否定 |
| `AUDIENCE_HYPOTHESIS` | 某类观众可能不理解结尾 | 清楚说明推测，不能伪装真实反馈 |

来源至少包含 `sourceType/sourceId/versionId/processingJobId/timeRange`。模型输出的自评置信度不是校准概率，不用“95% 确定”掩盖缺少证据。

### 14.3 确定性事实禁止模型改写数值

静音段用工具返回的整数毫秒区间计算数量、总长和比例。报告直接引用计算结果，模型只解释可能影响；不让它重新加一遍。

画面模型看无音轨副本时不能推断起声时间、音量或配乐。字幕是否有底板优先查渲染工程和实际图像，不能沿用粗审文字覆盖原片事实。

对系统生成的作品，工程可以提供“原计划放置了什么”的先验证据；但仍要检查实际输出。工程存在字幕底板不等于编码后像素必然可见。

### 14.4 片段复核触发规则

当前 `PreflightSegmentReviewService` 主要按严重程度或模型低置信度选择片段；`needsHumanReview` 不天然覆盖所有高置信度错误。

新增候选来源应包括：

1. 模型观察与确定性事实冲突。
2. 结论涉及关键时间、字幕可见性、音频存在性等可核查事实。
3. 标记了 `needsHumanReview`，并能定位实际证据。
4. 重要结论没有有效证据，或证据与所述对象不一致。

先做代码层冲突检测，再在剩余费用和原片可用范围内选择有限片段复核。超出复核上限就显示未确认，不把候选过多全部当作已验证。

### 14.5 禁止无关证据自动补位

当前 `AudienceScreeningService` 存在缺少有效引用时回填第一条 evidence ID 的逻辑。它是需要修改的静态风险点；本次体验没有证明所有回填路径都实际触发。

新规则：无有效证据时，删除事实性断言、降为无证据假设或返回待确认，禁止补一个不相关 ID 凑合通过结构校验。引用存在、归属正确和内容相关是三个不同检查。

### 14.6 三类观众不是三个独立证人

三类观众共享已经校验的事实包，分别生成可能反应。界面说明它们是模拟视角，不显示为三份相互独立的验证。

同一错误不能因为被三个角色复述就提高可信度。重复问题归并回原证据和观察；允许整次试映返回零个确认问题。

### 14.7 修改建议与发布门禁分开

新手应先看到“已确认的技术问题”“待核对观察”“可选表达建议”。不得用推测出的审美问题阻止导出或要求逐条清空。

本地媒体确实损坏、归属不匹配、试映未完成等仍按原业务规则阻止后链路。模型认为节奏不够好，不能自动变成不可发布。

## 15. 前端交互、进度与平台助手

### 15.1 页面组织

保留现有工作台、任务和发布后模块，在自动制作模式提供以作品为中心的工作区：

- 主区域：当前视频或样片播放器、当前阶段、自然语言修改输入。
- 次区域：简报摘要、素材区、场景卡片、版本切换、投稿材料。
- 可折叠区域：制作步骤、费用、处理日志、完整试映和来源说明。

不是再增加一套与原任务无关的首页。未启用自动制作的旧任务保持原页面；“已有成片”路径继续直达原试映功能。

现有 `task/prePublish/production/preflight/feedback/report` 导航反映业务阶段。新界面可合并呈现前几步，但底层状态和恢复逻辑不随视觉合并而跳过。

### 15.2 有结果时优先展示结果

完整视频就绪后首屏提供播放。已生成视频而试映仍在运行时，可以先播放并说明尚待哪些检查；用户不必看完整日志才能看到作品。

样片明确标注时长、所含场景和用途。不能给 12 秒样片标“75 秒视频已完成”。准备阶段只有故事板时用对应预览，不能用静态封面伪装可播放视频。

素材区显示真实上传/探测状态、尺寸、时长和预览；场景卡片提供选素材、截取、声音来源和排序。样片、制作预览、字幕/封面和正式包的下载入口按实际可用产物开放，不要求用户理解资产 ID 或渲染协议。

### 15.3 刷新、离开和多任务切换

- 页面进入先获取工作区快照和活动运行，不依赖上次浏览器内存。
- 任务 ID、运行 ID、版本 ID 绑定请求生命周期。切任务后取消旧订阅，旧响应不得覆盖新任务。
- 刷新不再提交制作请求；没有活动运行时也不自动付费重试。
- 请求超时先查询幂等结果，显示“确认后台状态中”，而不是立即显示失败。
- 同一视频的短签过期只刷新读取链接，不重传媒体、不重跑分析。
- 终态停止轮询，失败展示保留的产物和明确恢复动作。

### 15.4 SSE 与轮询

优先复用现有 SSE 事件封装和连接方式。新事件至少描述 `runId/runRevision/type/stage/status`，事件只作更新提示，客户端必要时重新 GET 快照。

初始可每 2–5 秒轮询作为恢复，后台等待按实际页面可见性退避。事件丢失、重连或序号跳变后读取快照，不要求新建持久事件总线。

若现有 SSE 不支持可靠历史重放，不应在文档和 UI 承诺 `Last-Event-ID` 一定能重放全部历史。没有持久日志时就明确采用“快照恢复”。

### 15.5 让状态可理解

使用“正在合成第 3/8 段配音”“画面已完成，正在检查声音和字幕”等实际可验证的说明，不给用户展示 Agent 内部类名或供应商重试堆栈。

显示：排队时间、当前阶段开始时间、真实已完成项、是否仍有心跳、下一可做动作。没有新进度时可以说明正在等待供应商，不把动画进度条当成真实进展。

模型思考强度按场景配置：字段映射、短文案、受限修改优先低延迟结构化调用；复杂内容策划才使用更强推理。不能用全局最高思考配置处理所有页面操作。

### 15.6 平台助手的职责

现有平台助手可以读取当前工作区、解释支持形式、提出制作/修改计划、提供确认卡，并调用新业务服务查询状态。

建议工具能力限定为：

| 工具行为 | 是否可直接自动执行 |
|---|---|
| 查询当前工程、运行、版本、费用 | 可以，只读 |
| 提出具体制作/修改计划 | 可以，提案 |
| 启动已由专用界面确认、范围匹配的操作 | 可以，使用实际授权快照 |
| 未确认就付费、扩大预算、替用户批准方向 | 不可以 |
| 操作另一条任务、修改 BV 绑定或自动投稿 | 不属于当前制作授权 |

复用当前 `PlatformOperationsTool` 等固定目录和确认机制，新能力接领域服务，不写聊天专用旁路。整个计划确认后，允许范围内连续执行；不能每一步反复问同一个确认，也不能把真正的确认藏进模型工具调用。

### 15.7 记忆与案例库

- 长期记忆只提供偏好建议，如喜欢温暖配色、习惯较大字幕；不保存或替代本次执行授权。
- 用户本条明确要求优先于历史偏好。
- 案例检索是可选辅助，首条制作没有案例库也应可运行。
- 不因本功能改向量库或记忆架构，不把真实素材、完整旁白和私有文件地址默认写成长期记忆。

## 16. 费用、预算和未知用量

### 16.1 预算的范围

作者对本次真实体验提出每条任务不超过 20 元。新功能建议以任务级 20 元作为可调整的初始上限，明确这是本地创作成本保护，**不是多租户用户配额**。

同一任务的准备、样片、整片、局部修改、失败调用、ASR、视觉分析和文本试映合并计入，不能通过换运行 ID 重置预算。

默认展示人民币，并保留供应商原币、价格和换算快照。固定 8 元/美元只曾作为体验中的保守估算，不能永久当作真实汇率或账单价格。

本地计算、已有订阅、存储和流量哪些纳入展示要明确。无法按单任务精确计量的项目列为“未纳入/预留”，不能记成 0 后声称完整结算。

### 16.2 预留公式

```text
已占用金额 = 已知费用 + 未知调用的保留金额 + 尚未结束调用的预留金额
可新增授权金额 = MIN(任务预算剩余, 本次执行授权剩余)
允许发起 = 已占用金额 + 本次调用保守上界 <= 任务预算
           且本次调用保守上界 <= 本次执行授权剩余
```

在短事务内锁工作区、归并已计费用、检查余额并创建预留，再发起物理调用。不能先调用后发现超预算，也不能让两个并发步骤都看见同一余额。

### 16.3 一次调用的记账生命周期

```text
RESERVED -> SETTLED
         -> UNKNOWN
         -> RELEASED
UNKNOWN  -> SETTLED 或在有充分未扣费依据后 RELEASED
```

- `SETTLED`：有真实供应商用量或返回费用；按该次价格快照估算或保存供应商值。
- `UNKNOWN`：请求可能已执行，但用量/费用未取得；保留预留并说明原因。
- `RELEASED`：确认没发送、供应商确认未执行或有明确未扣费证据；不能因前端关闭就释放。
- 调用已经产生用量但 JSON 解析失败，仍要计费。失败不是免费。
- 每次真实修复性重试有独立 `charge_key`，请求重放和日志写入不额外增加物理调用费用。

### 16.4 与现有日志归并

当前媒体费用与全局 LLM 日志存在分散记录，文本试映可能有 token 但媒体美元金额为空。统一费用视图必须归并以下项目：

| 能力 | 归并重点 |
|---|---|
| 文本策划/故事板/修改解释 | 实际模型输入、输出、思考和缓存用量，缺失项不补 0 |
| TTS | 按实际供应商计费口径与声音/模型记录，不假装 ASR |
| 可选生成图片 | 只有明确启用和授权才计入并调用 |
| ASR / 视频理解 | 复用媒体调用记录和真实时长/帧等口径 |
| 三类观众及其他文本试映 | 与全局日志关联，不能漏计或与媒体记录重复计 |
| 失败调用 | 保留真实用量或未知预留 |

`charge_key` 对应物理调用，`source_log_refs_json` 可同时引用全局日志和媒体日志。不得把同一次观众生成的两个日志金额相加。

如果底层现有客户端隐藏重试或不返回使用量，需要先补齐这条调用链的可观察性，再声称支持严格任务成本保护。

### 16.5 价格与严格上限的实质限制

模型价格、计费规则、音色和返回字段实施时查当前官方资料和真实报文，不将本文写成静态价格表。

要尽量实现 20 元内完成，必须限制发送文本长度、图片调用数、媒体时长、输出 token 和重试次数，并预留试映费用。先渲染把钱花光，再要求用户加钱检查，不算达成原预算。

当供应商无法给出可用的费用上界或当前请求是否已扣费无法判断时，停止新增付费并保留现有产物。界面如实说明费用未知；不能保证本地估算绝对等于最终账单，也不能悄悄无限重试。

若后验用量超过预留，记录异常并停止后续付费，不抹掉超出部分。该配置需要调整后才能继续宣称可靠预算控制。

### 16.6 用户看到的费用

至少同时显示：

- 已知费用：区分按用量估算与供应商返回金额。
- 尚在执行的预留。
- 用量未知的预留。
- 剩余可用预算。
- 未计入项目及其原因。

单一“实际费用”数字不能混合所有语义。最终发布包可包含费用摘要，但不夹带密钥、短签链接或私人供应商原文。

### 16.7 制作编排与子任务共用预算

制作运行创建原预处理/试映任务时，将任务、运行、执行授权和费用归并身份持久化到子任务上下文。子 worker 每次调用供应商前执行同一预算预留；线程上下文只能作为传递手段，不能成为重启后唯一依据。

父运行的阶段估算只是预测，不再以同一物理调用记一笔费用。实际调用才创建 `RESERVED`，返回后关联原日志并结算，避免父子两次计费。

启动前估算完整链路，后续每次付费前保守考虑剩余必需阶段开销，避免配音耗尽试映预算。自动模式任务的其他付费入口也必须加入同一任务预算，或明确拒绝并提示使用制作入口；不能留下助手旁路。

需要控制底层隐式重试。建议新制作调用使用“一次物理请求”的受限入口，结构修复由制作运行显式再发一次、单独预留。若当前客户端必然进行 strict 回退或自动重试，应先暴露并限制真实尝试数，不允许把一组内部请求当作一次低价调用。

跨 Java/Python 的 `invocationId` 与制作运行/步骤的映射由 Java 保存，不借用原 `workflowSessionId` 塞制作 ID。若需要扩展协议，按现有契约测试同时调整两端；不得直接改变已有 8 字段用量语境含义。

### 16.8 金额与配置校验

预算、预留和价格使用 `BigDecimal/DECIMAL`，拒绝负数、非正任务总预算、NaN、无穷值和超长精度，统一约定舍入。零新增费用只适用于明确禁止付费的操作。人民币显示可以保留两位，预算计算保留足够精度，不能用界面四舍五入后的 0.00 当成免费。

`maxAdditionalCostCny` 是该授权所有运行合计可新增金额，不是每次样片/整片各有一份。准备阶段的独立授权也有明确 ID 和累计边界。

## 17. 发布包、真实发布和复盘

### 17.1 发布包结构

建议每个包包含：

```text
release-<taskId>-<versionNo>/
  video.mp4
  subtitles.srt
  cover-landscape.jpg
  cover-alternative.jpg
  title.txt
  description.txt
  tags.txt
  publish-guide.md
  sources.json
  release-manifest.json
```

封面尺寸是输出模板能力，实施时按当时 B 站投稿页面核对，不在代码里假定平台尺寸要求永久不变。封面和标题必须忠于实际成片，不承诺未出现的内容。

### 17.2 清单不可缺少的关联

`release-manifest.json` 至少包含任务、故事板、完整视频版本、媒体对象摘要、处理任务、试映、选定文案版本、封面资产、生成时间、来源清单和未解决注意项。

同名 `video.mp4` 在不同包里可以存在，但清单摘要必须准确。打包前核对实际文件与选定版本，避免新版标题配旧视频。

`FULL/REVISION` 可以先生成可用默认文案包。用户另选标题/简介时创建新发布包快照，不覆盖原视频或旧包。

### 17.3 只改文案时的试映范围

视频字节和预处理产物未变，不重做配音、视频或 ASR。原报告继续明确显示当时使用的发布语境和标题。

新文案如需一致性检查，执行有限文本检查并保存独立结果；不能把旧报告冒充已经审过新标题。不得借此无条件重复整套付费试映。

### 17.4 导出门禁

- 正式发布包使用归属正确、媒体存在、匹配处理与完整试映完成的版本。
- 检查中的 MP4 可以作为“制作预览”单独下载，不能冒充就绪发布包或因此进入发布后链路。
- 样片按 SAMPLE 运行资产单独播放和下载，不要求创建整片版本，也不满足完整试映或发布门禁。
- SRT 和封面绑定其实际样片/视频版本；私有下载过期只重签，重复下载不重做音频或视频。
- 不要求清空所有可选 AI 建议。待确认观察和用户选择保留的表达建议随包说明。
- 打包不要求用户真的已经发布，也不修改 BV 绑定状态。

### 17.5 用户实际投稿

显示最终标题、简介、标签和封面，支持复制、下载，给出简明人工投稿步骤。保持由用户实际发布，不请求自动发布凭据，不在无人操作时产生投稿成功记录。

用户回填 BV 后，使用现有公开数据和归属校验，在事务外取得外部资料，保存前重新校验任务、选定发布版本及输入指纹。

### 17.6 发布后反馈

反馈和复盘只使用真实发布数据，包含采集时间与缺失项。没有真实 BV、播放、评论或弹幕时显示缺失，不能让三类 AI 观众填充成真实观众。

第一批视频的数据很少，不能把短时间低播放归因成脚本差，也不能据一条视频宣称制作方式提升流量。产品首先验证交付和修改能力，再观察用户是否愿意做下一条。

## 18. 配置、部署和运行前检查

### 18.1 尽量复用现有配置

沿用现有 OSS、媒体、FFmpeg/FFprobe、模型、日志和代理配置。只添加实际会使用的自动制作配置，建议统一前缀 `CREATOR_CREATION_*`：

| 建议配置 | 用途 / 初始原则 |
|---|---|
| `ENABLED` | 未通过阶段验收前默认关闭新入口 |
| `PYTHON_EXECUTABLE` | 实际可执行路径，不硬编码作者电脑的缓存目录 |
| `RENDERER_ROOT` | 已打包渲染器位置，不指向临时体验导出目录 |
| `WORK_DIR` | 可写、可检查磁盘空间的专用目录 |
| `MAX_CONCURRENT_RUNS` | 首发 1，先测资源再提高 |
| `DEFAULT_TASK_BUDGET_CNY` | 建议 20，正数，作为新任务初始值 |
| `RENDER_TIMEOUT_SECONDS` | 有界超时，按真实机器渲染耗时设置 |
| `LEASE_SECONDS` / `HEARTBEAT_SECONDS` | 不与超时混用，避免正常渲染被重复领取 |

制作配置中的分辨率、模板、字幕样式等可以保存在代码注册表与任务快照，不把每个视觉细节都做成部署环境变量。

模型和价格使用现有配置来源，TTS 若尚未接入则增加对应最小配置并在 `.env.example`、`application.yml`、Compose 之间保持一致。不能出现本地默认一个模型、容器默认另一个已下线模型。

### 18.2 运行时打包

Java worker 能启动的环境中必须具有锁定依赖的 Python、字体与 FFmpeg。Docker 部署要明确渲染器所在镜像、路径、运行用户和可写目录；主机安装成功不代表容器内可用。

不要求用户首次点击制作时临时 `pip install` 或下载字体。依赖在部署/构建阶段准备，不把生产运行建立在 `.tmp`、Codex 运行时路径或某次手工代理上。

首发统一合成继续采用 CPU 本地渲染。作者新增的 [可选 AI 视频生成](AI视频生成制作方式补充方案.md) 用于产生视频片段，再进入同一套工程合成、版本和试映流程；供应商与生成范围尚待确认，不能把本地合成能力写成已调用生视频模型。确有合成性能瓶颈时先记录阶段耗时和资源，再决定是否换引擎或部署形式。

### 18.3 能力检查分层

| 检查层 | 实际检查 | 不能据此声称 |
|---|---|---|
| 配置检查 | 所需字段、路径、模型 ID、开关是否存在 | 供应商一定可调用 |
| 本地运行检查 | 渲染器版本、字体、FFmpeg、短本地样例、目录权限与磁盘 | 真实 OSS 和供应商全链路可用 |
| 存储检查 | 从实际 backend 容器写/读专用小对象并验证 | 浏览器 CORS 一定正确 |
| 浏览器检查 | 实际页面 Origin 的预检、私有读取、ETag 和必要 Range 请求 | ASR 供应商回源一定可用 |
| 供应商检查 | 在明确测试预算内做最小真实调用并记录用量 | 所有模型和所有长视频都已验收 |

页面 GET 读取缓存检查状态，不默认触发付费自检。付费检查是部署者明确操作，计入专用测试预算。

### 18.4 OSS 网络与 CORS 要分开诊断

真实体验已经遇到：浏览器跨域规则错误、后端容器到香港 OSS 的 TLS/连接问题、主机和容器表现不同。三者不能统一报“视频文件损坏”。

- 浏览器检查以真实 `Origin` 为准，精确到协议、主机和端口；来源字符串不能带误输入的逗号。
- 方法、请求头和暴露 ETag 按实际上传需要设置；给出明确诊断，不自动扩大桶权限或改成公开读。
- 后端存储检查必须从最终运行容器执行；主机请求成功不能当作容器成功。
- 代理、OSS 内外网入口、浏览器入口和 ASR 回源入口按现有支持分别配置。
- FFprobe 协议错误、TLS 超时、签名过期、403 和真正无效媒体使用不同错误分类。
- 本次临时 CONNECT 通道已撤销，不能把它写成永久解决方案或内置服务。

### 18.5 启动前失败要可行动

缺字体、存储不可达、TTS 不可用等直接列出受影响能力和恢复建议。没有可用渲染器时仍允许独立生成标题简介，不能整个工作台白屏。

自动制作不能先收用户确认、花完策划费用，再首次发现部署没有 FFmpeg。能在付费前检查的依赖都提前检查。

## 19. 私有媒体、素材保留与删除

### 19.1 最小安全边界

本项目保护密钥和私有媒体。使用现有归属机制和私有存储即可，不把本功能升级为账号体系工程。

必须防止输入引用其他任务的私有资产、读取任意本地文件、执行任意命令、向模型泄露密钥。日志和导出包不包含鉴权头、完整短签 URL、`.env` 或供应商凭据。

### 19.2 缓存与历史的关系

- 资产可能被多个工程或视频版本引用，删除一个运行不能删除共有资产。
- 清理前同时检查当前版本、历史版本、活动运行、发布包和已发布版本引用。
- 同任务、同归属可复用不变资产。首发不做跨用户素材市场和全局私有内容缓存。
- 缓存命中不代表对象一定还在，使用前检查状态和实际可读性；缺失则重新准备或明确失败。

### 19.3 主动删除与工程可编辑性

接入现有媒体主动删除能力，增加清楚的选择与影响说明：只删除某版可播放媒体、删除制作中间素材、或删除整项任务，语义不能混淆。

删除报告可保留的事实和删除实际媒体是不同操作。若原片或关键制作资产被删除，界面说明不能继续播放/编辑，不以还保留的工程 JSON 假装媒体仍存在。

正在制作、正在被处理、被发布快照引用的对象按明确业务规则阻止删除或要求专门动作。不要静默破坏旧 BV 的资料依据。

### 19.4 本地临时目录

所有运行目录带任务、运行和尝试身份。配置容量上限和本功能专用的保留策略，但清理不进入创作者主流程。

测试结束清理本轮测试资源，保留作者要求的真实体验记录和发布产物。递归删除前核对规范化绝对路径属于本次测试目录；不得将 PowerShell 枚举结果交给另一种 Shell 拼命令删除。

## 20. 兼容、数据初始化与回退

### 20.1 存量任务不强制迁移

新功能默认关闭，按任务显式启用。没有创作工作区的旧任务保持原有读取行为；打开页面只读，不在 GET 中批量创建新表记录或修改历史版本。

启用时事务内创建工作区、校验原任务归属、识别当前有效 V1，并计算下一序号。若存在异常多条旧数据，列出冲突让部署者处理，不随意取一条。

### 20.2 SQL 的执行要求

- 使用统一 `init.sql` 的现有幂等方式增量建表和补列；执行前检查真实库结构。
- 判断库名使用当前连接或 `DATABASE()`，避免新补丁硬编码 `link_agent` 而误操作隔离测试库之外的环境。
- 不删除历史媒体表、历史版本和已生成报告，不先清空表“方便验收”。
- 对唯一键、默认值、非空字段和索引在隔离空库及含旧数据的隔离库各验证一次。
- 不把正常初始化脚本变成需要人工猜顺序的一组临时 SQL。
- 数据回填只补可验证关系；无法证明的发布版本保持未知。

### 20.3 代码兼容点

| 兼容点 | 必查行为 |
|---|---|
| 旧任务与已有成片入口 | 不强制重做发布方案和蓝图；仍不能跳过试映 |
| 旧上传会话恢复 | 会话继续对应原目标版本，不误指向当前新版本 |
| 精确版本接口 | owner、task、version 三者一致 |
| “当前”接口 | 工作区指针优先；旧任务 V1 回退有清楚边界 |
| 制作步骤失效 | 新候选不会提前删除旧媒体与旧报告 |
| 已发布绑定 | 不随当前选择改变，不补造缺失版本事实 |
| 原手动制作 | 不被自动 worker 批量勾选步骤 |
| 关闭功能开关 | 停止新自动制作，保留历史读取和必要取消能力 |

### 20.4 灰度与回退

初次只在隔离测试任务启用，先证明固定工程真实渲染，再接模型和真实供应商。达到阶段验收后再用于作者的下一条新视频。

回退采用关闭新入口和停止接收新运行，妥善取消/结束活动任务；保留新表和已存在对象，不用删库回退。旧链路继续工作，不把旧任务改成假 `planning_skipped` 来恢复页面。

已经生成并导出的文件不因回退消失。已发布作品的绑定和反馈仍读取原快照。

## 21. 实施顺序与每步交付

### 21.1 实施方式

按下表顺序推进，每轮只选择一个可闭环步骤或其明确子步骤。先向作者说明本轮范围，再实现、验证、交付；不要一次启动表中所有工作。

每步都要保留：改动清单、实际命令、观察结果、费用、未覆盖项和本轮资源清理记录。必要确认针对具体可审阅方案，不重复询问目标用户和产品主线。

| 步骤 | 交付目标 | 是否必须真实付费 |
|---|---|---|
| S0 | 代码/环境基线与接入差异清单 | 否；实际供应商检查另授权 |
| S1 | 创作持久化、任务预算基础和真实多版本 | 否 |
| S2 | 固定结构化工程真正生成媒体 | 否，可用有来源的本地音频 |
| S3 | 自动制作产物接入原有全链路 | 完整供应商试映验收需要 |
| S4 | 用户素材接入、混合媒体工程、结构化生成和配音 | 纯素材处理不需要；模型/TTS/ASR 按实际调用授权 |
| S5 | 素材与场景操作、样片/整片与下载、新手确认和恢复 | 模型路径需要；布局与现成产物下载不需要 |
| S6 | 素材/声音/范围的局部修改和新版对比 | 语义解释、新配音或 ASR 按实际需要 |
| S7 | 试映可信度、正式发布包和历史兼容收口 | 真实试映回归按需 |
| S8 | 跨主题、真实新手和发布后验证 | 用户实际投稿后才有真实反馈 |

阶段 S3 即需最小真实发布包，S7 是可信度与兼容收口，不能等到 S7 才首次实现 `FULL` 完成所需的打包步骤。

### 21.2 S0：建立基线

输入：本文、最新 AGENTS、文档索引、当前源码和工作区改动。

工作：

- 记录当前 Agent 迁移进度与模型调用实际归属。
- 枚举固定 V1、制作门禁、上传续传、处理/试映当前查询、BV 绑定和删除调用点。
- 核对实际 OSS 运行路径、字体、FFmpeg、Python 和配置来源。
- 标出原型中可提取模块与故事专有代码，禁止直接上线原型脚本。
- 根据实际资源修订默认超时、并发和本地目录设计；不操作已有服务和数据。

交付：一份短差异记录与 S1 的具体改动范围。发现影响 API、Schema 或产品交互的新取舍时，先给出具体差异请求确认，不能默默推翻本文。

验收：知道每个业务事实由谁写、已有门禁在哪里、阶段要用哪些真实资源。单纯核对配置不能标记环境全链路通过。

### 21.3 S1：先解决状态和版本

工作：

- 增量建立工作区、故事板、资产、授权、运行、步骤和费用的必要字段；暂未使用的能力不做空框架。
- 实现指纹、幂等、工作区乐观锁、唯一活动运行、任务预算预留的基础约束。
- 改造固定 V1 查询为明确当前指针，保留旧任务回退。
- 上传创建与续传绑定版本，精确版本查询不受当前指针变化影响。
- 维护已发布版本关系，拒绝 P0 已绑定任务的自动重制。

主要涉及：`init.sql`、`MediaUploadMapper`、上传服务、`CreatorMediaWorkflowGateService`、处理/试映查询、任务与绑定服务，以及拟新增 `creator/creation/` 模块。

验收：隔离旧任务 V1 仍可用；两版并存、独立读取；切换当前不覆盖旧版；续传不清空旧片；所有发布后入口校验实际选中版；并发启动只有一条运行；预算不能被并发透支。

不能用“表建好了”和纯 Mapper mock 代替数据库行为验收。

### 21.4 S2：固定工程真实渲染

工作：

- 建立 `RenderInputV1`、清单、受控布局、字体、音轨、字幕和错误契约。
- 将原型的有效制作路径提取到稳定 `renderer/`，去掉 `.env` 和供应商调用。
- 用预置真实素材与本地音频产生完整 MP4、SRT、封面和清单。
- 实现本地质量检查、进程超时/取消、工作目录边界和有界内存。

验收：同一结构支持至少几个不同内容工程，生成可解码可播放的完整视频；文字没有被裁掉；字幕和真实声音一致；错误工程明确拒绝；渲染进程不访问外网或读取密钥。

本步不需要调用模型。交付时说“确定性工程渲染已验证”，不能说“自然语言自动制作已完成”。

### 21.5 S3：接入现有业务全链路

工作：

- 实现持久化 worker、租约代数、阶段结果恢复与取消。
- 自动蓝图采用真实产物驱动，消除循环前置。
- 使用存储服务上传、验证并注册完整成片；不经过浏览器重复上传。
- 接原探测、预处理、完整试映，保存精确子任务关系。
- 实现最小版本发布包，完整运行最后才 `COMPLETED`。
- 真实供应商调用前接费用预留及现有日志归并。

验收：使用固定工程通过真实媒体链路；后台重启能恢复；浏览器刷新不重做；试映未完成时不误放行；没有伪造方案确认、制作完成或跳过状态。

完整供应商试映的真实验证需有明确测试预算；若只做到了本地媒体处理，按真实边界交付，不用替身报告补齐 `COMPLETED`。

### 21.6 S4：素材接入、结构化生成与声音处理

工作：

- 实现独立素材上传、探测、规范化和引用，不挤占完整视频版本；补齐用户音频/视频的真实元数据。
- 升级 RenderInputV2，支持场景视频截取、用户录音/原声、字幕来源和受控 BGM 混音，保留 V1 工程读取。
- 生成与验证简报、脚本、故事板和初版文案，复用当前模型调用栈。
- 将现有发布方案与新工程关联，减少为旧表单重复生成内容。
- 实现 TTS 适配与实际时长探测，按真实音频重建时间线。
- 限制修复性调用次数、输出量、价格和未知费用。
- RenderInputV2 能力实现后，跨主题使用同一渲染器版本，不为每个主题修改源码。

验收：至少三个不同主题均得到与输入相关、真实可观看的初稿；不能只改标题或把同一故事换名。素材需通过补充方案 M01–M08 的真实处理检查，不能用完整成片上传冒充片段导入。所有事实、素材、声音和调用有来源，任务费用没有漏项。

如果一个主题超出支持形式，准确返回边界和可行方案，不用未执行的生成步骤假装满足。

- 完成第 22 节跨主题、局部修改和恢复验收。
- 作者实际投稿后，用真实 BV 继续发布后链路；没有真实数据的阶段保持未验证。
- 根据第 23 节决定继续扩模板、改交互，还是先修交付质量。

验收：最终结论区分已验证能力、人工协助、失败案例、真实费用、未验证后链路。记录不能只保留最终顺利路径。

### 21.11 三个对外可解释的里程碑

| 里程碑 | 最少证据 |
|---|---|
| A：系统内完成第一条初稿 | 用户入口、真实工程、实际媒体、后台状态、可播放和导出；说明试映完整性 |
| B：不同主题无需改代码 | 三个不同主题，同一 renderer 版本，内容工程不同，均能播放 |
| C：一句话准确改出新版 | 原指令、修改提案、媒体差异、未变资产复用、费用和新版试映 |

“目录里出现一个 MP4”仅能证明 A 的部分证据，不是全部产品目标。

## 22. 测试与验收矩阵

### 22.1 证据等级

| 等级 | 可证明 | 不可证明 |
|---|---|---|
| 静态检查 | 路径、字段、约束和调用关系符合设计 | 运行时一定成功 |
| 单元 / mock | 指定输入下的分支、计算和拒绝行为 | 真供应商、OSS、浏览器链路可用 |
| 隔离集成 | 真实数据库并发、真实 FFmpeg、对象接口行为 | 新手能理解或愿意继续使用 |
| 真实供应商 | 指定模型与请求当次可用、用量真实 | 所有模型/所有内容都可用 |
| 浏览器端到端 | 实际用户入口和持久化状态能闭环 | 任意部署网络和真实流量效果 |
| 真实用户及发布 | 所选用户的操作、实际作品和观众数据 | 因果提升、普遍受欢迎或一定赚钱 |

以前修复通过的测试不计入新功能验收。每次报告都写明本次实际跑了哪一层。

### 22.2 工程契约与渲染

| ID | 场景 | 预期行为 / 证据 |
|---|---|---|
| R01 | 正常工程、本地图片和真实音频 | 生成清单与全部实际媒体，解码及浏览器播放通过 |
| R02 | 空场景、重复 ID、未知布局 | 在外部调用前拒绝，错误定位到字段 |
| R03 | CJK、标点、英文和长句混排 | 字体覆盖、实际换行、无溢出和裁字 |
| R04 | 字体不存在或缺字 | 明确失败/受控回退，不输出乱码冒充成功 |
| R05 | 图片 MIME 伪造、解码炸弹、越界路径 | 拒绝实际非法输入，不读取无关文件 |
| R06 | TTS 实测比预计长 | 重建时间线，字幕不越界，超目标时按策略处理 |
| R07 | 有转场重叠与不同场景长度 | 时长公式、帧数和最终文件相符 |
| R08 | 音轨缺失、削波、超响音乐 | 确定性检查发现，不能依靠视觉模型判断 |
| R09 | 渲染中断、编码失败、磁盘不足 | 有界停止，保留错误和已验证缓存，不注册假成片 |
| R10 | 相同输入、相同运行配置 | 关键输出或内容摘要符合确定性预期；容器/编码元信息差异单独解释 |
| R11 | 三个不同主题 | 渲染器源码和模板版本不变，内容与用户主题实际不同 |

不要为争取 MP4 二进制完全相同而隐藏编码元信息差异。缓存复用以已存在的原始资产摘要和受控工程输入为依据，验收说明可重复范围。

### 22.3 状态、并发和版本

| ID | 场景 | 预期行为 / 证据 |
|---|---|---|
| V01 | 同幂等键连续或并发提交 | 只创建一条业务运行、一次对应物理调用 |
| V02 | 同键不同正文 | 409，原运行不被改写 |
| V03 | 两页面同时开始制作 | 只有一个活动运行，另一个得到可恢复冲突 |
| V04 | 旧页面接受修改 | 预期版本校验失败，不覆盖新工程 |
| V05 | 租约过期后旧 worker 返回 | 不能完成新阶段或切换版本，真实费用仍归账 |
| V06 | 上传完对象后进程崩溃 | 按清单恢复或标记孤立对象，不重复发布或乱删 |
| V07 | V1 完整、V2 正在检查 | V1 仍可读；新版不能用 V1 报告进入后链路 |
| V08 | V2 上传失败后续传 | 只恢复 V2，不重置 V1 |
| V09 | 样片成功、整片失败 | 样片可看，完整版本没有被伪造 |
| V10 | 取消时供应商已提交 | 停止新调用，费用未知保留，旧片不被删除 |
| V11 | 任意 ID 引用另一任务资产 | 拒绝；不通过猜 ID 获取私有对象 |
| V12 | 当前版本变化后旧试映返回 | 报告归属旧版，不覆盖新版就绪状态 |
| V13 | 已绑定 BV 的任务尝试自动重制 | 按 P0 边界拒绝并提供新建任务方式 |
| V14 | 原有跳过任务后来启用自动制作 | 原上传版仍按真实跳过事实读取；系统生成版不能继承跳过确认 |

### 22.4 费用与供应商

| ID | 场景 | 预期行为 / 证据 |
|---|---|---|
| C01 | 准备、样片、整片、修改连续执行 | 同任务累计，不因新运行重置 |
| C02 | 两步骤争抢仅够一次的余额 | 事务预留只有一次成功，无透支 |
| C03 | 供应商超时且是否扣费未知 | 保留 UNKNOWN，不自动无限重试 |
| C04 | 有真实用量但 JSON 解析失败 | 仍计费，修复调用单独计费 |
| C05 | 全局日志和媒体日志描述同次调用 | 只按一个 `charge_key` 累计 |
| C06 | 取消或关闭页面 | 不释放已经发生/可能发生的费用 |
| C07 | 任务预算不足以完成试映 | 制作前就纳入预估，无法满足则提出缩减方案 |
| C08 | 模型 ID 不存在、声音无权限 | 快速失败，不对同一错误连试多次 |
| C09 | 缓存有效 | 不发生新 TTS/生图调用；不是仅将新费用隐藏 |
| C10 | 供应商实际值大于预留 | 记录异常并停止新增付费，不截断账目 |

### 22.5 修改的实际效果

| ID | 用户指令 | 必须核对 |
|---|---|---|
| E01 | “结尾这句话换成……” | 新音频确实说出新句，字幕相同，其他音频复用 |
| E02 | “字幕大一点” | 最终 MP4 字幕像素尺寸改变，不只是工程字段改变 |
| E03 | “第三幕用我这张图” | 正确场景实际显示该图，别的场景没有错换 |
| E04 | “第二幕放到最后” | 顺序、旁白、字幕和时长一起正确移动 |
| E05 | “标题换一个，视频不用动” | MP4 摘要不变，发布包文案变化，无额外媒体付费 |
| E06 | “更高级一点” | 给出具体可选提案，不静默整片重做 |

对 E01–E04 至少保留旧/新版抽帧、音频/字幕对照、场景映射和实际费用。不能只断言 patch JSON 等于预期。

### 22.7 浏览器与新手体验

实际页面检查至少覆盖：

- 新任务一句话开始；仅标题、仅简介和已有成片三个分流。
- 样片和整片区别，确认范围和费用可理解。
- 页面刷新、换任务、离开后回来、网络暂断和请求超时恢复。
- 当前运行结束自动显示视频，浏览器完整播放到结束，检查声音、字幕、帧和错误。
- 字幕以约 390px 宽的实际播放器截图检查，而非只在 1080p 原图看。
- 一条局部修改真实导出新版，旧版仍能播放。
- 真实浏览器私有对象读取、短签过期刷新、必要上传预检和 ETag。
- 生产入口与开发入口若不同，分别记录验证，不能用一个入口通过替代另一个。

真实用户体验记录应包含所有外部救场：开发者修改配置、人工改脚本、手工挪数据、另开工具渲染。发生救场就计入干预次数，不从结论里删掉。

## 23. 产品试验与继续投入的判断

### 23.1 第一轮不是验证流量增长

先验证配置好的部署能否独立交付作品。部署门槛与创作门槛分别统计，不能让用户装完环境花一小时，然后只报告“制作只用了两分钟”。

建议先让 3–5 名符合目标的人各完成一次，记录观察，不将小样本结果宣传成统计显著结论。若暂时只有作者和开发 AI 体验，明确样本限制。

### 23.2 指标定义

| 指标 | 具体定义 | 用途 |
|---|---|---|
| 初稿交付率 | 有实际可播放完整 MP4 的任务 / 明确开始制作的任务 | 看执行是否闭环 |
| 独立完成率 | 无专家代操作得到发布包的用户 / 参与用户 | 看是否真的服务新手 |
| 首次可观看耗时 | 用户确认准备/制作动作到可播放样片或初稿；两者分别统计 | 找出等待发生在哪一段 |
| 整片全链路耗时 | 明确制作动作到完整试映与发布包完成 | 不用 HTTP 返回时间冒充制作速度 |
| 局部修改成功率 | 用户要求的可支持修改实际生效 / 可支持修改请求 | 看可控性 |
| 外部干预次数 | 改代码、改库、改环境或代用外部工具的次数 | 揭示隐藏救场成本 |
| 任务费用 | 已知、未知预留、未计入分别统计 | 看预算可靠性 |
| 错误建议率 | 经逐项原片核对为错误的事实性建议 / 被核对建议 | 看试映可信度 |
| 自发第二条 | 用户未被要求演示，主动提出或开始第二条 | 看持续价值 |

没有完整记录的数据保持未知。不能只统计成功者、剔除卡在部署或付费失败的任务来抬高比例。

### 23.3 初始目标是实验目标

建议争取在配置完成的普通运行环境中，用户以少量明确决策得到 60–90 秒初稿，任务累计费用控制在约定上限内。性能目标在 S2/S3 测得实际吞吐后定，不先承诺“几分钟必出片”。

首次试验重点看：是否需要作者救场、是否愿意用结果投稿、是否能轻松改成自己想要的样子。有人看了初稿说“不喜欢”是有用反馈，应记录原因，而不是只增加一个模型评分。

### 23.4 根据结果决定下一步

| 观察 | 优先行动 |
|---|---|
| 能稳定出片，但用户觉得像模板 | 改构图、节奏、视觉差异和可选风格，不先接更多 Agent |
| 内容不错，但等待太久 | 分解真实耗时，减少重复模型调用、降低不必要思考、复用资产 |
| 初稿能看，但一句话改不对 | 优先改受限修改、场景映射和依赖失效 |
| 用户不会判断该改什么 | 给少量基于真实画面的可选改法和样例，不堆报告 |
| 费用和失败不透明 | 先修预留、恢复和用量归并 |
| 无人愿意做第二条 | 访谈首稿与预期差距，收窄场景，不用自动发布掩盖问题 |
| 受控素材组合已稳定且有人持续用 | 再评估竖屏输出、更多模板和新引擎 |

## 25. 风险、取舍与实施时需要确认的边界

### 25.1 已经可以按方向推进的决定

目标用户、新手优先、尽可能自动实现视频内容、独立文案入口、用户实际发布、个人自托管边界都已明确，不重复围绕这些问题停工。

本方案选择单一图文旁白形式、确定性渲染和局部修改作为建议落地路线。实施前评审具体范围，之后局部且可撤销的实现选择遵循现有惯例，不每个字段问一次。

### 25.2 主要风险与判断方法

| 风险 | 如何暴露 | 应对 |
|---|---|---|
| 自动出片但内容平庸 | 跨主题、真实用户评阅和自发第二条 | 先改内容与构图，不盲目增加模型 |
| 工程结构正确但画面不符合意图 | 原始请求、场景对照、真实预览 | 受限模板、样片、修改闭环 |
| 模型把不支持操作说成已完成 | 实际 MP4、资产和执行记录核对 | 能力白名单、结果基于真实运行 |
| CPU 渲染慢或占满资源 | 阶段耗时、峰值内存/磁盘 | 并发 1、流式生成、样片和缓存 |
| 老 V1 逻辑遗漏 | 上传/删除/试映/BV 的多版本回归 | 明确指针、版本上下文、逐调用审查 |
| 新候选破坏旧版就绪 | 取消后选回旧版的测试 | 确认与计划按版本保存，不只看最新候选 |
| 账目重复或未知被当零 | 调用 ID、日志关联和预留测试 | 物理调用去重，未知保留 |
| 三人设放大错误 | 同源观察与证据对照 | 共用事实包、假设标识、冲突复核 |
| OSS 主机通、容器不通 | 最终运行容器与真实浏览器分别验证 | 分类排查，禁止靠临时通道宣布永久解决 |
| Python 迁移与制作重复建栈 | 服务写表权限和模型客户端核对 | Java 业务所有权，复用当前协议与调用层 |
| 功能过多导致无法验收 | 每阶段产物与退出条件 | 按 S0–S8 推进，暂不扩任意视频 |
