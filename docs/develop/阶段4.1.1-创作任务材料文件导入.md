# 阶段 4.1.1：创作任务材料文件导入

## 需求分析

阶段 4.1 已经把创作任务、标题草稿、简介草稿、文稿和字幕的手工输入跑通了，但作者在实际使用时还需要把本地写好的文本文件直接导入到任务里，减少重复复制粘贴。

本阶段服务的还是 UP 主、内容运营者和内容复盘者。

要解决的场景是：

1. 用户先在本地整理好文稿或字幕文件。
2. 第一次创建任务时，用户可以先把本地文本文件导入到表单，再创建任务。
3. 用户打开已有创作任务时，可以把本地文本文件导入到对应材料。
4. 导入后继续做发布前优化、反馈分析和复盘。

本阶段只做：

1. 给已有创作任务补一个本地文本文件导入接口。
2. 在前端任务输入区提供常显文件选择入口。
3. 创建模式下先把文件内容填入表单，创建任务时再统一保存。
4. 编辑模式下通过后端接口覆盖已有材料，并让任务回到可重新分析的状态。

本阶段不做：

1. 复杂附件系统。
2. 二进制文件解析。
3. 平台采集或批量导入。

## 设计方案

### 后端设计

复用现有的 `creator_task` 和 `creator_material`：

1. 文件上传后只做 UTF-8 文本读取。
2. 按 `materialType` 定位到对应材料。
3. 使用已有材料表覆盖写入，不新增附件表。
4. 如果材料内容发生变化，把任务状态压回 `DRAFT`，避免旧建议继续被误用。

### API

```text
POST /api/creator/tasks/{taskId}/materials/import
```

请求方式：

```text
multipart/form-data
```

表单字段：

1. `materialType`
2. `file`

### 前端设计

1. 导入区常显在任务表单前面，保证首次创建任务时也能直接使用。
2. 创建模式没有 `taskId`，所以先用浏览器本地读取文件内容，填入标题草稿、简介草稿、文稿或字幕输入框。
3. 编辑模式已有 `taskId`，所以仍然调用后端导入接口覆盖数据库材料。
4. 导入完成后刷新当前任务和材料预览。

### 设计原因

1. 任务材料本身就是文本，没必要为了文件导入再建一张表。
2. 导入本质上是“覆盖当前材料”，和手工编辑是一类操作。
3. 创建模式还没有任务主键，不能直接调用材料导入接口；先填表再创建，才符合首次使用路径。
4. 编辑模式必须走后端接口，才能同步任务状态和旧分析结果。

## 编码实现

### 后端

新增：

1. `CreatorTaskController#importMaterial`
2. `CreatorTaskService#importMaterial`

实现重点：

1. 校验任务ID、材料类型和文件大小。
2. 只接受 TXT、MD、SRT、ASS 文本文件。
3. 读取 UTF-8 文本并去掉 BOM。
4. 复用 `creator_material` 覆盖对应材料。
5. 材料变化后将任务状态回退到 `DRAFT`。

### 前端

新增：

1. 任务输入区的常显文件导入面板。
2. 材料类型选择。
3. 创建模式本地读取并回填表单。
4. 编辑模式选择文件并上传到后端。

## 测试验证

作者本地需要验证：

1. 创建任务前选择 TXT/MD/SRT/ASS 文件，是否能直接填入对应输入框。
2. 正常上传 TXT/MD/SRT/ASS 文件是否能覆盖已有任务对应材料。
3. 空文件、超大文件、错误后缀是否返回明确错误。
4. 不存在的 `taskId` 是否返回 404。
5. 导入后任务状态是否回到 `DRAFT`。
6. 前端切换任务后，文件选择状态是否会清空。

## 后续体验调整

阶段 5 后，创建任务页已移除“本地文本文件导入”常显入口。

调整原因：

1. 当前产品主线更强调由 Agent 根据创作者任务推荐标题、简介和内容方向。
2. 如果用户已经完整写好文稿，再导入文件并不是创建任务的主要场景。
3. 文件导入入口会把首屏注意力从“创建创作任务”分散到“上传已有材料”，不利于引导用户使用智能工作台。

保留边界：

1. 后端 `POST /api/creator/tasks/{taskId}/materials/import` 仍作为兼容接口保留。
2. 当前主界面不暴露创建态导入，也不暴露已有任务材料文件覆盖导入。
3. 如后续确实需要恢复，应放在任务详情或高级操作区，并明确它是备用能力，不是默认创作入口。
