# 阶段 6.2 - PaE 重规划

## 一、需求分析

阶段 6 的 PaE 是一次性 Planner -> Executor -> Synthesizer。它能提升复杂任务覆盖度，但遇到工具不存在、工具失败或结果不足时，原计划会继续僵硬执行，后续步骤容易基于缺失事实被跳过。

本轮目标是在 PaE 中增加受控 Replanner。

本轮做：

- 执行失败时把已执行步骤、剩余步骤和失败指纹交给 Replanner。
- Replanner 只重规划剩余步骤，不重写已经成功的步骤。
- 重规划步骤重新编号，避免和旧步骤冲突。
- 最多重规划 2 次，防止在失败路径上来回振荡。
- Replanner 失败时保留原剩余计划，不让辅助能力成为主链路单点。

本轮不做：

- 不做每步无条件 Replanner。
- 不做 ReWOO 变量依赖图。
- 不持久化计划状态。

## 二、设计方案

### 2.1 执行状态

新增 `PlanExecutionState`：

- `objective`：原始目标。
- `executedSteps`：已经发生的执行事实。
- `remainingSteps`：尚未执行的原计划步骤。
- `failedFingerprints`：失败过的 action + actionInput。

### 2.2 Replanner

新增 `AgentReplanner`。

输入：

- 用户请求。
- 对话上下文。
- `PlanExecutionState`。
- 工具清单。

输出仍然是 `AgentPlan`，但语义上只包含剩余步骤。

### 2.3 执行器调整

`PlanAndExecuteAgent` 从固定 for 循环改为剩余步骤队列。

流程：

```text
Planner -> 执行一步 -> 失败时 Replanner -> 替换 remainingSteps -> 继续执行 -> Synthesizer
```

如果 Replanner 产出新步骤，会用 `AgentPlanNormalizer.reindexRemainingSteps` 重新编号。

## 三、验证清单

- 工具不存在时触发 Replanner。
- Replanner 不能重复已失败的 action + actionInput。
- Replanner 返回空步骤时，原失败保留为未完全成功。
- Replanner 失败时保留原剩余步骤。
- 成功重规划后的新步骤在 trace 中使用新的 stepId。
