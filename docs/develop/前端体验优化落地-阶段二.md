# 前端体验优化落地（阶段二：CreatorWorkspace 模板拆分）

## 目标

本阶段按 `前端体验优化落地-阶段二-拆分方案.md` 执行 CreatorWorkspace 拆分，先把用户可见的 tab 内容和左侧任务面板从主壳中移出，降低后续维护时定位模板的成本。

## 本轮改动

- `frontend/src/components/CreatorWorkspace.vue`：保留任务恢复、SSE 编排、toast、tab 导航和各类弹窗；tab 内容替换为子组件。
- `frontend/src/components/creator/TaskListPanel.vue`：承载左侧当前任务面板。
- `frontend/src/components/creator/MaterialsTab.vue`：承载视频资料表单。
- `frontend/src/components/creator/PrePublishTab.vue`：承载发布方案入口、AnalysisProgress 时间轴、偏好记忆和语境词预览。
- `frontend/src/components/creator/FeedbackTab.vue`：承载反馈导入、自动读取、手动粘贴和分析入口。
- `frontend/src/components/creator/ReportTab.vue`：承载复盘报告入口和 Markdown 导出入口。
- `frontend/src/components/creator/UsageTab.vue`：承载开发者模式下的 API 开销统计。
- `frontend/src/composables/creator/creatorWorkspaceUtils.ts`：集中展示格式化、标签翻译、状态判断等纯函数，避免子组件重复实现。
- `frontend/src/composables/creator/useCreatorWorkspaceContext.ts`：提供主壳到子组件的注入入口，保证子组件不重新创建工作流、反馈、任务等 composable。
- `frontend/src/types/creator.ts`：补充 `ResultModalTarget` 和 `CreatorActiveStep` 共享类型，避免类型继续散落在单个组件里。

## 边界说明

- 本轮没有修改 `package.json`，也没有新增样式文件；子组件继续使用全局 `creator-*` 类。
- 结果弹窗、开发者测试弹窗、工作流消息/过程弹窗和语境库弹窗继续留在主壳，因为这些弹窗依赖多个 tab 的数据和主壳状态。
- 当前 `CreatorWorkspace.vue` 仍保留旧桥接编排脚本。为了不改变任务恢复和 SSE 行为，子组件通过 context 调用主壳函数，而不是直接调用裸 composable 方法。

## 验证建议

开发者未执行构建、测试或启动命令，原因是项目规则禁止开发者执行此类命令。

作者需要执行：

```bash
cd frontend && npm run type-check
```

预期结果：类型检查通过。若失败，优先检查 `useCreatorWorkspaceContext.ts` 的注入字段和子组件模板引用。

作者需要执行：

```bash
cd frontend && npm run dev
```

预期结果：访问 `/creator` 后，视频资料、发布方案、观众反馈、复盘报告和开销统计 tab 均可正常切换；刷新页面后仍能恢复上次任务和 tab。
