# S3d：真实产物驱动自动蓝图

日期：2026-10-20。承接 [S3c 后台执行](视频自动制作-S3c固定工程后台执行.md)，落实总体方案 12.3–12.4 的自动步骤规则。输入仍为已确认的固定工程，公开入口仍关闭；本步不代表整个 S3 或自然语言自动制作完成。

## 需求与方案

之前的系统成片登记要求制作步骤已经完成，而后台制作正是这些步骤的执行者。测试预先完成步骤可以验证保存，却不能证明自动制作能自行通过门禁。

新增内部 `AutomaticProductionPlanService.start`，在同一事务内建立专属蓝图、受理 FULL 运行并绑定步骤。它要求当前真实发布方案确认，不能使用已有成片跳过入口替代确认。相同幂等键恢复同一次受理，改变输入会冲突；过期修订、预算不足等失败会连同新蓝图和步骤回滚。已有视频、报告及人工蓝图不被重置。

没有新增对外 API、前端页面、Agent 调用或 Redis 依赖。内部请求包含发布会话/结果、基准视频、故事板、工程内容摘要和目标时长，继续受当前固定工程 V1 的时长边界约束。新表只在统一 `init.sql` 中维护。

## 六个步骤及证据

| 步骤 | 何时完成 | 保存的依据 |
| --- | --- | --- |
| APPROVED 内容与工程已确认 | 整片受理成功 | 真实确认会话、方案、执行授权、故事板与内容摘要 |
| ASSETS 素材已准备 | 渲染产物实际验收后 | 本次工程资产与已核验文件事实 |
| TIMELINE 配音和时间线就绪 | 同上 | 工程时序、实际验收清单、场景和字幕数量 |
| RENDERED 成片和字幕生成 | 同上 | 文件名、字节数、SHA-256 与清单摘要 |
| LOCAL_QA 本地质量检查通过 | 同上 | 通过现有渲染器和 Java 产物验收的本次文件事实 |
| SAVED 私有成片与初版素材已保存 | 八个实际对象完成 PUT/HEAD/GET 校验后 | 私有桶、本次不可变对象引用和摘要 |

这不是六次模型调用，也不是逐阶段实时进度：当前固定执行器在实际本地渲染验收结束后记录四项本地证据，再由存储校验推进最后一步。初版素材限现有封面、字幕、抽帧、日志和清单；没有声称已生成投稿文案或最终发布包。

## 实现与一致性

- `creator_creation_auto_step` 只保存运行与原制作步骤的精确绑定及证据，步骤状态继续使用 `creator_production_step`，不另建状态副本。
- 每条产物证据绑定执行代数与尝试 ID。接管时不能采纳旧执行者的证据；重复保存相同证据不反复递增步骤版本。
- 自动步骤和成片登记共用 `CreationRuntimeService.requireProductionLease` 的数据库执行权检查。取消、失租、授权失效或进入发布后流程时不能继续采纳。
- `GeneratedDraftService` 在实际文件验收后记录本地证据，实际存储校验后记录保存证据；随后仍经过原完整制作门禁登记 UPLOADED 视频。
- `ProductionPlanPersistenceService.updateStep` 拒绝人工勾选或跳过系统步骤。原有未绑定的手工步骤继续按原规则更新，旧固定工程兼容路径保留。
- 没有自动写入完整试映、实际发布或 FULL 完成。登记后仍等待精确视频版本的媒体依赖。

## 验证及下一步

真实隔离 MySQL 覆盖受理幂等、旧视频/报告保留、失效确认、原子回滚、手动跳过保护、本地/存储证据顺序、取消和租约接管。实际 Spring 调度测试改为从六个待执行步骤开始，仅受理时完成 APPROVED；真实渲染和私有存储后完成全部六步。真实媒体取消测试检查其余步骤没有伪造完成。
