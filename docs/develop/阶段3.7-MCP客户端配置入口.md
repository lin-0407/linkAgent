# 阶段 3.7：MCP 客户端配置入口

## 上下文

阶段 3.5 已经把 Spring AI `ToolCallback` 适配为项目内部 `Tool`，阶段 3.6 确认了 Spring AI 1.1.4 已经提供 MCP 客户端自动配置。本轮把 MCP 客户端配置入口补到 `application.yml`，让后续接真实 MCP Server 时不需要再改 Java 代码。

## 本轮目标

让项目默认不启用 MCP，但保留完整配置入口。需要接入外部 MCP Server 时，只通过环境变量或配置文件打开。

## 本轮变更

- 修改 `application.yml`：
  - 新增 `spring.ai.mcp.client` 基础配置。
  - 默认 `MCP_CLIENT_ENABLED=false`，避免本地无 MCP Server 时启动失败。
  - 以注释形式保留 `stdio` 和 `streamable-http` 两类连接示例，避免空 `connections` 在 IDE 中报错。
  - 默认开启 `toolcallback`，让 MCP 工具能通过 Spring AI 自动生成 `ToolCallbackProvider`。

## 接入链路

```text
application.yml
  -> Spring AI MCP Client AutoConfiguration
  -> ToolCallbackProvider
  -> ToolRegistry
  -> SpringAiToolCallbackAdapter
  -> ToolExecutor
  -> AgentExecutor
```

这条链路的关键点是：MCP Server 不直接进入 `AgentExecutor`，而是先变成 Spring AI 的 `ToolCallback`，再适配成项目内部 `Tool`。

## 配置示例

### stdio MCP Server

```yaml
spring:
  ai:
    mcp:
      client:
        enabled: true
        type: sync
        stdio:
          connections:
            github:
              command: npx
              args:
                - -y
                - @modelcontextprotocol/server-github
              env:
                GITHUB_PERSONAL_ACCESS_TOKEN: ${GITHUB_TOKEN}
```

### streamable-http MCP Server

```yaml
spring:
  ai:
    mcp:
      client:
        enabled: true
        type: sync
        streamable-http:
          connections:
            docs:
              url: http://localhost:3001
              endpoint: /mcp
```

## 设计说明

本轮没有内置某个具体 MCP Server，因为当前项目还没有确定业务 Demo 场景。先把配置入口打开，等确定要接 GitHub、文件系统、浏览器或自定义业务 MCP Server 时，再新增对应的环境变量说明和验证案例。

## 验证方式

本项目约定 Maven 编译和测试由作者执行。当前默认关闭 MCP，本轮建议执行：

```bash
cd backend
mvn test -Dtest=ToolRegistryTest,ToolExecutorTest
```
