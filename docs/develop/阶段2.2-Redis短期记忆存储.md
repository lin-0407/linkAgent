# 阶段 2.2：Redis 短期记忆存储

## 上下文

阶段 2.1 已经完成进程内短期记忆，`AgentExecutor` 可以在同一个 `sessionId` 下读取最近几轮 Human / AI 对话。

本轮只解决一个问题：把短期记忆的“业务入口”和“存储实现”拆开，并新增 Redis 存储实现。默认仍使用进程内 Map，避免本地开发和单元测试强依赖 Redis。

## 本轮变更

- 新增 `ShortTermMemoryStore`：短期记忆存储接口。
- 新增 `InMemoryShortTermMemoryStore`：保留原来的进程内滑动窗口实现。
- 新增 `RedisShortTermMemoryStore`：使用 Redis List 保存同一 session 的最近消息。
- 修改 `ShortTermMemory`：只负责业务入口和窗口大小，不直接持有 Map。
- 新增配置 `agent.memory.short-term.store-type`：
  - `memory`：默认值，进程内存储。
  - `redis`：启用 Redis 存储。
- 补充内存存储单元测试。

## 关键设计

### 1. 保持 AgentExecutor 不感知存储细节

`AgentExecutor` 仍然只依赖 `ShortTermMemory`：

```java
shortTermMemory.getRecentMessages(sessionId);
shortTermMemory.append(sessionId, "Human", userMessage);
```

这样后续从 Redis 继续演进到 MySQL、摘要记忆或长期记忆时，Agent 主循环不需要频繁变化。

### 2. Redis 使用 List 做滑动窗口

写入时执行：

```text
RPUSH key message
LTRIM key -maxMessages -1
```

这能保留最近 `maxMessages` 条消息，读取顺序仍然是从旧到新，和内存实现一致。

### 3. 默认不强依赖 Redis

默认配置是：

```yaml
agent:
  memory:
    short-term:
      store-type: ${SHORT_TERM_MEMORY_STORE_TYPE:memory}
```

只有设置 `SHORT_TERM_MEMORY_STORE_TYPE=redis` 时，才启用 Redis 存储实现。

## 验证方式

### 默认内存模式

```bash
cd backend
mvn test -Dtest=ShortTermMemoryTest,InMemoryShortTermMemoryStoreTest
```

### Redis 模式

先启动 Redis，然后设置环境变量：

```bash
set SHORT_TERM_MEMORY_STORE_TYPE=redis
set REDIS_HOST=127.0.0.1
set REDIS_PORT=6379
```

启动后端后，连续请求同一个 `sessionId`，再用 Redis 查看：

```bash
LRANGE link-agent:memory:short-term:<sessionId> 0 -1
```
